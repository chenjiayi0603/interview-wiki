## 1. 项目概述

### 1.1 项目定位

OpenIM 是一个面向开发者的开源即时通讯（IM）解决方案。与微信、Telegram、Signal 等面向终端用户的独立聊天应用不同，OpenIM 专为开发者提供即时通讯 SDK 和服务端，帮助开发者快速在自己的应用中集成强大的 IM 功能。

### 1.2 核心设计理念：双核心架构

```
┌─────────────────────────────────────────────────────────────────┐
│                         OpenIM 整体架构                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────────────┐ │
│  │  核心组件   │    │  核心组件   │    │     业务系统        │ │
│  ├─────────────┤    ├─────────────┤    ├─────────────────────┤ │
│  │ OpenIM     │    │ OpenIM     │    │  OpenIM Chat        │ │
│  │ Server     │    │ SDK Core   │    │  (用户系统+后台管理) │ │
│  │            │    │            │    │                     │ │
│  │ IM服务端   │    │ 跨平台SDK  │    │  管理后台前端        │ │
│  │ 私有化部署 │    │ 核心库     │    │  多平台Demo应用     │ │
│  └─────────────┘    └─────────────┘    └─────────────────────┘ │
│                                                                 │
│  核心框架稳定，业务层可二次开发，互不影响                        │
└─────────────────────────────────────────────────────────────────┘
```

### 1.3 技术亮点

- **自研批处理器**：高性能泛型批处理，支持并发和负载均衡
- **多级缓存策略**：Redis 缓存 + 本地 LRU 缓存，提升访问性能
- **实时消息同步**：WebSocket 长连接 + 增量同步机制
- **智能机器人框架**：可扩展的 AI 代理系统
- **协议驱动开发**：基于 protobuf 的 API 设计优先

## 2. 完整技术栈

### 2.1 编程语言

| 语言 | 占比 | 使用场景 |
|------|------|----------|
| **Go** | 97.1% | 核心服务端、SDK、工具链 |
| Shell | 1.4% | 部署脚本、运维脚本 |
| Dockerfile | 1.2% | 容器构建 |

**Go 语言选型原因**：
- 高并发：Goroutine 天然支持百万级连接
- 轻量级：内存占用低，适合微服务架构
- 跨平台：一次编译，多平台部署
- 丰富生态：成熟的 WebSocket、gRPC、Redis 客户端库

### 2.2 核心框架与库

| 框架/库 | 用途 | 代码路径 |
|---------|------|----------|
| **Gin** | HTTP/WebSocket 网关 | `api/` |
| **gRPC** | 服务间 RPC 通信 | `rpc/` |
| **gorilla/websocket** | WebSocket 长连接 | `msggateway/` |
| **Protocol Buffers** | 接口定义与序列化 | `proto/` |

### 2.3 数据库组件

#### 2.3.1 MongoDB

```yaml
用途：消息持久化存储
代码路径：pkg/common/storage/database/mgo/
配置：config/mongodb.yml
```

**使用场景**：
- 聊天记录存储（消息量大、schema 灵活）
- 群组信息存储
- 用户会话数据
- 历史消息查询与归档

**选型原因**：
- 文档模型：消息格式灵活，支持富媒体消息
- 高写入性能：适合 IM 场景的高并发写入
- 水平扩展：支持分片集群，满足海量数据存储

#### 2.3.2 MySQL

```yaml
用途：结构化业务数据
代码路径：pkg/common/storage/database/mysql/
配置：config/mysql.yml
```

**使用场景**：
- 用户账户信息
- 好友关系（好友列表、黑名单）
- 群组成员关系
- 系统配置数据

**选型原因**：
- 事务支持：好友关系、群组关系需要 ACID 保证
- 关联查询：复杂的关系查询更高效
- 成熟稳定：生产环境验证充分

#### 2.3.3 Redis

```yaml
用途：缓存与实时状态
代码路径：pkg/common/storage/database/redis/
配置：config/redis.yml
```

**使用场景**：
| 功能 | Redis 数据结构 | 说明 |
|------|---------------|------|
| 消息序列号 | String | 保证消息全局唯一序号 |
| Token 存储 | String + Hash | 用户认证 token |
| 在线状态 | Hash | 用户-设备映射关系 |
| 消息推送队列 | List | 离线消息待推送 |
| 订阅发布 | Pub/Sub | 状态变更通知 |
| 分布式锁 | String | rockscache 实现缓存一致性 |

**选型原因**：
- 超高性能：内存数据库，毫秒级响应
- 丰富数据结构：String/Hash/List/Pub-Sub
- 持久化支持：RDB + AOF 保证数据安全

### 2.4 消息队列：Kafka

```yaml
用途：异步消息处理、系统解耦
代码路径：pkg/common/storage/kafka/
配置：config/kafka.yml
```

**Kafka Topic 设计**：

| Topic 名称 | 生产者 | 消费者 | 用途 |
|-----------|--------|--------|------|
| `latestMsgToRedis` | 消息网关 | 消息转发 | 最新消息写入 Redis |
| `msgToMongo` | 消息网关 | 消息转发 | 消息持久化到 MongoDB |
| `msgToModify` | 消息网关 | 消息修改 | 消息撤回/编辑 |
| `triggerPushEvent` | 各服务 | 推送服务 | 触发离线推送 |
| `offlinePush` | 推送服务 | 离线推送处理器 | 离线消息推送 |

**选型原因**：
- 高吞吐量：支持每秒 10 万+ 消息
- 持久化：消息不会丢失
- 分区扩展：支持水平扩展消费能力
- 消费组：多消费者负载均衡

### 2.5 服务发现：etcd

```yaml
用途：服务注册与发现
代码路径：pkg/common/discovery/etcd/
配置：config/etcd.yml
```

**使用场景**：
- RPC 服务注册：各微服务启动时注册到 etcd
- 服务发现：客户端通过 etcd 发现可用的服务节点
- 配置中心：存储和管理配置信息
- 分布式锁：服务间协调

**选型原因**：
- 高可用：Raft 协议保证强一致性
- 轻量级：比 Zookeeper 更简单易用
- TTL 机制：服务健康检查自动化
- Go 原生支持：clientv3 库官方支持

### 2.6 对象存储：MinIO

```yaml
用途：文件存储（图片、语音、视频、文件）
配置：config/minio.yml
```

**使用场景**：
- 用户头像
- 图片消息
- 语音/视频消息
- 文件传输

**选型原因**：
- S3 兼容：与 AWS S3 API 完全兼容
- 私有部署：数据完全自主控制
- 分布式：支持多节点集群部署
- 高性能：支持大文件分块上传

### 3.2 服务职责详解

#### 3.2.1 API 网关服务 (openim-api)

```yaml
代码路径：cmd/openim-api/
配置文件：config/openim-api.yml
端口：10002 (默认)
```

**职责**：
- 提供 RESTful API 接口
- HTTP 请求路由到对应的 RPC 服务
- 请求认证与参数校验
- 响应格式统一处理

**核心 API 分组**：

| API 分组 | 路径前缀 | 用途 |
|---------|----------|------|
| 认证 API | `/auth/` | 用户登录、注册、Token 刷新 |
| 用户 API | `/user/` | 用户信息管理 |
| 好友 API | `/friend/` | 好友关系管理 |
| 群组 API | `/group/` | 群组管理 |
| 消息 API | `/message/` | 消息发送与历史查询 |
| 会话 API | `/conversation/` | 会话管理 |

#### 3.2.2 消息网关服务 (openim-msggateway)

```yaml
代码路径：cmd/openim-msggateway/
配置文件：config/openim-msggateway.yml
端口：10001 (WebSocket默认)
```

**职责**：
- WebSocket 连接管理
- 用户登录认证
- 消息路由与转发
- 在线状态管理
- 心跳检测

**技术实现**：
```go
// 连接结构设计
type UserConn struct {
    UserID      string
    DeviceID    string
    PlatformID  int
    Conn        *websocket.Conn
    HeartbeatAt time.Time
}

// 用户-连接映射 (多设备支持)
type UserConnMap struct {
    sync.RWMutex
    // UserID -> []*UserConn (多设备)
    conns map[string][]*UserConn
}
```

// etcd 服务注册
type ServiceRegistry struct {
    client     *clientv3.Client
    leaseID    clientv3.LeaseID
    serviceName string
    endpoint    string
}

// 注册服务
func (r *ServiceRegistry) Register(ctx context.Context) error {
    // 1. 创建租约 (TTL 10秒)
    resp, err := r.client.Grant(ctx, 10)
    if err != nil {
        return err
    }
    r.leaseID = resp.ID
    
    // 2. 注册服务
    key := fmt.Sprintf("/services/%s/%s", r.serviceName, r.endpoint)
    _, err = r.client.Put(ctx, key, r.endpoint, clientv3.WithLease(r.leaseID))
    if err != nil {
        return err
    }
    
    // 3. 续约 (保活)
    go r.keepAlive(ctx)
    
    return nil
}

// 服务发现
func (r *ServiceRegistry) Discover(ctx context.Context, serviceName string) ([]string, error) {
    prefix := fmt.Sprintf("/services/%s/", serviceName)
    
    resp, err := r.client.Get(ctx, prefix, clientv3.WithPrefix())
    if err != nil {
        return nil, err
    }
    
    var endpoints []string
    for _, kv := range resp.Kvs {
        endpoints = append(endpoints, string(kv.Value))
    }
    
    return endpoints, nil
}
