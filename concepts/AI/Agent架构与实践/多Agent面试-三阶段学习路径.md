# Multi-Agent 学习路径（三阶段 · 纯展开）

> 按《学习资料》阶段一～三的任务树整理；每项下为「学什么、掌握到什么程度」，**不含链接与资源表**。

---

## 阶段一：基础入门（1～2 周）

### 1. 理解 Agent 核心概念

#### 阅读：AI Agent 面试精选 15 题（基础概念部分）

把「Agent」从聊天里拆出来：有目标、能多步执行、能调用外部能力（工具/API）、能根据反馈调整下一步。基础概念部分重点搞清：和普通「一问一答」差在哪，最小闭环（感知 → 决策 → 行动 → 再感知）长什么样，以及面试里常问的「规划、工具、记忆、终止条件」各指什么层次。读完后能用自己的话 1 分钟讲清楚「什么叫 Agent」，并说出两类反例（不该硬上 Agent 的场景）。

#### 阅读：Agent 核心面试题 2026（Q1～Q3）

把前几道题当成「口述题」练：每题按「结论 → 理由 → 例子 → 边界」四句话组织，避免背定义。若题里出现多 Agent、协作、反思等词，先建立**词汇与问题域的对应**，不必一次挖透；标记不会的词条，留给阶段二、三补。目标是：任选一题能录音 1 分钟，不跑题、不空洞。

#### 实践：运行一个简单的 ReAct Agent

ReAct 本质是「推理」和「行动」交替：模型先想一步，再决定要不要调工具，把工具结果放回上下文再继续想，直到给出最终答案或触达停止条件。实践上你要真的跑通一轮：工具列表、调用格式、最大步数或超时、如何避免死循环。跑完后能画一张**时序图**（用户 → 模型 → 工具 → 模型 → … → 答案），并能口头对比「多步 ReAct」和「单次思维链」的差别。

---

### 2. 掌握 Multi-Agent 基础

#### 阅读：六大核心协作模式

建立「拓扑感」：任务在多个 Agent 之间是顺序传递、路由到某一支、并行再汇合，还是更松散的网状、更高自主度的形态。每种模式脑子里要有一个**业务例子**（例如流水线审批、分类后分派、多源检索合并）。同时要能说清代价：延迟、成本、调试难度、一致性——面试问「为什么不用并行」时，能答到冲突与聚合问题。

#### 阅读：五大经典设计模式

区分「谁负责什么」：分层、对等、工具链、责任链、共享状态等，是在谈**角色与职责**，和上一节的「执行拓扑」互补。读的时候做一件事：用**同一个场景**分别用「一种六大模式 + 一种五大模式」各描述一版架构，避免两套术语混成一锅粥。目标是能回答：共享状态会带来什么一致性与并发问题，责任链和顺序流水线有什么同与不同。

#### 阅读：MetaGPT 实战解析（架构部分）

只抓架构：多角色如何分工、标准作业过程（SOP）如何驱动从需求到产物的流转、中间产物为什么往往是结构化文档或代码树（便于下一角色消费和人可读）。阶段一不必深究部署与业务细节；能口述「角色—输入输出—谁依赖谁」即可，并为阶段三里「读懂 MetaGPT 代码结构」留钩子。

---

### 3. 了解主流框架

#### 体验：CrewAI Quick Start

建立「班组」心智：Agent（人设与能力）、Task（工单与交付物）、Crew（一组角色与任务）、Process（先后或协作策略）。动手改一个角色描述或增加一个任务，观察输出变化。阶段一目标：能用 CrewAI 的概念**对应**到你在「六大模式」里学过的某一种拓扑（例如顺序班组）。

#### 体验：MetaGPT Minimal Example

建立「软件工程多角色 + SOP」心智：跑通最小示例后，对照架构阅读里提到的角色，在日志或产物里指出「这一步是哪个角色」。体会「结构化中间产物」对排错的意义。阶段一目标：能说明若某一环输出变差，你优先会改 SOP、角色提示，还是工具与环境。

#### 阅读：AutoGen Getting Started

建立「对话式多 Agent」心智：多个 Agent 如何通过消息协作、会话何时结束、框架默认帮你承担了哪些路由与状态工作（与 CrewAI 的 Task/Crew 叙事对比）。阶段一以读懂概念为主，本地是否跑通视时间而定。目标：一句话比较「班组工单式」与「多角色对话式」各自更适合什么沟通形态。

## 阶段二：核心深入（2～3 周）

### 1. 深度理解协作模式

#### 阅读：谷歌八种设计模式

在阶段一的「顺序 / 路由 / 并行 / 层次」之上，补全工业叙事里常见的变体：例如协调器与分发器、扇出与聚合、生成器与评判器、迭代改进、人机在环、复合模式等（以原文为准）。重点不是背八种名字，而是能说明**每一种解决什么协调问题、增加什么系统复杂度**。读完能画「我们业务」适用哪一种，并说出不选别种的理由。

#### 阅读：Agent 编排三种模式

从「权力结构」理解：单 Agent 独走、主从（中央调度与执行者）、对等网络（多节点协商）。把它和「执行时序」类模式对照：前者回答谁说了算，后者回答谁先谁后、谁并行。能回答：主从的瓶颈在哪，对等网络下如何避免震荡或死锁式扯皮（工程上常用超时、仲裁、共识简化版等）。

#### 阅读：Microsoft 编排模式指南

把官方术语（如顺序、并发、交接、监督者等，以文档为准）落到**可观测行为**：状态存在哪、交接时上下文怎么传递、监督者如何做路由与重试。目标：若面试官让你设计 Azure 风格的 Agent 编排，你能用文档里的分类组织答案，并点出人机交接与审计需求。

---

### 2. 掌握通信协议

#### 阅读：MCP / A2A / ACP / ANP 协议详解（对比类材料）

建立分层观：哪些协议偏「模型宿主与工具/资源对接」，哪些偏「Agent 与 Agent 跨系统互操作」，哪些偏「人机界面或应用协议」。面试常见追问：与 REST、gRPC、消息队列是什么关系——通常协议规范的是**能力发现、认证、消息语义**，传输仍可由现有基础设施承载。阶段二结束能做单选题式判断：给定场景该先谈 MCP 还是 A2A。

#### 阅读：AI Agent 协议深度研究

在对比阅读基础上，抓一条主线：**谁发现谁、谁认证谁、错误与幂等怎么处理、长任务怎么关联会话**。能用自己的话说明「没有协议时团队会踩哪些集成坑」，以及引入协议后仍未解决哪些问题（例如业务语义一致、成本与权限）。

---

### 3. 理解记忆系统

#### 阅读：Agent 记忆综述

从「形式—功能—动态」或类似框架理解记忆：存什么、为谁服务、如何随时间更新与遗忘。不必死记论文段落，要能画一张**记忆分层图**（工作记忆 / 情景 / 语义 / 偏好等常见分法），并对应到工程组件（上下文窗口、向量库、KV/图库、摘要任务）。

#### 阅读：Agent 记忆完全指南

把分层记忆和具体实现手段对齐：何时写入、何时检索、何时压缩摘要、多 Agent 共享记忆时一致性与隐私怎么处理。能回答：为什么多 Agent 系统里「共享状态」既是设计模式又是工程风险点。

#### 阅读：RAG 与 Memory 对比

分清检索增强与跨会话记忆：前者偏「查外部知识」，后者偏「持续个性化与经验积累」；二者可结合。能举例：仅 RAG 不够的场景、仅 Memory 不够的场景，以及 Agentic RAG 与记忆写回怎样配合。

---

### 4. 阅读核心论文

#### MetaGPT 论文

抓贡献与系统结构：多角色、消息与动作、如何落到可执行软件工件。精读图表与算法块，弱读实验数字。能用 3 分钟口述「问题—方法—适合场景—局限」。

#### ReAct 论文

抓「推理与行动交织」相对纯推理或纯工具调用的收益与条件。能说明在工程里 ReAct 对工具描述、停止策略、上下文长度的依赖；并和阶段一的实践闭环对上号。

## 阶段三：面试冲刺（1～2 周）

### 1. 面试题专项

#### AI Agent 面试精选 15 题（全部）

按主题分组刷：基础概念、ReAct 与工具、规划与执行、多 Agent 架构。每题写「30 秒版 + 2 分钟版」两种口述稿；重复问法合并，避免背 15 个孤立答案。目标：随机抽题能开口，不依赖提示词小抄。

#### Agent 面试速成清单

用来**压缩知识**：把清单当目录，不会的回到阶段一、二对应块补缺。重点过一遍「高频闭环」：工具、规划、评估、安全、成本。目标：考前 1～2 天能靠清单过一轮无断层。

#### AI Agent 面试八股文 100 问

用来**补广度**：不必全背，标记高频与自身简历相关条目，其余知道「属于哪一类、该从哪条线答」。目标：减少「完全没听过」的盲区，把陌生词归并到已建立的框架里。

---

### 2. 面经实战

#### 阿里 Agent 一面经验

当模拟题库：限制时间写要点，再对照原文看自己漏了哪类考点（LangChain/LangGraph、多 Agent、协议等）。提炼「追问链」：面试官从一个答案会怎么往下钻，提前准备第二层答复。

#### Multi-Agent 协同模拟面试

练「系统设计口吻」：角色、数据流、故障与降级、观测与评估。答完一轮录音，检查是否堆砌名词而无拓扑与状态归属。

#### 牛客 Agent 面试题整理

查漏补缺：安全、评估指标、通信协调等易忽略块。把题目按标签归档到自己的笔记，避免重复劳动。

---

### 3. 项目准备

#### 使用 CrewAI 构建一个多 Agent 协作项目

准备可演示的一条链路：输入 → 多角色协作 → 可交付输出。能说清：为何拆成这些角色、Process 选型的理由、失败如何处理、成本与延迟大致来自哪里。简历与面试叙事与代码一致，避免「只会 demo 说不清为什么」。

#### 理解 MetaGPT 代码架构

在仓库层面知道：角色与动作注册在哪、消息总线或调度入口在哪、产物落盘与配置从哪读。目标：面试官问「若二次开发从哪改」时能指到模块层级，并结合阶段一的 SOP 叙事解释扩展点。
