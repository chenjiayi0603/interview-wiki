## 一、阶段定位与总目标

### 1.1 你在本阶段要解决什么问题

| 维度 | 阶段一结束时你应能…… |
|------|----------------------|
| **概念** | 说清楚 Agent 与「单次 Chat」的区别；能解释规划、工具、记忆、多步闭环在面试里常怎么问。 |
| **单 Agent** | 理解 ReAct（Reason + Act）循环；能口述一步「观察–思考–行动」与工具返回如何进入下一轮。 |
| **多 Agent** | 区分「协作模式」与「设计模式」两套说法；能举例 2–3 种典型拓扑（顺序、路由、并行等）。 |
| **工程感知** | 在本地跑通至少一个 ReAct 类 demo；对 CrewAI / MetaGPT / AutoGen 各有一次「从文档到运行」的体验。 |

### 1.2 时间建议（1–2 周）

- **偏理论**：每天 1.5–2.5 小时，按下面「每日建议」拆块。  
- **偏动手**：同一周可多留 2–3 个半天给框架 Quick Start，避免只读不跑。

### 1.3 建议产出物（写进笔记即可）

1. **一页纸**：ReAct 循环示意图 + 自己话写的 5 句话总结。

3. **运行记录**：三个框架各一条命令级记录（环境、版本、跑的示例名、报错与解决）。

## 二、模块 1：理解 Agent 核心概念

对应原路径：

- 阅读：AI Agent 面试精选 15 题（基础概念部分）  
- 阅读：Agent 核心面试题 2026（Q1–Q3）  
- 实践：运行一个简单的 ReAct Agent  

### 2.1 阅读任务 A：AI Agent 面试精选 15 题（基础概念部分）

- **链接**：https://blog.csdn.net/lvaolan168/article/details/156113926  
- **怎么读**  
  1. 第一遍：只标出**定义句**和**对比句**（Agent vs 工作流、Agent vs RAG 等若文中出现）。  
  2. 第二遍：把每道题改成「**如果是我，30 秒怎么答**」的口头提纲（条目式，不抄全文）。  
- **建议抓取的知识点**  
  - Agent 的**最小闭环**：目标 / 感知（上下文、工具结果）/ 决策 / 行动 / 终止条件。  
  - 与「纯 Prompt 一次问答」相比，多出来的**状态**与**外部动作**是什么。  
  - 面试里高频词：**工具调用（function calling）**、**规划（planning）**、**反思（reflection）**——先建立词汇与场景的对应，不要求一次深透。  
- **自测**  
  - 能否不看文章，用**自己的项目或生活例子**类比「Agent」？  
  - 能否说出「什么时候不该上 Agent」？

### 2.2 阅读任务 B：Agent 核心面试题 2026（Q1–Q3）

- **链接**：https://blog.csdn.net/m0_57081622/article/details/157394199  
- **怎么读**  
  - 每题按 **Claim（观点）→ Reason（理由）→ Example（例子）→ Limit（边界）** 四行整理。  
  - 若文中出现「Multi-Agent / 设计模式 / 反思」等，**只记与 Q1–Q3 直接相关的部分**，其余留到阶段二、三。  
- **与模块 2、3 的衔接**  
  - Q1–Q3 里若已出现「协作、角色、冲突」等词，读完后在模块 2 的「六大模式」里**找对应标签**，形成重复记忆。  
- **自测**  
  - 任选一道，**录音 1 分钟**自答，听是否啰嗦、是否缺「边界条件」。

### 2.3 实践：运行一个简单的 ReAct Agent

- **理论补充阅读（可选但强烈推荐）**  
  - ReAct 原理（母文档 3.1）：https://blog.csdn.net/pythonhy/article/details/138720102  
  - 论文（阶段二会再读，此处可扫摘要）：*ReAct: Synergizing Reasoning and Acting in Language Models* — https://arxiv.org/abs/2210.03629  
- **实践目标（验收标准）**  
  1. 环境中能调用 LLM（本地或云端 API 均可）。  
  2. 跑通一个**最小**循环：**模型输出思考 → 决定调用某工具或不调用 → 若有工具则执行并把结果塞回上下文 → 再推理直至结束**。  
  3. 在笔记里记录：**工具列表、终止条件、最大步数**（防止死循环）。  
- **实现路径示例（择一即可）**  
  - **LangChain 文档**中的 Agent 快速入门（母文档 1.3 编排处亦有入口）：https://docs.langchain.org.cn/oss/python/langchain/quickstart  
  - 或后续模块的 CrewAI / MetaGPT 中带 ReAct 风格的示例，但阶段一更建议**先小后大**：优先最小脚本或 LangChain 单 Agent，再进多 Agent 框架。  
- **常见坑（面试也会问）**  
  - 工具描述不清导致**错选工具**；  
  - 无步数上限导致**循环**；  
  - 把「工具返回」原样堆进上下文导致**上下文爆炸**（可先了解，阶段二再系统学记忆与压缩）。  
- **自测**  
  - 画一张**时序图**：User → LLM → Tool → LLM → … → Final Answer。  
  - 口头回答：ReAct 与「一次性 CoT」差在哪里？

## 三、模块 2：掌握 Multi-Agent 基础

对应原路径：

- 阅读：六大核心协作模式  
- 阅读：五大经典设计模式  
- 阅读：MetaGPT 实战解析（架构部分）  

### 3.1 阅读：六大核心协作模式

- **链接**：https://blog.csdn.net/Gaga246/article/details/151399049  
- **文中典型模式（与记忆对齐）**  
  - **Sequential**：流水线，上游输出作下游输入。  
  - **Router**：由调度或分类决定走哪条分支。  
  - **Parallel**：多路并行再汇总。  
  - **Generator**：一类生成 + 可能的多版本或迭代（视原文表述为准）。  
  - **Network**：更灵活的网状交互（与固定流水线相对）。  
  - **Autonomous Agents**：更高自主性、目标驱动（注意与「无人值守」风险话题的联系）。  
- **怎么读才不算白读**  
  为每种模式建表（建议直接贴在个人笔记里）：

| 模式名 | 一句话 | 适用场景 | 主要风险 / 代价 |
|--------|--------|----------|-----------------|
| … | … | … | … |

- **面试挂钩**  
  - 「你们业务更像 Sequential 还是 Router？」  
  - 「并行之后怎么聚合？投票还是 LLM 摘要？」  

### 3.2 阅读：五大经典设计模式

- **链接**：https://blog.csdn.net/2403_88078374/article/details/159435841  

- **五种模式各举一例**（场景统一用「软件需求 → 交付」好记；实际可换成客服、投研等）  

  1. **分层协作**  
     - **含义**：上层做决策与分解，下层执行并上报，职责按层级切开。  
     - **举例**：「架构师 Agent」只产出模块边界与技术选型；「开发 Agent」只按接口实现；「测试 Agent」只对照契约写用例。上层不直接改代码，下层不擅自改总体方案。  

  2. **对等协作**  
     - **含义**：多个 Agent 地位相近，通过协商、投票或轮流发言达成一致。  
     - **举例**：「安全审查」「性能审查」「业务审查」三个 Agent 各自审同一版设计文档，最后由「协调 Agent」汇总冲突点（如对某接口是否暴露）再迭代一版文档。  

  3. **工具调用**  
     - **含义**：Agent 不自带全部能力，通过统一工具接口访问外部系统（检索、执行代码、查库）。  
     - **举例**：「实现 Agent」在写模块前调用 `grep_repo` 查是否已有类似实现；写完后调用 `run_tests`；失败则读日志再改——工具是能力外延，不是又一个聊天角色。  

  4. **责任链**  
     - **含义**：请求依次经过多个处理者；每个只处理自己这一段，可传递、可终止、可改写上下文。  
     - **举例**：用户故事进来 →「合规 Agent」过滤敏感需求 →「拆任务 Agent」切成 ticket →「估时 Agent」补工时 → 某一环打回则链上回溯，不要求所有环并行知晓全局。  

  5. **共享状态**  
     - **含义**：多个 Agent 读写同一块状态（黑板、文档、数据库、向量库），协作围绕「当前真理」展开。  
     - **举例**：全员读写一份「需求规格 + API 草案」的在线文档或结构化 JSON；「产品 Agent」改优先级后，「开发 Agent」下一轮必须读到新版本，否则会实现错需求——工程上要解决锁、版本号或冲突合并。  

- **与「六大协作模式」的关系（带举例）**  

  - **六大**回答「**先做什么、后做什么、是否分叉、是否并行**」（拓扑 / 执行流）；**五大**回答「**谁听谁的、谁和谁平级、能力从哪来、状态放哪**」（职责与关系）。  
  - **举例对照**：同样是「顺序做需求 → 设计 → 编码」：  
    - 用 **Sequential**：强调**执行顺序**——设计没定稿就不开写代码。  
    - 用 **分层协作**：强调**权力结构**——只有「Lead Agent」能拍板技术栈，执行 Agent 不能越级改决策。二者可同时成立：拓扑是流水线，关系是上下级。  
  - **显式映射举例**（读原文时把术语对上号即可）：  
    - **责任链** + **Sequential**：常见组合——链上每一环顺序推进，和流水线天然合拍。  
    - **责任链** + **Router**：某一环根据输入类型**分叉**到不同下一环（如「缺陷单走热修链 / 常规模块走正常链」）。  
    - **共享状态** + **Network / Parallel**：多 Agent 同时读写作业板时，更像网状或并行读写，要格外注意**冲突与版本**（谁覆盖谁、是否需乐观锁）。  
    - **工具调用** + 任意拓扑：工具是**横切能力**——Sequential 里每一步都可能调 API；Parallel 里多个 Agent 可并行调同一检索服务，但要限流与缓存。  

- **自测（附参考答案思路）**  

  - **题目**：用同一业务线「需求分析 → 设计 → 编码 → 评审」，分别用「一种六大模式 + 一种五大模式」各讲一版架构。  
  - **参考答法 1**：**Sequential** + **分层协作**——四步严格顺序；PM/架构/开发/评审各一层，下级不越级改上级已定事项。  
  - **参考答法 2**：**Parallel** + **对等协作**——设计与测试用例大纲并行起草，两个 Agent 对等；汇总后再进入编码 **Sequential** 段。  
  - **要求**：你能脱离原文，用自己的项目或生活例子各造一版即可，不必与参考答案字面相同。

### 3.3 阅读：MetaGPT 实战解析（架构部分）

- **链接**：https://zhxin.blog.csdn.net/article/details/147962854  
- **阅读范围**  
  - 阶段一只读 **架构部分**：角色、消息流、SOP、与仓库 `MetaGPT` 的模块边界即可；具体部署、业务案例可延后。  
- **建议抓取的概念**（与官方叙事一致方向即可，不必背版本号）  
  - **Code = SOP(Team)**：用标准作业程序描述多角色协作。  
  - **角色（Role）** 与 **动作 / 产出物**：每个角色输入输出是什么。  
  - **为何需要「结构化中间产物」**：便于人读、便于下一角色消费、便于调试。  
- **与官方文档对照（可选）**  
  - MetaGPT 中文文档：https://docs.deepwisdom.ai/main/zh/  
  - 仓库：https://github.com/FoundationAgents/MetaGPT  
- **自测**  
  - 不看文章，1 分钟解释「MetaGPT 把软件工程拆成哪些典型角色」。  
  - 若面试官问「和 CrewAI 比」，阶段一只需答到：**MetaGPT 偏 SOP/软件工程全链路抽象；CrewAI 偏 Task/Crew/Process 编排**（细对比留模块 3）。

### 4.1 体验：CrewAI Quick Start

- **官方文档**：https://docs.crewai.com/  
- **仓库**：https://github.com/joaomdmoura/crewAI  
- **建议步骤**  
  1. 安装与环境：按官方当前推荐方式（`pip` / `uv` 等以文档为准）。  
  2. 跑通最小 **Agent + Task + Crew + Process** 示例，改一个**角色描述**、加一个**任务**，观察输出变化。  
  3. 记录：`Process` 选 `sequential` 与「你认为的并行」若有演示差异，写下来。  
- **阶段一要搞懂的组件**  
  - **Agent**：人设 + 工具 + 目标；  
  - **Task**：可交付物描述、依赖关系；  
  - **Crew**：一组 Agent 与 Task 的运行容器；  
  - **Process**：协作流程策略。  
- **自测**  
  - 用 CrewAI 的概念**翻译**模块 2 里的一种「六大模式」（例如 Sequential）。

### 4.2 体验：MetaGPT Minimal Example

- **文档入口**：https://docs.deepwisdom.ai/main/zh/（快速入门 / 示例）  
- **建议步骤**  
  1. 按文档安装并配置 LLM（密钥与模型名写在**本地**配置，勿提交仓库）。  
  2. 跑官方 **Minimal / Quickstart** 级示例（具体命令以文档为准），观察终端里**角色切换**与**中间文件**（若有）。  
  3. 在笔记中对照模块 2.3：标出「哪个步骤对应哪个 Role」。  
- **自测**  
  - 「若某角色输出质量差，你会改 SOP、改 Role、还是改工具？」——阶段一只要**有思路**即可。

### 4.3 阅读：AutoGen Getting Started

- **文档**：https://microsoft.github.io/autogen/  
- **仓库**：https://github.com/microsoft/autogen  
- **背景（面试加分）**

- **阅读重点**  
  - **多 Agent 对话**如何发起、如何终止；  
  - **与单 Agent + 工具**相比，框架默认帮你做了什么（消息路由、会话状态等——以当前文档为准）。  
- **是否必须本地跑通**
