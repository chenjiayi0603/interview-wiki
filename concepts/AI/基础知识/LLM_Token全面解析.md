# LLM Token 全面解析

## 一、Token是什么？

Token是大语言模型（LLM）处理文本的基本单位。LLM不直接识别文字，而是将文字转换为Token序列进行处理。

### 换算关系

| 语言 | 换算关系 | 示例 |
|------|---------|------|
| 英文 | 1 Token ≈ 0.75个单词 ≈ 4个字母 | "Hello world" → 2个Token |
| 中文 | 1 Token ≈ 1.3个汉字 ≈ 一个词 | "你好" → 1个Token，"我吃饭" → 2个Token |

## 四、Token计算冷知识

1. **标点符号也算Token**
   - "，。？！" 这些都单独计算
   - 空格也会被算作Token

2. **英文比中文省Token**
   - 同样内容，英文Token数约为中文的60%
   - 做英文产品成本显著更低

3. **数字按长度计算**
   - "123" → 1个Token
   - "123456789" → 2-3个Token

4. **重复内容不节省**
   - "哈哈哈哈哈哈" → 每个"哈"都单独计数
   - 文本重复不会因为重复而减少Token消耗

## 五、Token优化技巧（行业常用）

| 优化技巧 | 节省效果 | 说明 |
|---------|---------|------|
| Prompt精简 | 20-30% | 去掉冗余描述，直奔主题 |
| 使用缩写简称 | 10-15% | 能用简称不用全称 |
| 去除冗余格式 | 5%左右 | 去掉不必要的空格、换行 |
| 长上下文做摘要 | 50%+ | 对话历史过长时先摘要再传入 |
| 英文做内部处理 | 40% | 中间处理环节可用英文降低成本 |

## 六、Token成本控制最佳实践

### 1. 分层策略
- **简单任务**：用小模型（GPT-3.5、Llama 7B），成本低
- **复杂推理**：用大模型（GPT-4、Claude 3），保证效果
- 实现模型路由，自动选择最合适的模型

### 2. 缓存策略
- **Query缓存**：相同问题直接返回结果
- **Embedding缓存**：重复文本不重复计算向量
- **中间结果缓存**：常用数据预处理后复用

### 3. 批量处理
- 合并多个请求批量处理
- 异步队列削峰填谷
- 非实时任务用批量接口

### 4. 监控与告警
- Token消耗实时统计
- 单用户/单任务配额控制
- 异常消耗自动告警

## 八、总结

Token是LLM应用的核心成本单元，理解Token机制对于AI产品的成本控制、性能优化至关重要。

**核心原则：**
- 该省则省：简单任务用小模型、加缓存
- 该花则花：核心环节用大模型保证体验
- 精细运营：监控Token消耗，持续优化

对于Interview Pro这类产品，合理的Token优化策略可将成本降低50%以上，同时不影响用户体验。
