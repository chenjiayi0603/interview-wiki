# B+Tree 与 B-Tree 对比

| 对比维度 | **B-Tree** | **B+Tree** |
|---------|-----------|-----------|
| **数据存储** | 所有节点都存数据 | 只有叶子节点存数据，内节点只做索引 |
| **查找路径** | 可能在任意层结束 | 查找必然走到叶子节点 |
| **有序遍历效率** | 需"中序遍历"树，效率较低 | 叶子节点用链表顺序连接，高效区间遍历 |
| **磁盘读写性能** | 查询命中内节点可返回 | 内节点更小，每层可包含更多节点，树高更低 |
| **空间利用率** | 略低（内节点冗余数据） | 更高（内节点只有键） |
| **范围查询性能** | 较差 | 极优，叶节点链表直接线性访问 |
| **常见应用场景** | 传统文件/磁盘索引 | 数据库索引（MySQL/InnoDB）、文件系统 |

> B+Tree 由于**内节点不存数据**、**叶子节点链表连接**，特别适合大量磁盘存储的索引结构，是数据库索引的主流方式。
