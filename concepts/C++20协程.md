# C++20 协程

See also: [[C++语言特性]]

## 概念速查

| 概念 | 含义（一句话） |
|------|----------------|
| 协程帧（frame） | 编译器为某次协程调用分配的一块内存：内有 promise 对象、跨挂起局部变量、挂起点状态等；活得比单次普通栈帧长。 |
| `std::coroutine_handle<P>` | 指向帧的句柄（实现上常等价一根指针），不是帧本体；`resume()` 驱动执行，`destroy()` 释放整块帧。 |
| 返回类型（如 `LazyTask`） | 协程函数的返回类型，通常只包一个 `handle`，给调用方 `resume`/`destroy`；≠ 协程本身，是句柄外壳。 |
| `promise_type`（类型） | 你写的「承诺」类型；实例由编译器在帧里构造。指定方式：常见为嵌套 `R::promise_type`；亦可特化 `std::coroutine_traits<R, Args...>::promise_type`（不必嵌套在 `R` 内）。 |
| Awaitable | `co_await` 右边的表达式所代表的「可被等待」之物（经 `operator co_await` / `await_transform` 等解析）。 |
| Awaiter | 真正被调用 `await_ready` / `await_suspend` / `await_resume` 的对象。 |

## 生命周期（极简）

- **promise 对象**：在帧里，从协程创建到 `handle.destroy()`，与帧同生死。
- **每次 `co_await` 的 Awaitable/Awaiter 临时物**：仅在当前挂起点前后存活（如 `SimpleDelayAwaitable` 临时量）；不等同于 promise。
- **`LazyTask` 里的 `handle`**：指向同一块帧；`destroy()` 一次即结束该协程实例。

## 协程骨架

理解 `promise_type`、`initial_suspend`、`final_suspend`、`get_return_object` 是读懂所有示例的基础。

### 最小协程：`suspend_always` 的惰性协程

- **核心类型**：`LazyCoroutine`
  - `promise_type::initial_suspend()` 返回 `std::suspend_always`：协程创建后立即挂起，需要外部显式 `resume()` 才会继续执行。
  - `final_suspend()` 返回 `std::suspend_always`：在结束时也挂起一次，便于外部在最终挂起点观察状态。
  - 协程体多次 `co_await std::suspend_always{}`，每次 `resume()` 推进到下一个挂起点。
- **要点**：展示了协程的最小骨架，手动管理 `std::coroutine_handle` 的生命周期（在析构时 `destroy()`）。

### `co_yield` 生成器 `Generator<T>`（Fibonacci）

- **核心思想**：用协程实现惰性序列，支持 range-for。
- **`Generator<T>` 结构**：
  - `promise_type` 中保存 `current_value`，在 `yield_value(T)` 中更新并 `co_yield`。
  - `initial_suspend()` / `final_suspend()` 均为 `suspend_always`，方便外部控制。
  - 自定义 `iterator`，封装 `operator!= / operator++ / operator*`，与 `std::default_sentinel_t` 搭配形成 range。
  - `begin()` 中首先 `handle.resume()`，让协程跑到第一个 `co_yield`。
- **Fibonacci 示例**：协程体中维护局部变量 `a, b`，循环中 `co_yield a`，并更新 Fibonacci 序列。协程挂起/恢复时会自动保存/还原局部状态。

### `co_return` 返回值协程：`TaskInt` / `TaskDouble`

- **目的**：演示如何通过 `co_return` 返回结果。
- **关键点**：
  - 在 `promise_type` 中实现 `return_value(T v)`，保存结果到 `value`。
  - `TaskX::get()` 中循环 `handle.resume()` 直到 `handle.done()`，再从 `promise().value` 取结果。
  - 通过 `co_return` 直接返回 `int` / `double` 等值。

### `suspend_never`：协程创建即执行

- **`EagerCoroutine`**：
  - `initial_suspend()` 返回 `std::suspend_never`：协程一旦创建，立即执行到第一个挂起点。
  - `final_suspend()` 为 `suspend_always`。
- **要点**：与“惰性协程”（`initial_suspend = suspend_always`）形成对比，用于说明不同的启动策略。

## Awaitable 设计

- `await_ready`：决定是否需要真正挂起。
- `await_suspend`：可以在此发起 I/O、切线程、注册回调等。
- `await_resume`：收尾，返回结果或重新抛出异常。

### 自定义 Awaitable：`SimpleDelayAwaitable`

- **目的**：实现可被 `co_await` 的对象，控制挂起/恢复逻辑。
- **实现**：
  - `await_ready()`：`ms <= 0` 返回 `true`（不挂起），否则 `false`。
  - `await_suspend(h)`：用 `sleep_for` 当前线程休眠（阻塞模拟耗时），然后调用 `h.resume()` 手动恢复协程。
  - `await_resume()`：无返回值。

### `await_transform`：promise 作为「翻译器」

- **场景**：希望写 `co_await 500ms` 这类表达式，但 `std::chrono::milliseconds` 本身没有协程接口。
- **做法**：在 `promise_type` 里定义 `await_transform`。编译器在遇到 `co_await X` 时，若 promise 上存在 `await_transform`，会先把 `X` 交给 promise，用其返回值作为真正的 Awaiter。
- **要点**：
  - **优先级**：若 `promise_type` 提供了与 `co_await` 操作数匹配的 `await_transform`，编译器会走这条路径。
  - **Awaitable**：此处 `500ms`（类型为 `std::chrono::milliseconds`）只是被动数据，不懂协程。
  - **Awaiter**：由 `await_transform(ms)` 构造的 `SleepAwaiter` 才包含挂起、在线程里 `sleep`、再 `resume` 的逻辑。
  - **用途**：框架作者可集中限制「允许被 await 的类型」、打日志、统一超时/取消语义等。

### 带返回值的 Awaitable：`ValueAwaitable`

- **`ValueAwaitable`**：
  - 持有一个 `int value`。
  - `await_ready()` 返回 `true`（同步就绪，不会真正挂起）。
  - `await_resume()` 返回 `value`，供 `co_await` 表达式使用。
- **示例**：`int a = co_await ValueAwaitable{100};` 展示了“`co_await` 拿值 + `co_return` 返回新值”的基本组合。

### 嵌套 `co_await`：协程 await 另一个协程 `SimpleTask`

- **`SimpleTask` 特性**：同时实现了作为返回类型的协程 `Task` 和作为 Awaitable（实现 `await_ready / await_suspend / await_resume`），因此可以被 `co_await`。
- **示例**：`int x = co_await add(1, 2);` 展示了协程之间通过 `co_await` 进行组合、复用逻辑。

## 生成器进阶

### 无限生成器与手动 `take`：`infinite_counter`

- **核心思想**：生成器本身可产生无限序列，消费方根据条件主动 `break` 来“截断”。
- **实现**：`infinite_counter(int start) -> Generator<int>`：内部 `for (int i = start; ; ++i) co_yield i;`

### 生成器作为 range：`example_generator_as_range`

- **`range_gen(int from, int to) -> Generator<int>`**：协程体中 `for (int i = from; i < to; ++i) co_yield i;`，配合 `Generator<int>` 的 `begin()/end()` 与迭代器，实现标准 range 接口。

## 协程异常传播

- **`TaskWithException`**：
  - `promise_type` 中保存 `std::exception_ptr ep`。
  - `unhandled_exception()` 中将当前异常捕获到 `ep`。
  - `run()` 中循环 `resume()` 直到 `done()`，若 `ep` 非空，调用 `std::rethrow_exception(ep)` 对外抛出。
- **要点**：体现了“在协程内部抛出的异常可以通过 `unhandled_exception` 收集，并在协程结束时统一对外传播”。

## 协程封装 I/O

- **`FileReadAwaitable`**：后台线程文件读取
  - `await_ready()` 返回 `false`：总是会挂起，表示真正的异步 I/O。
  - `await_suspend(h)`：启动一个新线程，在其中用 `std::ifstream` 读取整个文件，将结果保存到 `result`，异常通过 `ep` 保存，读取完毕后调用 `h.resume()` 恢复协程。
  - `await_resume()`：如有异常则 `rethrow`，否则返回读取到的 `std::string`。
- **`SimulatedIoAwaitable`**：模拟网络/磁盘延迟
  - 在 `await_suspend` 中睡眠若干毫秒后 `resume`，`await_resume()` 返回事先构造好的 `mock_data`。
- **`IoTask`**：返回 `std::string` 的 Task
  - `promise_type::return_value(std::string)` 存储最终结果。
  - `initial_suspend()` 为 `suspend_never`，创建即执行。
  - `final_suspend()` 为 `suspend_always`。

## 协程帧 / promise / handle 关系

### frame / promise / handle 互相定位

- **frame 是实体**：协程实例的内存块，活得比一次函数调用栈更久（可跨多次挂起/恢复）。
- **promise 是 frame 的子对象**：编译器在 frame 内构造 promise；协程销毁时析构。
- **handle 是控制柄**：几乎可以当成“指向 frame 的指针 + 操作入口”；`resume/destroy` 都是对 frame 的操作。
- **handle↔promise 的互相定位**：
  - `handle.promise()`：从 frame 定位到 promise（编译器知道偏移）。
  - `std::coroutine_handle<promise_type>::from_promise(p)`：从 promise 反推出对应的 handle/frame。

### `std::coroutine_handle` 内部大致长什么样（示意实现）

- **本质**：`std::coroutine_handle` 自身几乎只是一根指向 frame 的指针，大小通常等于一个指针。
- **状态**：真正的状态机状态、`promise`、提升的局部变量、awaiter 等全部都在 frame 里。
- **行为**：`resume/destroy/done/promise/from_promise` 等成员函数，只是围绕这根指针做地址换算 + 函数跳转。

### 这块 frame 一定在堆上吗？

- **通常情况**：协程会通过自己的 `operator new` 为 frame 分配内存，如果没有自定义，一般实现就是“在堆上分配一块足够大的内存”，因此“大多数时候 frame 在堆上”这个说法是对的。
- **但标准并不强制必须是堆**：你可以为某个协程自定义 `operator new`，让 frame 从内存池/arena/共享内存等地方分配。

## 面试速记：C++20 协程 vs Go 协程的“保存现场/恢复”差异

### 1）保存现场：保存的内容是什么

- **C++20 coroutine（协程帧 coroutine frame）**：保存的是“语义状态”，核心在 `coroutine frame`（状态机对象）里：
  - 状态机状态/恢复点：下一次 `resume()` 应跳到哪个挂起点之后（逻辑上的 PC）。
  - `promise_type` 对象：返回对象、异常传播、`final_suspend` 行为等都由它承载。
  - 跨挂起点存活的数据：会被编译器“提升”进 frame 的局部变量、临时值、中间结果。
  - awaiter/等待状态（按需）：`co_await` 相关 awaiter 及其恢复所需的引用/句柄，是否保存取决于 awaiter 语义与优化。
  - 异常状态（按需）：常见是 promise 持有 `exception_ptr` 以便恢复后传播。
  - **要点**：通常不按“纤程/用户态线程”那样保存一整套寄存器快照；恢复靠 `resume()` 进入编译器生成的状态机分发。
- **Go goroutine（runtime 上下文 + 栈）**：保存的是“执行上下文”，核心是 runtime 保存足够恢复的上下文 + 保留 goroutine 栈：
  - 调度上下文：至少 PC/SP（以及少量实现需要的寄存器/指针寄存器等）用于恢复执行。
  - 局部变量主要在 goroutine 栈上：挂起时栈内存仍在；扩栈/缩栈时 runtime 可能搬迁整段栈内容。
  - **要点**：也不建议表述为“保存所有寄存器”；更准确是保存“最小可恢复上下文”。

### 2）触发时机：什么时候保存/挂起

- **C++20**：只在语言级挂起点触发（`co_await/co_yield/initial_suspend/final_suspend`）。
  - `await_ready()==true`：不挂起（不需要切出/恢复）。
  - `await_ready()==false` 且进入 `await_suspend`：挂起，后续由 awaiter 决定何时恢复。
- **Go**：在 goroutine 被 park/切换时保存上下文，触发源包括：
  - channel/锁/定时器/网络 I/O 等阻塞点（runtime 介入）。
  - 运行时抢占与调度切换（在安全点让出）。

### 3）恢复时机：谁决定何时继续跑

- **C++20**：由“持有 `coroutine_handle` 的人”决定：awaiter/executor/event-loop 在合适时机调用 `handle.resume()`。
- **Go**：由 runtime 调度器决定：条件满足后将 G 置为 runnable，随后在某个线程上被调度继续执行。

### 4）一句话总结（最常用面试回答）

- **C++20 协程保存现场 = 保存语义状态（frame）**；**Go 协程保存现场 = 保存执行上下文（PC/SP 等 + 栈）**。
- **C++20 不自带调度**（机制），**Go 自带调度**（策略）；因此性能“谁更快”取决于分配/调度/线程切换路径，不能一概而论。

## 附录：`std::future` 外包 `awaiter`（额外线程 / 轮询）

标准库没有 `co_await std::future`。若要把已有 `std::future` 接进协程，需自定义 awaiter；常见代价是：

- **额外线程**：在 `await_suspend` 里 `detach` 一个线程执行 `fut.wait()`，就绪后 `h.resume()`。
- **轮询**：在同一线程里反复 `wait_for(短间隔)` 直到就绪再 `resume`（占满线程、浪费 CPU，仅作示意）。
