# C++ STL 内存管理

See also: [[智能指针]], [[STL容器与算法]], [[STL源码考点]]

## 0. 核心要点总结（快速参考） ✅

### 0.1 智能指针三剑客对比

| 类型 | 所有权 | 拷贝 | 引用计数 | 开销 | 使用场景 |
|------|--------|------|----------|------|----------|
| **unique_ptr** | 独占 | 禁止，只能移动 | 无 | 零开销 | 单对象所有权、工厂模式 |
| **shared_ptr** | 共享 | 可拷贝 | use_count（强引用） | 控制块开销 | 多对象共享、复杂生命周期 |
| **weak_ptr** | 无所有权 | 可拷贝 | weak_count（弱引用） | 控制块开销 | 打破循环引用、观察者模式 |

### 0.2 核心原则与最佳实践

#### 智能指针选择原则
- **优先使用 `unique_ptr`**：默认选择，零开销，语义清晰
- **需要共享时用 `shared_ptr`**：多对象共享同一资源
- **避免循环引用用 `weak_ptr`**：观察但不影响生命周期

#### 创建方式推荐
- ✅ **`make_unique<T>(args...)`**：异常安全、性能好、代码简洁
- ✅ **`make_shared<T>(args...)`**：一次内存分配（控制块+对象），性能最优
- ❌ **避免 `shared_ptr<T>(new T)`**：两次内存分配，性能较差

#### 关键机制
- **`shared_ptr` 控制块**：包含 `use_count`（强引用）、`weak_count`（弱引用）、对象指针、删除器
- **`make_shared` 优势**：控制块和对象在同一块内存，只有一次分配
- **循环引用**：`shared_ptr` 相互持有导致对象无法释放，用 `weak_ptr` 打破

### 0.3 内存分配器核心概念

| 概念 | 说明 |
|------|------|
| **分配器作用** | 控制容器如何分配和释放内存 |
| **默认分配器** | `std::allocator`，使用 `new/delete` |
| **自定义分配器** | 实现特定内存策略（内存池、对齐、性能优化） |
| **分配器接口** | `allocate()`、`deallocate()`、`construct()`、`destroy()` |

### 0.4 面试高频考点速查

1. **`make_shared` vs `shared_ptr(new T)`**：一次分配 vs 两次分配
2. **循环引用问题**：如何用 `weak_ptr` 解决
3. **`shared_ptr` 线程安全**：引用计数原子操作，对象访问需外部同步
4. **`unique_ptr` 移动语义**：禁止拷贝，只能移动
5. **控制块生命周期**：`use_count == 0` 销毁对象，`weak_count == 0` 销毁控制块
6. **RAII 机制**：智能指针自动管理资源，异常安全

### 0.5 常见陷阱

- ❌ 不要用原始指针初始化多个 `shared_ptr`（会导致多次释放）
- ❌ 不要返回 `shared_ptr` 的原始指针（可能导致悬空指针）
- ❌ 避免循环引用（使用 `weak_ptr` 打破）
- ❌ 不要混用 `make_shared` 和 `shared_ptr(new T)` 管理同一对象
