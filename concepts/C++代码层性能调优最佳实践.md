# C++ 代码层性能调优最佳实践

## 数据结构

紧凑连续内存，避免 std::map 滥用，优先 flat_map/array、矢量化友好容器。

**举例**：键值数量 < 几千且需顺序遍历时用 `std::vector<std::pair<K,V>>` 或 flat_map 比 std::map 更 cache 友好；数值计算用 SoA（如 `vector<double> x, y, z`）便于 SIMD。

**分析**：数据布局决定 cache 命中与分支预测；优先连续与紧凑，再考虑算法复杂度。

## 接口设计

传引用/指针而非值；返回值优化（RVO）；避免不必要的 std::function/多态。

**举例**：大对象用 `const T&` 或 `std::string_view` 入参，返回用可 RVO 的按值返回或 optional；热路径避免 `std::function` 回调，用模板或函数指针。

**分析**：减少拷贝与虚调用能直接降低 CPU 与分支失败；接口设计阶段就考虑调用频率。

## 异常与日志

核心路径避免异常；日志分级、采样、异步落盘。

**举例**：解析与网络层用错误码或 std::expected，不在热路径 try-catch；INFO 日志按 1/100 采样，ERROR 全量但异步写盘，避免持锁写 fwrite。

**分析**：异常与同步日志会拉高尾延迟并加剧锁竞争；核心路径以返回码为主，日志以异步与采样为主。

## 时间与时钟

使用单调时钟（steady_clock）计算延迟；减少系统调用。

**举例**：用 `std::chrono::steady_clock::now()` 做耗时统计，不用 `gettimeofday`/系统时钟，避免 NTP 回拨导致负延迟；批量请求共用一个 now() 再分摊，减少 clock 调用次数。

**分析**：单调时钟避免时间回拨带来的逻辑错误；少调系统调用能降低抖动与 CPU。

## 配置热更新

支持动态调整线程数/队列长度/批量大小。

**举例**：通过配置中心或信号量下发“线程池大小、批处理条数、队列上限”，进程定期读取或监听变更并 apply，无需重启即可应对流量变化或做 A/B 调参。

**分析**：热更新能快速止血与调优，避免“改配置就要重启”带来的可用性损失。
