# IP头部

IP（Internet Protocol）报文头部用于网络层，用来描述源IP/目的IP、分片、路由等关键信息。

## IPv4头部字段

- **版本（Version）**：4位，通常为4，表示IPv4协议
- **首部长度（IHL）**：4位，单位为4字节，通常取值为5（即20字节，无选项时）
- **服务类型（Type of Service, TOS）**：8位，指示服务质量相关信息
- **总长度（Total Length）**：16位，整个IP数据包（头部+数据）的长度
- **标识（Identification）**：16位，分片时用于识别数据包
- **标志位（Flags）**：3位，控制分片/重组
- **分片偏移（Fragment Offset）**：13位，指示分片在原始报文中的位置
- **生存时间（TTL）**：8位，数据包在网络中的最大跳数
- **协议（Protocol）**：8位，表示上层协议类型（如TCP=6，UDP=17等）
- **首部校验和（Header Checksum）**：16位，IP头部差错检验
- **源IP地址（Source Address）**：32位，发送端IP
- **目的IP地址（Destination Address）**：32位，接收端IP
- **选项（Options）**：可选字段，长度可变

## 为什么地址在IP头部、端口在TCP头部？

1. **网络协议分层设计（OSI/四层协议栈）**：
   - IP属于“网络层”，负责寻址和路由转发。它关心的是“主机到主机”/“网络到网络”之间的通信，因此源IP/目的IP地址放在IP包头，唯一标识网络中的主机。
   - TCP属于“传输层”，负责端到端的可靠数据传输和多路复用。传输层要将不同进程/应用之间的数据流加以区分，因此使用源端口/目的端口放在TCP包头，用于标识具体“主机内部的进程或服务”。

2. **作用不同**：
   - IP包头的“地址”用于引导数据包在网络中找到目标主机，实现主机间的可达性。
   - TCP报文的“端口”用于标识主机上的具体进程，使多个应用可以并发使用网络。

3. **“寻址范围”不同**：
   - IP地址解决“到哪台机器”；
   - 端口号解决“到这台机器上的哪个应用/服务”。

4. **协议解耦与灵活性**：
   - 网络层不关心应用细节，只管主机地址；
   - 传输层独立实现端口多路复用，简化协议实现和扩展。

**结论**：地址需在IP头部用于网络路由，端口则在TCP头部用于主机内部区分进程，两者分别服务于协议栈的不同分工，层次清晰、逻辑隔离。

## C语言结构体示例

```c
struct iphdr {
#if __BYTE_ORDER == __LITTLE_ENDIAN
    uint8_t ihl:4,        // 首部长度（以4字节为单位，常为5）
            version:4;    // 版本号（4=IPv4）
#else
    uint8_t version:4,
            ihl:4;
#endif
    uint8_t tos;          // 服务类型TOS
    uint16_t tot_len;     // 总长度（字节）
    uint16_t id;          // 标识符（分片用）
    uint16_t frag_off;    // 分片偏移+标志
    uint8_t ttl;          // 生存时间 TTL
    uint8_t protocol;     // 上层协议类型（TCP=6, UDP=17等）
    uint16_t check;       // 头部校验和
    uint32_t saddr;       // 源IP地址
    uint32_t daddr;       // 目的IP地址
    // 选项(option)字段通常省略，首部长度>5时才出现
};
```

一个典型的IPv4头部长度为20字节（无选项）。源/目的IP均为4字节。选项字段可变。
