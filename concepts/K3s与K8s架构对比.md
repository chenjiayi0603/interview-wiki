# K3s 与 K8s 架构对比

## 二、架构设计差异

```
┌─────────────────────────────────────────────────────────────────┐
│                        Kubernetes 集群                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │

│         │                │                │                     │
│  ┌──────┴──────┐  ┌──────┴──────┐  ┌──────┴──────┐              │
│  │ Scheduler   │  │ Scheduler   │  │ Scheduler   │              │
│  └──────┬──────┘  └──────┬──────┘  └──────┬──────┘              │
│         │                │                │                     │
│  ┌──────┴──────┐  ┌──────┴──────┐  ┌──────┴──────┐              │
│  │ControllerMgr│  │ControllerMgr│  │ControllerMgr│              │

```

**K8s 架构特点：**
- **多组件分离**：每个控制平面组件独立运行
- **高可用设计**：支持多 Master 节点集群
- **强一致性**：依赖 etcd 分布式存储
- **模块化架构**：组件可独立升级和替换

### 2.2 K3s 架构

```
┌─────────────────────────────────────────────────────────────────┐
│                      K3s 单进程架构                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌────────────────────────────────────────────────────────────┐ │
│  │                    K3s Server 进程                         │ │
│  │  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐        │ │
│  │  │API Server│ │Scheduler │ │Controller│ │ K3s Agent│        │ │
│  │  │          │ │          │ │  Manager │ │          │        │ │
│  │  └────┬─────┘ └────┬─────┘ └────┬─────┘ └──────────┘        │ │
│  │       │            │            │                         │ │
│  │  ┌────┴────────────┴────────────┴────┐                    │ │
│  │  │         数据存储层 (SQLite/etcd)    │                    │ │
│  │  └─────────────────────────────────────┘                    │ │
│  └────────────────────────────────────────────────────────────┘ │
│                                                                 │
│  ┌────────────────────────────────────────────────────────────┐ │
│  │                    K3s Agent 进程                           │ │
│  │  ┌──────────┐ ┌──────────┐ ┌──────────┐                    │ │
│  │  │  kubelet  │ │kube-proxy│ │ContainerD│                    │ │
│  │  └──────────┘ └──────────┘ └──────────┘                    │ │
│  └────────────────────────────────────────────────────────────┘ │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**K3s 架构特点：**
- **单二进制文件**：所有 Master 组件打包为一个进程
- **嵌入式存储**：默认使用嵌入式 SQLite，支持切换 etcd
- **Agent 简化**：Worker 节点只运行 kubelet、kube-proxy、容器运行时
- **轻量化设计**：移除云提供商特定的功能

### 2.3 架构对比总结

| 架构特性 | K3s | K8s |
|----------|-----|-----|
| 进程模式 | 单进程多组件 | 多进程独立组件 |
| 控制平面 | 高度集成 | 组件分离 |
| 存储方案 | SQLite（默认）/ etcd | 外部 etcd 集群 |
| 网络模型 | CNI + 内置 Traefik | CNI + 独立 Ingress |
| 高可用实现 | 嵌入式 HA | Kube-apiserver HA + etcd HA |
| 二进制数量 | 1个（server）+ 1个（agent） | 10+ 独立组件 |
