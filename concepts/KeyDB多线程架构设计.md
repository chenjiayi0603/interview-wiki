## 与 Redis 6 多线程的本质区别

| 维度 | Redis 6 | KeyDB |
|------|---------|-------|
| **线程化范围** | 仅 I/O 读写 | 事件循环 + 网络 I/O + 命令解析 + 命令执行 |
| **命令执行** | 单线程串行 | 多线程并行 |
| **线程模型** | 主线程分发 I/O 任务给 I/O 线程 | 每个 Worker 独立运行完整的事件循环 |
| **锁机制** | 不需要（单线程执行） | FastLock 自旋锁保护共享数据 |
| **扩展上限** | io-threads > 4 后几乎无提升 | 线程数线性扩展（测试到 7 线程仍线性） |
| **本质** | I/O 并行，计算串行 | **真正的对称多线程（Symmetric Multi-Threading）** |

Redis 6 的 io-threads 只是把**网络读写**操作并行化，所有命令仍在主线程中串行执行。这意味着：
- 当瓶颈在 CPU 计算（如复杂命令）时，io-threads 帮助有限
- 当瓶颈在网络 I/O 时，io-threads 有帮助但上限受限于主线程处理能力

KeyDB 则将**整个请求生命周期**都并行化：读取 → 解析 → 执行 → 响应。
