# MySQL主从复制与高可用

See also: [[MySQL存储引擎]]

## 主从复制原理

### 复制流程
1. **主库（Master）**：记录所有数据变更到二进制日志（binlog）
2. **从库（Slave）**：
   - IO线程：从主库读取binlog，写入中继日志（relay log）
   - SQL线程：读取relay log，执行SQL语句，实现数据同步

### 复制方式
- **异步复制**：主库提交事务后立即返回，不等待从库同步（默认）
- **半同步复制**：主库提交事务后，至少等待一个从库确认收到binlog
- **全同步复制**：主库提交事务后，等待所有从库都同步完成（性能较差，较少使用）

## 主从复制的应用场景

### 1. 读写分离
- 主库处理写请求
- 从库处理读请求，分担主库压力

### 2. 数据备份
- 从库作为主库的数据备份
- 可以在从库上进行备份操作，不影响主库性能

### 3. 高可用
- 主库故障时，可以切换到从库
- 配合哨兵（Sentinel）或MHA实现自动故障转移

### 4. 数据分析
- 在从库上进行数据分析、报表生成等操作
- 不影响主库的实时业务

## 高可用架构

### 1. 主从 + 哨兵（Sentinel）
- **架构**：一主多从 + 哨兵集群
- **功能**：自动故障检测和主从切换
- **适用场景**：中小型应用

### 2. MHA（Master High Availability）
- **架构**：主从 + MHA管理节点
- **功能**：自动故障转移、主从切换
- **适用场景**：中大型应用

### 3. 双主架构
- **架构**：两个主库互为主从
- **功能**：实现双写，提高可用性
- **注意**：需要解决数据冲突问题

### 4. 分库分表 + 主从
- **架构**：分库分表 + 每个分片都有主从
- **功能**：既解决数据量问题，又保证高可用
- **适用场景**：大型应用

## 主从延迟问题

### 延迟产生的原因
- 网络延迟
- 从库性能不足
- 主库并发写入过高
- 从库执行慢查询

### 解决方案
- 优化网络环境
- 提升从库硬件性能
- 使用并行复制（MySQL 5.7+）
- 避免在从库执行慢查询
- 使用半同步复制保证数据一致性
