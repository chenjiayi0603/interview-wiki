# RPC 与网络延迟速查

> 微信级微服务 RPC 指标、同机房延迟、Nginx 代理链路 RT 等速查总结。

---

## 一、微信 RPC 服务概况

### 1.1 QPS 规模

| 层级 | 规模 | 说明 |
|------|------|------|
| 入口服务 | 日请求 10 亿～100 亿 | 登录、发消息、支付等 |
| 整体后台 | **每秒数亿次请求** | 链式调用放大 |
| 核心服务 | **每秒上亿次** | 微服务相互调用 |
| 机器规模 | 2 万+ 台 | 3000+ 微服务 |
| 单库 QPS | < 3000 | 数据库分片控制 |

### 1.2 RT 延迟指标

| 指标 | 数值 | 说明 |
|------|------|------|
| 默认超时 | 500ms | RPC 框架默认 |
| 过载阈值 | **队列等待 > 20ms** | 请求到达→开始处理的排队时间 |
| 目标 RT | **毫秒级** | 正常负载下 |
| 过载策略 | 快降慢升 | 超 20ms 触发限流 |

*来源：微信 SOCC 2018 论文《Overload Control for Scaling Wechat Microservices》*

## 二、内部节点 RPC RT（服务间调用）

### 2.1 微信未公开具体数字

微信主要披露队列等待（20ms）和超时（500ms），未单独公布内部 RPC 的 P50/P99。

### 2.2 业界同机房 RPC 参考

| 层级 | 典型延迟 |
|------|----------|
| 网络基础（同机房 ping） | 0.5～2ms |
| 纯 RPC 调用（无 DB） | P50: 1～2ms，P99: 5～15ms |
| 含 DB/缓存 | 10～100ms+ |
| 跨机房 | 数十 ms～200ms+ |

### 2.3 推断量级（同机房）

| 调用类型 | 合理范围 |
|----------|----------|
| 纯 RPC 一跳（无下游） | 1～5ms |
| 短链 RPC（1～2 层） | 5～20ms |
| 长链 RPC（多级 + DB） | 50～200ms+ |
| 超时 | 500ms |

## 三、1ms 以内能否实现？

### 3.1 结论

**可以**。在合理条件下，无下游调用的 RPC 可稳定做到 1ms 以内。

| 场景 | 可达延迟 |
|------|----------|
| 同机本地（UNIX socket） | **0.1ms 级别** |
| 同机房跨机器 | **<1ms**（需优化） |
| 同机房默认配置 | 1～5ms |

### 3.2 时间组成（无下游）

| 环节 | 典型耗时 |
|------|----------|
| 网络 RTT | 0.2～0.5ms |
| 序列化/反序列化 | 几十 μs |
| 连接获取（热连接） | 几 μs |
| 连接建立（冷连接） | 50～200ms |
| Handler 逻辑 | 几 μs～几十 μs |

### 3.3 必要条件

1. 连接池 + 预热
2. 同机房 / 同机架
3. 简单 handler（无 DB、无下游 RPC）
4. 序列化优化（buffer 池、避免 reflection、小 payload）

## 四、同机房跨机 RT

| 层级 | 网络 RTT | 完整 RPC RT |
|------|----------|-------------|
| 同机架 | 0.1～0.3ms | **0.5～1.5ms** |
| 同机房 | 0.2～0.5ms | **0.8～2ms** |
| 同城多机房 | 0.5～2ms | **2～5ms** |

**结论**：同机房跨机、优化到位时，可做到 **1ms 以内**。

## 五、Nginx 链路 RT

### 5.1 链路示意

```
Client → [网络] → Nginx(代理) → [网络] → 后端服务(同机房)
```

### 5.2 延迟拆分（proxy_pass）

| 环节 | 典型耗时 |
|------|----------|
| Nginx 解析与转发 | 0.05～0.2ms |
| Nginx → 后端（网络） | 0.15～0.5ms |
| 后端处理 | 视业务而定 |
| 后端 → Nginx（网络） | 0.15～0.5ms |
| Nginx 回传 | 0.05～0.2ms |

**Nginx 代理开销**：约 0.1～0.5ms  
**同机房往返网络**：约 0.3～1ms

### 5.3 典型场景 RT

| 场景 | 典型 RT |
|------|---------|
| Nginx 静态小文件（内存 cache） | 0.1～0.5ms |
| Nginx proxy_pass → 同机房后端（无下游） | 0.5～2ms |
| Nginx proxy_pass → 同机房后端（有 DB） | 5～50ms+ |

---

## 六、全链路 RT 对比

### 6.1 Client 同机房时

```
Client(同机房) → Nginx → 后端(同机房)
```

| 环节 | 耗时 |
|------|------|
| Client ↔ Nginx（网络 2 次） | 0.3～1ms |
| Nginx 代理处理 | 0.1～0.5ms |
| Nginx ↔ 后端（网络 2 次） | 0.3～1ms |
| 后端处理（无下游） | 0.1～1ms |
| **合计** | **约 1～3ms** |

### 6.2 Client 公网时

| 环节 | 耗时 |
|------|------|
| Client ↔ Nginx | 20～200ms+ |
| Nginx + 后端（同机房段） | 1～2ms |
| **合计** | **50～200ms+**（由公网主导） |

---

## 七、Nginx 代理 vs 直接返回

| 方式 | 链路 | 典型 RT（同机房 Client） |
|------|------|-------------------------|
| **proxy_pass 往返** | Client → Nginx → 后端 → Nginx → Client | **约 1～3ms** |
| **直接返回** | Client → Nginx → Client | **约 0.4～1.2ms** |

**差异**：直接返回少 0.5～2ms，约为 1/3～1/2 的 RT。

---

## 八、压测时 CPU 100% 的 RT 变化

### 8.1 两种场景对比

| 负载 | Nginx 直接返回 | Nginx 转发后端 |
|------|----------------|----------------|
| **正常**（CPU < 70%） | 0.4～1.2ms | 1～3ms |
| **接近饱和**（CPU 70～95%） | 1～5ms | 3～20ms |
| **饱和**（CPU 100%） | 5～50ms+ | 20～200ms+ |

### 8.2 延迟升高的来源

**Nginx 直接返回**：瓶颈只在 Nginx，CPU 100% 时 accept、解析、读文件、发送全部变慢。

**Nginx 转发后端**：瓶颈可能在 Nginx 或后端；后端 CPU 100% 时 RT 恶化更明显（增加后端处理耗时）。

| 环节 | 正常 | Nginx CPU 100% | 后端 CPU 100% |
|------|------|----------------|---------------|
| Nginx 解析转发 | ~0.1ms | 1～10ms | ~0.1ms |
| 网络到后端 | ~0.3ms | ~0.3ms | ~0.3ms |
| 后端处理 | ~0.5ms | ~0.5ms | 10～100ms+ |
| 网络返回 | ~0.3ms | ~0.3ms | ~0.3ms |
| Nginx 回传 | ~0.1ms | 1～10ms | ~0.1ms |
| **合计** | **1～3ms** | **5～25ms** | **15～110ms+** |

### 8.3 瓶颈判断

| 现象 | 瓶颈 |
|------|------|
| Nginx CPU 高、后端 CPU 低 | **Nginx** |
| Nginx CPU 低、后端 CPU 高 | **后端** |
| 两边 CPU 都高 | 两边均接近瓶颈 |

### 8.4 恶化倍数（相对正常 RT）

| 场景 | 正常 RT | CPU 100% 时 RT | 倍数 |
|------|---------|----------------|------|
| Nginx 直接返回 | 0.4～1.2ms | 5～50ms+ | 约 10～50x |
| 转发后端（瓶颈在后端） | 1～3ms | 20～200ms+ | 约 20～100x |
| 转发后端（瓶颈在 Nginx） | 1～3ms | 5～25ms | 约 5～10x |

---

## 九、简要结论

| 场景 | 典型 RT |
|------|---------|
| 纯 RPC 同机房（无下游） | 0.5～2ms，优化后 <1ms |
| Nginx 直接返回 | 0.4～1.2ms |
| Nginx proxy_pass 往返 | 1～3ms |
| 全链路同机房 | 1～3ms |
| 含公网 Client | 50～200ms+ |
| **CPU 100% 时** | 上述 RT 可恶化 10～100 倍 |
