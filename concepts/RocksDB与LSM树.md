# RocksDB与LSM树

## 一、RocksDB概述

### 1. 基本介绍
- **来源**：Facebook开源，LevelDB的继承者
- **定位**：嵌入式KV存储引擎
- **特点**：LSM树结构、高性能、支持高效写入
- **应用**：Redis KV存储、MySQLrocksdb引擎、消息队列存储层

### 2. 与传统数据库区别
| 特性 | 传统B+树（InnoDB） | RocksDB（LSM树） |
|------|------------------|------------------|
| 写入性能 | 中等 | 高 |
| 读取性能 | 高 | 中等（需多层级查找） |
| 空间放大 | 低 | 较高（压缩前） |
| 写放大 | 中等 | 较高 |
| 内存需求 | 较高 | 较低 |

## 二、LSM树（Log-Structured Merge Tree）

### 1. LSM树结构
```
┌──────────────────────────────────────┐
│             MemTable                 │
│         (内存，WAL备份)                │
├──────────────────────────────────────┤
│          L0 (Immutable)              │
│      (内存，合并后的小文件)             │
├──────────────────────────────────────┤
│               L1                     │
│          (第一层SSTable)              │
├──────────────────────────────────────┤
│               L2                     │
│         (第二层SSTable)               │
├──────────────────────────────────────┤
│               L3                     │
│           (更大的SSTable)             │
├──────────────────────────────────────┤
│               Ln                     │
│         (最大层级，N*10GB)             │
└──────────────────────────────────────┘
```

### 2. 写入流程
1. 写入WAL（Write-Ahead Log）
2. 写入MemTable（内存跳表）
3. MemTable写满后变为Immutable
4. 后台线程将Immutable刷盘为L0的SSTable
5. 触发Compaction合并层级

### 3. Compaction策略
- **Level Compaction**：每层大小递增
- **Universal Compaction**：多层同时合并，空间放大小但读放大
- **FIFO Compaction**：按时间淘汰

## 三、SSTable格式

### 1. 文件结构
```
┌─────────────────────────────────────┐
│       Data Block 1 (数据块)           │
├─────────────────────────────────────┤
│       Data Block 2                   │
├─────────────────────────────────────┤
│            ...                       │
├─────────────────────────────────────┤
│     Index Block (索引块)             │
│   key -> block_offset                │
├─────────────────────────────────────┤
│    Filter Block (布隆过滤器)          │
├─────────────────────────────────────┤
│    Meta Index Block                  │
├─────────────────────────────────────┤
│           Footer (8B)                │
│     index_handle + filter_handle     │
└─────────────────────────────────────┘
```

### 2. Block结构
- **数据块**：默认64KB，可配置
- **Restart Point**：用于二分查找
- **前缀压缩**：减少存储空间
- **块缓存**：LRU策略缓存热点数据
