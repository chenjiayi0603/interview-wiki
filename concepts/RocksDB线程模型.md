## 二、线程模型说明

| 模块 | 说明 |
|------|------|
| 用户线程 | Put/Get/Delete 线程安全，底层通过 WriteThread、细粒度锁、MemTable 并发设计实现 |
| MemTable | 每个 DB 实例一组，由用户线程读写；Flush 后变为 Immutable，由后台线程落盘 |
| Flush | 每个 SST 由单线程独占写入，无需文件级锁；元数据由 VersionSet 串行调度 |
| Compaction | 同一 SST 仅被一个任务操作，由 Manifest/VersionSet 调度保证 |
| SST 读写 | Flush/Compaction 持写锁，Iterator/BlockCache 持读锁（RWMutex） |
| WAL | 由 Leader 线程串行写入，无独立 WAL 线程；正常运行时无读写并发 |

## 三、关键设计要点

### 3.1 用户线程
- 调用方创建的线程，直接执行 Put/Get/Delete 操作。
- 线程安全通过 WriteThread 组提交、细粒度锁、MemTable 并发写入实现。

### 3.2 MemTable
- 每个 DB 实例一组 MemTable（Active + Immutable）。
- 由用户线程直接读写，无独立 MemTable 线程。
- 写满后转为 Immutable，由后台 Flush 线程落盘。

### 3.3 Flush 线程池
- 配置参数：`max_background_flushes`。
- 负责将 Immutable MemTable 写入为 L0 SST 文件。
- 每个 SST 由单线程独占写入，无需文件级锁。
- 元数据由 VersionSet 串行调度。

### 3.4 Compaction 线程池
- 配置参数：`max_background_compactions`。
- 负责 SST 合并、层级整理。
- 同一 SST 仅被一个任务操作，由 Manifest/VersionSet 调度保证。

### 3.5 WAL 写入
- 由 Leader 线程串行写入，无独立 WAL 线程。
- 正常运行时无读写并发。
- 崩溃恢复时读线程以读锁保护。

### 3.6 辅助线程
- Statistics/Timer Thread：统计收集、定时任务执行。
