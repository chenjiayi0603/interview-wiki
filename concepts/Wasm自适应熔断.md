# Wasm自适应熔断

See also: [[性能优化]]

## 概述

Wasm自适应熔断是基于Envoy Wasm插件实现的动态熔断机制，根据历史数据动态调整熔断阈值，替代传统的固定阈值熔断策略。

[src: raw/ingested/3项目/服务网格-即构/面试故事-服务网格.md]

## 算法原理

### 核心参数

| 参数 | 含义 | 默认值 | 说明 |
|------|------|--------|------|
| protection | 保护阈值 | 5 | 请求数小于等于protection则不会触发熔断 |
| k | 熔断敏感系数 | 1.5 | 范围1.1~2，越小越容易熔断 |
| window | 滑动窗口大小 | 10s | 统计窗口 |

### 熔断判定逻辑

```
if (k * accepts >= total - protection) {
    // 不熔断
} else {
    // 概率性熔断
    熔断概率 = (((total - protection) - (k * accepts)) / (total + 1)) * 100%
}
```

其中：
- `accepts`：窗口内成功请求数
- `total`：窗口内总请求数

[src: raw/ingested/3项目/服务网格-即构/面试故事-服务网格.md]

## 实现方式

- **技术栈**：Envoy Wasm插件（Rust语言）
- **拦截位置**：在filter层面统计请求结果
- **熔断行为**：超过阈值直接返回503，不转发到后端

## 熔断恢复

| 指标 | 数值 | 说明 |
|------|------|------|
| 错误率阈值 | 50% | 超过即熔断 |
| 熔断时间 | 30s | 默认配置 |
| 半开试探 | 1个请求 | 试探是否恢复 |
| 恢复时间 | < 5s | 从熔断到正常（自适应优化后） |

**熔断过程时间线**：
```
T+0s    错误率升至60%
T+0.5s  熔断触发，返回503
T+30s   进入半开，试探请求
T+30.5s 试探成功，恢复
T+31s   正常服务

总恢复时间：31s
优化后（自适应阈值）：5s内恢复
```

## 本地压测结论

- 在QPS较低时，调节系数k和统计窗口，对于一直返回错误的场景，影响较大
- k系数越小熔断概率越高
- 统计滑动窗口越大，熔断概率越高，越接近预期概率
- 压测请求数会产生影响，因为算法是反馈型的，在开始时未有采样数据
- 请求数越多和压测时间越长，则压测结果数据越准确，熔断也越接近预期概率
- 最长统计时长越长，计算结果数据越准确，但同时也会可能增加熔断生效时延
- 参考：go-zero使用基于滑动窗口，10s/40窗口

## 面试问答

**Q: 自适应熔断是怎么实现的？**

> "传统熔断是固定阈值，比如错误率超过50%就熔断。但实际场景中，不同服务能承受的错误率不同，固定阈值不合理。
> 
> **自适应熔断思路**：
> - 根据历史数据动态调整阈值
> - 用滑动窗口统计最近的成功率
> - 成功率下降时逐步降低阈值，自动恢复时逐步放开
> 
> **实现**：
> - Envoy Wasm插件（Rust语言）
> - 在filter层面统计请求结果
> - 超过阈值直接返回503，不转发到后端
> 
> **效果**：
> - 异常流量自动隔离
> - 恢复时间 < 5秒
> - 不需要人工干预"
