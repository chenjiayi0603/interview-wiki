# gRPC 架构与 RPC 类型

## 整体架构

```
┌────────────────────────────────────────────────────────────────────┐
│                         客户端 (Go/Java/...)                         │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────────────┐  │
│  │ 业务代码      │→ │ Stub/Client   │→ │ HTTP/2 + protobuf 编码   │  │
│  └──────────────┘  └──────────────┘  └──────────────────────────┘  │
└───────────────────────────────┬────────────────────────────────────┘
                                 │ 网络
                                 ▼
┌────────────────────────────────────────────────────────────────────┐
│                         服务端 (Go/Java/...)                         │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────────────┐  │
│  │ 业务 Handler  │← │ 框架分发     │← │ HTTP/2 + protobuf 解码   │  │
│  └──────────────┘  └──────────────┘  └──────────────────────────┘  │
└────────────────────────────────────────────────────────────────────┘
```

- **Stub/Client**：由 `protoc` 根据 `.proto` 生成的客户端，封装请求/响应序列化与 HTTP/2 调用。
- **服务端**：根据 `.proto` 生成服务接口，你实现具体 Handler，框架负责路由、反序列化、流控。

## 四种 RPC 类型

| 类型           | 请求     | 响应     | 典型场景           |
|----------------|----------|----------|--------------------|
| 一元 (Unary)   | 1 个请求 | 1 个响应 | 普通查询、写入     |
| 服务端流       | 1 个请求 | 流式响应 | 服务端推送、大列表 |
| 客户端流       | 流式请求 | 1 个响应 | 上传、批量写入     |
| 双向流         | 流式请求 | 流式响应 | 聊天、实时协作     |
