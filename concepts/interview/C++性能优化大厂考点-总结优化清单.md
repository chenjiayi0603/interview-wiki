# C++ 性能优化大厂考点 - 总结优化清单

> 本文整理自大厂 C++ 性能优化考点，提供一份可直接对照执行的优化清单。

See also: [[C++代码层性能调优最佳实践]], [[C++性能调优关键指标]], [[C++多线程与并发]], [[C++并发性能优化]], [[智能指针优化]], [[C++性能分析常见问题与技巧]]

## 一、性能分析（优化前必做）

- [ ] 建立性能基准测试，记录关键指标
- [ ] 使用 `perf record/report` 定位热点函数
- [ ] 使用 `perf stat` 分析 IPC、缓存命中率、分支预测
- [ ] 生成火焰图可视化性能瓶颈
- [ ] 使用 Valgrind 检测内存问题
- [ ] 确认瓶颈类型：CPU密集/内存密集/I/O密集

## 二、编译器优化

- [ ] 生产环境使用 `-O2` 或 `-O3` 编译
- [ ] 性能关键模块启用 LTO（`-flto`）
- [ ] 使用 `-march=native` 针对目标CPU优化
- [ ] 合理使用 `inline` / `__attribute__((always_inline))`
- [ ] 使用 `constexpr` 进行编译期计算
- [ ] SIMD场景启用 `-mavx2 -mfma`

## 三、内存优化

### 内存分配
- [ ] 容器预分配容量（`reserve`）
- [ ] 复用内存（`clear` 而非重新分配）
- [ ] 高频分配场景使用对象池/内存池
- [ ] 小对象优先栈分配（`std::array`）
- [ ] 使用 `make_shared`/`make_unique` 减少分配次数

### 内存布局
- [ ] 结构体成员按大小降序排列（减少padding）
- [ ] 多线程共享数据使用 `alignas(64)` 缓存行对齐
- [ ] 避免 False Sharing（padding填充或thread_local）

### 内存访问
- [ ] 优先顺序访问（行优先遍历二维数组）
- [ ] 使用连续内存容器（`vector` 优于 `list`）
- [ ] 减少指针间接访问

## 四、CPU优化

### 分支预测
- [ ] 减少分支数量（使用查找表）
- [ ] 常见分支放前面，使用 `likely`/`unlikely` 提示
- [ ] 简单分支用位运算或三元运算符替代

### SIMD向量化
- [ ] 使用 `__restrict__` 告诉编译器指针不重叠
- [ ] 使用 `#pragma omp simd` 帮助自动向量化
- [ ] 热点循环手动 SIMD 优化（AVX2/AVX512）
- [ ] 数据对齐到 32/64 字节

### 缓存优化
- [ ] 提高时间局部性和空间局部性
- [ ] 热点数据预取（`__builtin_prefetch`）
- [ ] 循环展开/多累加器增加 ILP

## 五、算法与数据结构优化

- [ ] 降低算法时间复杂度（O(n²) → O(n log n) → O(n)）
- [ ] 根据场景选择数据结构：
  - 频繁查找：`unordered_map`/`unordered_set`
  - 有序遍历：`map`/`set`
  - 随机访问：`vector`
- [ ] 预分配哈希表桶数量（`reserve`）
- [ ] 使用更高效的哈希函数（如 FNV-1a）
- [ ] 缓存计算结果（空间换时间）

## 六、多线程优化

### 锁优化
- [ ] 使用细粒度锁（拆分大锁）
- [ ] 读多写少场景使用 `shared_mutex`
- [ ] 减少锁持有时间（临界区最小化）

### 无锁编程
- [ ] 简单计数器用 `std::atomic`
- [ ] 使用 `memory_order_relaxed`（无需严格顺序时）
- [ ] 高性能队列考虑无锁实现

### 并发优化
- [ ] 线程数匹配CPU核心数
- [ ] 使用 `thread_local` 避免竞争
- [ ] 负载均衡（工作窃取模式）
- [ ] 避免过度并行化（小任务合并）

## 七、I/O优化

- [ ] 文件I/O使用缓冲（`setvbuf` / 批量读写）
- [ ] 大文件使用内存映射（`mmap`）
- [ ] 网络I/O使用零拷贝（`sendfile`/`splice`）
- [ ] 批量发送（`writev` 分散写入）
- [ ] 异步I/O避免阻塞

## 八、优化后验证

- [ ] 对比优化前后性能指标
- [ ] 确认缓存未命中率 < 10%
- [ ] 确认分支预测失败率 < 5%
- [ ] IPC > 1.0（CPU利用率良好）
- [ ] 回归测试确保正确性
- [ ] 压力测试验证稳定性

---

**优化原则**：
1. **先测量，再优化** —— 找准瓶颈，避免盲目优化
2. **80/20法则** —— 优化20%热点获得80%收益
3. **避免过早优化** —— 先保证正确，再追求性能
4. **权衡取舍** —— 性能 vs 可读性 vs 维护性
5. **持续监控** —— 防止性能回退
