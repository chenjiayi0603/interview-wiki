### 4.2 启动时间详细数据

| 操作 | K3s | K8s | 加速比 |
|------|-----|-----|--------|
| 首次启动（Control Plane） | 5-10 秒 | 30-60 秒 | **6x** |
| Agent 节点启动 | 2-5 秒 | 15-30 秒 | **6x** |
| 集群初始化 | 10-30 秒 | 2-5 分钟 | **5-10x** |
| Pod 调度时间 | <100ms | <200ms | **2x** |
| API 响应时间 | <50ms | <100ms | **2x** |

### 4.3 性能基准测试

| 测试场景 | K3s | K8s | 备注 |
|----------|-----|-----|------|
| **Pod 创建延迟** | 50-100ms | 100-200ms | 小规模集群（<50 Pods） |
| **Pod 启动时间** | 1-3 秒 | 2-5 秒 | 冷启动 |
| **API Server QPS** | 500-1000 | 1000-3000 | 取决于硬件 |
| **网络吞吐量** | 线速 | 线速 | 取决于 CNI 插件 |
| **存储 IOPS** | 取决于后端 | 取决于后端 | SQLite vs etcd |

### 4.4 性能优化建议

**K3s 性能调优：**
```bash
# 使用嵌入式 etcd 替代 SQLite（多节点场景）
k3s server --cluster-init

# 调整 SQLite 缓存大小
k3s server --storage-backend=etcd3

# 禁用不需要的组件
k3s server --disable traefik --disable servicelb
```

**K8s 性能调优：**
```yaml
# API Server 性能优化
apiVersion: kubeproxy.config.k8s.io/v1alpha1
kind: KubeProxyConfiguration
mode: "ipvs"
ipvs:
  scheduler: "least_connections"
```
