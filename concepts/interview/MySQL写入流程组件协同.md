### 3.2 Change Buffer 写优化

```
Change Buffer（MySQL 5.7 前叫 Insert Buffer）的作用：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  当更新的二级索引页不在 Buffer Pool 中时，
  不立即读取索引页，而是将修改操作缓存到 Change Buffer
  等该索引页被读取时或后台 Merge 时再应用这些修改

  减少随机读，将以"读索引页+修改+写回"变为"写 Change Buffer+延迟Merge"

工作原理：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  UPDATE users SET name='Jerry' WHERE id=100;
  假设 idx_name 索引页不在 Buffer Pool 中

  【不用 Change Buffer】
      读 idx_name 索引页（随机读 ██）
      修改 name 索引
      写 Redo Log
      写回索引页（随机写 ██）
      → 需要随机读 + 随机写

  【使用 Change Buffer】
      修改记录写入 Change Buffer（顺序写 ██）
      写 Redo Log
      → 只需顺序写，随机读被延迟到真正需要时

  适用场景：写多读少的二级索引（如日志表、流水表）
  不适用：唯一索引（必须检查唯一性，必须立即读）
```

### 3.3 Doublewrite Buffer

```
Doublewrite Buffer 保护的是数据页写入的完整性：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  问题：InnoDB 的数据页大小是 16KB，操作系统页大小是 4KB
        如果 Page Cleaner 写一个 16KB 页时发生部分写入（只有部分 4KB 写完）
        这个页就"断裂"了，数据页损坏

  Doublewrite 解决：
    1. 先顺序写入 Doublewrite Buffer (共享表空间中的连续 128个页)
       → 顺序写很快
    2. 再随机写入数据文件 (.ibd)
       → 如果发生部分写入故障

    崩溃恢复时：
    1. 检查 .ibd 中数据页的 checksum
    2. 如果损坏，从 Doublewrite Buffer 中获取完整副本恢复
    3. 保证数据页不会"断裂"

  Doublewrite 是"提交后的安全机制"，不是事务提交的一部分
```
