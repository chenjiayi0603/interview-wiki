## 9.1 性能问题诊断流程

**四步诊断法**：
1. **症状识别**：明确性能问题表现（延迟高、吞吐低、CPU高、内存涨等）
2. **数据收集**：使用perf、火焰图、系统监控等工具收集数据
3. **根因分析**：分析数据，定位瓶颈点（CPU、内存、IO、网络等）
4. **优化实施**：针对性优化，验证效果

## 9.2 常见性能问题与解决方案

| 问题症状 | 可能原因 | 诊断工具 | 解决方案 |
|----------|----------|----------|----------|
| **尾延迟高** | 锁竞争、GC停顿、IO抖动、排队 | 火焰图、分布式Trace、perf sched | 无锁数据结构、内存池、IO调度优化 |
| **QPS上不去（CPU满）** | 热点函数、分支预测失败、缓存失效 | perf top、火焰图、cachegrind | 算法优化、分支预测提示、缓存友好数据结构 |
| **QPS上不去（CPU闲）** | IO瓶颈、连接池满、下游限流 | iostat、netstat、线程状态 | 异步IO、连接池优化、批量处理 |
| **CPU高但业务量低** | 空转循环、重试风暴、锁竞争自旋 | perf、strace、业务日志 | 避免忙等待、退避算法、锁优化 |
| **内存持续增长** | 内存泄漏、缓存未释放、碎片 | heaptrack、jemalloc统计、valgrind | 智能指针、对象池、内存分配器优化 |
| **上下文切换频繁** | 线程过多、锁争用、频繁唤醒 | pidstat -w、perf sched | 线程池优化、无锁数据结构、批量处理 |
| **网络延迟高** | 缓冲区满、TCP参数不合理、网络拥塞 | netstat、tcpdump、iperf | 增大缓冲区、优化TCP参数、使用零拷贝 |
| **磁盘IO瓶颈** | 磁盘慢、调度器不合理、文件系统问题 | iostat、iotop、blktrace | 使用SSD、优化调度器、调整文件系统参数 |
| **系统调用频繁** | 频繁read/write、过多系统调用 | strace、perf trace | 批量处理、零拷贝、用户态网络栈 |

## 9.3 性能优化检查清单

**CPU优化检查项**：
- [ ] 热点函数是否优化（perf top检查）
- [ ] 分支预测是否合理（likely/unlikely提示）
- [ ] 缓存局部性是否良好（cachegrind分析）
- [ ] SIMD向量化是否启用（-march=native）
- [ ] CPU亲和性是否设置（taskset/numactl）
- [ ] 频率缩放是否禁用（performance模式）

**内存优化检查项**：
- [ ] 内存分配器是否优化（jemalloc/tcmalloc）
- [ ] 对象池是否使用（避免malloc/free）
- [ ] 缓存行对齐是否处理（避免false sharing）
- [ ] 热冷数据是否分离（提高缓存命中率）
- [ ] 内存泄漏是否检查（valgrind/heaptrack）
- [ ] 大页内存是否启用（HugePages）

**网络优化检查项**：
- [ ] 零拷贝是否使用（sendfile/mmap）
- [ ] 批量处理是否实现（readv/writev）
- [ ] TCP参数是否优化（TCP_NODELAY等）
- [ ] 缓冲区大小是否合理（SO_SNDBUF/SO_RCVBUF）
- [ ] 连接复用是否启用（HTTP keep-alive）
- [ ] 用户态网络栈是否考虑（DPDK/XDP）

**系统优化检查项**：
- [ ] 文件系统参数是否优化（noatime等）
- [ ] I/O调度器是否合适（deadline/noop）
- [ ] 内核参数是否调整（sysctl.conf）
- [ ] 实时调度是否启用（PREEMPT_RT）
- [ ] 中断亲和性是否设置（smp_affinity）
- [ ] 资源限制是否合理（ulimit）
