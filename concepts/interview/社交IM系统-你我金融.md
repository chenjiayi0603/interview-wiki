## 分库分表方案

**分片规则**：
```cpp
// 用户ID分片
int GetShardId(uint64_t user_id) {
    return user_id % 32;  // 32个库
}

// 表ID
int GetTableId(uint64_t user_id) {
    return (user_id / 32) % 64;  // 每库64张表
}

// 完整表名
string GetTableName(uint64_t user_id) {
    int shard_id = GetShardId(user_id);
    int table_id = GetTableId(user_id);
    return "message_" + to_string(shard_id) + "_" + to_string(table_id);
}
```

**路由中间件**：
```cpp
class DBRouter {
public:
    // 获取数据库连接
    mysql_conn* GetConnection(uint64_t user_id) {
        int shard_id = user_id % 32;
        return connection_pool_[shard_id].GetConnection();
    }
    
    // 执行查询（自动路由）
    ResultSet Query(uint64_t user_id, const string& sql) {
        auto conn = GetConnection(user_id);
        string table_name = GetTableName(user_id);
        string real_sql = ReplaceTable(sql, table_name);
        return conn->Query(real_sql);
    }
    
private:
    vector<ConnectionPool> connection_pool_;  // 32个连接池
};
```

## 框架性能实测

**测试环境**：6核CPU，16G内存，300.0 GB硬盘，1000Mb网卡和路由。

| 服务 | 功能 | 并发连接 | 每连接请求数 | 高峰平均并发(trans/sec) |
|------|------|---------|-------------|------------------------|
| 网络收发（http Web服务器） | 返回默认响应 | 300 | 300 | 23255.81 qps |
| web→dataproxy→redis→dbagentwrite→mysql | 发送写数据请求 | 400 | 300 | 1861.16 qps |
| web→dataproxy→redis→dbagentread→mysql | 发送读取数据请求 | 1000 | 300 | 929.34 qps |
| 数据代理（web→dataproxy→redis/ssdb） | 发送读取数据请求 | 300 | 300 | 14657.98 qps（string读） |
| 数据代理（同上） | 发送写数据请求 | 300 | 300 | 12228.26 qps（string写） |
| 数据代理（同上） | hmget获取哈希表单个键的20多个fields | 300 | 300 | 约7000+ qps |

**瓶颈分析**：MySQL的单分片集群是性能瓶颈（dbagentwrite 1861.16 qps, dbagentread 929.34 qps）。

### 常问问题

**Q: 分库分表怎么做的？**

> 按用户ID取模分片，比如32个库，每个库64张表。查询时根据用户ID路由到对应库表。

**Q: 敏感词过滤怎么实现？**

> 用DFA算法（确定有限状态自动机），把敏感词构建成树形结构，O(n)时间复杂度匹配。
