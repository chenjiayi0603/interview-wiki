# 观察者模式详解 - 多个被观察者的管理

## 7. 多个被观察者的管理

### 7.1 问题：如果多个被观察者（Subject），怎么管理？

**答案**：Observer 持有多个 Subject 的 weak_ptr，实现多订阅（常用方案）

### 7.2 Observer 和 Subject 接口定义

```cpp
// 前向声明
class Observer;

// 主题（被观察者）接口
class Subject {
public:
    virtual void attach(std::shared_ptr<Observer> observer) = 0;
    virtual void detach(std::shared_ptr<Observer> observer) = 0;
    virtual void notify(const std::string& message) = 0;
    virtual ~Subject() = default;
};

// 观察者接口
class Observer {
public:
    virtual void update(const std::string& message) = 0;
    virtual ~Observer() = default;
};
```

### 7.3 enable_shared_from_this 和 shared_from_this 详解

#### 7.3.1 为什么需要 enable_shared_from_this？

**问题场景**：
- 在 `MultiSubjectObserver` 的 `subscribe()` 方法中，我们需要将 `this` 指针传递给 `subject->attach()`
- 但是 `attach()` 方法需要的是 `std::shared_ptr<Observer>`
- 我们不能直接将 `this` 转换为 `shared_ptr`，因为：
  1. `this` 是普通指针，不是 `shared_ptr`
  2. 如果直接 `std::shared_ptr<Observer>(this)`，会创建一个新的控制块，导致多个 `shared_ptr` 管理同一个对象，这是未定义行为！

**错误示例**：
```cpp
class MultiSubjectObserver : public Observer {
    void subscribe(std::shared_ptr<Subject> subject) {
        // ❌ 错误！会创建新的控制块，导致未定义行为
        subject->attach(std::shared_ptr<Observer>(this));
    }
};
```

**问题**：
- 如果对象已经由某个 `shared_ptr` 管理（例如 `auto observer = std::make_shared<MultiSubjectObserver>(...)`）
- 然后我们又用 `std::shared_ptr<Observer>(this)` 创建了另一个 `shared_ptr`
- 这两个 `shared_ptr` 有不同的控制块，但它们都指向同一个对象
- 当第一个 `shared_ptr` 被销毁时，对象会被删除，但第二个 `shared_ptr` 不知道，导致悬空指针！

#### 7.3.2 enable_shared_from_this 的作用

`std::enable_shared_from_this<T>` 是一个基类模板，它提供了 `shared_from_this()` 方法。

**工作原理**：
1. `enable_shared_from_this` 内部维护一个 `weak_ptr`，指向对象本身
2. 当对象被 `shared_ptr` 管理时，`shared_ptr` 会设置这个 `weak_ptr`
3. `shared_from_this()` 通过这个 `weak_ptr` 获取管理当前对象的 `shared_ptr`
4. 这样就能安全地获取指向自己的 `shared_ptr`，而不会创建新的控制块

**内部实现原理（简化版）**：
```cpp
template<typename T>
class enable_shared_from_this {
private:
    mutable std::weak_ptr<T> weak_this_;  // 指向自己的 weak_ptr

public:
    std::shared_ptr<T> shared_from_this() {
        return std::shared_ptr<T>(weak_this_);  // 从 weak_ptr 构造 shared_ptr
    }
    
    // shared_ptr 的构造函数会调用这个函数来设置 weak_this_
    template<typename U>
    void _internal_accept_owner(std::shared_ptr<U> const* p) const {
        if (weak_this_.expired()) {
            weak_this_ = std::shared_ptr<T>(*p, static_cast<T*>(this));
        }
    }
};
```

#### 7.3.2.1 weak_this_ 什么时候赋值？

**赋值时机**：在 `shared_ptr` 构造时自动赋值

**详细过程**：

1. **shared_ptr 构造时的检测机制**：
   ```cpp
   // shared_ptr 的构造函数（简化版）
   template<typename T>
   shared_ptr<T>::shared_ptr(T* ptr) {
       // 1. 创建控制块
       control_block_ = new ControlBlock(ptr);
       
       // 2. 检查 ptr 是否继承自 enable_shared_from_this
       if (auto* base = dynamic_cast<enable_shared_from_this<T>*>(ptr)) {
           // 3. 如果继承，调用 _internal_accept_owner 设置 weak_this_
           base->_internal_accept_owner(this);
       }
   }
   ```

2. **具体示例**：
   ```cpp
   // 当执行这行代码时：
   auto observer = std::make_shared<MultiSubjectObserver>("test");
   
   // 内部发生的过程：
   // 1. 在堆上创建 MultiSubjectObserver 对象
   // 2. 创建 shared_ptr，传入对象指针
   // 3. shared_ptr 构造函数检测到 MultiSubjectObserver 继承自 enable_shared_from_this
   // 4. 调用 _internal_accept_owner(this)，设置 weak_this_
   // 5. 此时 weak_this_ 指向刚创建的 shared_ptr
   ```

3. **时间线**：
   ```
   T1: 对象在堆上创建
       MultiSubjectObserver* raw_ptr = new MultiSubjectObserver("test");
       // 此时 weak_this_ 还是空的（未初始化）
   
   T2: shared_ptr 开始构造
       std::shared_ptr<MultiSubjectObserver> sp(raw_ptr);
       // shared_ptr 检测到 enable_shared_from_this
   
   T3: 调用 _internal_accept_owner
       base->_internal_accept_owner(&sp);
       // weak_this_ = std::weak_ptr<MultiSubjectObserver>(sp);
       // 此时 weak_this_ 被赋值，指向 sp
   
   T4: shared_ptr 构造完成
       // 现在可以安全调用 shared_from_this() 了
   ```

4. **为什么是 weak_ptr 而不是 shared_ptr？**
   - 如果 `weak_this_` 是 `shared_ptr`，会形成循环引用：
     - `shared_ptr` 持有对象
     - 对象内部的 `weak_this_` 也持有 `shared_ptr`
     - 导致引用计数永远不会为 0，内存泄漏！
   - 使用 `weak_ptr` 可以避免循环引用：
     - `shared_ptr` 持有对象
     - 对象内部的 `weak_this_` 是 `weak_ptr`，不增加引用计数
     - 不会形成循环引用

#### 7.3.2.2 从 weak_ptr 构造 shared_ptr 的机制

**语法**：
```cpp
std::shared_ptr<T> sp(wp);  // 从 weak_ptr 构造 shared_ptr
```

**工作原理**：
```cpp
template<typename T>
class shared_ptr {
private:
    T* ptr_;                    // 指向对象的指针
    ControlBlock* control_block_;  // 指向控制块的指针

public:
    // 从 weak_ptr 构造 shared_ptr 的构造函数
    shared_ptr(const weak_ptr<T>& wp) {
        // ⚠️ 注意：这是构造函数，不需要 return 语句
        // 构造函数会自动构造对象并返回
        
        // 1. 检查 weak_ptr 是否有效（对象是否还存在）
        if (wp.expired()) {
            throw std::bad_weak_ptr();  // 对象已被销毁，抛出异常
        }
        
        // 2. 尝试原子地增加引用计数
        if (wp.control_block_->try_increment_use_count()) {
            // 3. 成功：对象还存在，初始化 shared_ptr 的成员变量
            control_block_ = wp.control_block_;  // 共享控制块
            ptr_ = wp.ptr_;                      // 指向同一个对象
            // 引用计数已经在 try_increment_use_count() 中增加了
            // 此时 use_count += 1
        } else {
            // 4. 失败：对象已被销毁（在检查后、增加引用计数前被销毁）
            // 构造函数抛出异常，对象构造失败
            throw std::bad_weak_ptr();
        }
        
        // 5. 构造函数执行完毕，自动返回构造好的 shared_ptr 对象
        // 不需要显式的 return 语句
    }
};
```

**关键理解**：

1. **这是构造函数，不是普通函数**：
   - 构造函数没有返回类型（连 `void` 都没有）
   - 构造函数不需要 `return` 语句
   - 构造函数执行完毕后，会自动返回构造好的对象

2. **构造过程**：
   ```cpp
   // 当执行这行代码时：
   std::shared_ptr<Observer> sp(wp);
   
   // 内部发生的过程：
   // 1. 在栈上分配 shared_ptr 对象的内存空间
   // 2. 调用构造函数 shared_ptr(const weak_ptr<T>& wp)
   // 3. 在构造函数中初始化成员变量（control_block_, ptr_）
   // 4. 构造函数执行完毕，返回构造好的 shared_ptr 对象
   // 5. sp 现在是一个有效的 shared_ptr 对象
   ```

3. **完整的构造流程**：
   ```cpp
   // 步骤1：声明变量（分配内存）
   std::shared_ptr<Observer> sp;
   // 此时 sp 还没有被初始化
   
   // 步骤2：调用构造函数
   sp = std::shared_ptr<Observer>(wp);
   // 或者直接：
   std::shared_ptr<Observer> sp(wp);
   
   // 步骤3：构造函数执行
   // - 检查 wp.expired()
   // - 尝试增加引用计数
   // - 初始化 control_block_ 和 ptr_
   
   // 步骤4：构造函数返回
   // - 不需要 return 语句
   // - 自动返回构造好的 shared_ptr 对象
   // - sp 现在是一个有效的 shared_ptr
   ```

4. **与普通函数的区别**：
   ```cpp
   // 普通函数需要 return
   std::shared_ptr<T> create_shared_ptr() {
       // ... 一些操作 ...
       return std::shared_ptr<T>(...);  // 需要 return
   }
   
   // 构造函数不需要 return
   shared_ptr<T>::shared_ptr(const weak_ptr<T>& wp) {
       // ... 初始化操作 ...
       // 不需要 return，自动返回构造好的对象
   }
   ```

5. **如果构造失败**：
   ```cpp
   // 如果构造函数抛出异常，对象构造失败
   try {
       std::shared_ptr<Observer> sp(wp);  // 如果 wp 已过期，抛出异常
       // sp 不会被创建
   } catch (const std::bad_weak_ptr& e) {
       // 构造失败，sp 不存在
   }
   ```

**关键点**：
1. **原子操作**：整个过程是原子的，保证线程安全
2. **检查有效性**：先检查对象是否还存在
3. **增加引用计数**：如果对象存在，原子地增加引用计数
4. **可能失败**：即使检查时对象存在，在增加引用计数前可能被销毁

**示例**：
```cpp
std::weak_ptr<Observer> wp;

{
    auto observer = std::make_shared<Observer>();
    wp = observer;  // wp 指向 observer
    // observer 离开作用域，引用计数变为 0，对象被销毁
}

// 尝试从 weak_ptr 构造 shared_ptr
try {
    auto sp = std::shared_ptr<Observer>(wp);  // ❌ 抛出 std::bad_weak_ptr
} catch (const std::bad_weak_ptr& e) {
    // 对象已被销毁
}
```

**安全用法**：
```cpp
// 推荐方式：使用 lock() 而不是构造函数
if (auto sp = wp.lock()) {
    // 对象还存在，可以安全使用
} else {
    // 对象已被销毁
}
```

#### 7.3.2.3 从 shared_ptr 构造 weak_ptr 的机制

**语法**：
```cpp
std::weak_ptr<T> wp(sp);  // 从 shared_ptr 构造 weak_ptr
```

**工作原理**：
```cpp
template<typename T>
weak_ptr<T>::weak_ptr(const shared_ptr<T>& sp) {
    if (sp.control_block_) {
        // 1. 共享同一个控制块
        control_block_ = sp.control_block_;
        
        // 2. 增加 weak_count（weak_ptr 计数）
        control_block_->weak_count_++;
        
        // 3. 不增加 use_count（shared_ptr 计数）
        // 这是关键：weak_ptr 不增加引用计数
    } else {
        // sp 是空的，weak_ptr 也是空的
        control_block_ = nullptr;
    }
}
```

**关键点**：
1. **共享控制块**：`weak_ptr` 和 `shared_ptr` 共享同一个控制块
2. **不增加引用计数**：`weak_ptr` 不增加 `use_count`，只增加 `weak_count`
3. **不影响对象生命周期**：对象是否被销毁只取决于 `use_count`，与 `weak_count` 无关

**示例**：
```cpp
auto observer = std::make_shared<Observer>();
// use_count = 1, weak_count = 0

std::weak_ptr<Observer> wp = observer;
// use_count = 1 (不变), weak_count = 1 (增加)

observer.reset();  // 或离开作用域
// use_count = 0, weak_count = 1
// 对象被销毁（因为 use_count = 0）
// 但控制块还存在（因为 weak_count > 0）

wp.lock();  // 返回空指针，因为对象已被销毁
```

#### 7.3.2.4 两者的区别和联系

**对比表**：

| 特性 | 从 weak_ptr 构造 shared_ptr | 从 shared_ptr 构造 weak_ptr |
|-----|---------------------------|---------------------------|
| **语法** | `shared_ptr<T> sp(wp)` | `weak_ptr<T> wp(sp)` |
| **前提条件** | weak_ptr 观察的对象必须还存在 | shared_ptr 可以为空 |
| **失败情况** | 如果对象已销毁，抛出异常 | 如果 shared_ptr 为空，weak_ptr 也为空 |
| **引用计数** | 增加 use_count | 不增加 use_count，只增加 weak_count |
| **对象生命周期** | 延长对象生命周期 | 不影响对象生命周期 |
| **线程安全** | 原子操作，线程安全 | 原子操作，线程安全 |
| **性能** | 需要检查对象是否存在 | 直接赋值，性能更好 |
| **使用场景** | 在 shared_from_this() 中 | 在 enable_shared_from_this 中设置 weak_this_ |

**在 enable_shared_from_this 中的应用**：

1. **设置 weak_this_（从 shared_ptr 构造 weak_ptr）**：
   ```cpp
   // 在 _internal_accept_owner 中
   weak_this_ = std::weak_ptr<T>(sp);  // 从 shared_ptr 构造 weak_ptr
   // 不增加引用计数，只增加 weak_count
   ```

2. **获取 shared_ptr（从 weak_ptr 构造 shared_ptr）**：
   ```cpp
   // 在 shared_from_this() 中
   return std::shared_ptr<T>(weak_this_);  // 从 weak_ptr 构造 shared_ptr
   // 增加引用计数（如果对象还存在）
   ```

**完整流程示例**：
```cpp
// 1. 创建对象
auto observer = std::make_shared<MultiSubjectObserver>("test");
// 内部：shared_ptr 检测到 enable_shared_from_this
// 调用：weak_this_ = std::weak_ptr<MultiSubjectObserver>(observer);
// 此时：use_count = 1, weak_count = 1

// 2. 调用 shared_from_this()
auto sp = observer->shared_from_this();
// 内部：return std::shared_ptr<MultiSubjectObserver>(weak_this_);
// 从 weak_ptr 构造 shared_ptr，增加引用计数
// 此时：use_count = 2, weak_count = 1

// 3. sp 离开作用域
// use_count = 1, weak_count = 1

// 4. observer 离开作用域
// use_count = 0, weak_count = 1
// 对象被销毁，但控制块还存在（因为 weak_count > 0）

// 5. 控制块被销毁（当 weak_count 也变为 0 时）
```

**关键理解**：
- **从 shared_ptr 到 weak_ptr**：不增加引用计数，只是"观察"对象
- **从 weak_ptr 到 shared_ptr**：增加引用计数，真正"拥有"对象
- **enable_shared_from_this**：利用这两个机制，让对象能够安全地获取指向自己的 shared_ptr

#### 7.3.3 使用要求

**必须满足的条件**：
1. 类必须继承 `std::enable_shared_from_this<T>`，其中 `T` 是类本身
2. 对象必须已经被 `shared_ptr` 管理（不能是栈对象或裸指针）
3. 在对象构造完成后才能调用 `shared_from_this()`

**错误示例**：
```cpp
// ❌ 错误1：对象不是由 shared_ptr 管理
MultiSubjectObserver observer("test");
observer.subscribe(subject);  // 调用 shared_from_this() 会抛出 std::bad_weak_ptr 异常

// ❌ 错误2：在构造函数中调用
class MultiSubjectObserver : public Observer, 
                             public std::enable_shared_from_this<MultiSubjectObserver> {
    MultiSubjectObserver(const std::string& name) : name_(name) {
        // ❌ 错误！此时对象还没有被 shared_ptr 管理
        auto sp = shared_from_this();  // 会抛出异常
    }
};
```

**正确示例**：
```cpp
// ✅ 正确：对象由 shared_ptr 管理
auto observer = std::make_shared<MultiSubjectObserver>("test");
observer->subscribe(subject);  // 此时可以安全调用 shared_from_this()
```

#### 7.3.4 shared_from_this() 的实现细节

```cpp
template<typename T>
std::shared_ptr<T> enable_shared_from_this<T>::shared_from_this() {
    // 1. 检查 weak_this_ 是否有效
    if (weak_this_.expired()) {
        throw std::bad_weak_ptr();  // 对象没有被 shared_ptr 管理
    }
    
    // 2. 从 weak_ptr 构造 shared_ptr
    return std::shared_ptr<T>(weak_this_);
}
```

**关键点**：
- `shared_from_this()` 返回的 `shared_ptr` 与创建对象的 `shared_ptr` 共享同一个控制块
- 引用计数会正确增加
- 不会创建新的控制块，避免了未定义行为

#### 7.3.5 在 MultiSubjectObserver 中的使用

```cpp
class MultiSubjectObserver : public Observer, 
                             public std::enable_shared_from_this<MultiSubjectObserver> {
    void subscribe(std::shared_ptr<Subject> subject) {
        // ✅ 正确：使用 shared_from_this() 获取指向自己的 shared_ptr
        subject->attach(shared_from_this());
        // 注意：shared_from_this() 返回的是 std::shared_ptr<MultiSubjectObserver>
        // 但 attach() 需要的是 std::shared_ptr<Observer>
        // 由于 MultiSubjectObserver 继承自 Observer，可以自动转换
    }
};
```

**为什么可以自动转换**？
- `shared_ptr` 支持从派生类到基类的隐式转换
- `std::shared_ptr<MultiSubjectObserver>` 可以隐式转换为 `std::shared_ptr<Observer>`
- 这是安全的，因为 `MultiSubjectObserver` 是 `Observer` 的子类

### 7.4 MultiSubjectObserver 完整实现

MultiSubjectObserver 场景举例：用户用一部手机 App 同时关注多个气象站

应用场景举例：
假设有多个气象站（Subject），每个气象站发布天气变化通知。用户的手机 App（MultiSubjectObserver）希望同时订阅这几个气象站的天气信息。当任意气象站发生气温变化时，App 都会收到消息。

```cpp
// 改进的观察者：可以订阅多个 Subject（完整实现）
// 注意：需要继承 enable_shared_from_this 才能使用 shared_from_this()
#include <iostream>
#include <memory>
#include <vector>
#include <algorithm>
#include <string>

// 前置声明
class Observer;

// 基础接口同上略...

// 具体气象站实现（简化版）
class WeatherStation : public Subject {
private:
    std::vector<std::weak_ptr<Observer>> observers_;
    float temperature_;
    std::string location_;
public:
    WeatherStation(const std::string& loc) : location_(loc) {}

    void attach(std::shared_ptr<Observer> observer) override {
        observers_.push_back(observer);
    }
    void detach(std::shared_ptr<Observer> observer) override {
        observers_.erase(
            std::remove_if(observers_.begin(), observers_.end(),
                [&observer](const std::weak_ptr<Observer>& wp){
                    auto sp = wp.lock();
                    return !sp || sp == observer;
                }),
            observers_.end()
        );
    }
    void notify(const std::string& message) override {
        for (auto it = observers_.begin(); it != observers_.end();) {
            if (auto sp = it->lock()) {
                sp->update("[" + location_ + "] " + message);
                ++it;
            } else {
                it = observers_.erase(it); // 清理失效 weak_ptr
            }
        }
    }
    void setTemperature(float temp) {
        temperature_ = temp;
        notify("温度变为 " + std::to_string(temp));
    }
};

// 多气象站订阅者
class MultiSubjectObserver : public Observer, public std::enable_shared_from_this<MultiSubjectObserver> {
private:
    std::string name_;
    // ❌ 不能只保留 Subject 的 observers_，去掉 Observer 侧的 subjects_。
    //
    // 【理由】：
    // 1）如果 Observer 不持有 subjects_，将无法主动统一取消所有订阅（例如析构时自动解除所有 Subject 的 attach）。
    // 2）只靠 Subject 的 observers_ 并不能知道「我（Observer 实例）当前正在观察哪些 Subject」——无法双向管理。
    // 3）Observer 持有 subjects_ 可以主动防止悬空指针（Observer 析构时解绑）与保证资源一致性；否则可能出现 Observer 销毁后 Subject 还持有失效 observer（虽然弱引用可缓解，但主动 detach 更安全）。
    // 4）例如你要“取消所有订阅/unsubscribeAll”，没有 subjects_ 做不到。
    //
    // 【最佳实践】：
    // > Observer 持有 subjects_，Subject 持有 observers_ —— 双向弱引用是多对多管理和资源正确释放的关键。
    //
    // 总结：subjects_ 不能省略，只靠 observers_ 会丢失 Observer─Subject 订阅关系、导致析构残留。

    std::vector<std::weak_ptr<Subject>> subjects_;
public:
    MultiSubjectObserver(const std::string& name) : name_(name) {}
    // ⚠️ 注意：不能在构造函数中调用 shared_from_this()
    // 因为此时对象还没有被 shared_ptr 管理

    void subscribe(std::shared_ptr<Subject> subject) {
        if (!subject) return;
        subjects_.push_back(subject);
        subject->attach(shared_from_this());
        // ✅ 使用 shared_from_this() 获取指向自己的 shared_ptr
        // shared_from_this() 返回 std::shared_ptr<MultiSubjectObserver>
        // 可以隐式转换为 std::shared_ptr<Observer>
    }
    // 取消订阅一个 Subject
    void unsubscribe(std::shared_ptr<Subject> subject) {
        if (!subject) return;
        
        // 从 subjects_ 中移除
        subjects_.erase(
            std::remove_if(subjects_.begin(), subjects_.end(),
                [&subject](const std::weak_ptr<Subject>& wp) {
                    auto locked = wp.lock();
                    return locked && locked == subject;
                }),
            subjects_.end()
        );
        
        // 从 Subject 的观察者列表中移除
        // ✅ 使用 shared_from_this() 获取指向自己的 shared_ptr
        if (auto sp = shared_from_this()) {
            subject->detach(sp);
        }
    }

    // 取消订阅所有 Subject
    void unsubscribeAll() {
        for (auto it = subjects_.begin(); it != subjects_.end();) {
            if (auto subject = it->lock()) {
                // ✅ 使用 shared_from_this() 获取指向自己的 shared_ptr
                if (auto sp = shared_from_this()) {
                    subject->detach(sp);
                }
                ++it;
            } else {
                it = subjects_.erase(it);  // 移除已销毁的 Subject
            }
        }
        subjects_.clear();
    }
    void update(const std::string& message) override {
        std::cout << "用户 [" << name_ << "] 的 App 收到通知: " << message << std::endl;
    }
    ~MultiSubjectObserver() {
        unsubscribeAll();  // 析构时自动取消所有订阅
    }
};

// 场景演示

    auto stationA = std::make_shared<WeatherStation>("海淀气象站");
    auto stationB = std::make_shared<WeatherStation>("朝阳气象站");

    app->subscribe(stationA); // 订阅海淀气象站
```

### 7.6 常见错误和注意事项

**错误1：对象不是由 shared_ptr 管理**
```cpp
// ❌ 错误
MultiSubjectObserver observer("test");
observer.subscribe(subject);  // 会抛出 std::bad_weak_ptr 异常
```

**错误2：在构造函数中调用 shared_from_this()**
```cpp
class MultiSubjectObserver : public Observer, 
                             public std::enable_shared_from_this<MultiSubjectObserver> {
    MultiSubjectObserver(const std::string& name) : name_(name) {
        // ❌ 错误！此时对象还没有被 shared_ptr 管理
        auto sp = shared_from_this();  // 会抛出异常
    }
};
```

**错误3：直接使用 this 创建 shared_ptr**
```cpp
void subscribe(std::shared_ptr<Subject> subject) {
    // ❌ 错误！会创建新的控制块，导致未定义行为
    subject->attach(std::shared_ptr<Observer>(this));
}
```

**正确做法**：
```cpp
// ✅ 正确：使用 shared_ptr 创建对象
auto observer = std::make_shared<MultiSubjectObserver>("test");
observer->subscribe(subject);  // 可以安全使用 shared_from_this()
```
