# 进程地址空间布局

## 进程地址空间组成

```
进程虚拟地址空间（VSZ）
├── 栈（Stack）：函数调用、局部变量，向下增长
├── 内存映射段：共享库、mmap 映射的文件，可读、可写、可执行等不同权限
├── 堆（Heap）：malloc/new 分配的内存，向上增长
├── BSS段：未初始化的全局变量（可读写）
├── 数据段（Data）：已初始化的全局变量（可读写）
├── 只读数据段（Read-only Data / .rodata）：存放常量字符串、const全局常量，只读属性，可能与代码段紧邻
└── 代码段（Text）：可执行机器指令，只读共享
```

## 各区域详细说明

### 静态区域

这些区域在程序编译链接后大小就基本固定，在进程生命周期内保持稳定。

- **代码段（Text Segment）**：
  - 也称为文本段，存放由 CPU 执行的机器指令
  - 通常是只读和共享的，这意味着内存中只需一份副本即可被多个相同程序的进程实例共享

- **数据段（Data Segment）**：
  - 存放显式初始化且初始值不为零的全局变量和静态变量（包括全局和局部静态变量）

- **BSS 段（Block Started by Symbol）**：
  - 存放未初始化或显式初始化为零的全局变量和静态变量
  - 操作系统负责在程序加载时将整个 BSS 段清零
  - 它在磁盘上的可执行文件中不占空间，节省了存储

### 动态区域

这些区域在程序运行期间大小可变化，是内存动态管理的核心。

- **堆（Heap）**：
  - 用于程序运行时的动态内存分配
  - 通过 `malloc`、`calloc`、`realloc`（C）或 `new`（C++）申请的内存位于此处
  - 堆通常向高地址增长
  - **注意**：当分配非常大块的内存时，现代的内存分配器（如 glibc 的 malloc）可能会直接使用 `mmap` 创建一块独立的匿名映射区域，而不是在标记为 [heap] 的区域中分配，这时在内存映射中会显示为 [anon]

- **内存映射段（Memory Mapping Segment）**：
  - 这是一个非常灵活的区域，用途广泛：
    - 加载共享库（如 C 标准库 libc.so.6）
    - 通过 `mmap` 系统调用进行文件映射，将文件内容直接映射到内存，方便读写
    - 创建匿名映射，常用于大块内存分配或进程间共享内存

- **栈（Stack）**：
  - 每个线程通常都有自己独立的栈
  - 用于管理函数调用，存储局部变量、函数参数、返回地址等
  - 栈向低地址方向增长
  - **注意**：栈空间是有限的，过度递归或定义非常大的局部变量可能导致栈溢出

### 内核空间

- 这是操作系统内核代码和数据驻留的区域
- 它位于每个进程地址空间的最高处（例如，在 32 位系统中，通常为 3GB-4GB 的部分）
- 受到保护，用户态进程无法直接访问，从而确保内核的安全和稳定

## 变量存储位置速查

| 类型/示例                        | 存放位置             | 访问属性 | 共享特性     | 备注                         |
|---------------------------------|--------------------|---------|------------|----------------------------|
| 字符串字面量/全局const等           | 只读数据段            | 只读    | 全局共享     | 位于.rodata                 |
| static const 局部常量           | 多数直接存.rodata（编译期常量），只读、不可修改，通常不会分配在栈/BSS，常被内联优化 |
| vtable/类型信息等编译器生成        | 只读数据段            | 只读    | 全局共享     | RTTI等同上                  |
| 未初始化全局变量/静态变量（如 int g; static int s;） | BSS段（未初始化数据段） | 可读写  | 全局可见（或内部链接） | 只在程序启动时清零分配，不占二进制体积   |
| 已初始化全局变量/静态变量（如 int g = 1; static int s = 2;） | 数据段（Data）        | 可读写  | 全局可见（或内部链接） | 初始值存于可执行文件，加载时赋值         |

## 常量与只读数据段

- 常量字符串字面量、`const` 全局常量，以及大多数 **`static const` 静态局部常量**（如果值在编译期就能计算出来），一般会被放进进程虚拟空间的**只读区域**（如 `.rodata` 段），实现全局共享、只读，不会出现在堆、栈或普通数据段。尽管这些变量的内存分配在程序加载时已完成，但对于 `static` 局部变量来说，C++ 标准规定"首次进入作用域时才初始化"（即所谓"懒初始化"），以确保即使变量初始化依赖于运行时状态也能正确处理。

- 不过**如果静态局部常量是编译期常量（如 static const int x = 1）**，编译器通常可提前初始化到只读段，甚至直接内联，不产生实际内存存储。总结：虽然"初始化"语义上发生在首次使用，但只要能编译期求值，内存空间实则早已分配并初始化，运行时仅是语义保证。

- **什么是"编译期求值"？** 编译期求值就是变量的值在编译阶段已经被确定，而不是等到程序运行时才计算。若变量初始化表达式仅涉及常量、字面量或编译期能确定结果的运算，编译器就能直接在编译阶段把这个值"写死"进可执行文件的只读段。

- **结论**：
  - `static` 局部变量/常量只分配一次（程序加载时或首次用到时），
  - 常量值可能进入只读段（如.rodata），否则与普通static变量一样在数据段，
  - 从不在栈上，也不是运行时重复分配。

## 关键点

- 所有线程共享：代码段、数据段、BSS段、堆、共享库
- 每个线程私有：栈、寄存器上下文、信号掩码、TLS（Thread Local Storage，线程局部存储，指每个线程拥有独立的一块用于存放线程私有变量的数据区）

## 常用查看工具

- `readelf -S your.o` 查看各段信息
- `objdump -s -j .rodata your.o` 直接观察只读段内容
- 调试/反汇编工具：可确认常量与字符串不分配在堆、栈或 data/bss 区
