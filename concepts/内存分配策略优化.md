# 内存分配策略优化

## 2.1 栈 vs 堆分配

**栈分配（推荐）**：
- **优点**：速度快、自动管理、无碎片
- **限制**：大小受限（通常 1-8MB）、生命周期固定
- **适用场景**：小对象、局部变量、临时对象

```cpp
// 推荐：栈分配
void process() {
    std::array<int, 1000> buffer;  // 栈分配，快速
    // 使用 buffer
}  // 自动释放

// 不推荐：堆分配小对象
void process() {
    int* buffer = new int[1000];  // 堆分配，慢
    // 使用 buffer
    delete[] buffer;  // 容易忘记
}
```

## 2.2 对象池（Object Pool）

**原理**：预分配对象池，复用对象，避免频繁分配/释放

```cpp
template<typename T>
class ObjectPool {
private:
    // 为什么用 queue？队列天然适合对象池“先进先出”回收和复用，可以让热数据优先重用（缓存友好），避免频繁分配；同时接口简单、线程安全性也易于保障
    std::queue<std::unique_ptr<T>> pool_;
    std::mutex mutex_;
    size_t max_size_;

public:
    ObjectPool(size_t max_size = 100) : max_size_(max_size) {
        // 预分配对象
        for (size_t i = 0; i < max_size_; ++i) {
            pool_.push(std::make_unique<T>());
        }
    }

    std::unique_ptr<T> acquire() {
        std::lock_guard<std::mutex> lock(mutex_);
        if (pool_.empty()) {
            // 此处会调用T的构造函数，确保新对象初始化
            return std::make_unique<T>();  // 池空时创建新对象（会调用构造函数）
        }
        auto obj = std::move(pool_.front());
        pool_.pop();
        return obj;
    }

    void release(std::unique_ptr<T> obj) {
        std::lock_guard<std::mutex> lock(mutex_);
        if (pool_.size() < max_size_) {
            obj->reset();  // 为什么不析构？因为对象池的目的是复用对象：这里只是调用成员reset()将状态重置，保留对象本体在池中，避免频繁构造/析构带来的性能开销
            pool_.push(std::move(obj));
        }
        // 否则自动释放
    }
};
```

**适用场景**：
- 频繁创建/销毁的小对象
- 网络连接、线程对象
- 游戏中的子弹、粒子等

## 2.3 内存池（Memory Pool）

**原理**：预分配大块内存，按需切分，减少系统调用

```cpp
class MemoryPool {
private:
    struct Block {
        char* data;
        size_t size;
        bool in_use;
    };
    
    std::vector<Block> blocks_;
    size_t block_size_;
    size_t pool_size_;

public:
    MemoryPool(size_t block_size, size_t num_blocks) 
        : block_size_(block_size), pool_size_(block_size * num_blocks) {
        // 一次性分配大块内存
        char* pool = static_cast<char*>(std::malloc(pool_size_));
        
        // 切分为多个块
        for (size_t i = 0; i < num_blocks; ++i) {
            blocks_.push_back({pool + i * block_size_, block_size_, false});
        }
    }

    void* allocate(size_t size) {
        if (size > block_size_) {
            return std::malloc(size);  // 大对象直接分配
        }
        
        // 查找空闲块
        for (auto& block : blocks_) {
            if (!block.in_use) {
                block.in_use = true;
                return block.data;
            }
        }
        
        return std::malloc(size);  // 池满时回退到系统分配
    }

    void deallocate(void* ptr) {
        for (auto& block : blocks_) {
            if (block.data == ptr) {
                block.in_use = false;
                return;
            }
        }
        std::free(ptr);  // 不在池中的内存
    }

    ~MemoryPool() {
        if (!blocks_.empty()) {
            std::free(blocks_[0].data);
        }
    }
};
```

**优势**：
- 减少系统调用次数
- 降低内存碎片
- 提高分配速度（通常快 10-100 倍）

### 2.3.3 内存池 vs. 对象池

**相同点：**
- 都是**复用机制**，通过预分配和重用已分配的内存/对象来减少频繁的系统分配与释放，从而提升分配效率、降低碎片。
- 目的相同，即避免频繁的`malloc/free`（或`new/delete`），提高分配性能，优化内存局部性。

**区别：**

|  | 内存池（Memory Pool） | 对象池（Object Pool） |
|:----|:----------------------|:-------------------------|
| 粒度 | 原始的**内存块**      | **完整对象实例**         |
| 关注点 | 只关心字节分配与回收 | 包含对象构造/析构管理    |
| 泛用性 | 可为任意类型分配内存 | 适用于具体某类对象       |
| 生命周期 | 分配/回收内存       | 管理对象的创建/重用      |
| 使用方式 | 类似于malloc/free   | 通过get/release、acquire/recycle操作 |
| 复杂性 | 较低；主要用于无复杂生命周期、POD类型 | 较高；需保障对象复用的正确性  |

**示例场景：**
- **内存池**：适合管理频繁小块分配（如自定义容器、网络包缓冲等），可做分配器底层实现。
- **对象池**：适合复用短命周期、构造/析构昂贵的业务对象，如连接对象、线程任务、数据库句柄。

**代码示例小结：**

- **内存池**仅负责`void*`内存分配和释放，不负责对象生命周期：

    ```cpp
    void* raw = memoryPool.allocate(sizeof(MyObject));
    // placement new（中文常称“定位new”或“定址new”）：在已有内存（raw）上原地构造对象（不会分配新内存）
    MyObject* obj = new(raw) MyObject(...); // 等价于：调用 MyObject 的构造函数，把 obj 放进 raw 指向的内存
    // 常见语法：new(地址) 类型(构造参数)
    // 应用场景：如内存池、重载 operator new、手动对象生命周期管理等
    // (使用完)手动析构:
    obj->~MyObject();
    memoryPool.deallocate(raw);
    ```

- **对象池**负责**完整管理对象创建和重用**，一般通过返回指针或智能指针，并在回收时自动调用析构：

    ```cpp
    MyObject* obj = objectPool.acquire();
    // 用完后归还 pool
    objectPool.release(obj);
    // 或：
    // auto handle = objectPool.get();
    ```

**性能简评：**
- 内存池更低层，粒度细，灵活但可能需要配合对象构造/析构手动管理。
- 对象池面向高开销对象，防止频繁构造/析构，能极大提升复用型场景下的性能。

**实际工程**中，常将“内存池+对象池”组合使用，内存池提供block分配，对象池管理业务对象。

## 2.4 自定义分配器（Custom Allocator）

**C++ 标准库分配器接口**：

```cpp
template<typename T>
class FastAllocator {
public:
    using value_type = T;
    
    T* allocate(size_t n) {
        // 使用内存池或对齐分配
        return static_cast<T*>(::operator new(n * sizeof(T)));
    }
    
    void deallocate(T* p, size_t n) {
        ::operator delete(p);
    }
    
    template<typename U>
    bool operator==(const FastAllocator<U>&) const { return true; }
    
    template<typename U>
    bool operator!=(const FastAllocator<U>&) const { return false; }
};

// 使用自定义分配器
std::vector<int, FastAllocator<int>> vec;
```

**应用场景**：
- STL 容器优化
- 特定内存对齐需求
- 性能关键路径
