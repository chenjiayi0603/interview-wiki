# 内存涨 / 碎片

## 内存

- 自定义/替换分配器（jemalloc/mimalloc/tcmalloc），对象池，Arena/Pool，减少碎片与频繁 malloc/free。
- 避免大对象跨 NUMA/跨 socket 频繁迁移，尽量就地更新；合理设置 huge page。

**举例**：

- 链接 tcmalloc 替换 glibc malloc：
  ```
  -ltcmalloc
  ```
- per-thread pool:
  ```cpp
  thread_local vector<T> pool;
  ```
- numa 本地分配：
  ```
  numactl --cpunodebind=0 --membind=0 ./myserver
  ```
- 启用 Transparent Huge Page (临时)：
  ```
  echo always > /sys/kernel/mm/transparent_hugepage/enabled
  ```

- 监控碎片和分配延迟：
  ```cpp
  mallctl("stats.arenas.0.small.allocated", ...)
  ```

**分析**：内存瓶颈多表现为分配慢、碎片多、RSS 涨；先换分配器或池化，再考虑 NUMA 与大页。

## 自定义分配器与对象池

**要点**：默认 glibc malloc 在高并发、多尺寸分配下容易碎片和锁争用。可替换为 **jemalloc / mimalloc / tcmalloc**，或对热点对象做 **对象池**（预分配一批同类型对象，用完归还池而非 free）、**Arena/Pool**（一块大内存按需切分，生命周期结束整块释放），减少碎片与频繁 malloc/free。

**举例**：

- jemalloc 配置 LD_PRELOAD:
  ```
  LD_PRELOAD=/usr/lib/libjemalloc.so ./myservice
  ```
- thread_local vector pool:
  ```cpp
  thread_local std::vector<T*> pool;
  ```
- arena/pool 用法（如 protobuf Arena）:
  ```cpp
  google::protobuf::Arena arena;
  MyMsg* msg = google::protobuf::Arena::CreateMessage<MyMsg>(&arena);
  ```

## gcc自定义小对象内存池

对于大量小对象（如几百字节以内 struct），直接用 `malloc/free` 性能低下且易碎片。可以自定义简单的 slab/memory pool：预先分配一块大内存，切分成等长小块，用空闲链表管理分配和释放。

**经典实现**（以 64字节对象为例，线程不安全，示意代码）：

```cpp
#include <cstddef>
#include <vector>

class MyObjPool {
    static const size_t OBJ_SIZE = 64;   // 每个对象大小
    static const size_t OBJ_COUNT = 1024; // 预分配对象数
    char*  buf_;                 // 内存池
    void*  free_list_;           // 空闲链表头

public:
    MyObjPool() {
        buf_ = new char[OBJ_SIZE * OBJ_COUNT];
        free_list_ = nullptr;
        // 初始化空闲链表
        for (size_t i = 0; i < OBJ_COUNT; ++i) {
            void* slot = buf_ + i * OBJ_SIZE;
            // 前8字节存下一节点指针
            *reinterpret_cast<void**>(slot) = free_list_;
            free_list_ = slot;
        }
    }
    ~MyObjPool() { delete[] buf_; }

    void* alloc() {
        if (!free_list_) return nullptr; // pool exhausted
        void* obj = free_list_;
        free_list_ = *reinterpret_cast<void**>(free_list_);
        return obj;
    }
    void free(void* p) {
        *reinterpret_cast<void**>(p) = free_list_;
        free_list_ = p;
    }
};

// 用法示例
// MyObjPool pool;
// void* ptr = pool.alloc();
// ... 使用ptr (强转为你的类型指针) ...
// pool.free(ptr);
```

- 多线程下可用每线程一个 pool 或加锁/无锁队列。
- 适用于"频繁创建/销毁小对象、生命周期类似"场景，如 cache 节点、消息对象等。
- 通常比 malloc/free 快一个数量级，基本无碎片。

如果对象有析构需求，可用 placement new（在分配的内存上构造对象），free 前显式析构。更高级可研究 boost pool、folly small object allocator、tcmalloc/jemalloc 的 arena 实现。


- perf top 观察 malloc/free热点

## NUMA 与 Huge Page

**要点**：**NUMA**：大对象或频繁访问的结构尽量在"当前线程所在 NUMA 节点"上分配，避免跨 socket 访问（延迟可差 2～3 倍）。**Huge Page**：大块连续内存（如大 hash 表、buffer 池）使用 2MB 大页，可减少 TLB miss 和页表遍历，对高随机访问的工作负载尤其有效。

**举例**：

- numa 绑定：
  ```
  numactl --membind=0 ./mydaemon
  ```
- jemalloc/malloc 大页配置环境变量：
  ```
  export LD_PRELOAD=/usr/lib/libjemalloc.so
  export MALLOC_CONF=thp:always
  ```
- 使用 mmap 创建 hugepage 内存：
  ```cpp
  void* ptr = mmap(0, size, PROT_READ|PROT_WRITE, MAP_PRIVATE|MAP_ANONYMOUS|MAP_HUGETLB, -1, 0);
  ```

- perf stat -e 'dTLB-load-misses' 监测页表 miss
