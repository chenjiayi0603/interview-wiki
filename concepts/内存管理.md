# 内存管理

> 本文涵盖虚拟内存、堆栈、malloc/new、mmap、GC、内存池、零拷贝等内存管理核心概念。

See also: [[Linux系统调用-内存管理]], [[进程内存区域与资源限制]], [[C++内存模型]], [[Go内存管理]], [[Redis内存问题]]

## 一、虚拟内存

### 1.1 虚拟内存概述

虚拟内存是操作系统提供的一种内存管理技术，它为每个进程提供一个独立的、连续的虚拟地址空间。

**核心特性：**
- **地址隔离**：每个进程拥有独立的虚拟地址空间
- **按需分页**：物理内存按页（通常 4KB）分配，按需加载
- **内存保护**：不同页面可设置读/写/执行权限
- **内存映射**：文件可直接映射到虚拟地址空间

### 1.2 页表与 MMU

- **MMU（Memory Management Unit）**：硬件单元，负责虚拟地址到物理地址的转换
- **页表**：存储虚拟页到物理页的映射关系
- **TLB（Translation Lookaside Buffer）**：页表缓存，加速地址转换
- **多级页表**：减少页表占用的内存空间

### 1.3 页面置换算法

| 算法 | 说明 | 特点 |
|------|------|------|
| FIFO | 淘汰最先进入的页面 | 简单，可能淘汰常用页 |
| LRU | 淘汰最久未使用的页面 | 效果好，实现复杂 |
| LFU | 淘汰使用频率最低的页面 | 适合热点数据 |
| Clock | 近似 LRU，使用访问位 | 实际常用 |

## 二、堆与栈

### 2.1 栈（Stack）

- **自动管理**：函数调用时自动分配，返回时自动释放
- **大小限制**：通常 8MB（可通过 `ulimit -s` 查看/修改）
- **存储内容**：局部变量、函数参数、返回地址、寄存器保存
- **生长方向**：x86 下向低地址生长
- **速度快**：仅移动栈指针（rsp）

### 2.2 堆（Heap）

- **手动管理**：通过 `malloc/free` 或 `new/delete` 管理
- **大小限制**：受物理内存 + 交换空间限制
- **存储内容**：动态分配的对象和数据
- **生长方向**：通常向高地址生长
- **速度较慢**：需要查找空闲块、可能触发系统调用

### 2.3 内存布局（Linux 进程）

```
高地址
+------------------+
|      栈 (Stack)   | ← 向低地址生长
+------------------+
|        ↓         |
|     (空闲空间)    |
|        ↑         |
+------------------+
|  内存映射区域      | ← mmap 分配
|  (共享库、文件映射) |
+------------------+
|        ↑         |
|      堆 (Heap)    | ← brk/sbrk 分配，向高地址生长
+------------------+
|    BSS 段         | ← 未初始化全局变量
+------------------+
|    Data 段        | ← 已初始化全局变量
+------------------+
|    Text 段        | ← 代码段（只读）
+------------------+
低地址
```

## 三、malloc/new 实现原理

### 3.1 malloc 内部机制

- **小内存分配**：使用内存池（arena），从已映射的内存中切割
- **大内存分配**：直接使用 `mmap` 分配，释放时 `munmap`
- **阈值**：通常 128KB（可通过 `M_MMAP_THRESHOLD` 调整）

### 3.2 常见分配器

| 分配器 | 特点 |
|--------|------|
| ptmalloc2 (glibc) | 多线程优化，多 arena |
| jemalloc | Facebook 开发，碎片少，并发好 |
| tcmalloc | Google 开发，线程缓存 |
| mimalloc | 微软开发，性能优异 |

### 3.3 new/delete 与 malloc/free 的区别

| 特性 | malloc/free | new/delete |
|------|-------------|------------|
| 类型 | C 函数 | C++ 运算符 |
| 构造函数 | 不调用 | 调用 |
| 析构函数 | 不调用 | 调用 |
| 返回类型 | void* | 类型指针 |
| 大小计算 | 手动 | 自动 |
| 失败行为 | 返回 NULL | 抛出 std::bad_alloc |
| 重载 | 不可重载 | 可重载 |

## 四、mmap 系统调用

### 4.1 mmap 功能

- **文件映射**：将文件内容映射到内存，实现零拷贝
- **匿名映射**：分配匿名内存（类似 malloc 大块内存）
- **共享内存**：进程间共享内存

### 4.2 mmap 参数

```c
void *mmap(void *addr, size_t length, int prot, int flags, int fd, off_t offset);
```

- **prot**：PROT_READ | PROT_WRITE | PROT_EXEC | PROT_NONE
- **flags**：MAP_SHARED | MAP_PRIVATE | MAP_ANONYMOUS | MAP_FIXED

### 4.3 mmap 与 read/write 对比

| 特性 | mmap | read/write |
|------|------|------------|
| 拷贝次数 | 1 次（DMA → 用户空间） | 2 次（DMA → 内核 → 用户） |
| 适用场景 | 随机访问、大文件 | 顺序读写 |
| 内存占用 | 占用虚拟地址空间 | 占用用户缓冲区 |
| 页错误开销 | 有 | 无 |

## 五、零拷贝技术

### 5.1 传统 I/O 流程

```
磁盘 → 内核缓冲区 → 用户缓冲区 → Socket 缓冲区 → 网卡
（4 次拷贝，4 次上下文切换）
```

### 5.2 sendfile

```c
ssize_t sendfile(int out_fd, int in_fd, off_t *offset, size_t count);
```

- 减少到 3 次拷贝（DMA → 内核 → DMA）
- 减少到 2 次上下文切换

### 5.3 splice

```c
ssize_t splice(int fd_in, loff_t *off_in, int fd_out, loff_t *off_out,
               size_t len, unsigned int flags);
```

- 内核空间内数据传输，零 CPU 拷贝

### 5.4 mmap + write

- 减少到 3 次拷贝
- 适合小文件

## 六、内存池

### 6.1 内存池优势

- **减少系统调用**：批量申请内存
- **减少碎片**：统一管理内存块
- **提高缓存命中**：相关对象内存相邻
- **便于追踪**：统一释放、内存泄漏检测

### 6.2 简单内存池实现

```cpp
class MemoryPool {
    struct Block {
        Block* next;
    };
    Block* free_list = nullptr;
    size_t block_size;
    size_t pool_size;
    std::vector<char*> chunks;
    
public:
    MemoryPool(size_t block_size, size_t pool_size = 1024)
        : block_size(std::max(block_size, sizeof(Block)))
        , pool_size(pool_size) {}
    
    void* allocate() {
        if (!free_list) {
            allocate_chunk();
        }
        Block* block = free_list;
        free_list = free_list->next;
        return block;
    }
    
    void deallocate(void* ptr) {
        Block* block = static_cast<Block*>(ptr);
        block->next = free_list;
        free_list = block;
    }
    
private:
    void allocate_chunk() {
        char* chunk = new char[block_size * pool_size];
        chunks.push_back(chunk);
        for (size_t i = 0; i < pool_size; ++i) {
            deallocate(chunk + i * block_size);
        }
    }
};
```

## 七、GC 机制

### 7.1 常见 GC 算法

| 算法 | 说明 | 代表语言 |
|------|------|----------|
| 引用计数 | 维护对象引用计数，为 0 时回收 | Python, Swift |
| 标记-清除 | 标记可达对象，清除不可达对象 | Go (三色标记) |
| 标记-整理 | 标记后整理碎片 | JVM 老年代 |
| 复制算法 | 将存活对象复制到新空间 | JVM 新生代 |
| 分代收集 | 按对象年龄分代，不同代用不同算法 | JVM, V8 |

### 7.2 Go GC 特点

- **并发三色标记**：与用户代码并发执行
- **写屏障**：保证并发标记的正确性
- **STW 极短**：通常 < 1ms
- **内存利用率优先**：GOGC 参数控制

## 八、面试高频问题

### Q1: 虚拟内存的作用？
- 地址隔离，保护进程安全
- 扩展可用内存（交换空间）
- 内存映射，实现零拷贝
- 共享内存，进程间通信

### Q2: malloc 分配 1 字节实际占用多少内存？
- 取决于分配器实现
- glibc ptmalloc2：通常占用 16-32 字节（含元数据）
- 实际映射内存以页为单位（4KB）

### Q3: 什么是内存碎片？如何解决？
- **内部碎片**：分配的内存大于实际使用
- **外部碎片**：空闲内存被分割成小块
- **解决**：内存池、slab 分配器、定期整理

### Q4: mmap 和 brk 的区别？
- **brk/sbrk**：移动 program break，分配连续内存，适合小块
- **mmap**：映射独立内存区域，适合大块，可映射文件
