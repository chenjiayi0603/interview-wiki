# C++ 性能调优关键指标

> 本文总结了 C++ 后台程序性能调优中需要关注的关键指标，涵盖吞吐、延迟、资源、GC/内存和业务五个维度。

## 吞吐类指标

QPS、TPS、成功率、并发连接数。

**举例**：网关压测时同时看 QPS（每秒成功请求数）、成功率（成功数/总请求）、以及当前 ESTABLISHED 连接数，若 QPS 不涨但连接数持续上升，说明有堆积或下游变慢。

**分析**：吞吐要与成功率一起看，高 QPS 低成功率可能是重试或错误风暴；并发连接数反映“占用多少资源在做事”。

## 延迟类指标

P50/P90/P99/P999、尾延迟占比、抖动（方差/CV）。

**举例**：接口 P50=5ms、P99=200ms 说明多数请求很快，但约 1% 请求极慢；再算 P99/P50 比值和 P99 方差，可判断是“偶发尖刺”还是“整体拖尾”。

**分析**：仅看平均值会掩盖尾延迟问题；P99/P999 和方差更能反映用户体验和系统稳定性。

## 资源类指标

CPU 利用率/饱和度、Load、上下文切换、内存占用/碎片、page fault、磁盘/网络 IOPS、带宽、队列长度。

**举例**：CPU 80% 但 load 达 32（8 核机），说明大量进程在等 CPU（饱和度高）；`pidstat -w` 显示每秒 50 万次上下文切换，往往伴随锁竞争或线程过多。

**分析**：资源指标用于判断瓶颈在 CPU、IO 还是内存；队列长度和饱和度能解释“为什么 CPU 没打满但延迟高”。

## GC/内存类指标

malloc 次数、arena/fragmentation、RSS、OOM、cache miss。

**举例**：heaptrack 显示某路径每秒 malloc 数百万次、且对象多为 64B，可考虑对象池或 jemalloc；RSS 持续升而业务量不变，需排查泄漏或缓存无界。

**分析**：分配次数和碎片率直接关系延迟与吞吐；cache miss（如 perf stat 中 cache-misses）可解释“算得少但 CPU 高”的现象。

## 业务类指标

超时率、失败率、重试率、排队时长。

**举例**：下游故障时，本机重试率飙升、超时率上升，可据此触发熔断或降级；排队时长与 P99 强相关，队列满时新请求排队时长会陡增。

**分析**：业务指标是 SLO 的直接体现，优化最终要落到这些指标改善；与资源指标结合可区分“本机慢”还是“下游/网络慢”。
