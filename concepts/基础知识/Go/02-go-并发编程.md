## 一、Goroutine

### 1.1 创建与启动

**解决的问题**：轻量级并发执行单元，比线程轻量得多（初始栈仅 2-4KB）。

```go
go func() { fmt.Println("hello") }()
go func(msg string) { fmt.Println(msg) }("hello")
go process(data)
```

**性能对比**：

| 维度 | Goroutine | OS 线程 |
|:-----|:----------|:--------|
| 初始栈大小 | 2-4 KB | ~8 MB |
| 创建时间 | ~0.1 us | ~10 us |
| 切换时间 | ~0.1 us（用户态） | ~1 us（内核态） |
| 数量上限 | 百万级 | 万级 |

### 1.2 GMP 调度模型

**解决的问题**：Go 运行时的核心调度器，实现 M:N 调度。

**三个核心组件**：

| 组件 | 数量 | 职责 |
|:-----|:-----|:------|
| **G** (Goroutine) | 无限制 | 协程，包含栈、PC、SP |
| **M** (Machine) | 最多 10000 | OS 线程，执行 Go 代码 |
| **P** (Processor) | GOMAXPROCS（CPU 核心数） | 本地 G 队列（256 个） |

**调度策略**：

1. **本地队列优先**：M 优先从绑定的 P 的本地队列取 G
2. **全局队列 stealing**：每 61 次调度从全局队列取一次
3. **work stealing**：P 本地队列为空时，从其他 P 偷取一半 G
4. **hand off**：G 进入 syscall 阻塞时，M 交出 P，P 被其他 M 接管
5. **抢占调度**（Go 1.14+）：10ms 后信号强制抢占

### 1.3 抢占调度演进

| 版本 | 策略 | 说明 |
|:-----|:-----|:------|
| Go 1.0 | 协作式 | 依赖 G 主动让出 |
| Go 1.2 | 协作式+插入点 | 函数调用处插入抢占检查 |
| Go 1.14 | **信号式抢占** | SIGURG 信号强制抢占 |

## 二、Channel

### 2.1 无缓冲 Channel

**解决的问题**：同步通信（发送和接收必须同时准备好）。

```go
ch := make(chan int)
go func() { ch <- 42 }()
value := <-ch  // 阻塞直到有人发送
fmt.Println(value)
```

### 2.2 有缓冲 Channel

**解决的问题**：异步通信（缓冲区未满时发送不阻塞）。

```go
ch := make(chan int, 3)
ch <- 1
ch <- 2
ch <- 3
// ch <- 4  // 满，阻塞
fmt.Println(<-ch) // 1
```

| 类型 | 发送者等待 | 接收者等待 | 适用场景 |
|:-----|:----------|:----------|:---------|
| 无缓冲 | 直到有人接收 | 直到有人发送 | 同步、信号 |
| 有缓冲 | 缓冲区未满 | 缓冲区非空 | 异步、流水线 |

### 2.3 关闭 Channel

```go
ch := make(chan int, 3)
close(ch)
for v := range ch { }  // 自动退出
v, ok := <-ch  // ok=false 表示已关闭
```

**关闭规则**：

| 操作 | 已关闭的 channel |
|:-----|:-----------------|
| 发送 | **panic** |
| 接收 | 返回零值+false |
| 重复关闭 | **panic** |
| range 遍历 | 自动退出 |

### 2.4 select 多路复用

```go
select {
case v := <-ch1:
    fmt.Println("got:", v)
case ch2 <- 42:
    fmt.Println("sent")
default:
    fmt.Println("no channel ready")
}
```

**特性**：随机选择（多个就绪时）、nil channel 永远阻塞、default 非阻塞、空 select{} 永久阻塞。

## 三、sync 包

### 3.1 Mutex

**解决的问题**：保护临界区，防止数据竞争。

```go
var mu sync.Mutex
mu.Lock()
counter++
mu.Unlock()
// 推荐
mu.Lock()
defer mu.Unlock()
counter++
```

**模式**：正常模式（FIFO+自旋）和饥饿模式（等待>1ms 启用）。

### 3.2 RWMutex

**解决的问题**：读多写少场景，多读并发。

```go
rw.RLock()
defer rw.RUnlock()  // 读锁
rw.Lock()
defer rw.Unlock()   // 写锁
```

### 3.3 WaitGroup

```go
var wg sync.WaitGroup
for i := 0; i < 10; i++ {
    wg.Add(1)
    go func(id int) {
        defer wg.Done()
        fmt.Println("done", id)
    }(i)
}
wg.Wait()
```

**注意**：Add() 在 go 之前；Wat() 不能在 goroutine 内。

### 3.4 Once

```go
var once sync.Once
once.Do(func() { /* 只执行一次 */ })
```

### 3.5 Cond

```go
cond := sync.NewCond(&mu)
// 等待
mu.Lock()
for !ready { cond.Wait() }
mu.Unlock()
// 通知
cond.Broadcast()  // 唤醒所有
```

### 3.6 Map

**解决的问题**：并发安全 map，读多写少优化。

```go
var m sync.Map
m.Store("k", "v")
v, ok := m.Load("k")
m.Range(func(k, v any) bool { return true })
```

### 3.7 Pool

**解决的问题**：对象复用，减少 GC。

```go
var pool = sync.Pool{
    New: func() any { return make([]byte, 1024) },
}
buf := pool.Get().([]byte)
pool.Put(buf)
```

## 五、Context

### 5.1 创建 Context

| 函数 | 触发取消 |
|:-----|:---------|
| `WithCancel(parent)` | 调用 cancel() |
| `WithTimeout(parent, d)` | 超时或 cancel() |
| `WithDeadline(parent, t)` | 到时间或 cancel() |
| `WithValue(parent, k, v)` | 同父（不传播取消） |

```go
ctx, cancel := context.WithCancel(context.Background())
defer cancel()
```

### 5.2 取消传播

- **向下传播**：父取消 -> 所有子取消
- **向上不传播**：子取消 -> 父不取消

```go
func worker(ctx context.Context) {
    for {
        select {
        case <-ctx.Done():
            return
        default:
            work()
        }
    }
}
```

## 六、并发模式

### 6.1 生产者消费者

```go
func producer(ch chan<- int) {
    for i := 0; i < 10; i++ { ch <- i }
    close(ch)
}
func consumer(ch <-chan int) {
    for v := range ch { fmt.Println(v) }
}
```

### 6.2 Work Pool

```go
func worker(jobs <-chan int, results chan<- int) {
    for j := range jobs { results <- j * 2 }
}
// 3 个 worker, 10 个任务
```

### 6.3 扇入扇出

```go
func fanIn(chs ...<-chan int) <-chan int {
    out := make(chan int)
    var wg sync.WaitGroup
    for _, ch := range chs {
        wg.Add(1)
        go func(c <-chan int) {
            defer wg.Done()
            for v := range c { out <- v }
        }(ch)
    }
    go func() { wg.Wait(); close(out) }()
    return out
}
```

## 七、协程对比：Go vs C++20 vs libgo

| 维度 | Go | C++20 | libgo |
|:-----|:---|:------|:------|
| 栈模型 | 有栈（可增长） | 无栈 | 有栈 |
| 调度器 | 内置 M:N（GMP） | 无，需自行构建 | 自带 M:N |
| 切换开销 | ~0.1 us | ~10-100 ns | ~124 ns |
| 通道 | 语言级 channel | 需自行实现 | 支持 |

## 八、常见陷阱

| 陷阱 | 说明 | 解决 |
|:-----|:-----|:------|
| goroutine 泄漏 | channel 阻塞不退出 | Context 管理 |
| 循环变量闭包 | 所有 goroutine 看到同一个 i | 传参 `go fn(i)` |
| 往关闭 channel 发送 | panic | 发送者 close |
| map 并发读写 | panic | sync.Map 或加锁 |
| Mutex 未解锁 | 死锁 | defer Unlock() |
