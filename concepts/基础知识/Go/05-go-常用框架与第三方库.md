## 一、Gin 框架

### 1.1 路由

**解决的问题**：高性能 HTTP 路由，支持路径参数、分组、中间件。

```go
import "github.com/gin-gonic/gin"

func main() {
    r := gin.Default()

    // 基本路由
    r.GET("/ping", func(c *gin.Context) {
        c.JSON(200, gin.H{"message": "pong"})
    })

    // 路径参数
    r.GET("/user/:name", func(c *gin.Context) {
        name := c.Param("name")
        c.String(200, "Hello %s", name)
    })

    // 查询参数
    r.GET("/search", func(c *gin.Context) {
        q := c.DefaultQuery("q", "default")
        page := c.Query("page")
        c.JSON(200, gin.H{"q": q, "page": page})
    })

    // 路由分组
    api := r.Group("/api")
    {
        api.GET("/users", listUsers)
        api.POST("/users", createUser)
        api.GET("/users/:id", getUser)
    }

    r.Run(":8080")
}
```

### 1.2 参数绑定

**解决的问题**：自动解析请求参数到结构体，支持 JSON/Form/URI。

```go
type LoginRequest struct {
    Username string `json:"username" binding:"required"`
    Password string `json:"password" binding:"required,min=6"`
    Age      int    `json:"age" binding:"gte=0,lte=120"`
}

func loginHandler(c *gin.Context) {
    var req LoginRequest
    if err := c.ShouldBindJSON(&req); err != nil {
        c.JSON(400, gin.H{"error": err.Error()})
        return
    }
    // req.Username, req.Password 已绑定
    c.JSON(200, gin.H{"status": "ok"})
}

// URI 绑定
type UserURI struct {
    ID   int64  `uri:"id" binding:"required"`
    Name string `uri:"name" binding:"required"`
}
func userHandler(c *gin.Context) {
    var uri UserURI
    c.ShouldBindUri(&uri)
}
```

**校验标签**：`required`, `min`, `max`, `gte`, `lte`, `email`, `oneof=a b c`

### 1.3 中间件

**解决的问题**：横切关注点（日志、认证、限流、跨域）。

```go
// 自定义中间件
func LoggerMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        start := time.Now()
        path := c.Request.URL.Path

        // 请求前
        c.Next()
        // 请求后

        latency := time.Since(start)
        status := c.Writer.Status()
        log.Printf("%s %s %d %v", c.Request.Method, path, status, latency)
    }
}

// 认证中间件
func AuthMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        token := c.GetHeader("Authorization")
        if token == "" {
            c.AbortWithStatusJSON(401, gin.H{"error": "unauthorized"})
            return
        }
        // 验证 token...
        c.Set("user", "alice")
        c.Next()
    }
}

// 使用
r := gin.Default()
r.Use(LoggerMiddleware())
r.Use(AuthMiddleware())

// 分组中间件
api := r.Group("/api")
api.Use(AuthMiddleware())
```

### 1.4 Gin vs 其他框架

| 框架 | 性能 | 生态 | 学习曲线 | 特点 |
|:-----|:-----|:-----|:---------|:-----|
| **Gin** | 高 | 丰富 | 低 | 轻量、高性能、最流行 |
| Echo | 高 | 丰富 | 低 | 类似 Gin，内置更多功能 |
| Fiber | 最高 | 中 | 低 | 类 Express API，fasthttp 后端 |
| Beego | 中 | 丰富 | 中 | 全栈框架（ORM/日志/缓存） |
| go-zero | 高 | 中 | 中 | 微服务全栈，代码生成 |

## 二、go-zero 微服务框架

### 2.1 核心特性

**解决的问题**：微服务全栈解决方案，代码生成 + 高可用设计。

| 特性 | 说明 |
|:-----|:------|
| **代码生成** | `goctl` 工具从 .api 文件生成 handler/logic/model |
| **内置组件** | 服务注册/发现、限流、熔断、链路追踪、指标监控 |
| **高可用** | 自适应降载、熔断器、超时控制、重试机制 |
| **性能** | 基于 gin 封装，零分配优化 |

### 2.2 API 定义与生成

```go
// user.api
type (
    LoginReq {
        Username string `json:"username"`
        Password string `json:"password"`
    }
    LoginResp {
        Token string `json:"token"`
    }
)

service user-api {
    @handler login
    post /api/login (LoginReq) returns (LoginResp)
}
```

```bash
goctl api go -api user.api -dir .
# 生成：handler/ logic/ model/ 等目录结构
```

### 2.3 典型项目结构

```
project/
  api/          # API 定义文件
  cmd/          # 入口 main.go
  internal/
    config/     # 配置解析
    handler/    # HTTP 处理器（自动生成）
    logic/      # 业务逻辑（手动编码）
    model/      # 数据模型
    middleware/ # 中间件
    svc/        # 依赖注入
```

## 三、Protobuf

### 3.1 基本语法

**解决的问题**：语言无关的序列化协议，比 XML/JSON 更小更快。

```protobuf
syntax = "proto3";

package user;

option go_package = "./pb";

message User {
    int64  id       = 1;
    string name     = 2;
    string email    = 3;
    int32  age      = 4;
    repeated string tags = 5;
    Address address = 6;
    // 枚举
    enum Role {
        UNKNOWN = 0;
        ADMIN   = 1;
        USER    = 2;
    }
    Role role = 7;
}

message Address {
    string country = 1;
    string city    = 2;
}
```

### 3.2 标量类型映射

| Protobuf | Go | Java | 说明 |
|:---------|:---|:-----|:------|
| double | float64 | double | 64位浮点 |
| float | float32 | float | 32位浮点 |
| int32 | int32 | int | 变长编码 |
| int64 | int64 | long | 变长编码 |
| uint32 | uint32 | int | 变长编码 |
| bool | bool | boolean | 布尔 |
| string | string | String | UTF-8 字符串 |
| bytes | []byte | ByteString | 字节序列 |

### 3.3 Protobuf vs JSON

| 维度 | Protobuf | JSON |
|:-----|:---------|:------|
| 编码大小 | ~50% 更小 | 大 |
| 编码速度 | ~10x 更快 | 慢 |
| 可读性 | 差（二进制） | 好（文本） |
| Schema | 必需（.proto） | 可选 |
| 兼容性 | 强（字段编号） | 弱（字段名） |
| 语言支持 | 多语言生成 | 所有 |

## 四、日志库

### 4.1 标准库 log

```go
log.Println("info message")
log.Printf("user %s logged in", name)
log.Fatalf("fatal: %v", err)  // 输出后 os.Exit(1)
```

**缺点**：无日志级别、无结构化输出、性能一般。

### 4.2 zap（推荐）

**解决的问题**：高性能结构化日志，零分配序列化。

```go
import "go.uber.org/zap"

// 生产模式
logger, _ := zap.NewProduction()
defer logger.Sync()

// 开发模式（带行号、美化输出）
logger, _ := zap.NewDevelopment()

// 结构化字段
logger.Info("user login",
    zap.String("username", "alice"),
    zap.Int("age", 30),
    zap.Duration("elapsed", 100*time.Millisecond),
)

// SugaredLogger（类似 fmt.Printf，稍慢）
sugar := logger.Sugar()
sugar.Infof("user %s login from %s", "alice", "127.0.0.1")
```

**zap vs 其他**：

| 日志库 | 性能 | 结构化 | 特点 |
|:-------|:-----|:-------|:------|
| **zap** | 最快 | 是 | 零分配反射，生产首选 |
| logrus | 中 | 是 | 易用，生态好 |
| zerolog | 快 | 是 | 零分配，API 简洁 |
| slog（标准库） | 快 | 是 | Go 1.21+，无需依赖 |

## 五、数据库

### 5.1 GORM

**解决的问题**：Go ORM，自动化 CRUD、迁移、关联查询。

```go
import "gorm.io/gorm"

type User struct {
    ID        uint      `gorm:"primaryKey"`
    Name      string    `gorm:"size:100;not null"`
    Age       int       `gorm:"default:0"`
    Email     string    `gorm:"uniqueIndex"`
    Orders    []Order   `gorm:"foreignKey:UserID"`
    CreatedAt time.Time
    UpdatedAt time.Time
}

// 自动迁移
db.AutoMigrate(&User{})

// CRUD
db.Create(&user)
db.First(&user, 1)
db.Model(&user).Update("Age", 35)
db.Delete(&user)

// 条件查询
db.Where("age > ?", 30).Find(&users)
db.Where("name LIKE ?", "%alice%").First(&user)

// 预加载关联
db.Preload("Orders").Find(&users)

// 事务
db.Transaction(func(tx *gorm.DB) error {
    tx.Create(&user)
    tx.Create(&order)
    return nil
})
```

### 5.2 Redis

```go
import "github.com/redis/go-redis/v9"

rdb := redis.NewClient(&redis.Options{
    Addr:     "localhost:6379",
    Password: "",
    DB:       0,
    PoolSize: 10,

ctx := context.Background()

rdb.LPush(ctx, "queue", "task1")

```

## 六、测试

### 6.1 单元测试

```go
// math.go
func Add(a, b int) int { return a + b }

// math_test.go
func TestAdd(t *testing.T) {
    got := Add(1, 2)
    want := 3
    if got != want {
        t.Errorf("Add(1,2) = %d; want %d", got, want)
    }
}

// 表格驱动测试
func TestAddTable(t *testing.T) {
    tests := []struct {
        a, b, want int
    }{
        {1, 2, 3},
        {0, 0, 0},
        {-1, 1, 0},
    }
    for _, tt := range tests {
        if got := Add(tt.a, tt.b); got != tt.want {
            t.Errorf("Add(%d,%d) = %d", tt.a, tt.b, got)
        }
    }
}
```

### 6.2 Mock

```go
type UserRepo interface {
    GetUser(id int) (*User, error)
}

// mock
type MockUserRepo struct {
    GetUserFunc func(int) (*User, error)
}

func (m *MockUserRepo) GetUser(id int) (*User, error) {
    return m.GetUserFunc(id)
}

// 使用
func TestService(t *testing.T) {
    mockRepo := &MockUserRepo{
        GetUserFunc: func(id int) (*User, error) {
            return &User{Name: "alice"}, nil
        },
    }
    svc := NewService(mockRepo)
    user, _ := svc.GetUser(1)
    assert.Equal(t, "alice", user.Name)
}
```
