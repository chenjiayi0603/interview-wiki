## 一、基础面试题

### Q1: Go 的 slice 和 array 的区别？

| 维度 | array | slice |
|:-----|:------|:-------|
| 长度 | 固定（类型的一部分） | 动态 |
| 传参 | 值拷贝（全部元素） | 引用语义（3 字描述结构） |
| nil | `[0]T{}` 不是 nil | `var s []T` 是 nil |
| 扩容 | 不能 | `append` 自动扩容 |

```go
arr := [3]int{1,2,3}   // array
slc := []int{1,2,3}    // slice

func f(arr [3]int) { }  // 拷贝整个数组
func f(slc []int) { }   // 拷贝 ptr/len/cap
```

### Q2: map 的并发安全性？

**答案**：`map` 并发读写会 **panic**。解决方案：

```go
// 1. sync.RWMutex
var mu sync.RWMutex
mu.Lock()
m["key"] = "value"
mu.Unlock()

// 2. sync.Map（读多写少）
var m sync.Map
m.Store("key", "value")
m.Load("key")
```

### Q3: defer 的执行顺序？

**答案**：**后进先出（LIFO）**。defer 在函数返回前执行，参数在 defer 声明时求值。

```go
func example() {
    x := 1
    defer fmt.Println(x)  // 输出 1（此时 x=1 已求值）
    x = 2
    // defer 在 return 之后执行
}
```

### Q4: make 和 new 的区别？

| 操作 | `new(T)` | `make(T, args)` |
|:-----|:---------|:----------------|
| 适用类型 | 所有类型 | slice/map/channel |
| 返回值 | `*T`（指针） | `T`（引用） |
| 初始化 | 零值 | 内部结构初始化 |

```go
p := new(int)          // *int → 0
s := make([]int, 5)    // []int → [0 0 0 0 0]
```

### Q5: Go 的面向对象特点？

- **封装**：小写私有，大写公开
- **继承**：结构体嵌入（组合而非继承）
- **多态**：接口隐式实现（duck typing）
- **没有**：class、继承、重载、构造函数

## 二、并发面试题

### Q6: goroutine 和 thread 的区别？

| 维度 | goroutine | OS thread |
|:-----|:----------|:----------|
| 创建开销 | ~2-4 KB 栈 | ~8 MB 栈 |
| 调度 | Go 运行时（用户态） | 内核调度 |
| 切换时间 | ~0.1 us | ~1 us |
| 数量 | 百万级 | 万级 |
| 通信 | channel（CSP） | 共享内存（通常） |

### Q7: GMP 模型中 G、M、P 各自的职责？

- **G（Goroutine）**：待执行的协程，包含栈、PC、SP
- **M（Machine）**：OS 线程，实际执行代码
- **P（Processor）**：逻辑处理器，持有本地 G 队列（256 个）

**调度策略**：work stealing + hand off + 信号抢占

### Q8: channel 关闭的注意事项？

1. 关闭已关闭的 channel → **panic**
2. 向已关闭的 channel 发送 → **panic**
3. 从已关闭的 channel 接收 → 返回零值 + false
4. 永远在**发送者** goroutine 中 close

### Q9: sync.Map 的适用场景？

**适用**：读多写少、key 稳定的场景（如配置缓存）
**不适用**：写多的场景（sync.Map 写操作有锁开销，不如 map+RWMutex）

### Q10: Context 取消信号的传播规则？

- **向下传播**：父取消 → 所有子 Context 取消
- **向上不传播**：子取消 → 父不受影响
- **WithValue**：不传播取消信号

### Q11: 如何防止 goroutine 泄漏？

```go
// 1. Context 管理生命周期
ctx, cancel := context.WithCancel(context.Background())
go func() {
    for {
        select {
        case <-ctx.Done(): return
        default: work()
        }
    }
}()

// 2. 确保 channel 最终关闭
// 3. 使用 WaitGroup 追踪
```

### Q12: 读写锁 RWMutex 的原理？

- 多个 goroutine 可同时持有**读锁**
- 写锁**互斥**（不能同时有读锁或写锁）
- 写锁等待时，新读锁**阻塞**（防止写饥饿）

## 三、内存与 GC 面试题

### Q13: Go 的逃逸分析是什么？

**答案**：编译器决定变量分配在栈还是堆上。栈更快（无需 GC），堆需要 GC。

```bash
go build -gcflags="-m" main.go  # 查看逃逸
```

**六种逃逸场景**（含示例）：

```go
// 1. 返回指针 —— 局部变量地址被函数返回
func escape1() *int {
    x := 42
    return &x  // x 逃逸到堆
}

// 2. interface 调用 —— 具体类型存入 interface 时逃逸
func escape2() {
    x := 42
    fmt.Println(x)  // x 逃逸（fmt.Println 参数为 interface{}）
}

// 3. 闭包捕获变量 —— 闭包内引用外部函数的局部变量
func escape3() func() int {
    x := 42
    return func() int {
        return x  // x 被闭包捕获，逃逸到堆
    }
}

// 4. channel 发指针 —— 指针通过 channel 在 goroutine 间传递
func escape4() {
    ch := make(chan *int)
    x := 42
    ch <- &x  // x 逃逸（可能被其他 goroutine 访问）
}

// 5. 大对象 —— 超过栈帧大小限制（通常 > 64KB）
func escape5() {
    data := make([]byte, 100000)  // 100KB > 栈限制，逃逸到堆
    _ = data
}

// 6. 切片扩容 —— append 超过 cap 导致重新分配
func escape6() {
    s := make([]int, 0, 3)
    for i := 0; i < 100; i++ {
        s = append(s, i)  // 多次扩容，新底层数组在堆上
    }
}
```

### Q14: Go GC 的演进？

| 版本 | 算法 | STW |
|:-----|:-----|:----|
| 1.0 | 串行标记-清除 | ~100ms |
| 1.5 | 并发三色标记+插入写屏障 | ~10ms |
| 1.8 | **混合写屏障** | **< 1ms** |
| 1.14 | 信号式抢占 | < 1ms |

### Q15: 三色标记法如何工作？

1. **白色**：初始状态，不可达（将被回收）
2. **灰色**：已访问，子对象未扫描完
3. **黑色**：已访问，子对象已扫描完

**流程**：Root → 灰色 → 扫描 → 黑色 → 重复 → 白色被回收

### Q16: 混合写屏障的作用？

**解决的问题**：并发标记时，防止黑色对象引用白色对象导致误回收。

**规则**：被添加引用的对象标记为灰色 + 被删除引用的对象标记为灰色。

### Q17: GOGC 的作用？

控制 GC 触发频率。默认 `GOGC=100`，堆内存增长 100% 时触发。

```go
debug.SetGCPercent(200)  // 2 倍堆时触发，减少 GC 频率
```

- 调大 → GC 频率降低，内存使用增加
- 调小 → GC 频率提高，内存使用降低

## 四、代码模板

### 4.1 并发工作池

```go
func workerPool(numWorkers, numJobs int) {
    jobs := make(chan int, numJobs)
    results := make(chan int, numJobs)

    for w := 0; w < numWorkers; w++ {
        go func(id int) {
            for j := range jobs {
                results <- process(j)
            }
        }(w)
    }

    for j := 0; j < numJobs; j++ { jobs <- j }
    close(jobs)
    for r := 0; r < numJobs; r++ { <-results }
}
```

### 4.2 限流器

```go
type Limiter struct {
    tokens chan struct{}
}

func NewLimiter(rate int) *Limiter {
    l := &Limiter{tokens: make(chan struct{}, rate)}
    go func() {
        ticker := time.NewTicker(time.Second / time.Duration(rate))
        for range ticker.C {
            select { case l.tokens <- struct{}{}: default: }
        }
    }()
    return l
}

func (l *Limiter) Wait() { <-l.tokens }
```

### 4.3 连接池

```go
type Pool struct {
    mu    sync.Mutex
    conns chan net.Conn
    newFn func() (net.Conn, error)
}

func (p *Pool) Get() (net.Conn, error) {
    select {
    case conn := <-p.conns:
        return conn, nil
    default:
        return p.newFn()
    }
}

func (p *Pool) Put(conn net.Conn) {
    select {
    case p.conns <- conn:
    default:
        conn.Close()  // 池满，关闭
    }
}
```

### 4.4 分布式锁

```go
type RedisLock struct {
    rdb    *redis.Client
    key    string
    token  string  // 随机值，保证锁安全释放
    ttl    time.Duration
}

func (l *RedisLock) Acquire(ctx context.Context) (bool, error) {
    return l.rdb.SetNX(ctx, l.key, l.token, l.ttl).Result()
}

func (l *RedisLock) Release(ctx context.Context) error {
    // Lua 脚本保证原子性：只有持有者才能释放
    script := `
        if redis.call("get", KEYS[1]) == ARGV[1] then
            return redis.call("del", KEYS[1])
        else
            return 0
        end
    `
    return l.rdb.Eval(ctx, script, []string{l.key}, l.token).Err()
}
```

### 4.5 优雅退出

```go
func gracefulShutdown(srv *http.Server) {
    quit := make(chan os.Signal, 1)
    signal.Notify(quit, syscall.SIGINT, syscall.SIGTERM)
    <-quit

    ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
    defer cancel()

    if err := srv.Shutdown(ctx); err != nil {
        log.Fatalf("shutdown: %v", err)
    }
}
```

## 六、常见陷阱速查

| 陷阱 | 示例 | 解决方案 |
|:-----|:------|:---------|
| 循环变量闭包 | `go func() { fmt.Println(i) }()` | `go func(i int) { }(i)` |
| map 并发读写 | 多个 goroutine 同时写 map | `sync.Map` 或加锁 |
| nil map 写入 | `var m map[int]int; m[1]=2` | 用 `make` 初始化 |
| slice 共享底层 | 截取后修改影响原数据 | `copy` 创建独立副本 |
| 接口 nil 判断 | 接口值持有 nil 指针 | 用反射检查 |
| Mutex 复制 | `func f(mu sync.Mutex)` 传值复制 | 用指针传递 `*sync.Mutex` |
| channel 死锁 | 无消费者发送，无生产者接收 | 确保匹配的收发 |
| 大 map 不释放 | map 只增不减，GC 不回收 | 重新创建 map |
| goroutine 泄露 | 启动不退出 | Context 超时/取消 |
| 无限 for 循环 | `for { }` 无退出条件 | 确保有 break 或 return |
