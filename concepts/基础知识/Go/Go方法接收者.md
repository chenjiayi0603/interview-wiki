# Go 方法接收者

> Go 没有"类（class）"，但有"方法（method）"。方法通过**接收者（Receiver）**绑定到类型上。

See also: [[Go接口]], [[Go语言基础]], [[Go常用数据结构]]

---

## 一、Go 没有类，但有类型

在 Go 里，一切对象都是基于 `type` 定义的：

```go
type User struct {
    Name string
    Age  int
}
```

`User` 只是一个结构体类型（Struct Type），它本身不携带行为（没有成员函数）。Go 把**数据（struct）**和**行为（method）**解耦开来，行为是通过**给类型"绑定方法"**实现的。

---

## 二、方法语法：`func (r Receiver) MethodName()`

Go 给类型绑定方法的语法如下：

```go
func (u User) SayHello() {
    fmt.Println("Hello,", u.Name)
}
```

这里 `(u User)` 就是所谓的**方法接收者（receiver）**。Go 的设计是通过这种"显式声明"把函数与类型关联起来。

相当于告诉编译器：

> "这个函数属于 `User` 类型"。

调用方式：

```go
u := User{Name: "Alice"}
u.SayHello()  // ✅ 类似面向对象调用
```

---

## 三、Go 为什么不用 `class`？

Go 是一门强调**简洁性、组合优于继承**的语言。它摒弃了传统 OOP 的复杂层级结构。

**核心设计理念：**

- 没有类（class）
- 没有继承（inheritance）
- 有组合（composition）
- 有接口（interface）

通过这些特性，Go 达到：

- 更低的复杂度
- 更少的隐式行为
- 更清晰的依赖关系

---

## 四、值接收者 vs 指针接收者

```go
func (u *User) GrowUp() {
    u.Age++
}
```

区别：

| 接收者类型 | 行为 |
|:----------|:-----|
| `(u User)` | 值接收者，传值副本，方法内修改不影响原对象 |
| `(u *User)` | 指针接收者，修改原对象 |

调用上两者语法一致：

```go
u := User{Name: "Tom", Age: 10}
u.GrowUp()  // Go 自动处理 * 和 &
```

> ✅ Go 编译器会自动帮你解引用或取地址，语法保持一致。

---

## 五、这种语法的设计优势

| 优势 | 说明 |
|:-----|:-----|
| ✅ 更显式 | 一眼就能看到方法属于哪个类型 |
| ✅ 可对任意类型添加方法 | 不仅 struct，任何自定义类型都能绑定方法 |
| ✅ 支持灵活组合 | 比继承更灵活 |
| ✅ 更简单的编译模型 | 方法只是普通函数 + 语法糖 |

甚至可以给基础类型绑定方法：

```go
type MyInt int

func (m MyInt) Double() int {
    return int(m * 2)
}

fmt.Println(MyInt(5).Double()) // 10
```

---

## 六、底层原理（简述）

在编译层面，`func (r T) Foo()` 其实被编译成普通函数，只是参数多了个 `r`：

```go
func Foo(r T)
```

编译器自动帮你做了方法调用的语法糖：

```go
r.Foo()  // 等价于 Foo(r)
```

这让 Go 保持了简单的调用机制，同时支持"伪类"的写法。

---

## 七、与 C++/Java 对比

| 语言 | 定义方式 | 绑定关系 | 特点 |
|:-----|:---------|:---------|:-----|
| C++ / Java | 类内部定义 | 函数属于类 | 支持继承、多态 |
| Go | 函数外部定义 | 通过 `func (r T)` 绑定类型 | 组合优先、无继承、简单直接 |

---

## 面试要点

- **值接收者 vs 指针接收者**：何时用值接收者（不需要修改、小对象、并发安全），何时用指针接收者（需要修改、大对象、避免拷贝）
- **方法集（Method Set）**：值接收者方法同时属于值和指针的方法集；指针接收者方法只属于指针的方法集
- **与接口的关系**：实现接口不需要显式声明，只要方法集匹配即可（鸭子类型）
