# Go 核心必背（15题）

## 1. GMP模型
- G（Goroutine）：Go的轻量级协程，初始栈2KB（可动态增长），由Go runtime管理，可创建百万级
- M（Machine）：操作系统线程，真正在CPU上执行G，数量默认不超过10000
- P（Processor）：逻辑处理器，维护本地G队列（runq），M必须绑定P才能执行G，数量由`GOMAXPROCS`决定（默认=CPU核数）
- 调度流程：G优先从P的本地队列取，没有则从全局队列或其他P偷（work-stealing）

## 2. Channel原理
- 底层是`hchan`结构：环形缓冲区（buf）+ 发送等待队列（sendq）+ 接收等待队列（recvq）+ 互斥锁
- 无缓冲：发送方必须等待接收方就绪（同步），反之亦然
- 有缓冲：buf未满时发送不阻塞，buf非空时接收不阻塞
- `close(ch)`后仍可读取残留数据；再读返回零值和`false`；向已关闭channel发送会`panic`

## 3. Slice底层
- `SliceHeader`：`{ptr *array, len int, cap int}`，是数组的视图
- 多个切片可共享底层数组，子切片修改会影响原切片
- `append`超过cap时：分配新数组 → 复制数据 → 返回指向新数组的切片，不影响原切片
- `copy(dst, src)`：安全拷贝，避免共享底层数组的副作用

## 4. Map底层
- `hmap`结构：桶数组（每桶8个kv对）+ 溢出桶链表 + 元数据（count、B、flags）
- 扩容条件：负载因子 > 6.5（翻倍扩容）或溢出桶过多（等量扩容整理碎片）
- 渐进式扩容：写操作时每次迁移最多2个旧桶，避免一次性迁移阻塞；迁移未完成时读写两个桶
- 并发不安全：并发读写会panic，需用`sync.RWMutex`或`sync.Map`

## 5. Defer执行
- 函数返回前按LIFO（后进先出）顺序执行所有defer
- defer参数在defer语句执行时立即求值（值拷贝），函数体延迟执行
- 通过闭包可以访问并修改命名返回值（实现defer修改返回值的技巧）
- `panic`时defer仍会执行，可以在defer中用`recover()`捕获panic

## 6. Panic/Recover
- `panic`：触发运行时错误，开始栈展开（unwind），依次执行当前goroutine各层函数的defer
- `recover()`：只在`defer`中有效，调用后捕获panic值，阻止程序崩溃，函数正常返回
- 跨goroutine：panic只在当前goroutine传播，子goroutine的panic无法被父goroutine recover
- 最佳实践：库函数内部panic转为error返回；HTTP handler的顶层defer recover防止单请求crash整个服务

## 7. Interface原理
- `eface`（空接口`interface{}`）：`{_type *_type, data unsafe.Pointer}`，仅存类型描述符和数据指针
- `iface`（非空接口）：`{tab *itab, data unsafe.Pointer}`，`itab`包含接口类型、具体类型、方法指针数组（缓存加速）
- 接口判nil的坑：`var p *MyStruct = nil; var i interface{} = p`，`i != nil`为true（接口有类型信息）
- 类型断言：`v, ok := i.(T)`；类型switch：`switch v := i.(type)`

## 8. GC算法
- 三色标记：白色（未访问，初始全白）→ 灰色（已发现，子节点未处理）→ 黑色（已完全处理）；GC结束后白色对象回收
- 混合写屏障（go1.14+）：对象赋值时触发，保证标记期间新建/修改的引用不丢失，减少STW时间
- 并发执行：标记阶段与用户程序并发，只有STW（Stop The World）极短暂（通常<1ms）
- 触发GC：堆内存达到上次GC后2倍 or 距上次GC超2分钟 or 手动`runtime.GC()`

## 9. 内存分配
- 类tcmalloc思想：对象按大小分级（tiny/small/large），不同级别不同策略
- mcache：每个P持有，本地span缓存，无锁分配，对应不同size class
- mcentral：全局按size class管理span列表，mcache耗尽时从此申请，需加锁
- mheap：直接向OS申请内存页，管理大对象（>32KB）和给mcentral补充span

## 10. Goroutine泄露
- channel阻塞：goroutine等待永远不来的数据或向无人接收的channel发送
- 定时器泄露：循环中用`time.After()`，每次创建新Timer，应改用`time.NewTimer()`+Reset
- WaitGroup误用：`Add`/`Done`数量不匹配，`Wait()`永久阻塞
- 检测工具：`pprof` goroutine profile（`go tool pprof`）；线上用`runtime.NumGoroutine()`监控增长趋势

## 11. Context用途
- 超时/截止时间：`WithTimeout`/`WithDeadline`，子goroutine通过`ctx.Done()`感知超时取消
- 主动取消：`WithCancel`返回cancel函数，调用cancel后所有子context的Done关闭
- 请求作用域值：`WithValue`存储请求ID、traceID等，不应存业务数据（无类型安全）
- 约定：context作第一个参数，命名`ctx`，不要存入struct字段，传递而非存储

## 12. Sync包
- `Mutex`：互斥锁；正常模式（FIFO+自旋）和饥饿模式（等待超1ms直接获得锁）自动切换
- `RWMutex`：读写锁，多goroutine可同时持有读锁，写锁独占；写锁优先（防饥饿）
- `WaitGroup`：`Add(n)`→启动n个goroutine各自`Done()`→主goroutine`Wait()`阻塞直到全Done
- `Once`：`Do(f)`保证f只执行一次，即使并发调用；常用于懒初始化单例
- `Pool`：临时对象池，GC时可能回收；减少频繁分配/GC压力，如`bytes.Buffer`池

## 13. Go调度
- 工作窃取（work-stealing）：P本地队列空时，随机选其他P偷一半G，充分利用多核
- 协作式抢占（go1.14前）：只在函数调用时检查抢占标志，死循环无法被抢占
- 基于信号的异步抢占（go1.14+）：`SIGURG`信号强制抢占，解决无函数调用时的CPU占用问题
- 全局队列：当本地队列满（256个）时放入全局队列；M启动时也检查全局队列

## 14. 切片扩容规则
- go1.18之前：期望容量 < 1024时，新cap = 旧cap×2；≥1024时，新cap = 旧cap×1.25（循环直到足够）
- go1.18+：新算法，阈值改为256，增长更平滑（防止256附近突变）
- 扩容后进行内存对齐，实际cap可能比计算值大（如期望5，实际分配8）
- 扩容产生新底层数组，原切片不受影响（两者独立）

## 15. make vs new
- `new(T)`：为T分配零值内存，返回`*T`指针；适用于任何类型；类似C的`calloc`
- `make(T, args)`：仅用于slice/map/channel，初始化内部数据结构（如map的哈希桶），返回T本身（非指针）
- `make([]int, 5, 10)`：长度5容量10的切片，元素初始化为0
- `make(map[K]V)`：必须make后才能赋值，否则nil map赋值会panic
