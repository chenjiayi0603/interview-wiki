# MySQL存储引擎

See also: [[MVCC多版本并发控制]]

## InnoDB vs MyISAM

| 特性维度 | InnoDB 引擎 | MyISAM 引擎 |
|---------|------------|------------|
| **索引类型** | 聚簇索引（主键索引）+ 辅助索引（二级索引） | 非聚簇索引（主键索引和辅助索引在结构上相同） |
| **数据与索引存储** | 数据文件本身就是主键索引（聚簇索引），数据行存储在叶子节点上 | 索引文件与数据文件分离，索引叶子节点存储指向数据行的物理地址 |
| **主键索引** | 必须有。若未显式定义，引擎会自动生成一个隐藏的主键 | 可以没有主键 |
| **辅助索引（二级索引）** | 叶子节点存储的是对应记录的主键值。查询时需要回表 | 叶子节点存储的是数据的物理地址。查询时直接通过地址访问数据 |
| **事务支持** | 支持事务、行级锁、外键 | 不支持事务、表级锁、外键 |
| **适用场景** | 需要事务支持、高并发写操作、要求数据一致性的场景（如订单系统、银行交易） | 读操作为主、不需要事务、对 count(*) 查询快的场景（如日志分析、数据仓库） |

## 二级索引对比

| 特性对比 | MyISAM 的索引（包括主键索引） | InnoDB 的二级索引 |
|---------|---------------------------|-----------------|
| **索引类型** | 全部是二级索引（非聚簇索引） | 标准的二级索引 |
| **叶子节点存储内容** | 指向数据行在 .MYD 数据文件中的物理地址（指针） | 对应记录的主键值 |
| **数据存储方式** | 索引文件（.MYI）与数据文件（.MYD）分离 | 索引与主键数据同在聚簇索引（B+树）中，叶子节点即数据行 |
| **查询路径（回表）** | 通过索引找到物理地址，再到 .MYD 文件中读取数据 | 通过索引找到主键值，再回到聚簇索引中查找完整行记录 |

## 实践建议

1. **InnoDB 是现代应用的默认选择**：由于其支持事务（保证数据一致性）和行级锁（支持高并发写入），现在绝大多数应用（特别是Web应用）都应选择 InnoDB。MySQL 从 5.5 版本开始也将其作为默认存储引擎。

2. **为 InnoDB 表显式定义简短的主键**：建议使用自增整数（AUTO_INCREMENT）作为主键。这样插入的新数据会顺序添加到索引末尾，能有效减少页分裂，提高写入性能。

3. **善用覆盖索引优化 InnoDB 查询**：如果一个查询只需要从辅助索引中获取数据，而无需"回表"查主键索引，这个索引就称为"覆盖索引"，能显著提升查询速度。

4. **MyISAM 的特定场景**：除非有非常明确的理由（例如，表几乎只有读操作，且需要极高的全表COUNT(*)速度），否则不建议再选择 MyISAM。
