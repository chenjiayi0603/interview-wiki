# MySQL 读写流程详解

> 本文档系统梳理 MySQL 的读流程（SQL 查询执行）和写流程（DML 修改提交流程），深入 InnoDB 存储引擎内部机制，涵盖 Buffer Pool、Redo Log、Undo Log、Binlog、Change Buffer 等核心组件的协作原理。

---

## 一、SQL 查询执行流程（读流程）

### 1.1 整体架构概览

```
                        ┌──────────────────────┐
                        │      客户端/应用       │
                        └──────────┬───────────┘
                                   │ SQL: SELECT * FROM users WHERE id = 100
                                   ▼
┌──────────────────────────────────────────────────────────────┐
│                     MySQL Server 层                           │
│                                                              │
│  ┌────────────┐   ┌────────────┐   ┌────────────┐           │
│  │   连接器    │──►│   分析器    │──►│   优化器    │           │
│  │  Connector │   │  Parser    │   │ Optimizer  │           │
│  └────────────┘   └────────────┘   └─────┬──────┘           │
│                                          │                   │
│  ┌───────────────────────────────────────▼──────────────┐   │
│  │                    执行器 Executor                     │   │
│  │           调用 Handler API 与存储引擎交互              │   │
│  └───────────────────────────────────────┬──────────────┘   │
│                                          │                   │
├──────────────────────────────────────────┼───────────────────┤
│                     InnoDB 存储引擎层     │                   │
│                                          ▼                   │
│  ┌───────────────────────────────────────────────────────┐  │
│  │                   Buffer Pool (缓冲池)                 │  │
│  │  ┌─────────┬─────────┬─────────┬─────────────────┐   │  │
│  │  │ 数据页   │ 索引页   │ Undo页  │ Change Buffer   │   │  │
│  │  │ (Data)  │(Index)  │ (Undo)  │ (Insert Buffer) │   │  │
│  │  └─────────┴─────────┴─────────┴─────────────────┘   │  │
│  └───────────────────────────┬───────────────────────────┘  │
│                              │ 未命中                        │
│                              ▼                              │
│  ┌───────────────────────────────────────────────────────┐  │
│  │              磁盘 (ibd / ibdata1 文件)                  │  │
│  └───────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

### 1.2 读流程的 8 步详解

```
步骤  阶段              谁负责           做什么
────  ────────────     ────────────    ──────────────────────────────────
 ①   连接建立          连接器           接收TCP连接、验证身份、检查权限
 ②   查询缓存          查询缓存          检查是否命中（MySQL 8.0已移除）
 ③   词法语法分析       分析器/Parser    词法分析→Token分解；语法分析→AST抽象语法树
 ④   执行计划生成       优化器           选择索引、确定JOIN顺序、成本估算
 ⑤   调用引擎接口       执行器           调用Handler API，如 ha_index_read()
 ⑥   Buffer Pool查找   InnoDB引擎      先查内存中的Buffer Pool
 ⑦   磁盘读取           InnoDB引擎      Buffer Pool未命中时，从磁盘读取数据页
 ⑧   返回结果           执行器→客户端    结果集通过网络返回给客户端
```

### 1.3 各阶段详细分析

#### ① 连接器 (Connector)

```
客户端连接 ──► TCP三次握手 ──► 连接线程分配
                                    │
                              ┌─────▼─────┐
                              │ 身份认证    │
                              │ (用户名密码)│
                              └─────┬─────┘
                                    │
                              ┌─────▼─────┐
                              │ 权限检查    │
                              │ (读权限表) │
                              └─────┬─────┘
                                    │
                              ┌─────▼─────┐
                              │ 等待SQL    │
                              │ (空闲状态) │
                              └───────────┘

关键特性：
  - 长连接：持续复用，减少连接开销
  - 短连接：执行完即断开
  - wait_timeout 控制空闲超时（默认8小时）
  - 权限在连接时读取并缓存，修改权限不影响已有连接
```

#### ② 分析器 (Parser)

```
输入SQL: SELECT name, age FROM users WHERE id = 100

词法分析 (Lexical Analysis)：                       语法分析 (Syntax Analysis)：
───────────────────────────                       ──────────────────────────
  SELECT   → 关键字 (查询)                              SELECT
  name     → 标识符 (列名)                               │
  ,        → 分隔符                            ┌────────┼────────┐
  age      → 标识符 (列名)                     name    age    FROM
  FROM     → 关键字                                           │
  users    → 标识符 (表名)                                users
  WHERE    → 关键字                                          │
  id       → 标识符 (列名)                             WHERE
  =        → 运算符                                          │
  100      → 字面量 (整数)                                  id = 100

                        生成 AST (抽象语法树)
                        验证表名、列名是否存在
                        检查用户是否有 SELECT 权限
```

#### ③ 优化器 (Optimizer)

```sql
-- 优化器需要决策的核心问题：

-- 问题1：用哪个索引？
-- 表 users 上有 PRIMARY KEY(id)，INDEX idx_name(name)，INDEX idx_age(age)
SELECT * FROM users WHERE name = 'Tom' AND age > 20;

-- 优化器决策过程：
-- 方案A：用 idx_name 索引 → 扫描所有 name='Tom' 的行，逐一过滤 age
-- 方案B：用 idx_age 索引  → 扫描所有 age>20 的行，逐一过滤 name
-- 方案C：全表扫描
-- → 基于统计信息（索引区分度/基数 Cardinality）选择成本最低的方案

-- 问题2：多表 JOIN 的顺序？
SELECT * FROM a JOIN b ON a.id = b.a_id WHERE a.status = 1;

-- 方案A：先查 a（小表驱动大表）→ 再 JOIN b
-- 方案B：先查 b → 再 JOIN a
-- → 基于行数估算和索引情况选择最优 JOIN 顺序

-- 查看优化器选择：
EXPLAIN SELECT * FROM users WHERE name = 'Tom' AND age > 20;
```

**优化器核心决策项：**

| 决策项 | 说明 | 示例 |
|--------|------|------|
| 索引选择 | 选哪个索引成本最低 | idx_name vs idx_age vs 全表扫描 |
| JOIN 顺序 | 多表关联时的驱动表选择 | 小表驱动大表 |
| JOIN 算法 | Nested Loop / Hash Join / Sort Merge | MySQL 8.0 支持 Hash Join |
| 子查询优化 | 子查询转 JOIN，物化等 | `IN (subquery)` → semi-join |
| 排序优化 | 是否有索引排序可用 | filesort vs index |

#### ④ 执行器 (Executor)

```
执行器调用存储引擎的 Handler API（以 InnoDB 为例）：

SELECT name, age FROM users WHERE id = 100;

执行步骤：
  ┌──────────────────────────────────────────────┐
  │ 1. ha_index_read(id=100)                     │
  │    调用 InnoDB 的索引读取接口                  │
  │                                              │
  │ 2. InnoDB 定位到主键索引 B+Tree 叶子节点       │
  │    找到 id=100 的行记录                       │
  │                                              │
  │ 3. 返回 {id:100, name:'Tom', age:25, ...}    │
  │                                              │
  │ 4. 执行器提取需要的列 name, age               │
  │    过滤掉不需要的列                           │
  │                                              │
  │ 5. 返回结果集给客户端                          │
  └──────────────────────────────────────────────┘

与无索引的全表扫描对比：
  ┌──────────────────────────────────────────────┐
  │ 1. ha_rnd_init()   → 初始化全表扫描            │
  │ 2. ha_rnd_next()   → 逐行读取                  │
  │ 3. ha_rnd_next()   → 逐行读取                  │
  │ 4. ha_rnd_next()   → 逐行读取                  │
  │ 5. ...              → 直到把所有行读完           │
  │ 6. ha_rnd_end()    → 结束扫描                  │
  └──────────────────────────────────────────────┘
```

#### ⑤ InnoDB Buffer Pool 查找

```
                  ┌─────────────────────────┐
                  │    查询请求：读某页某行   │
                  └───────────┬─────────────┘
                              │
                    ┌─────────▼─────────┐
                    │  查 Buffer Pool    │
                    │  (自适应Hash索引)  │
                    └─────────┬─────────┘
                              │
                   ┌──────────┴──────────┐
                   │                     │
              命中 (Hit)             未命中 (Miss)
                   │                     │
            ┌──────▼──────┐       ┌──────▼──────────┐
            │ 直接返回数据  │       │ 从磁盘读取数据页  │
            │ (内存操作)    │       │ (物理IO操作)     │
            └─────────────┘       └──────┬──────────┘
                                         │
                                  ┌──────▼──────────┐
                                  │ 加载到 Buffer    │
                                  │ Pool 的空闲页    │
                                  │ (如无空闲需LRU)  │
                                  └──────┬──────────┘
                                         │
                                  ┌──────▼──────────┐
                                  │ 返回数据          │
                                  └─────────────────┘
```

#### Buffer Pool 内存结构

```
Buffer Pool 内存布局：

┌────────────────────────────────────────────────────────────┐
│                      Buffer Pool Instance                   │
│                                                             │
│  ┌──────────────────────────────────────────────────────┐  │
│  │                  LRU List (页链表)                     │  │
│  │                                                       │  │
│  │  ┌─────────────────────┐  ┌────────────────────────┐  │  │
│  │  │     Young 区域       │  │       Old 区域          │  │  │
│  │  │  (热数据, 5/8)       │  │  (冷数据, 3/8)          │  │  │
│  │  │  经常访问的页         │  │  刚加载或快被淘汰的页    │  │  │
│  │  └─────────────────────┘  └────────────────────────┘  │  │
│  │                                                       │  │
│  │  新页加载 → 插入 Old 头部                               │  │
│  │  再次访问 → 移动到 Young 头部                           │  │
│  │  淘汰     → 从 Old 尾部移除                            │  │
│  └──────────────────────────────────────────────────────┘  │
│                                                             │
│  ┌──────────────────────────────────────────────────────┐  │
│  │             Free List (空闲页链表)                      │  │
│  │             存放未被使用的空闲页                         │  │
│  └──────────────────────────────────────────────────────┘  │
│                                                             │
│  ┌──────────────────────────────────────────────────────┐  │
│  │             Flush List (脏页链表)                       │  │
│  │             已被修改但未刷盘的脏页                       │  │
│  │             Page Cleaner 线程据此刷脏页                  │  │
│  └──────────────────────────────────────────────────────┘  │
│                                                             │
│  ┌──────────────────────────────────────────────────────┐  │
│  │         Adaptive Hash Index (自适应哈希索引)            │  │
│  │         对频繁访问的索引页自动建立哈希索引               │  │
│  │         将 B+Tree 的 O(logn) 降到 O(1)                 │  │
│  └──────────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────┘
```
