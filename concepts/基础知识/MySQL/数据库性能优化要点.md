# 数据库性能优化要点

## 索引优化
- 为WHERE、JOIN、ORDER BY、GROUP BY列建索引
- 使用覆盖索引避免回表
- 遵循最左前缀原则

## SQL优化
- 避免SELECT *、函数计算、LIKE '%xxx'
- 使用JOIN替代子查询
- 合理使用LIMIT

## EXPLAIN关键字段
- **type**：system > const > eq_ref > ref > range > index > ALL
- **Extra**：Using index（覆盖索引）、Using where（WHERE过滤）

## 架构设计要点

### 分库分表
- **水平分表**：按范围/哈希/目录分表
- **垂直分表**：按列拆分，热点与冷字段分离
- **问题**：跨库查询、分布式事务、ID生成、数据迁移

### 主从复制
- **流程**：主库binlog → 从库relay log → SQL线程执行
- **方式**：异步（默认）、半同步、全同步
- **应用**：读写分离、数据备份、高可用、数据分析

### 高可用方案
- 主从 + 哨兵（Sentinel）
- MHA（Master High Availability）
- 双主架构
- 分库分表 + 主从

## 数据库调优实践

| 调优维度 | 核心要点 |
|---------|---------|
| **硬件优化** | 多核CPU、充足内存（提升缓冲池命中率）、SSD、低延迟网络、RAID配置 |
| **配置优化** | `innodb_buffer_pool_size`（内存70-80%）、`max_connections`、慢查询日志、binlog/redo log配置 |
| **索引优化** | WHERE/JOIN/ORDER BY/GROUP BY列建索引、覆盖索引、最左前缀原则 |
| **SQL优化** | 避免SELECT *、函数计算、LIKE '%xxx'、全表扫描、使用JOIN替代子查询 |
| **应用优化** | 连接池配置、Redis缓存、避免长事务、减少死锁 |
| **架构优化** | 分库分表、主从复制、读写分离、高可用方案 |
| **监控运维** | QPS/TPS、慢查询、连接数、锁等待、主从延迟、自动告警、定期备份 |

**调优原则**：软硬件协同，贯穿设计、开发、运维全生命周期，持续优化瓶颈
