## 一、Istio 架构

```
                   数据平面
┌────────────────────────────────────┐
│  Sidecar   Sidecar   Sidecar       │
│  (Envoy)   (Envoy)   (Envoy)      │
│    │         │         │           │
└────┼─────────┼─────────┼───────────┘
     │         │         │
┌────┼─────────┼─────────┼───────────┐
│    ▼         ▼         ▼  控制平面  │
│  Pilot     Citadel    Galley      │
│ (配置分发) (安全证书) (配置验证)    │
│                                    │
│  Mixer（遥测）                     │
└────────────────────────────────────┘
```

### 组件职责

| 组件 | 作用 |
|------|------|
| **Pilot** | 配置分发、服务发现 |
| **Citadel** | TLS 证书管理、身份认证 |
| **Galley** | 配置验证与处理 |
| **Envoy** | 数据平面代理（Sidecar） |

### Sidecar 注入原理

- **自动注入**：通过 MutatingAdmissionWebhook
- **手动注入**：`istioctl kube-inject`
- 注入后：init 容器设置 iptables 规则，流量全部经过 Sidecar

## 二、Envoy 核心

### 2.1 核心概念

| 概念 | 说明 |
|------|------|
| Listener | 监听端口 |
| Route | 路由规则 |
| Cluster | 服务集群 |
| Endpoint | 后端实例 |
| Filter Chain | 过滤器链 |

### 2.2 Envoy 配置示例

```yaml
static_resources:
  listeners:
  - name: http
    address:
      socket_address:
        address: 0.0.0.0
        port_value: 8080
    filter_chains:
    - filters:
      - name: envoy.filters.network.http_connection_manager
        typed_config:
          "@type": type.googleapis.com/envoy.extensions.filters.network.
            http_connection_manager.v3.HttpConnectionManager
          stat_prefix: ingress_http
          route_config:
            virtual_hosts:
            - name: service
              domains: ["*"]
              routes:
              - match: { prefix: "/" }
                route:
                  cluster: my_service
          http_filters:
          - name: envoy.filters.http.router

  clusters:
  - name: my_service
    connect_timeout: 0.25s
    type: STRICT_DNS
    lb_policy: ROUND_ROBIN
    load_assignment:
      cluster_name: my_service
      endpoints:
      - lb_endpoints:
        - endpoint:
            address:
              socket_address:
                address: my-service
                port_value: 8080
```

### 2.3 熔断（Circuit Breaker）

```yaml
circuit_breakers:
  thresholds:
  - max_connections: 100
    max_pending_requests: 100
    max_requests: 100
    max_retries: 10
```

### 2.4 Envoy Wasm 插件

通过 EnvoyFilter 动态加载 Wasm 扩展：

```yaml
apiVersion: networking.istio.io/v1alpha3
kind: EnvoyFilter
metadata:
  name: my-wasm-filter
spec:
  workloadSelector:
    labels:
      app: my-app
  configPatches:
  - applyTo: HTTP_FILTER
    match:
      context: SIDECAR_INBOUND
    patch:
      operation: INSERT_BEFORE
      value:
        name: my-wasm-filter
        config_discovery:
          config_source:
            ads: {}
          type_url: type.googleapis.com/envoy.extensions.filters.http.wasm.v3.Wasm
```

## 三、gRPC

### 3.1 Protocol Buffers 定义

```protobuf
syntax = "proto3";
package user;

service UserService {
    rpc GetUser(GetUserRequest) returns (GetUserResponse);
    rpc ListUsers(ListUsersRequest) returns (ListUsersResponse);
    rpc CreateUser(stream CreateUserRequest) returns (CreateUserResponse);
    rpc StreamUsers(GetUserRequest) returns (stream User);
}

message User {
    int32 id = 1;
    string name = 2;
    string email = 3;
}
```

### 3.2 gRPC 拦截器

```go
// 服务端拦截器
grpc.UnaryInterceptor(func(ctx context.Context, req interface{},
    info *grpc.UnaryServerInfo, handler grpc.UnaryHandler) (interface{}, error) {
    start := time.Now()
    resp, err := handler(ctx, req)
    log.Printf("method=%s duration=%v", info.FullMethod, time.Since(start))
    return resp, err
})

// 客户端拦截器（添加认证）
grpc.WithUnaryInterceptor(func(ctx context.Context, method string,
    req, reply interface{}, cc *grpc.ClientConn, invoker grpc.UnaryInvoker) error {
    md := metadata.Pairs("token", "my-token")
    ctx = metadata.NewOutgoingContext(ctx, md)
    return invoker(ctx, method, req, reply, cc)
})
```

### 3.3 gRPC vs HTTP/REST

| 特性 | gRPC | HTTP/REST |
|------|------|-----------|
| 协议 | HTTP/2 | HTTP/1.1/2 |
| 序列化 | Protobuf（二进制） | JSON（文本） |
| 代码生成 | 自动 | OpenAPI |
| 流式 | 双向流 | 单向 |
| 性能 | 高 | 中 |

## 四、微服务架构

### 4.1 设计原则

- 单一职责
- 自治独立
- 围绕业务建模
- 基础设施自动化

### 4.2 服务发现（Consul 示例）

```go
import consul "github.com/hashicorp/consul/api"

client, _ := consul.NewClient(consul.DefaultConfig())
registration := &consul.AgentServiceRegistration{
    ID:   "my-service-1",
    Name: "my-service",
    Port: 8080,
    Check: &consul.AgentServiceCheck{
        HTTP:     "http://localhost:8080/health",
        Interval: "10s",
    },
}
client.Agent().ServiceRegister(registration)
```

### 4.3 分布式追踪（OpenTelemetry）

```go
import "go.opentelemetry.io/otel"

tracer := otel.Tracer("my-service")
_, span := tracer.Start(ctx, "handleRequest")
defer span.End()
```

### 4.4 蓝绿部署 / 金丝雀

- **蓝绿**：两套环境，切换流量
- **金丝雀**：逐步增加流量比例
- Istio VirtualService 支持权重路由

## 五、面试考点

### Q1: 服务网格如何选型？

| 方案 | 特点 |
|------|------|
| Istio | 功能全，复杂 |
| Linkerd | 轻量，简单 |
| Envoy | 灵活，自主集成 |

### Q2: 为什么用 Envoy Wasm 插件？
**A**：扩展能力强、动态加载、沙箱隔离、多语言实现（Rust/C++/Go）。

### Q3: Istio Sidecar 注入原理？
**A**：自动注入通过 MutatingAdmissionWebhook，手动注入 `istioctl kube-inject`。注入后 init 容器设 iptables 规则，流量全部经过 Sidecar。
