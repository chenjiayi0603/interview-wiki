# 流程图 · IM 消息推送流程

> 详细流程图见原 `面试突击-流程图.md`

---

## 一、单聊消息推送

```
发送者 → Access网关A → Msg服务 → 写MongoDB → MQ → PushServer
  → 查Redis路由 → Access网关B → 接收方
  └── 离线: ACK MQ → APNs → 上线后拉取
```

**核心**: MQ ACK 在网关 TCP 确认后触发，不等客户端业务 ACK

---

## 二、群聊消息推送（关键）

```
1000 人群:
  优化前: MsgServer → 推 999 人（每人 1 次 RPC）
  优化后: 按网关合并 → 10 网关 = 10 次推送

流程:
  MsgServer → MQ → PushServer(批量拉取)
    → 按网关分组 → 推 Access × N (N=网关数)
    → 每个网关 ACK 后汇报 PushServer → ACK MQ
```

---

## 三、连接管理

```
Manager 父进程(accept)
    ├── Worker[0] epoll → 3-5 万连接
    ├── Worker[1] epoll → 3-5 万连接
    └── Worker[N] epoll → 3-5 万连接

通信: SHM Ring Buffer + POSIX 信号量
路由: 连接按 fd % N 分配到 Worker
```

---

## 四、未读数

```
用户收到消息 → 查 lastReadMsgId → count(msgId > lastReadMsgId AND msgState != 4)
打开会话 → 上报已读位置(lastReadMsgId) → 未读数清零
```

---

## 五、三层限流

```
iptables (每IP 60s限5新连接)
  → Nginx (limit_conn 20000 + limit_req 5000r/s)
  → Access (单连接限速 + 命令字限频)
```
