# 系统设计 · 秒杀系统

> 面试频率：⭐⭐⭐⭐⭐（阿里必考）

---

## 一、需求

```
业务: 定时抢购限量商品（如 100 台手机）
挑战: 瞬时高并发（万人抢 100 台）+ 超卖 + 防刷
目标: 不超卖、不宕机、用户体验好
```

---

## 二、架构方案

```
CDN (静态页) → Nginx (限流) → 网关 (限流) → 应用层 → Redis (库存) → MQ → DB

分层:
  1. CDN: 秒杀页面静态化，扛住前端流量
  2. Nginx: limit_conn + limit_req 限流
  3. 业务层: 校验 + 防刷 + 限频
  4. Redis: Lua 原子扣减库存
  5. MQ: 异步落单，削峰填谷
  6. DB: 最终持久化
```

---

## 三、库存扣减（核心）

```lua
-- Redis Lua 原子扣减
local stock = redis.call('GET', KEYS[1])
if stock and tonumber(stock) >= tonumber(ARGV[1]) then
    redis.call('DECRBY', KEYS[1], ARGV[1])
    return 1
end
return 0
```

```
扣减路径:
  请求 → 布隆过滤器(防刷) → Redis Lua 扣减
      成功 → 创建订单 → MQ → DB 异步扣
      失败 → "库存不足"
```

---

## 四、防超卖体系

| 层次 | 措施 | 作用 |
|------|------|------|
| 前端 | 按钮置灰 3s | 防重复提交 |
| 网关 | 每用户限频 | 防脚本刷单 |
| 应用 | 布隆过滤器 | 防恶意 ID |
| Redis | Lua 原子操作 | 核心防超卖 |
| DB | 乐观锁 UPDATE ... WHERE stock > 0 | 最终兜底 |

---

## 五、优化点

```
热点 Key:
  └── 单个商品库存集中在 1 个 Redis Key
  └── 拆分: 分片存储库存 ("stock:{id}:{shard}")

库存预热:
  └── 提前加载库存到 Redis
  └── 设置过期时间（防内存泄漏）

异步落库:
  └── Redis 扣减成功 → MQ 异步写 DB
  └── DB 写入失败 → MQ 重试 + 库存回滚

降级:
  └── Redis 挂了 → 直接降级到 DB 乐观锁（限流降低）
```

---

## 六、追问应对

```
Q: "库存扣完但用户没付款怎么办？"
A: "设置订单过期时间（如 15 分钟），超时释放库存"

Q: "怎么防止黄牛刷单？"
A: "每用户限购 + 设备指纹 + 风控模型"

Q: "Redis 库存和 DB 库存不一致？"
A: "定时对账任务，差异自动补偿"
```
