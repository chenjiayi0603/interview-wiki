# 系统设计 · 分布式 KV 存储

> 面试频率：⭐⭐⭐⭐（华为云/腾讯云必考）

---

## 一、需求

```
高可用、可扩缩、强一致/最终一致可选
支持 Redis 协议兼容
容量近乎无限
```

---

## 二、架构

```
客户端 → Proxy/Cluster 层 → 分片节点 (RocksDB + WAL)
                              ↓
                          OBS 对象存储（持久化）
```

---

## 三、核心设计要素

| 要素 | 方案 | 说明 |
|------|------|------|
| **数据分片** | 一致性哈希 / 固定槽位 | Redis Cluster 16384 槽 |
| **副本** | Raft 多数派 / 异步复制 | 强一致 vs 高吞吐 |
| **一致性** | Etcd + OBS 强一致 | 写 OBS 成功才返回 |
| **持久化** | WAL + LSM-Tree | RocksDB 默认 |
| **扩缩容** | 槽迁移 + 虚拟节点 | 不停服迁移 |
| **故障恢复** | 自动选主 + 数据追齐 | Etcd 租约 + 心跳 |

---

## 四、存算分离方案

```
热数据: 本地 RocksDB（Block Cache + MemTable）< 1ms
冷数据: OBS 对象存储，延迟 2-10ms
元数据: Etcd（文件位置、分片信息、版本号）

冷热判断:
  ├── 时间: 超过 7 天未访问 → 冷
  ├── 频次: 滑动窗口 < threshold → 冷
  └── 大小: > 10KB 优先下沉
```

---

## 五、优化点

```
冷数据延迟高: 异步预取 + 连接池
Compaction 抖动: 分时段限速（低峰全速，高峰限速）
写放大: 增大 MemTable(256MB→512MB)
一致性: 先写 OBS → 成功后更新 Etcd
缓存: 本地 LRU + Etcd 版本校验
```

---

## 六、追问应对

```
Q: "Redis 挂了怎么办？"
A: "主从切换 + 哨兵/Cluster + 降级限流"

Q: "怎么做性能压测？"
A: "定义目标→打流量→观察瓶颈→逐层优化"

Q: "RocksDB 和 LevelDB 区别？"
A: "RocksDB 多线程 Compaction、Merge Operator、BlobDB 等"
```
