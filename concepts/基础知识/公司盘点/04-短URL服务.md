# 系统设计 · 短 URL 服务

> 频率：⭐⭐⭐（常见热身题）

---

## 一、需求

```
输入: 长 URL → 输出: 短 URL（如 https://t.cn/Abc123）
访问短 URL → 302 重定向到长 URL
支持过期时间、数据统计
```

---

## 二、核心方案

```
ID 发号器 → 62 进制编码 → 短码

ID 生成:
  ├── Redis INCR（单机，10 万+/s）
  ├── Snowflake（分布式，无依赖）
  └── DB 号段（批量取 ID，如每次 10000 个）

编码:
  ├── 62 进制: 0-9 + a-z + A-Z
  ├── 6 位: 62^6 ≈ 568 亿
  └── 7 位: 62^7 ≈ 3.5 万亿
```

---

## 三、读写路径

```
写:
  长 URL → 取 ID → 62 进制编码 → 存储 {short:long}
  缓存（Redis） + 持久化（MySQL）

读:
  访问 short URL → 查缓存 → 命中返回 302
                  → 未命中查 DB → 回写缓存 → 返回 302
```

---

## 四、优化点

```
哈希冲突:
  ├── 方案 A: 发号器保证唯一（推荐）
  └── 方案 B: 哈希 + 冲突检测重试

短码复用:
  └── 同一长 URL 返回同一短码（空间换时间）

过期策略:
  ├── Redis TTL 自动过期
  └── DB 定时清理过期记录

统计:
  ├── Redis INCR 访问计数
  └── 异步写 DB 持久化
```
