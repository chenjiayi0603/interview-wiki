# 系统设计 · 实时 AI 语音对话

> 频率：⭐⭐⭐⭐（外企/AI 方向高频）

---

## 一、需求

```
用户语音提问 → STT 转文字 → AI 回答 → TTS 合成语音 → 播放
端到端延迟 < 5s
支持 1 万并发
```

---

## 二、架构

```
客户端 → WebSocket 网关 → 对话管理
                              ├── STT（阿里云/Whisper）
                              ├── AI（DeepSeek/ChatGPT）
                              └── TTS（阿里云/火山）
```

---

## 三、核心流程

```
语音流处理:
  客户端采集 PCM → Opus 压缩 → 流式上传
  服务端组装 → 调 STT API → 中间结果触发 AI

AI 流式响应:
  调 DeepSeek API stream=true
  逐 chunk 转发给客户端（打字机效果）
  TTS 流式合成，边合成边播

完整流程耗时:
  问题生成 3s + TTS 1s + 用户听 4.5s
  → 回答上传 0.5s + STT 0.5s + AI 分析 2s = 总共 ~7s
```

---

## 四、优化点

| 阶段 | 优化前 | 优化后 | 方式 |
|------|-------|-------|------|
| AI 首字 | 2s | 0.5s | 流式响应 |
| TTS 合成 | 2s | 1s | 引擎预热 |
| STT | 800ms | 500ms | 流式上传 |
| 内存 | 5GB | 3GB | 对象池复用 |

```
引擎预热:
  服务启动时预加载 TTS 模型 → 省 500ms 加载时间

流式合成:
  边合成边转发 → 不用等完整音频

对话状态管理:
  session_id 关联同一轮对话
  超时 30 分钟无活动销毁
```

---

## 五、成本控制

```
单次成本: DeepSeek ¥0.05 + 语音 ¥0.1 = ¥0.15/次
定价 ¥5 → 毛利率 97%

降成本:
  ├── 缓存常见问题的 AI 回复
  ├── 限制单用户频率（10 次/分钟）
  └── AI 不可用时预置模板回复
```
