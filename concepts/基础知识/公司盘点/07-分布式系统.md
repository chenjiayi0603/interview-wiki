# 分布式系统速查

---

## 一、CAP / BASE

```
CAP: 一致性 / 可用性 / 分区容忍性 三者选二
  实际: CP（ZK/Etcd）或 AP（Eureka）

BASE: Basically Available + Soft State + Eventual Consistency
```

---

## 二、一致性算法

| 算法 | 特点 | 适用 |
|------|------|------|
| Raft | 选主+日志复制，易理解 | Etcd、TiKV |
| Paxos | 理论完备，难实现 | Chubby、ZAB |
| ZAB | ZK 原子广播 | ZooKeeper |
| Gossip | 最终一致，去中心 | Cassandra、Redis Cluster |

---

## 三、分布式事务

| 方案 | 优点 | 缺点 |
|------|------|------|
| 2PC | 强一致 | 阻塞、协调者单点 |
| TCC | 灵活 | 业务侵入强 |
| 本地消息表 | 简单 | 轮询压力 |
| 事务消息(RocketMQ) | 成熟 | 需回查 |
| Saga | 高性能 | 弱隔离 |

---

## 四、Raft 核心

```
选主:
  └── 节点状态: Leader / Follower / Candidate
  └── 超时选举: 随机 150-300ms，获得多数票即当选

日志复制:
  └── Leader 接收客户端请求 → AppendEntries → 多数派写入 → Apply
  └── 所有节点日志必须一致（Term+Index）
```

---

## 五、分布式锁对比

```
Redis: 性能高(10万+/s)，主从切换可能丢锁
ZK: 强一致(ZAB)，性能略低(几千/s)
Etcd: gRPC+JSON，运维简单，写10000+/s
```
