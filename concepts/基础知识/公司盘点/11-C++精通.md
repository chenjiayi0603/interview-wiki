## 一、模板元编程（TMP）

> **先区分两个概念：**
>
> **模板编程（Template Programming）** = 用模板写泛型代码，编译期实例化。
> 例如：`std::vector<T>`、`std::sort`、上面的 CRTP 单例、Fold Expressions 都是模板编程，属于泛型技巧，不算元编程。
>
> **模板元编程（Template Metaprogramming, TMP）** = **用模板在编译期执行计算**，输入是类型/常量，输出是类型/常量，运行时零开销。
> 核心特征：递归模板实例化 + 特化做条件分支 + 编译期常量计算。
>
> 简单判断：**代码里有递归模板特化，在编译期算东西的，才算 TMP。** SFINAE 是 TMP 的工具，CRTP/Fold 是模板编程技巧。

### Q1: SFINAE 原理及实际应用？

SFINAE = Substitution Failure Is Not An Error
模板实例化时，如果某个特化的参数替换失败，不报错，继续尝试其他特化。

**应用场景:**
1. 根据类型特性启用/禁用重载（enable_if）
2. 检测类型是否有某个成员函数（has_member）
3. 编译期判断类型是否是整数/浮点/可调用

```cpp
#include <type_traits>

// enable_if 控制重载
template<typename T>
std::enable_if_t<std::is_integral_v<T>, void>
process(T val) { /* 整数处理 */ }

template<typename T>
std::enable_if_t<std::is_floating_point_v<T>, void>
process(T val) { /* 浮点处理 */ }
```

### Q2: CRTP（奇异递归模板模式）

CRTP = Curiously Recurring Template Pattern
基类模板将派生类作为模板参数，实现静态多态。

```cpp
// 静态多态（代替虚函数）
template<typename Derived>
class Shape {
public:
    double area() const {
        return static_cast<const Derived*>(this)->area_impl();
    }
};

class Circle : public Shape<Circle> {
    double r_;
public:
    explicit Circle(double r) : r_(r) {}
    double area_impl() const { return 3.14159 * r_ * r_; }
};
```

#### SFINAE 完整实战：检测是否有成员函数

```cpp
#include <type_traits>
#include <iostream>
#include <vector>

// ═══════════════════════════════════════════════════
// 以下两个模板合起来是 TMP（模板元编程）
// 在编译期通过 SFINAE 机制"计算" T 是否有 reserve()
// 输入: 类型 T    输出: true_type / false_type（编译期常量）
// ═══════════════════════════════════════════════════

// has_reserve<T> : 编译期检测 T 是否有 reserve(size_t) 成员函数
template<typename T, typename = void>
struct has_reserve : std::false_type {};  // 默认: 没有 reserve

// SFINAE: 如果 T 有 reserve(size_t)，匹配这个特化 → 结果为 true
template<typename T>
struct has_reserve<T, std::void_t<decltype(
    std::declval<T>().reserve(std::declval<size_t>())
)>> : std::true_type {};

// ═══════════════════════════════════════════════════
// 以下不是 TMP，只是消费 TMP 的计算结果
// if constexpr 读取编译期常量，决定保留哪条分支
// ═══════════════════════════════════════════════════

// 使用: 有 reserve 就调用，没有就跳过
template<typename Container>
void reserve_if_possible(Container& c, size_t n) {
    // has_reserve<Container>::value ← 这就是 TMP 算出来的编译期常量
    // if constexpr 在编译期读取它，决定保留哪条分支
    if constexpr (has_reserve<Container>::value) {  // ← 消费 TMP 结果的地方
        c.reserve(n);
    }
}

// 验证
static_assert(has_reserve<std::vector<int>>::value,    "vector has reserve");
static_assert(!has_reserve<std::string>::value,         "string has no reserve");

// 调用场景: 泛型批量处理函数，适配任意容器
template<typename Container, typename T>
void fill_large(Container& c, T value, size_t count) {
    reserve_if_possible(c, count);  // 有 reserve 就预分配，没有跳过
    for (size_t i = 0; i < count; ++i) {
        c.push_back(value);
    }
}

// 调用:
//   std::vector<int> v;
//   fill_large(v, 42, 10000);    // vector: 预分配 10000，避免反复扩容
//
//   std::list<int> lst;
//   fill_large(lst, 42, 10000);  // list: 没有 reserve，跳过，正常 push_back

// enable_if 控制构造函数重载
struct Widget {
    // 只接受整数类型
    template<typename T, typename = std::enable_if_t<std::is_integral_v<T>>>
    explicit Widget(T value) : data_(static_cast<int>(value)) {}

    // 只接受浮点类型
    template<typename T, typename = std::enable_if_t<std::is_floating_point_v<T>>>
    explicit Widget(T value) : data_(static_cast<int>(value * 100)) {}

    int data_;
};
```

```
面试话术:
  "SFINAE 最实用的场景是检测类型是否有某个成员函数。
   has_reserve 这种 trait 在泛型容器代码中很常见——
   有 reserve 就预分配提升性能，没有就跳过。
   void_t 是 C++17 的技巧，把任意类型映射到 void，
   让 SFINAE 更简洁。C++20 之后用 Concept 替代大部分 SFINAE。"
```

### Q2b: Fold Expressions（折叠表达式，C++17）

```
C++17 引入，简化变参模板的展开操作。

四种折叠:
  ├── 一元右折叠: (args op ...)  →  (arg1 op (... op (argN-1 op argN)))
  ├── 一元左折叠: (... op args)  →  (((arg1 op arg2) op ...) op argN)
  ├── 二元右折叠: (args op ... op init)
  └── 二元左折叠: (init op ... op args)
```

```cpp
#include <iostream>
#include <string>
#include <vector>

// 1. 求和（一元右折叠）
template<typename... Args>
auto sum(Args... args) {
    return (args + ...);  // 一元右折叠: (1 + (2 + (3 + 4)))
}

// 2. 打印所有参数（逗号运算符折叠）
template<typename... Args>
void print_all(Args... args) {
    ((std::cout << args << " "), ...);  // 逗号折叠: (cout<<1, (cout<<2, ...))
    std::cout << "\n";
}

// 3. 检查是否全部满足条件（&& 折叠）
template<typename... Args>
bool all_true(Args... args) {
    return (... && args);  // 一元左折叠: ((true && true) && false)
}

// 4. 检查是否有任一满足条件（|| 折叠）
template<typename... Args>
bool any_true(Args... args) {
    return (... || args);
}

// 5. push_back 多个元素到 vector
template<typename T, typename... Args>
void push_all(std::vector<T>& vec, Args&&... args) {
    (vec.push_back(std::forward<Args>(args)), ...);
}

// 6. 类型匹配检测
template<typename T, typename... Args>
bool is_any_of() {
    return (... || std::is_same_v<T, Args>);
}

// 使用示例
void demo() {
    auto s = sum(1, 2, 3, 4);       // s = 10
    print_all("hello", 42, 3.14);    // 输出: hello 42 3.14
    auto a = all_true(true, true, false);  // a = false
    auto b = any_true(false, true, false); // b = true

    std::vector<int> v;
    push_all(v, 1, 2, 3, 4);         // v = {1,2,3,4}

    auto check = is_any_of<int, double, float, std::string>();  // check = false
    // int 不在 <double, float, string> 中
}
```

```
面试话术:
  "Fold Expressions 让变参模板的可读性大幅提升。
   C++11/14 时代展开参数包需要递归模板或复杂的 enable_if，
   C++17 一行 (...) 搞定。最常用的是逗号折叠做批量操作，
   &&/|| 折叠做条件判断，加法折叠做累加。
   注意折叠方向：... op args 是左折叠（从左到右），
   args op ... 是右折叠（从右到左）。"
```

### Q2c: CRTP 实战——单例模板

```cpp
// CRTP 实现单例基类
template<typename Derived>
class Singleton {
public:
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;

    static Derived& instance() {
        static Derived inst;  // C++11 起线程安全的静态局部变量
        return inst;
    }

protected:
    Singleton() = default;  // 防止外部构造
};

// 使用: 任意类继承 Singleton<Derived> 即可获得单例能力
class Logger : public Singleton<Logger> {
    friend class Singleton<Logger>;  // 基类能调用私有构造
public:
    void log(const std::string& msg) {
        std::cout << "[LOG] " << msg << "\n";
    }
private:
    Logger() = default;  // 私有构造，防止外部实例化
};

// 使用
// Logger::instance().log("hello");

// CRTP 实现对象计数
template<typename Derived>
class ObjectCounter {
public:
    static size_t count() { return count_; }

protected:
    ObjectCounter() { ++count_; }
    ObjectCounter(const ObjectCounter&) { ++count_; }
    ~ObjectCounter() { --count_; }

private:
    static inline size_t count_ = 0;  // C++17 inline 变量
};

class Widget : public ObjectCounter<Widget> {
    // Widget 自动获得计数能力
};

void demo_counter() {
    Widget a, b;
    Widget c = a;
    // Widget::count() == 3
}
```

```
面试话术:
  "CRTP 最实用的两个模式是单例和对象计数。
   单例用 CRTP 比手写每个类省去重复代码，
   对象计数常用于内存泄漏排查或资源限制。
   CRTP 的本质是'派生类作为模板参数传给基类'，
   基类可以 static_cast<Derived*>(this) 调用派生类方法，
   实现编译期多态，零运行时开销。"
```

### Q5: C++20 Coroutine 执行流程深度

#### 完整代码（面试手写模板）

```cpp
#include <coroutine>
#include <optional>
#include <iostream>

// 协程返回类型: Task<T>
template<typename T>
struct Task {
    struct promise_type {
        std::optional<T> result_;

        Task get_return_object() {
            return Task{std::coroutine_handle<promise_type>::from_promise(*this)};
        }
        std::suspend_never initial_suspend() { return {}; }  // 创建后不挂起
        std::suspend_always final_suspend() noexcept {       // 结束前挂起
            if (continuation_) continuation_.resume();
            return {};
        }
        void return_value(T v) { result_ = std::move(v); }
        void unhandled_exception() { std::terminate(); }

        std::coroutine_handle<> continuation_;  // 链式调用用
    };

    using handle_type = std::coroutine_handle<promise_type>;
    handle_type handle_;

    T get() {
        if (!handle_.done()) handle_.resume();
        return std::move(*handle_.promise().result_);
    }

    ~Task() { if (handle_) handle_.destroy(); }
};

// 使用协程
Task<int> async_fetch_data() {
    std::cout << "协程开始执行...\n";
    co_await std::suspend_always{};  // 主动让出，等待 resume
    std::cout << "协程恢复执行...\n";
    co_return 42;
}

// int main() {
//     Task<int> task = async_fetch_data();
//     std::cout << "结果: " << task.get() << "\n";
// }
```

#### 为什么返回 `Task<int>`，不是 `int`？

```
C++20 协程的返回类型由 promise_type 决定，不是由 co_return 决定。

编译器看到函数中有 co_await / co_return / co_yield → 识别为协程 → 自动改写:

  Task<int> async_fetch() {
      ? 编译器展开成:
      {
          // 1. 分配协程帧（堆上）
          auto __frame = new coroutine_frame{...};
          // 2. 构造 promise_type
          auto& __promise = __frame->promise;
          // 3. 调用 get_return_object() → 这就是函数"返回"的 Task<int>
          auto __return = __promise.get_return_object();
          // 4. initial_suspend
          co_await __promise.initial_suspend();
          try {
              // 5. 执行你的协程体...
              co_await std::suspend_always{};
              co_return 42;
          } catch(...) {
              __promise.unhandled_exception();
          }
          // 6. final_suspend
          co_await __promise.final_suspend();
      }

  Task<int> 不是函数真正的返回值，而是通过 promise.get_return_object()
  创建的"协程控制句柄包装器"。
```

#### `co_return 42;` 之后做了什么？

```
第 1 步: 调用 promise.return_value(42)
   → result_ = optional<int>(42)  把值存进协程帧

第 2 步: 调用 final_suspend() 挂起在终点
   → 协程帧仍在内存（不释放！），result_ 可被调用方读取

第 3 步: 调用方取结果
   → task.get() → handle_.promise().result_ → 42

第 4 步: Task 析构 → handle_.destroy() → 释放协程帧
```

#### 完整生命周期图

```
调用 async_fetch()
  │
  ├── ① 分配协程帧（堆）
  ├── ② 构造 promise_type
  ├── ③ get_return_object() → Task<int>（控制句柄）
  ├── ④ initial_suspend() → suspend_never（不挂起，继续）
  │
  ├── ⑤ 执行协程体...
  │     ├── co_await suspend_always{} → 挂起
  │     ├── 调用方 task.get() → handle_.resume() → 恢复
  │     └── co_return 42;
  │           ├── promise.return_value(42)    ← 42 存入协程帧
  │           └── final_suspend() → 挂起在终点  ← 帧还在！
  │
  ├── ⑥ 调用方 task.get() → 42
  └── ⑦ Task 析构 → handle_.destroy() → 释放协程帧
```

#### 对比普通函数

```cpp
// 普通函数: 返回值通过寄存器/栈传递，函数结束栈帧释放
int sync_fetch() { return 42; }

// 协程: 返回值通过 promise.return_value 存到协程帧
//       协程可挂起/恢复，帧一直存活到 handle.destroy()
Task<int> async_fetch() {
    co_await std::suspend_always{};
    co_return 42;
}
```

#### 面试话术

```
"协程返回 Task<int> 而不是 int，因为协程需要'活着'返回。
  调用方拿到的 Task 是一个控制句柄，真正的 42 存在堆上的协程帧里。
  co_return 42 只是调 promise.return_value(42) 把值存起来，
  等调用方通过 task.get() 来取。
  协程帧直到 handle.destroy() 才释放，所以协程可以挂起再恢复。"
```

## 三、C++ 内存模型与并发

### Q6: memory_order 详解

```cpp
#include <atomic>
#include <cassert>

// relaxed: 简单计数器
std::atomic<int> counter{0};
void inc() {
    counter.fetch_add(1, std::memory_order_relaxed);
}

// acquire-release: 建立 happens-before
std::atomic<bool> flag{false};
std::string data;

void writer() {
    data = "hello";
    flag.store(true, std::memory_order_release);
}

void reader() {
    while (!flag.load(std::memory_order_acquire));
    assert(data == "hello");  // 一定成功
}

// seq_cst: 全局顺序一致
std::atomic<int> x{0}, y{0};
int r1, r2;

void thread1() {
    x.store(1, std::memory_order_seq_cst);
    r1 = y.load(std::memory_order_seq_cst);
}

void thread2() {
    y.store(1, std::memory_order_seq_cst);
    r2 = x.load(std::memory_order_seq_cst);
}
```

### Q7: 无锁栈（Treiber Stack）

```cpp
template<typename T>
class LockFreeStack {
    struct Node {
        T data;
        Node* next;
    };
    std::atomic<Node*> head_{nullptr};

public:
    void push(T val) {
        Node* node = new Node{std::move(val), nullptr};
        node->next = head_.load(std::memory_order_relaxed);
        while (!head_.compare_exchange_weak(
            node->next, node,
            std::memory_order_release,
            std::memory_order_relaxed));
    }

    bool pop(T& val) {
        Node* node = head_.load(std::memory_order_acquire);
        while (node && !head_.compare_exchange_weak(
            node, node->next,
            std::memory_order_acquire,
            std::memory_order_relaxed));
        if (!node) return false;
        val = std::move(node->data);
        delete node;  // 注意 ABA 问题
        return true;
    }
};
```

## 六、异常安全

### Q13: 异常安全级别

```cpp
class SafeData {
    std::vector<int> data_;
    std::mutex mtx_;

public:
    // Strong Guarantee
    void add(const std::vector<int>& items) {
        std::lock_guard<std::mutex> lock(mtx_);
        auto copy = data_;
        copy.insert(copy.end(), items.begin(), items.end());
        data_ = std::move(copy);
    }

    // Noexcept
    void clear() noexcept {
```

## 八、高频白板题（必背）

### Q15: 实现线程池

```cpp
class ThreadPool {
    std::vector<std::thread> workers_;
    std::queue<std::function<void()>> tasks_;
    std::mutex mtx_;
    std::condition_variable cv_;
    bool stop_ = false;

public:
    explicit ThreadPool(size_t n) {
        for (size_t i = 0; i < n; ++i) {
            workers_.emplace_back([this] {
                while (true) {
                    std::function<void()> task;
                    {
                        std::unique_lock lock(mtx_);
                        cv_.wait(lock, [this] {
                            return stop_ || !tasks_.empty();
                        });
                        if (stop_ && tasks_.empty()) return;
                        task = std::move(tasks_.front());
                        tasks_.pop();
                    }
                    task();
                }
            });
        }
    }

    template<typename F, typename... Args>
    auto enqueue(F&& f, Args&&... args)
        -> std::future<std::invoke_result_t<F, Args...>>
    {
        using return_type = std::invoke_result_t<F, Args...>;
        auto task = std::make_shared<std::packaged_task<return_type()>>(
            std::bind(std::forward<F>(f), std::forward<Args>(args)...)
        );
        std::future<return_type> result = task->get_future();
        {
            std::lock_guard lock(mtx_);
            tasks_.emplace([task]() { (*task)(); });
        }
        cv_.notify_one();
        return result;
    }

    ~ThreadPool() {
        { std::lock_guard lock(mtx_); stop_ = true; }
        cv_.notify_all();
        for (auto& w : workers_) w.join();
    }
};
```

### Q16: 实现 shared_ptr 简化版

```cpp
template<typename T>
class SharedPtr {
    struct ControlBlock {
        std::atomic<int> ref_count_{1};
        T* ptr_;
        explicit ControlBlock(T* p) : ptr_(p) {}
    };
    T* ptr_;
    ControlBlock* cb_;

    void release() {
        if (cb_ && cb_->ref_count_.fetch_sub(1) == 1) {
            delete cb_->ptr_;
            delete cb_;
        }
    }

public:
    explicit SharedPtr(T* ptr = nullptr)
        : ptr_(ptr), cb_(ptr ? new ControlBlock(ptr) : nullptr) {}

    SharedPtr(const SharedPtr& other)
        : ptr_(other.ptr_), cb_(other.cb_) {
        if (cb_) cb_->ref_count_.fetch_add(1);
    }

    SharedPtr(SharedPtr&& other) noexcept
        : ptr_(other.ptr_), cb_(other.cb_) {
        other.ptr_ = nullptr; other.cb_ = nullptr;
    }

    ~SharedPtr() { release(); }
    T* operator->() const { return ptr_; }
    T& operator*() const { return *ptr_; }
};
```

### Q17: 实现 LRU Cache

```cpp
template<typename Key, typename Value>
class LRUCache {
    size_t capacity_;
    std::list<std::pair<Key, Value>> items_;
    std::unordered_map<Key, typename std::list<std::pair<Key, Value>>::iterator> cache_;

public:
    explicit LRUCache(size_t cap) : capacity_(cap) {}

    std::optional<Value> get(const Key& key) {
        auto it = cache_.find(key);
        if (it == cache_.end()) return std::nullopt;
        items_.splice(items_.begin(), items_, it->second);
        return it->second->second;
    }

    void put(const Key& key, const Value& value) {
        auto it = cache_.find(key);
        if (it != cache_.end()) {
            it->second->second = value;
            items_.splice(items_.begin(), items_, it->second);
            return;
        }
        items_.emplace_front(key, value);
        cache_[key] = items_.begin();
        if (cache_.size() > capacity_) {
            cache_.erase(items_.back().first);
            items_.pop_back();
        }
    }
};
```

### Q20: C++23 有哪些重要更新？

#### 核心特性

```
1. std::expected<T, E>（错误处理）
   #include <expected>
   std::expected<int, std::string> parse(const std::string& s) {
       if (s.empty()) return std::unexpected("empty string");
       return std::stoi(s);
   }
   // 调用: 优雅的错误处理，替代异常或 optional
   auto result = parse("42");
   if (result) { use(*result); }

   // 简化 CRTP，支持 lambda 自引用
```

### Q21: C++20 Modules 是什么？

```
传统头文件的问题:
  ├── 重复解析（每个 .cpp 都要处理 #include 链）
  ├── 宏污染（#define 影响所有 include 者）
  └── 编译慢（大项目头文件修改触发全量重编）

Modules 解决方案:
  ├── 编译单元独立编译，不重复解析
  ├── 没有头文件顺序依赖
  ├── 显式导出/隐藏符号
  └── 编译速度提升 2-10 倍
```

#### Module 示例

```cpp
// math.ixx (Module 接口单元)
export module math;

export int add(int a, int b) {
    return a + b;
}

// 内部函数，不导出
int internal_helper(int x) { return x * 2; }

// main.cpp
import math;  // 不需要 #include

int main() {
    return add(1, 2);
}
```

### Q22: std::span 和 std::string_view 的区别？

```
都是"视图"类型，不持有所有权，但应用场景不同:

| 特性 | std::string_view | std::span |
|------|-----------------|-----------|
| 元素 | char | T（任意类型） |
| 可变 | 只读 | 只读或读写 |
| 常见来源 | const char*, std::string | T*, std::vector, 数组 |
| 子串/切片 | substr(offset, count) | first(n) / last(n) / subspan(offset, count) |

string_view 面试陷阱:
  // 危险: 返回临时 string 的 view
  std::string_view get_name() {
      std::string name = "hello";  // 局部变量！
      return name;  // name 析构后 view 悬空
  }

span 面试陷阱:
  void process(std::span<int> data);  // 传值，轻量
  // 传入 vector、数组、原生指针+长度 都行
```

```
面试话术:
  "string_view 和 span 都是零开销抽象的典范。
   它们让接口更通用，调用方可以传各种形式的数据。
   关键是要记住它们不拥有数据，生命周期必须比 view 长。
   面试常考悬空问题。"
```
