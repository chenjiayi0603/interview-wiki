# 进程地址空间与系统内存

> 进程内存布局、VSZ/RSS/PSS 指标、虚拟内存与分页、TLB、mmap/HugePages。

## 一、进程地址空间布局

### 1.1 完整布局

```
┌─────────────────────────────┐ 0xFFFFFFFF (32位) / 0x7FFFFFFFFFFFFFFF (64位)
│        内核空间               │ 内核代码、数据、模块
│   (1GB 32位 / 128TB 64位)   │ 用户态不可直接访问
├─────────────────────────────┤
│        栈（Stack）           │ 局部变量、函数调用帧，向下增长
│            ↓                 │ 默认 8MB (Linux)，ulimit -s 可改
├─────────────────────────────┤
│        内存映射段             │ mmap 文件映射、共享库、大内存分配
│            ↓                 │
├─────────────────────────────┤
│            ↑                 │
│        堆（Heap）            │ malloc/new，向上增长，brk/sbrk 扩展
├─────────────────────────────┤
│        BSS 段                │ 未初始化全局/静态变量（启动时清零）
├─────────────────────────────┤
│       数据段                  │ 已初始化全局/静态变量
├─────────────────────────────┤
│       代码段 (.text)         │ 只读可执行指令
└─────────────────────────────┘ 0x00000000
```

### 1.2 各段特性

| 段 | 内容 | 特性 | 占用磁盘 |
|----|------|------|:--------:|
| 代码段 | 机器指令 | 只读、可共享 | ✅ |
| 数据段 | 已初始化全局/静态变量 | 可读写 | ✅ |
| BSS 段 | 未初始化全局/静态变量 | 可读写，OS 加载时清零 | ❌ |
| 堆 | 动态分配 | 向上增长，手动管理 | ❌ |
| 内存映射段 | 文件映射、共享库 | 动态，mmap 创建 | ❌ |
| 栈 | 局部变量、函数帧 | 向下增长，自动管理 | ❌ |

### 1.3 共享与私有

| 资源 | 共享方式 | 说明 |
|------|---------|------|
| 代码段 | 所有进程共享 | 同一程序多进程只加载一份 |
| 数据段 | 各进程私有 | COW：fork 后共享，写入时复制 |
| BSS 段 | 各进程私有 | — |
| 堆 | 进程内共享 | 线程间共享堆空间 |
| 栈 | 线程私有 | 每线程独立栈 |
| 共享库 | 所有进程共享 | 物理内存一份，VSZ 各算各的 |
| 内存映射文件 | 可配置共享 | MAP_SHARED vs MAP_PRIVATE |

## 二、内存指标：VSZ、RSS、PSS

### 2.1 定义

| 指标 | 全称 | 含义 | 类比 |
|------|------|------|------|
| **VSZ** | Virtual Memory Size | 进程虚拟地址空间总量（承诺的内存） | 菜谱收录的所有菜品 |
| **RSS** | Resident Set Size | 实际驻留在物理内存中的部分 | 今晚宴席准备好的食材 |
| **PSS** | Proportional Set Size | 按比例分摊的物理内存 | 公平分摊后的账单 |

### 2.2 VSZ >> RSS 的原因

| 原因 | 说明 | 示例 |
|------|------|------|
| **延迟分配** | malloc 申请虚拟地址，写入时才分配物理页 | 堆 VSZ=100MB, RSS=20MB |
| **共享库** | 多个进程共享物理内存，VSZ 重复计算 | 共享库 VSZ=50MB, RSS=5MB |
| **内存映射文件** | 整个文件映射，只加载活跃部分 | 文件 VSZ=500MB, RSS=10MB |
| **Swap 换出** | 内存换出到磁盘，VSZ 不变 RSS 减少 | Swap=30MB, RSS=0MB |

### 2.3 查看工具

```bash
ps aux                          # VSZ/RSS 列
cat /proc/<pid>/status          # VmRSS/VmSize
cat /proc/<pid>/maps            # 完整内存映射布局
pmap -x <pid>                   # 格式化显示内存映射
top -p <pid>                    # 实时内存占用
```

## 三、虚拟内存与分页

### 3.1 虚拟地址到物理地址转换

```
虚拟地址: [页号(高位)] [页内偏移(低位)]
                 ↓ 页表查询
物理地址: [物理页框号] [页内偏移]
```

**三步流程**：
1. **地址分解**：虚拟地址 = 页号 + 页内偏移
2. **页表查询**：先查 TLB（快），未命中则查多级页表（PGD→PUD→PMD→PTE）
3. **地址合成**：物理地址 = 物理页框号 + 页内偏移

### 3.2 页表项结构

```
┌──────┬──────┬──────┬──────┬──────────────┐
│ Valid│ Prot │ Dirty│ Ref  │  Frame No.   │
└──────┴──────┴──────┴──────┴──────────────┘
```

### 3.3 TLB（Translation Lookaside Buffer）

- CPU 高速缓存，缓存虚拟页 → 物理页映射
- 命中率通常 >95%
- **ASID**（Address Space ID）区分进程，避免上下文刷 TLB
- **大页**（HugePages）减少 TLB 压力

### 3.4 写时复制（Copy-On-Write）

fork 后父子进程共享物理内存，只有写入时才复制：

```bash
fork()
  ↓
父子进程共享所有物理页（标记为只读）
  ↓
一方写入 → 缺页异常 → 复制物理页 → 各自独立
```

## 四、mmap 与内存映射

### 4.1 mmap 三阶段

1. **创建虚拟映射**：在虚拟地址空间分配区域（未分配物理页）
2. **建立映射关系**：建立文件地址到虚拟地址的页表映射
3. **缺页异常加载**：首次访问时触发缺页异常，从磁盘加载数据

### 4.2 API

```cpp
#include <sys/mman.h>

void* mmap(void* addr, size_t length, int prot,
           int flags, int fd, off_t offset);
int munmap(void* addr, size_t length);

// mmap 使用场景：
// - 文件映射：读取大文件（避免 read/write 拷贝）
// - 匿名映射：分配大内存（malloc ≥128KB 的内部实现）
// - 动态链接：加载 .so 库
// - 共享内存：进程间通信（MAP_SHARED）
```

### 4.3 大页内存（HugePages）

```bash
# 查看大页配置
cat /proc/meminfo | grep Huge

# 设置大页数量（2MB 大页）
echo 20 > /proc/sys/vm/nr_hugepages

# 使用大页（程序）
void* p = mmap(NULL, size, PROT_READ|PROT_WRITE,
               MAP_PRIVATE|MAP_ANONYMOUS|MAP_HUGETLB, -1, 0);
```

**优势**：减少 TLB miss、减少页表开销。适合大内存应用（数据库、JVM）。

## 五、RLIMIT_DATA 与资源限制

### 5.1 RLIMIT_DATA

限制 Data + BSS + brk 堆三者总和：

```cpp
#include <sys/resource.h>

struct rlimit lim;
getrlimit(RLIMIT_DATA, &lim);   // 查询
lim.rlim_cur = 2ULL * 1024 * 1024 * 1024;  // 2GB
setrlimit(RLIMIT_DATA, &lim);   // 设置
```

```bash
ulimit -d              # 查看（KB）
ulimit -d 1048576      # 设为 1GB
ulimit -d unlimited    # 无限制
```

### 5.2 栈大小速查

| 平台 | 主线程 | 子线程 |
|------|--------|--------|
| Linux | ~8MB | ~8MB（可 `pthread_attr_setstacksize`） |
| macOS | ~8MB | ~512KB |
| Windows | ~1MB | ~1MB |

### 5.3 关键结论

- **小对象分配器**（如 jemalloc/tcmalloc/SGI 二级分配器）都是**堆上的内存池**，不是栈分配
- BSS 段与堆共享 `RLIMIT_DATA` 上限，BSS 大则堆空间少
- mmap 分配的大内存不受 `RLIMIT_DATA` 限制（受 `RLIMIT_AS` 限制）

## 六、面试高频追问

### Q1: VSZ 很大但 RSS 很小正常吗？
**正常**。常见原因：延迟分配（malloc 只分配虚拟地址）、共享库、内存映射文件、Swap 换出。
**关注 RSS**（物理内存实际占用），不是 VSZ。

### Q2: COW 如何实现？
- fork 后父子进程页表指向同一物理页，标记为只读
- 写入 → MMU 检测到写只读页 → 缺页异常 → 内核复制页 → 各自独立
- 省内存、省时间（只复制页表，不复制物理页）

### Q3: 大页为什么能提升性能？
- 标准 4KB 页，2MB 大页减少 512 倍页表项数
- TLB 覆盖范围变大（TLB 条目数固定），减少 TLB miss
- 适合数据库、JVM、DPDK 等大内存应用

### Q4: mmap 读文件 vs read() 谁快？
- mmap：减少用户态/内核态数据拷贝（缺页时直接映射），但缺页开销不确定
- read()：明确拷贝，延迟更可预测
- **大文件顺序读** → mmap 快；**小文件/随机读** → read() 更稳
