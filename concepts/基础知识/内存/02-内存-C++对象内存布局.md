# C++ 对象内存布局

> 构造函数初始化顺序、虚函数表指针、虚拟继承、内存对齐 —— 理解对象在内存中的真实模样。

---

## 一、构造函数初始化顺序

**核心规则**：初始化顺序由成员在类中的**声明顺序**决定，与初始化列表书写顺序无关。

```cpp
class X {
    int i;     // 先声明
    int j;     // 后声明
public:
    // ⚠️ 危险！初始化列表顺序 ≠ 声明顺序
    // i 先声明，所以先初始化 i(j)，但此时 j 未初始化！
    X(int val) : j(val), i(j) { }
};
```

**完整初始化顺序**：
1. 虚基类构造函数（按继承顺序）
2. 基类构造函数（按继承顺序）
3. 成员变量构造函数（按声明顺序）
4. 派生类构造函数体

**最佳实践**：
- 保持初始化列表顺序与声明顺序一致
- 避免用成员初始化另一个成员（用参数直接初始化）

## 二、虚函数表指针（vptr）

### 2.1 数量规则

| 继承情况 | vptr 数量 | 说明 |
|---------|:---------:|------|
| 无虚函数 | 0 | 没有虚函数表 |
| 单⼀继承 + 虚函数 | 1 | 派生类与基类共享虚表 |
| 普通多继承 + 虚函数 | = 含虚函数的直接基类数 | 每个含虚函数的基类一个 vptr |
| 虚拟继承 | 1+ | 额外引入 vbptr |

**记忆**："有几个有虚函数的爹，就有几个 vptr。"

### 2.2 内存布局

```cpp
class Base {
public:
    virtual void foo() {}
    virtual void bar() {}
    int data;
};

class Derived : public Base {
public:
    void foo() override {}
    virtual void baz() {}
    int extra;
};

// 内存布局（64位）：
// [0]   vptr (→ Base vtable)     8字节
// [8]   Base::data                4字节
// [12]  填充                      4字节
// [16]  Derived::extra            4字节
```

### 2.3 vtable 结构

```
vtable
├── typeinfo                    (RTTI 信息)
├── virtual ~Base()             (析构函数)
├── Base::foo()                 (未被重写)
├── Derived::foo()              (被重写 → 指向派生类版本)
├── Base::bar()                 (未被重写)
├── Derived::baz()              (派生类新增)
└── ...
```

## 三、虚拟继承（vbptr）

### 3.1 为什么要虚拟继承

解决**菱形继承**问题：D 继承自 B 和 C，B 和 C 都继承自 A，A 会被包含两次。

```cpp
class Base { int data; };

class Left : public virtual Base { int left_data; };
class Right : public virtual Base { int right_data; };

class Bottom : public Left, public Right { int bottom_data; };
```

### 3.2 内存布局（典型实现）

```
Bottom 对象内存布局（64位）：
[0]   vbptr (Bottom→Left)      // 指向 Left 的虚基类表
[8]   left_data                 // Left 的成员
[16]  vbptr (Bottom→Right)     // 指向 Right 的虚基类表
[24]  right_data                // Right 的成员
[32]  bottom_data               // Bottom 的成员
[36]  Base::data                // 只有一份！
```

**关键点**：
- `Base` 子对象只存在**一份**
- 通过 `vbptr` 间接访问虚基类成员（额外一次内存访问）
- 每个直接虚拟继承的基类对应一个 `vbptr`

### 3.3 代价

| 开销类型 | 说明 |
|---------|------|
| 内存开销 | 每个 vbptr 8 字节（64位） |
| 访问开销 | 虚基类成员访问需间接寻址 |
| 构造/析构 | 需要正确设置虚基类表 |

## 四、内存对齐

### 4.1 为什么需要对齐

CPU 按字长访问内存（64 位 CPU 一次 8 字节），未对齐访问需要多次内存操作。

### 4.2 对齐规则

```cpp
// 成员对齐到自身大小的整数倍
struct Example {
    char  a;   // 1 字节 → 偏移 0
    int   b;   // 4 字节 → 偏移 4（不是 1！）
    short c;   // 2 字节 → 偏移 8
};
// sizeof(Example) = 12（而不是 7）

// 结构体总大小对齐到最大成员大小的整数倍
```

### 4.3 控制对齐

```cpp
#pragma pack(1)  // 取消对齐（1 字节对齐）
struct Packed {
    char a;
    int  b;      // 偏移 1（不是 4）
};
#pragma pack()   // 恢复默认

// C++11 alignas
struct alignas(64) CacheLine {
    int data;    // 结构体对齐到 64 字节边界
};
```

### 4.4 面试考点

**Q**：为什么结构体大小不等于成员大小之和？
**A**：内存对齐导致填充（padding），目的是让成员满足其自然对齐要求，保证 CPU 一次访问即可读取。

**Q**：`#pragma pack(1)` 有什么问题？
**A**：节省空间但降低访问速度（某些平台甚至不支持未对齐访问）。

## 五、面试高频追问

### Q1: 为什么空类大小是 1 字节？
- C++ 标准要求同一个类的不同对象必须有唯一地址
- 编译器插入 1 字节占位，保证 `sizeof(Empty) = 1`
- EBO（空基类优化）：空基类不占用派生类空间

### Q2: 有虚函数的类 sizeof 是多少？
- 64 位系统：8 字节（vptr）+ 成员变量 + padding
- 单继承：一个 vptr
- 多继承：每层有虚函数的基类各一个 vptr
- **注意**：static 成员不计入 sizeof

### Q3: 为什么构造函数不能是虚函数？
- vptr 在构造函数初始化阶段才被设置
- 调用虚函数时需要通过 vptr 查 vtable
- 构造时 vptr 还未初始化完成 → 无法实现动态绑定

### Q4: 虚拟继承的额外开销？
- 每个虚拟继承的子类增加一个 vbptr（8 字节）
- 访问虚基类成员需要间接寻址（额外一次内存访问）
- 构造函数需要传递虚基类的构造参数
- **结论**：不是所有菱形继承都需要虚继承，明确只出现一次时才用
