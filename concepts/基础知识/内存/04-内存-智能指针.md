# 智能指针

> unique_ptr、shared_ptr、weak_ptr 三剑客：所有权语义、控制块、make_shared 原理、循环引用。

---

## 一、三剑客对比

| 特性 | unique_ptr | shared_ptr | weak_ptr |
|------|-----------|-----------|----------|
| 所有权 | 独占 | 共享 | 无所有权（观察者） |
| 拷贝 | 禁止（只能 move） | 可拷贝（引用计数+1） | 可拷贝 |
| 引用计数 | 无 | use_count（强引用） | weak_count（弱引用） |
| 开销 | 零（同裸指针） | 控制块（~24字节） | 控制块（共享） |
| 删除器 | 类型的一部分 | 类型擦除（可运行时指定） | — |

**选择原则**：优先 `unique_ptr` → 需共享用 `shared_ptr` → 避免循环引用用 `weak_ptr`。

---

## 二、unique_ptr

### 2.1 基本使用

```cpp
auto p = std::make_unique<int>(42);
// auto p2 = p;                 // ❌ 禁止拷贝
auto p2 = std::move(p);         // ✅ 移动转移所有权

// 数组特化
auto arr = std::make_unique<int[]>(10);
```

### 2.2 自定义删除器

```cpp
auto fileDeleter = [](FILE* fp) { if (fp) fclose(fp); };
std::unique_ptr<FILE, decltype(fileDeleter)> fp(fopen("a.txt", "r"), fileDeleter);

// 删除器是 unique_ptr 类型的一部分
```

### 2.3 优势

- **零开销抽象**：同裸指针大小和性能
- **异常安全**：作用域退出自动释放
- **语义清晰**：明确表达独占所有权

## 三、shared_ptr

### 3.1 控制块结构

```cpp
// 控制块（Control Block）
struct ControlBlock {
    std::atomic<long> use_count_;     // 强引用计数
    std::atomic<long> weak_count_;    // 弱引用计数
    void* ptr_;                       // 指向被管理对象
    Deleter deleter_;                 // 删除器（类型擦除）
};
```

### 3.2 make_shared vs shared_ptr(new T)

| 对比 | make_shared | shared_ptr(new T) |
|------|------------|------------------|
| 内存分配 | **1 次**（控制块+对象一起） | **2 次**（控制块和对象分开） |
| 异常安全 | ✅ 原子操作 | ✅ 也安全但效率较低 |
| 内存释放 | 控制块和对象同时释放 | 可分开释放 |
| weak_ptr 延迟 | **延迟释放对象内存** | 对象先释放 |

```cpp
// 推荐写法
auto sp = std::make_shared<int>(42);

// 不推荐：两次分配
std::shared_ptr<int> sp(new int(42));
```

**make_shared 的内存布局**：
```
一次分配:
┌──────────────────────────────┐
│  控制块 (use_count/weak_count) │
│  对象  (T)                    │
└──────────────────────────────┘
```

### 3.3 线程安全

```cpp
// shared_ptr 的线程安全：
// ✅ 引用计数的增减是原子操作，线程安全
// ❌ 对象本身的读写需要外部同步

// 线程安全使用：
std::shared_ptr<int> sp = std::make_shared<int>(42);
// 多个线程同时拷贝 shared_ptr 是安全的
// 但通过 sp 访问修改对象需要加锁
```

### 3.4 循环引用

```cpp
struct Node {
    std::shared_ptr<Node> next;  // ❌ 循环引用！
    // std::weak_ptr<Node> next;  // ✅ 用 weak_ptr 打破
    ~Node() { /* ... */ }
};

// a → b, b → a 形成循环，引用计数永不归零
auto a = std::make_shared<Node>();
auto b = std::make_shared<Node>();
a->next = b;
b->next = a;  // 内存泄漏！
```

## 四、weak_ptr

### 4.1 作用

- **打破循环引用**：观察但不影响生命周期
- **安全检测**：`lock()` 返回空表示对象已销毁

```cpp
std::weak_ptr<int> wp;

{
    auto sp = std::make_shared<int>(42);
    wp = sp;
    // use_count = 1, weak_count = 1
}

// sp 离开作用域，对象销毁
auto locked = wp.lock();  // 返回空 shared_ptr
if (!locked) {
    // 对象已销毁
}
```

### 4.2 lock() 原理

```cpp
// weak_ptr::lock() 的内部实现（简化）
shared_ptr<T> lock() const noexcept {
    if (control_block_ && control_block_->try_increment_use_count()) {
        return shared_ptr<T>(control_block_);  // 成功获得 shared_ptr
    }
    return shared_ptr<T>();  // 对象已销毁
}
```

**何时返回空指针**：
1. weak_ptr 默认构造（从未关联对象）
2. 观察的对象已被销毁
3. weak_ptr 被 reset

## 五、自定义删除器与 enable_shared_from_this

### 5.1 自定义删除器

```cpp
// shared_ptr 删除器通过类型擦除支持运行时指定
std::shared_ptr<FILE> fp(fopen("a.txt", "r"), fclose);

// lambda 删除器
std::shared_ptr<int> sp(new int[10], [](int* p) { delete[] p; });
```

### 5.2 enable_shared_from_this

当对象需要获取指向自己的 `shared_ptr` 时必须使用此机制：

```cpp
class Widget : public std::enable_shared_from_this<Widget> {
public:
    void register() {
        // ✅ 正确：使用 shared_from_this()
        registry.register(shared_from_this());
        
        // ❌ 错误：会创建新控制块，导致未定义行为
        // registry.register(std::shared_ptr<Widget>(this));
    }
};

auto w = std::make_shared<Widget>();  // 必须用 shared_ptr 管理
w->register();
```

**要求**：
1. 继承 `enable_shared_from_this<T>`
2. 对象必须由 `shared_ptr` 管理
3. 不能在构造函数中调⽤ `shared_from_this()`

## 六、常见陷阱

| 陷阱 | 说明 | 解决 |
|------|------|------|
| 裸指针构造多个 shared_ptr | 同一对象两个控制块 | 用 `make_shared` |
| 返回原始指针 | 悬空指针风险 | 返回 `shared_ptr` |
| 循环引用 | 引用计数永不归零 | 改用 `weak_ptr` |
| this 构造 shared_ptr | 多个控制块 | 继承 `enable_shared_from_this` |
| 混用 make_shared 和 new | 同一对象不同路径 | 统一使用一种方式 |

## 七、面试高频追问

### Q1: unique_ptr 为什么没有拷贝？移动后原指针状态？
- **禁止拷贝**：unique_ptr 代表独占所有权，拷贝语义违背独占性
- **移动后**：原指针置空（`nullptr`），新的 unique_ptr 获得所有权
- 可通过 `release()` 释放所有权返回裸指针

### Q2: shared_ptr 线程安全具体指什么？
- ✅ 引用计数增减是原子的，多线程同时拷贝/析构 shared_ptr 安全
- ✅ `weak_ptr::lock()` 原子操作
- ❌ **对象本身的读写**不是线程安全的，需要外部加锁
- ❌ 同一个 shared_ptr 被多个线程同时修改（指向不同对象）不安全

### Q3: make_shared 的潜在问题？
- **优点**：一次分配（控制块+对象），性能好
- **缺点**：对象和控制块在同一内存块，即使所有 shared_ptr 释放，只要还有 weak_ptr 引用，对象内存不释放
- 大对象 + long-lived weak_ptr → 避免用 make_shared

### Q4: enable_shared_from_this 为什么要用 weak_ptr 实现？
- 内部 `weak_ptr` 在 `shared_ptr` 构造时设置
- `shared_from_this()` 从 `weak_ptr::lock()` 获取 shared_ptr
- 避免从裸指针 `this` 重复创建控制块（会导致 double free 或 undefined behavior）

### Q5: weak_ptr::lock() 返回空指针的时机？
1. 观察的对象已被销毁
2. weak_ptr 默认构造（从未关联对象）
3. weak_ptr 被 reset
4. 对象由 `make_shared` 管理且所有 shared_ptr 已释放（控制块仍在，但对象已析构）
