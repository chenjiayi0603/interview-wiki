# 内存分配器与内存池

> malloc 内部结构、内存池/对象池、STL 分配器、tcmalloc/jemalloc、垃圾回收。

---

## 一、malloc 内部结构

### 1.1 glibc ptmalloc 分配器层次

```
Application
    ↓
malloc/free API
    ↓
┌─────────────────────────────┐
│ Tcache (Per-thread cache)   │ ← 线程本地，无锁，快速
├─────────────────────────────┤
│ Arena (主 arena + 非主)      │ ← 64 位系统最多 64 个 arena
├─────────────────────────────┤
│    fastbin (小对象，≤64B)    │ ← LIFO，不合并
│    smallbin (≤512B)          │ ← 双向链表
│    unsorted bin              │ ← 回收待分类
│    large bin (>512B)         │ ← 按大小排序
│    top chunk                 │ ← 堆顶剩余空间
└─────────────────────────────┘
    ↓
brk (<128KB) / mmap (≥128KB)
```

### 1.2 分配策略

| 大小 | 策略 | 说明 |
|------|------|------|
| ≤ 64B | fastbin | 不合并相邻空闲块，LIFO |
| ≤ 512B | smallbin | 双向链表，精确匹配 |
| ≤ 128KB | unsorted/large bin | 分类管理 |
| ≥ 128KB | mmap 匿名映射 | 直接调⽤ mmap，释放时 munmap |

### 1.3 关键特性

- **tcache**（glibc 2.26+）：每个线程一个缓存，无锁分配，大幅提升多线程性能
- **Arena**：64 位系统最多 64 个 arena，减少线程竞争
- **合并**：释放时尝试合并相邻空闲块，减少外部碎片
- **mmap 阈值**：默认 128KB，可通过 `mallopt(M_MMAP_THRESHOLD)` 调整

## 二、内存池

### 2.1 为什么需要内存池

- **减少 malloc 调用**：系统调⽤开销大
- **减少内存碎片**：固定大小块分配
- **提高分配速度**：O(1) 分配/释放
- **提高缓存命中率**：内存连续

### 2.2 简单内存池实现

```cpp
class MemoryPool {
    struct Block {
        Block* next;
        char data[0];       // 柔性数组
    };
    Block* freeList;
    size_t blockSize;

public:
    MemoryPool(size_t blockSize) : blockSize(blockSize), freeList(nullptr) {}

    void* allocate() {
        if (!freeList) {
            // 一次申请一大块，切分成多个 block
            size_t chunkSize = blockSize * 64;
            char* chunk = new char[chunkSize];
            for (size_t i = 0; i < 64; ++i) {
                Block* b = reinterpret_cast<Block*>(chunk + i * blockSize);
                b->next = freeList;
                freeList = b;
            }
        }
        Block* p = freeList;
        freeList = freeList->next;
        return p;
    }

    void deallocate(void* p) {
        Block* b = reinterpret_cast<Block*>(p);
        b->next = freeList;
        freeList = b;
    }
};
```

### 2.3 对象池（线程安全）

```cpp
template<typename T>
class ObjectPool {
    std::queue<T*> pool;
    std::mutex mtx;

public:
    std::shared_ptr<T> acquire() {
        std::lock_guard<std::mutex> lock(mtx);
        if (!pool.empty()) {
            auto p = pool.front(); pool.pop();
            return std::shared_ptr<T>(p, [this](T* obj) {
                std::lock_guard<std::mutex> l(mtx);
                pool.push(obj);
            });
        }
        return std::make_shared<T>();
    }
};
```

## 三、STL 分配器

### 3.1 std::allocator

默认分配器，内部调⽤ `new/delete`：

```cpp
std::vector<int, std::allocator<int>> v;  // 默认

// 自定义分配器接口
template<typename T>
struct MyAllocator {
    using value_type = T;
    T* allocate(size_t n) { return static_cast<T*>(::operator new(n * sizeof(T))); }
    void deallocate(T* p, size_t) { ::operator delete(p); }
    // 还需要 rebind、construct、destroy 等
};
```

### 3.2 分配器适配

```cpp
// scoped_allocator_adaptor：支持 propagate_on_container_copy/move/swap
// polymorphic_allocator（C++17）：运行时多态分配器

// 使用 pmr 分配器
#include <memory_resource>
std::pmr::vector<int> v;  // 使用默认的 new_delete_resource
```

## 四、tcmalloc / jemalloc

### 4.1 对比 ptmalloc

| 特性 | ptmalloc (glibc) | tcmalloc (Google) | jemalloc (Facebook) |
|------|:----------------:|:------------------:|:-------------------:|
| 线程缓存 | tcache | ThreadCache | tcache |
| 多线程扩展 | arena | 按大小分类 | arena + 按大小分类 |
| 内存碎片 | 一般 | 好 | 好 |
| 大页支持 | 无 | 无 | 支持（2MB/1GB） |
| 适用 | 通用 | 多线程、高性能 | 多线程、大内存 |

### 4.2 核心思想

- **线程本地缓存**：每个线程有独立的小对象缓存，无锁分配
- **大小分类**：按 8/16/32/... 字节分桶，减少内部碎片
- **垃圾回收**：线程缓存过多时归还到中心缓存

## 五、垃圾回收（GC）

### 5.1 引用计数

```cpp
class RefCounted {
    std::atomic<int> ref_count{1};
public:
    void addRef() { ref_count.fetch_add(1); }
    void release() {
        if (ref_count.fetch_sub(1) == 1) delete this;
    }
};
```

**优点**：实时回收、无暂停 | **缺点**：循环引用、计数开销

### 5.2 标记-清除（Mark-Sweep）

```
1. Stop The World
2. 根对象标记（全局变量、栈）
3. 递归标记可达对象
4. 清除未标记对象
5. 恢复执行
```

### 5.3 三色标记（Go GC）

```
白色：未扫描
灰色：已发现但未处理
黑色：已处理完成

并发标记：初始快照 → 扫描灰色 → 写屏障 → 最终标记 → 清理
```

### 5.4 分代收集

| 代 | 区域 | 频率 | 算法 |
|----|------|:----:|------|
| 年轻代 | Eden + S0 + S1 | Minor GC（高频率） | 复制算法 |
| 老年代 | Old | Major GC（低频率） | 标记-清除/整理 |

## 六、面试高频追问

### Q1: glibc malloc 为什么要有 tcache？
- tcache（glibc 2.26+）是每线程缓存，无锁分配
- 大幅减少多线程下的锁竞争（减少 80%+ 的锁操作）
- 小对象分配直接从 tcache 取，不进入 arena
- **代价**：每个线程多占用一些内存（可配置）

### Q2: 内存池和对象池的区别？
| 对比 | 内存池 | 对象池 |
|:----:|:------:|:------:|
| 管理对象 | 原始内存块 | 类型化对象 |
| 分配粒度 | 字节 | 对象实例 |
| 构造/析构 | 不调用 | 调用（placement new / 手动析构） |
| 典型应用 | pmr::monotonic_buffer_resource | ObjectPool\<T\> |

### Q3: jemalloc/tcmalloc 相比 glibc 好在哪里？
- **线程本地缓存**：减少锁竞争，多线程分配快 2-10 倍
- **大小分类**：减少内部碎片（8/16/32/... 分桶）
- **大页支持**：jemalloc 支持 2MB 大页
- **可观测性**：自带 heap profile、内存统计

### Q4: C++17 PMR 和传统 allocator 有何不同？
- 传统 allocator：类型绑定（`vector<T, Alloc<T>>`），编译时确定
- PMR：运行时多态（`vector<T, polymorphic_allocator<T>>`），可切换 memory_resource
- PMR 支持 nesting：可在单调资源上分配，然后统一释放
