# 内存调试与性能优化

> 内存泄漏检测、Valgrind/ASan 使用、缓冲区溢出、零拷贝、OOM 处理。

## 一、内存问题类型

### 1.1 堆内存泄漏

```cpp
void leak() {
    int* p = new int[100];
    // 忘记 delete[] p
}
```

**后果**：进程长期运行内存持续增长，最终 OOM。

### 1.2 缓冲区溢出

```cpp
// ❌ 危险
void unsafe(char* input) {
    char buf[64];
    strcpy(buf, input);  // 输入 > 64 字节则溢出
}

// ✅ 安全
void safe(const char* input) {
    char buf[64];
    strncpy(buf, input, sizeof(buf) - 1);
    buf[sizeof(buf) - 1] = '\0';
}
```

### 1.3 悬空指针

```cpp
int* dangling() {
    int x = 10;
    return &x;  // x 是局部变量，函数结束销毁
}

// 正确做法
void correct() {
    int* p = new int(10);
    delete p;
    p = nullptr;  // 置空避免悬空
}
```

### 1.4 重复释放 / Use-After-Free

```cpp
int* p = new int(42);
delete p;
// delete p;   // ❌ 重复释放：未定义行为
*p = 10;       // ❌ Use-After-Free
```

## 二、泄漏检测工具

### 2.1 Valgrind（Linux）

```bash
# 基本使用
valgrind --leak-check=full ./program

# 生成泄漏报告
valgrind --leak-check=full --show-leak-kinds=all --log-file=val.log ./program
```

| 泄漏类型 | 含义 |
|---------|------|
| **definitely lost** | 确定泄漏（无指针指向） |
| **indirectly lost** | 间接泄漏（结构体内指针丢失） |
| **possibly lost** | 可能泄漏（指针指向块内部） |
| **still reachable** | 进程退出时仍有指针指向（不算泄漏） |

**能检测的问题**：
- ✅ 内存泄漏
- ✅ Use-After-Free
- ✅ 缓冲区溢出
- ✅ 使用未初始化内存
- ✅ 重复释放

**缺点**：运行速度慢（慢 10-20 倍）、内存占用大。

### 2.2 AddressSanitizer（ASan，编译器内置）

```bash
# GCC/Clang 编译时开启
g++ -fsanitize=address -g -o program program.cpp
./program
```

**优点**：
- 速度快（仅慢 2-3 倍）
- 检测精确
- 集成在编译器中
- 支持 Linux/Windows/macOS

**检测能力**同 Valgrind，外加：
- 栈缓冲区溢出（局部变量溢出）
- 全局缓冲区溢出

### 2.3 Windows CRT Debug

```cpp
#define _CRTDBG_MAP_ALLOC
#include <crtdbg.h>

// 程序退出时输出泄漏报告
_CrtSetDbgFlag(_CRTDBG_ALLOC_MEM_DF | _CRTDBG_LEAK_CHECK_DF);
```

## 三、零拷贝技术

减少数据在内核态和用户态之间的拷贝次数：

```cpp
// sendfile：文件 → socket（无需经过用户空间）
#include <sys/sendfile.h>
sendfile(out_fd, in_fd, NULL, count);

// mmap：文件映射到进程地址空间
void* buf = mmap(NULL, len, PROT_READ, MAP_PRIVATE, fd, offset);
// 直接访问 buf，无需 read()

// scatter/gather I/O
struct iovec iov[2];
iov[0].iov_base = buf1;  iov[0].iov_len = len1;
iov[1].iov_base = buf2;  iov[1].iov_len = len2;
writev(fd, iov, 2);  // 一次系统调用写入多个缓冲区
```

## 四、OOM 与内存监控

### 4.1 OOM Killer

Linux 在内存不足时调⽤ OOM Killer 选择进程杀掉。选择依据：
- **oom_score**：根据内存使⽤量、运行时间、进程优先级计算
- **oom_adj**：手动调整（-1000 禁用 OOM kill，17 优先被杀）

```bash
# 查看进程的 oom_score
cat /proc/<pid>/oom_score

# 调整 oom_adj
echo -10 > /proc/<pid>/oom_adj
```

### 4.2 内存监控

```bash
# 进程内存
cat /proc/<pid>/status    # VmRSS, VmSize, VmPeak
cat /proc/<pid>/smaps     # 每块映射的详细信息

# 系统内存
free -h                   # 物理内存 + swap
cat /proc/meminfo         # 详细内存信息

# 监控工具
top -p <pid>              # 实时内存
htop                      # 交互式
```

### 4.3 高并发内存优化建议

1. **内存池 + 对象池**：减少 malloc 次数，降低锁竞争
2. **控制最大连接数**：避免无限增长
3. **设置内存上限**：`RLIMIT_AS`、`RLIMIT_DATA`
4. **监控内存趋势**：通过 `/proc/self/status` 定期采样
5. **熔断降级**：内存超过阈值时主动降级服务

## 五、面试高频追问

### Q1: Valgrind 和 ASan 哪个更好？
- **Valgrind**：更全面（检测范围广），但慢 10-50 倍，适合开发/CI 环境
- **ASan**：快（仅慢 2-3 倍），编译器内置，检测精确，适合日常开发和回归测试
- **结论**：开发用 ASan（快），CI 两者都跑

### Q2: Use-After-Free 为什么难以排查？
- 释放后内存可能被重新分配，写入时不会立即崩溃
- 只有当后续读取被篡改的数据时才会出现诡异行为
- ASan/Valgrind 会填充特殊字节并标记状态，访问时立即检测

### Q3: 生产环境如何检测内存泄漏？
- tcmalloc heap profile：`HEAPPROFILE=./hprof ./program`，定期 dump
- jemalloc profiler：`MALLOC_CONF=prof:true,lg_prof_interval:30`
- 监控 `/proc/self/status` 的 VmRSS 持续性增长
- 配合 CI 定期跑 ASan 检测

### Q4: 高并发服务的内存监控最佳实践？
- 定时（如 1min）记录 RSS/VSZ 到监控系统（Prometheus + Grafana）
- 设置告警阈值（RSS 超过基线 20% 持续 5 分钟）
- 核心对象池使用情况上报（命中率、分配次数）
- 热点数据的 RCU/引用计数监控

### 4.4 分布式/服务网格场景

- **消息内存池**：减少消息处理时的 malloc 次数
- **零拷贝消息传递**：避免大消息的多重拷⻉
- **连接池大小控制**：限制最大并发连接数
- **LRU 缓存限制**：设置内存上限，及时淘汰
