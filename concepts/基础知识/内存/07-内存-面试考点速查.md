# 面试考点速查

> 高频面试 Q&A、易错点总结、项目深挖问题。

---

## 一、高频面试 Q&A

### Q1: 栈和堆的区别？

| 特性 | 栈 | 堆 |
|------|----|----|
| 管理方式 | 编译器自动 | 程序员手动 |
| 速度 | 快（寄存器操作） | 慢（系统调用） |
| 大小 | 固定（Linux ~8MB） | 灵活（可到 GB 级） |
| 内存布局 | 连续，LIFO | 离散，易碎片 |
| 增长方向 | 向下（高→低地址） | 向上（低→高地址） |
| 线程 | 每个线程独立 | 进程内线程共享 |
| 主要问题 | 栈溢出 | 内存泄漏、碎片 |

---

### Q2: malloc 实现原理？

**参考答案**：
- **<128KB**：从堆（brk）分配，通过 ptmalloc 管理空闲块
- **≥128KB**：通过 mmap 匿名映射分配
- **内部层次**：tcache（线程缓存）→ fastbin → smallbin → unsorted/large bin → top chunk
- **释放**：相邻空闲块尝试合并，减少外部碎片
- **性能**：tcache 无锁分配，大幅提升多线程性能

---

### Q3: 什么是内存对齐？为什么需要？

**参考答案**：
- CPU 按字长访问内存（64 位 8 字节），对齐可单次完成访问
- 未对齐访问需要多次内存操作，甚至崩溃（某些架构）
- 结构体对齐规则：每个成员对齐到自身大小的整数倍，结构体总大小对齐到最大成员大小的整数倍
- 控制方式：`#pragma pack(1)`、`alignas(8)`
- 填充（padding）虽然浪费空间，但提升访问效率

---

### Q4: 什么是 TLB？如何提高命中率？

**参考答案**：
- TLB（Translation Lookaside Buffer）：CPU 内部缓存，缓存虚拟页→物理页映射
- 命中率通常 >95%，未命中需查多级页表（PGD→PUD→PMD→PTE），延迟大幅增加
- ASID 区分进程，避免上下文切换时刷 TLB
- 提高命中率：
  - 利⽤数据局部性
  - 使用大页（HugePages）：2MB/1GB 页减少页表项
  - 避免大量随机访问⼤内存映射

---

### Q5: new/delete 和 malloc/free 的区别？

| 对比 | new/delete | malloc/free |
|------|-----------|-------------|
| 语言 | C++ 操作符 | C 标准库函数 |
| 构造/析构 | ✅ 调⽤ | ❌ 不调⽤ |
| 返回类型 | 类型安全 | `void*` |
| 失败行为 | 抛 `bad_alloc` / nothrow 返 nullptr | 返回 nullptr |
| 能否重载 | ✅ 全局/类特定 | ⚠️ 通过钩子 |
| 大小推算 | 编译器 | 手动指定 |

---

### Q6: make_shared 和 shared_ptr(new T) 的区别？

**参考答案**：
- **make_shared**：**1 次**内存分配（控制块 + 对象一起），性能更好
- **shared_ptr(new T)**：**2 次**内存分配（控制块和对象分开）
- make_shared 的代价：即使外部 `shared_ptr` 全释放，只要还有 `weak_ptr` 引用，对象内存不会释放（控制块和对象在同一块内存上）
- 推荐默认使⽤ `make_shared`

---

### Q7: shared_ptr 的线程安全？

**参考答案**：
- ✅ 引用计数的增减是原子操作，多个线程同时拷贝/析构 `shared_ptr` 安全
- ❌ 对象本身的读写不是线程安全的，需要外部加锁
- ✅ `weak_ptr::lock()` 是原子操作，线程安全
- **结论**：引用计数操作安全，对象访问不安全

---

### Q8: 什么是循环引用？如何解决？

**参考答案**：
- 两个或多个对象相互持有 `shared_ptr`，导致引用计数永不归零
- 解决：用 `weak_ptr` 打破循环（`weak_ptr` 不增加引用计数）
- 适用于：观察者模式、树/图结构中的父→子引用

```cpp
struct Node {
    std::weak_ptr<Node> next;  // weak_ptr 打破循环
};
```

---

### Q9: new_handler 的作用和实现要点？

**参考答案**：
- `operator new` 分配失败时，在抛出 `bad_alloc` 前调用的用户自定义函数
- handler 必须：释放内存 或 抛异常 或 终结程序
- ❌ 什么都不做 → 无限循环
- ✅ 应限制重试次数
- C++11 起每个线程可设置独立的 handler

---

### Q10: VSZ 和 RSS 的区别？

**参考答案**：
- **VSZ**（Virtual Memory Size）：进程虚拟地址空间总量（承诺的内存），通常很大
- **RSS**（Resident Set Size）：实际驻留在物理内存中的部分
- **VSZ >> RSS 的原因**：延迟分配、共享库、内存映射文件延迟加载、Swap 换出
- 查看：`ps aux`、`cat /proc/<pid>/status`

---

### Q11: 什么是写时复制（Copy-On-Write）？

**参考答案**：
- fork 后父子进程共享物理内存页（标记为只读）
- 只有一方写入时触发缺页异常，内核复制该页
- 减少 fork 开销（只需拷贝页表）
- 适用于：fork + exec 场景

---

### Q12: 内存分配器的设计原则？

**参考答案**：
1. **最大化命中率**：利⽤数据局部性
2. **减少碎片**：内部碎片（大小分类）和外部碎片（合并）
3. **提高并发**：线程本地缓存（tcache/tcache）、多 arena
4. **高效回收**：快速合并空闲块，批量归还

## 二、易错点总结

| 编号 | 易错点 | 说明 |
|:----:|--------|------|
| 1 | `new[]` + `delete`（非 `delete[]`） | 只析构第一个元素，导致泄漏 |
| 2 | placement new 用了 `delete` | 应手动调析构，不能用 delete |
| 3 | 基类析构不是 `virtual` | 多态删除只调基类析构，派生类资源泄漏 |
| 4 | `shared_ptr` 循环引用 | 改用 `weak_ptr` |
| 5 | `this` 构造 `shared_ptr` | 继承 `enable_shared_from_this` |
| 6 | 构造中调 `shared_from_this()` | 此时 weak_ptr 还未设置 |
| 7 | 混用 `make_shared` 和 `shared_ptr(new T)` | 统一使用一种 |
| 8 | const static 局部变量的赋值时机误判 | 编译期常量在 `.rodata`，运行期常量首次进入时初始化 |

## 三、项目深挖问题

### Q1: 高并发 IM 如何优化内存？

- 消息内存池：复用消息对象，减少 malloc
- 连接池：限制最大并发连接数
- LRU 缓存：设置内存上限
- mmap ⽇志：大日志文件使用 mmap 写入

### Q2: 服务网格（Envoy）内存优化？

- Wasm 插件内存隔离
- 连接池大小控制
- 流量缓冲限制

### Q3: 如何监控进程内存泄漏？

- 定时读取 `/proc/self/status` 的 `VmRSS`
- 结合 CI 集成 Valgrind/ASan
- 生产环境用 tcmalloc/jemalloc 自带的内存分析工具
- **top -p / htop** 实时观察

### Q4: OOM 如何排查？

1. `dmesg | grep -i oom`：查看 OOM killer 日志
2. `cat /proc/<pid>/oom_score`：查看 OOM 评分
3. `free -h`：检查系统内存使用
4. `top` 按内存排序：`M` 键
5. 用 Valgrind/ASan 检测泄漏
