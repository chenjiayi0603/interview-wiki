# 内存优化

## 一、分配策略优化

### 1.1 栈分配 vs 堆分配

| 类型 | 速度 | 生命周期 | 大小限制 |
|------|------|----------|----------|
| 栈分配 | 纳秒级（单指令） | 作用域结束自动释放 | ~MB 级（取决于 ulimit） |
| 堆分配 | 微秒级（系统调用） | 手动控制 | 受限于物理内存 |

```cpp
// 小对象优先使用栈分配
// 优化前：堆分配
void process() {
    auto buf = std::make_unique<char[]>(1024);
    // ...
}

// 优化后：栈分配
void process() {
    char buf[1024];
    // ...
}

// 栈分配也适用于固定大小的容器
// 优化前
std::vector<int> ids = {1, 2, 3, 4, 5};

// 优化后：std::array 或 C 数组（大小固定时）
std::array<int, 5> ids = {1, 2, 3, 4, 5};
```

### 1.2 对象池

```cpp
template<typename T>
class ObjectPool {
    static_assert(sizeof(T) >= sizeof(void*), "T too small");
    
    union Node {
        T data;
        Node* next;
    };
    
    std::vector<Node*> blocks;
    Node* free_head = nullptr;
    
public:
    template<typename... Args>
    T* acquire(Args&&... args) {
        Node* n;
        if (free_head) {
            n = free_head;
            free_head = free_head->next;
        } else {
            // 批量分配新块
            constexpr size_t BLOCK_SIZE = 4096 / sizeof(Node);
            auto* block = new Node[BLOCK_SIZE];
            blocks.push_back(block);
            // 构建空闲链表
            for (size_t i = 1; i < BLOCK_SIZE; ++i) {
                block[i-1].next = &block[i];
            }
            block[BLOCK_SIZE-1].next = nullptr;
            free_head = &block[1];
            n = &block[0];
        }
        new (&n->data) T(std::forward<Args>(args)...);
        return &n->data;
    }
    
    void release(T* ptr) {
        Node* n = reinterpret_cast<Node*>(ptr);
        n->data.~T();
        n->next = free_head;
        free_head = n;
    }
    
    ~ObjectPool() {
        for (auto* block : blocks) {
            delete[] block;
        }
    }
};
```

### 1.3 内存池（连续大块分配）

```cpp
#include <pmr/memory_resource>

// 使用 monotonic_buffer_resource（快速分配，一次性释放）
char buffer[1024 * 1024];  // 1MB 预分配
std::pmr::monotonic_buffer_resource pool(buffer, sizeof(buffer));

std::pmr::vector<int> vec(&pool);  // 使用内存池分配
// 分配极快（指针移动），`pool` 析构时自动释放

// 适合大量短生命周期对象、HFT 场景
```

### 1.4 小对象分配优化（SBO/SOO）

```cpp
// std::string 的小字符串优化（SSO）
// 小字符串（通常 <= 15 或 22 字节）直接存储在栈上，不堆分配
std::string s1 = "hi";            // 栈分配（SSO）
std::string s2 = "very long...";  // 超出 SSO 阈值时堆分配

// std::function 的小函数优化
std::function<void()> f = [](){};  // 小函数对象栈存储

// 自定义 SmallVector
template<typename T, size_t N = 8>
class SmallVector {
    T inline_storage[N];  // 小情况用栈
    T* data_ = inline_storage;
    size_t size_ = 0;
    size_t capacity_ = N;
    
    // 超出 N 时切换到堆
};
```

### 1.5 string_view 避免拷贝

```cpp
// 优化前：拷贝字符串
void process(const std::string& key) {
    auto it = map.find(key);  // 隐式转换可能分配
}

// 优化后：string_view（零拷贝）
void process(std::string_view key) {
    auto it = map.find(key);
}

// 但注意：string_view 不拥有数据，需确保原字符串生命周期
```

## 二、内存布局优化

### 2.1 结构体重排（减少 padding）

```cpp
// 优化前：低效的内存布局
struct BadLayout {
    bool flag;      // 1 byte
    // 7 bytes padding
    double value;   // 8 bytes
    int id;         // 4 bytes
    // 4 bytes padding
    short count;    // 2 bytes
    // 2 bytes padding
};  // total: 32 bytes

// 优化后：按大小降序排列
struct GoodLayout {
    double value;   // 8 bytes
    int id;         // 4 bytes
    short count;    // 2 bytes
    bool flag;      // 1 byte
    // 1 byte padding
};  // total: 16 bytes（节省 50%）

// 使用 pragma pack 谨慎控制
#pragma pack(push, 1)
struct PackedStruct {
    bool flag;
    double value;
    int id;
};  // 不对齐，访问可能变慢
#pragma pack(pop)
```

## 三、智能指针与容器优化

### 3.1 智能指针选择

| 智能指针 | 大小 | 开销 | 适用场景 |
|----------|------|------|----------|
| `std::unique_ptr` | 8 bytes | 极低 | 独占所有权 |
| `std::shared_ptr` | 16 bytes | 较高（控制块、原子计数） | 共享所有权 |
| `std::weak_ptr` | 16 bytes | 中等 | 观察者、打破循环引用 |

```cpp
// shared_ptr 开销注意事项
std::shared_ptr<int> sp1 = std::make_shared<int>(42);
// make_shared 一次分配（数据和引用计数在同一块），效率更高

std::shared_ptr<int> sp2(new int(42));
// 两次分配（数据和引用计数分开），效率较低

// 避免不必要的 shared_ptr 拷贝（原子操作）
void process(const std::shared_ptr<int>& sp) {  // 传引用，避免计数增减
    // ...
}
```

### 3.2 容器选择

| 场景 | 推荐容器 | 原因 |
|------|----------|------|
| 尾部插入/随机访问 | `std::vector` | 连续内存，缓存友好 |
| 头部/中间插入 | `std::deque` | 分块连续，比 list 好 |
| 小集合查找 | `std::vector`（线性） | 缓存优于 hash |
| 大集合查找 | `std::unordered_map` | O(1) 平均 |
| 有序查找 | `std::map`（红黑树） | O(log n) |
| 频繁迭代 | `plf::colony` | 删除不失效迭代器 |

### 3.3 vector 预分配

```cpp
// 优化前：频繁扩容导致多次拷贝
std::vector<int> v;
for (int i = 0; i < 10000; ++i) {
    v.push_back(i);  // 可能多次 reallocation
}

// 优化后：预分配
std::vector<int> v;
v.reserve(10000);  // 一次分配
for (int i = 0; i < 10000; ++i) {
    v.push_back(i);  // 无需扩容
}
```

## 四、自定义分配器

### 4.1 何时需要自定义分配器

- 热点路径频繁分配/释放
- 需要 NUMA 感知分配
- 固定大小对象的大量分配
- 需要堆外内存管理

### 4.2 PMR（Polymorphic Memory Resource, C++17+）

```cpp
#include <memory_resource>
#include <vector>

// 1. 同步无锁的 monotonic_buffer_resource（推荐）
std::array<char, 4096> buffer;
std::pmr::monotonic_buffer_resource pool(buffer.data(), buffer.size(),
    std::pmr::null_memory_resource());

std::pmr::vector<int> vec(&pool);
// 分配就是指针递增，一次释放全部

// 2. 线程安全池
std::pmr::synchronized_pool_resource pool;
std::pmr::vector<int> vec(&pool);
```

### 4.3 tcmalloc / jemalloc 替代

```bash
# 无需改代码，LD_PRELOAD 替换分配器
LD_PRELOAD=/usr/lib/x86_64-linux-gnu/libtcmalloc_minimal.so.4 ./program

# tcmalloc 优势
# - 减少多线程锁争用
# - 线程本地缓存
# - 减少内存碎片

# jemalloc 优势
# - 更少的内存碎片
# - 支持 NUMA 感知
# - 更好的可扩展性
```

## 五、内存锁定（mlock）

### 5.1 为什么需要锁定内存？

- **防止被 swap**：实时/低延迟进程不能有页面错误
- **保障确定性**：内存访问延迟稳定

```cpp
#include <sys/mman.h>

// 锁定所有当前和未来内存页面
void lock_all_memory() {
    if (mlockall(MCL_CURRENT | MCL_FUTURE) != 0) {
        perror("mlockall failed");
    }
}

// 锁定特定内存区域
void lock_region(void* addr, size_t len) {
    if (mlock(addr, len) != 0) {
        perror("mlock failed");
    }
}

// 解锁
munlockall();
munlock(addr, len);
```

### 5.2 资源限制

```bash
# 查看 mlock 资源限制
ulimit -l

# 设置无限制（需 root 或配置 /etc/security/limits.conf）
ulimit -l unlimited

# /etc/security/limits.conf 配置
user soft memlock unlimited
user hard memlock unlimited
```

## 六、内存碎片治理

### 6.1 外碎片 vs 内碎片

- **外碎片**：频繁大小不同分配导致空闲区无法利用 → 使用对象池/区域分配器
- **内碎片**：分配粒度不对齐导致浪费 → 使用 jemalloc/tcmalloc

### 6.2 碎片监控

```bash
# /proc 查看进程内存布局
cat /proc/<pid>/maps

# pmap 查看内存映射
pmap -x <pid>

# smem 查看 RSS 详细
smem -p -P "your_program"

# valgrind Massif 查看堆分配模式
valgrind --tool=massif ./program
ms_print massif.out.*
```

### 6.3 内存池与分配器关系

```
malloc/free (glibc)
  ├── tcmalloc (Google, 线程缓存)
  ├── jemalloc (Facebook, 碎片少)
  ├── mimalloc (微软, 快速)
  └── pmr (C++17 标准, 灵活)
```

## 七、进程/线程/协程资源对比

| 资源类型 | 进程 | 线程 | 协程（C++20） |
|----------|------|------|---------------|
| 创建开销 | 高（复制地址空间） | 中等（10μs+） | 低（~100ns） |
| 上下文切换 | ~μs 级（内核） | ~μs 级（内核） | ~ns 级（用户态） |
| 内存隔离 | 完全独立 | 共享地址空间 | 共享地址空间 |
| 栈大小 | ~8MB | ~8MB（可调） | ~KB 级（可恢复） |
| 通信方式 | IPC/共享内存 | 共享内存 | 调用链直接返回 |
| 适用场景 | 强隔离 | 并行计算 | 高并发 I/O 等待 |

**C++20 协程优势**：
- 栈无栈（stackless），不分配完整栈帧
- 挂起开销仅 ~100ns（vs 线程上下文切换 ~μs）
- 适合大量等待操作（网络 I/O、事件驱动）

## 八、内存优化实战清单

| 场景 | 优化手段 | 预期收益 |
|:----:|:---------|:--------:|
| 大量小对象分配 | 对象池 / monotonic_buffer_resource | 减少 90% malloc 调用 |
| 多线程竞争分配 | tcmalloc / jemalloc（LD_PRELOAD 替换） | 降低锁竞争 50-80% |
| 高延迟尾抖动 | mlockall 防止 swap + 预分配 | 消除缺页异常 |
| 容器频繁扩容 | reserve 预分配 | 避免 reallocation 拷贝 |
| 大字符串拷贝 | string_view / move 语义 | 消除 O(n) 拷贝 |
| 结构体浪费空间 | 重排成员（大→小）+ SoA | 节省 20-50% 内存 |
| 缓存未命中 | 热冷分离 + 预取 | 降低 cache-miss 30-60% |

## 九、面试高频追问

### Q1: 为什么小对象用栈比堆快？
- 栈分配：一条指令（sub rsp），纳秒级
- 堆分配：系统调用（brk/mmap + 锁），微秒级
- **结论**：差异约 1000 倍

### Q2: std::string 的 SSO 具体多大？
- GCC：15 字节 + null 终止 → 最多存 15 字符
- MSVC：16 字节（SSO 阈值）
- Clang (libc++)：22 字节
- 超出阈值则堆分配

### Q3: 内存池适合什么场景？
- 频繁分配/释放固定大小对象
- 多线程分配竞争严重
- 需要分配延迟稳定的场景（低延迟）
- **不适合**：对象大小变化大、生命周期差异大的场景
