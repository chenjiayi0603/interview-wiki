# 内存分析工具

## 一、Valgrind 系列

### 1.1 Memcheck（内存错误检测）

```bash
# 完整检测（默认工具）
valgrind --leak-check=full --show-leak-kinds=all ./program

# 常见检测范围
# - 内存泄漏（definitely/possibly lost）
# - 使用未初始化内存
# - 越界读写（buffer overflow）
# - double-free / use-after-free
# - 不匹配的 malloc/delete
```

**输出解读**：
```
==12345== LEAK SUMMARY:
==12345==    definitely lost: 8 bytes in 1 blocks    # 确定泄漏
==12345==    indirectly lost: 0 bytes in 0 blocks    # 间接泄漏
==12345==      possibly lost: 0 bytes in 0 blocks    # 可能泄漏
==12345==    still reachable: 72,704 bytes in 1 blocks # 未释放但可访问
==12345==         suppressed: 0 bytes in 0 blocks    # 抑制的警告
```

**常见问题检测**：
```cpp
// 1. 越界写
int* arr = new int[5];
arr[5] = 100;  // 越界！Memcheck 报错

// 2. Use-after-free
int* ptr = new int(42);
delete ptr;
*ptr = 100;    // 使用已释放内存

// 3. 未初始化变量
int x;
if (x > 0) { }  // x 未初始化

// 4. double-free
int* p = new int;
delete p;
delete p;       // 重复释放
```

### 1.2 Massif（堆内存分析）

```bash
# 跟踪堆内存使用随时间变化
valgrind --tool=massif ./program
ms_print massif.out.* > heap_report.txt
```

**核心指标**：
- **heap**：堆分配的最大值
- **heap_admin**：堆管理元数据
- **stack**：栈使用情况
- **总内存峰值**：关键优化目标

**适用场景**：
- 定位内存使用峰值产生位置
- 分析内存随时间的增长模式
- 发现意外的内存分配

### 1.3 Callgrind（函数级性能分析）

```bash
valgrind --tool=callgrind ./program
kcachegrind callgrind.out.*   # 可视化分析
```

- 统计每个函数的 CPU 指令执行次数
- 显示调用关系图（调用者/被调用者）
- 适合分析算法复杂度级别的性能问题

### 1.4 Cachegrind（缓存分析）

```bash
valgrind --tool=cachegrind ./program
```

- L1/L2/L3 缓存命中/未命中统计
- 分析代码的缓存友好性
- 定位缓存未命中热点

### 1.5 Helgrind（数据竞争检测）

```bash
valgrind --tool=helgrind ./program
```

- 检测多线程程序中的数据竞争
- 分析锁使用顺序（检测死锁）
- POSIX pthreads API 误用检测

### 1.6 Valgrind 使用限制

| 特性 | 限制 |
|------|------|
| 性能开销 | 通常 10-50x 慢 |
| 内存开销 | 2-3x 内存使用 |
| 时间精度 | 非实时系统，不适合 profiling 微秒级 |
| 适用场景 | 开发/测试环境；CI 集成 |

**抑制文件（Suppression）**：
```bash
# 生成抑制文件模板
valgrind --gen-suppressions=all ./program 2> supp.txt

# 使用抑制文件
valgrind --suppressions=supp.txt ./program
```

## 二、Sanitizer 系列

### 2.1 AddressSanitizer（ASan）

```bash
# 编译启用
g++ -fsanitize=address -g -O1 -o program program.cpp
# 运行即可检测，无需额外工具
./program
```

**检测能力**：
- 堆/栈/全局缓冲区溢出
- Use-after-free
- Use-after-return
- 内存泄漏（需配合 LeakSanitizer）

**性能开销**：~2x，远低于 Valgrind

```cpp
// ASan 检测示例
int main() {
    int* arr = new int[5];
    arr[5] = 100;  // heap-buffer-overflow
    
    delete[] arr;
    arr[0] = 42;   // use-after-free
    
    return 0;
}
```

**典型输出**：
```
==12345==ERROR: AddressSanitizer: heap-buffer-overflow on address ...
WRITE of size 4 at 0x... thread T0
    #0 0x... in main example.cpp:5
    #1 0x... in __libc_start_main
```

### 2.2 LeakSanitizer（LSan）

```bash
# ASan 已内置 LSan，默认启用
# 独立使用（不开启 ASan）
g++ -fsanitize=leak -g -O1 program.cpp

# 通过环境变量控制检测行为
LSAN_OPTIONS=suppressions=lsan.supp ./program
```

### 2.3 MemorySanitizer（MSan，检测未初始化）

```bash
g++ -fsanitize=memory -g -O1 -fsanitize-memory-track-origins program.cpp
```

- 检测读取未初始化内存
- 可追踪未初始化数据的传播路径
- 性能开销约 2-3x

### 2.4 ThreadSanitizer（TSan，检测数据竞争）

```bash
g++ -fsanitize=thread -g -O1 -o program program.cpp -lpthread
```

- 检测多线程数据竞争
- 不检测死锁（用 Helgrind 补充）
- 性能开销约 5-10x

### 2.5 Sanitizer 对比

| 工具 | 检测目标 | 开销 | 适用阶段 |
|------|----------|------|----------|
| ASan | 内存越界、UAF | ~2x | 开发/测试 |
| LSan | 内存泄漏 | ~1x | 开发/测试 |
| MSan | 未初始化读取 | ~3x | 开发/测试 |
| TSan | 数据竞争 | ~5x | 多线程开发 |

## 三、系统工具

### 3.1 pmap 与 /proc

```bash
# 查看进程内存映射详情
pmap -x <pid>

# 查看具体内存区域
cat /proc/<pid>/maps

# 查看内存使用统计
cat /proc/<pid>/status
# VmRSS: 实际物理内存
# VmPeak: 峰值虚拟内存
# VmSize: 当前虚拟内存
# VmSwap: 已 swap 的内存

# 查看堆统计
cat /proc/<pid>/statm
```

### 3.2 top / htop

```bash
# top 内存相关列
# RES: 常驻内存（RSS）
# VIRT: 虚拟内存
# SHR: 共享内存

# htop 优势
# - 彩色显示
# - 可排序
# - 可查看树状进程关系

# 按内存排序
top -o %MEM
```

### 3.3 smem（更准确的 RSS 统计）

```bash
# 安装
apt-get install smem

# 按 RSS 排序显示
smem -rs rss

# 显示 PSS（Proportional Set Size），更公平的共享内存计量
smem -t -p
```

## 四、内存分析实战流程

### 4.1 内存泄漏排查

```
1. 用 ASan 初步检测（快速，低开销）
   → 发现问题可精确定位

2. 若 ASan 未检出，用 Valgrind Memcheck（慢但全面）
   → 关注 "definitely lost"

3. 生产环境可用 tcmalloc heap profile
   → HEAPPROFILE=./heap.hprof ./program
   → pprof --text ./program ./heap.hprof
```

### 4.2 内存膨胀排查

```
1. 用 pmap 查看映射，确定 RSS 组成
2. 用 Massif 分析分配时序和峰值
3. 检查是否有容器无限增长（如 std::map 缓存）
4. 检查是否有线程栈过大（ulimit -s 查看）
5. 检查是否打开了太多的 mmap 文件
```

### 4.3 内存优化优先级

1. **减少分配次数**：对象池、预分配、string_view
2. **减少分配大小**：紧凑布局、SoA、对齐优化
3. **减少碎片**：tcmalloc/jemalloc、pmr
4. **利用缓存**：热冷分离、结构性预取
