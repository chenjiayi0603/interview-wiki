# 性能分析工具

## 一、perf - Linux 性能分析工具

### 1.1 perf 核心命令速查

| 命令 | 用途 | 常用参数 |
|------|------|----------|
| `perf stat` | 统计整体性能指标 | `-e` 指定事件，`-p` 指定进程，`-I` 间隔输出 |
| `perf record` | 采集性能数据 | `-g` 记录调用栈，`-F` 采样频率，`-e` 指定事件 |
| `perf report` | 查看热点报告 | `-g` 显示调用栈，`--stdio` 文本输出 |
| `perf top` | 实时监控热点 | `-p` 指定进程，`-H` 按线程 |
| `perf script` | data 转文本 | 用于生成火焰图 |
| `perf annotate` | 查看汇编级热点 | 需带调试信息 |
| `perf list` | 列出可用事件 | |

### 1.2 perf stat - 整体评估

```bash
# 基础用法
perf stat ./program

# 统计关键硬件事件
perf stat -e cycles,instructions,cache-misses,branch-misses ./program

# 按进程统计（线上场景）
perf stat -p <pid> -- sleep 30

# 按间隔输出
perf stat -I 1000 -p <pid>  # 每秒输出
```

**输出示例与解读**：
```
 Performance counter stats for './program':
    1,002.13 msec task-clock          # 0.998 CPUs utilized
    3,143,230      cycles             # 3.137 GHz
    1,234,567      instructions       # 0.39  insn per cycle
       21,431      cache-references
        5,432      cache-misses       # 25.35% of all cache refs
          134      page-faults
          567      branch-misses      # 2.15% of all branches
```

**关键指标**：

| 指标 | 含义 | 正常值 |
|------|------|--------|
| **cycles** | CPU 时钟周期总数 | 越低越好 |
| **instructions** | 执行的指令条数 | 反映程序复杂度 |
| **IPC** | 每周期指令数，衡量流水线效率 | >1.0 好，<0.5 需优化 |
| **cache-misses%** | 缓存未命中率 | <10% 佳，>25% 需优化 |
| **branch-misses%** | 分支预测失败率 | <2% 佳，>10% 需优化 |
| **page-faults** | 缺页中断次数 | 越少越好（mlock 可消除） |
| **task-clock** | CPU 利用率 | 接近核数 * 时间最好 |

### 1.3 perf record + report - 定位热点

```bash
# 1. 记录 CPU 热点（带调用栈）
perf record -g ./program
# 或全系统采样
perf record -a -g -- sleep 30

# 2. 查看报告
perf report

# 3. 查看特定事件（如缓存未命中）
perf record -e cache-misses -g ./program
perf report
```

**判断瓶颈**：
- 锁竞争：`perf record -e sched:sched_switch -g ./program`
- 系统调用：`perf record -e syscalls:sys_enter_* ./program`
- 上下文切换：`perf record -e context-switches -g ./program`
- 锁争用：`perf record -e lock:contention_begin ./program`

### 1.4 perf top - 实时监控

```bash
# 全局实时热点
sudo perf top

# 按进程查看
perf top -p <pid>

# 按线程查看
perf top -p <pid> -H
```

### 1.5 火焰图生成

```bash
# 1. 安装 FlameGraph
git clone https://github.com/brendangregg/FlameGraph
cd FlameGraph

# 2. 采集数据
perf record -F 99 -a -g -- sleep 30

# 3. 转换格式
perf script > out.perf

# 4. 折叠样本
./stackcollapse-perf.pl out.perf > out.folded

# 5. 生成 SVG
./flamegraph.pl out.folded > flame.svg

# 浏览器打开 flame.svg 即可交互分析
```

**火焰图阅读方法**：
- **X 轴宽度** = 耗时比例（越宽越热点）
- **Y 轴高度** = 调用链深度
- **颜色**：无语义，仅区分
- **自底向上**：从底部到顶部看调用关系

### 1.6 perf diff - 对比优化效果

```bash
# 采集优化前后的数据
perf record -g ./program_before  # 生成 perf.data.old（若重命名）
perf record -g ./program_after   # 生成 perf.data

# 对比
perf diff perf.data.old perf.data
```

## 二、strace - 系统调用跟踪

### 2.1 基本用法

```bash
# 统计系统调用分布（开销较小）
strace -c ./program

# 跟踪文件 I/O 并显示耗时
strace -e trace=file -T ./program

# 跟踪网络操作
strace -e trace=network -T ./program

# 跟踪已运行进程
strace -p <pid> -c -T

# 跟踪子进程
strace -f ./program
```

### 2.2 判断 I/O 瓶颈

```bash
# 方法1：strace -c 统计系统调用耗时占比
strace -c ./program
# 如 read/write/open 等 I/O 调用总耗时 > 50%，则 I/O 是瓶颈

# 方法2：time -v 查看 User vs Elapsed
/usr/bin/time -v ./program
# User time << Elapsed time → I/O 等待

# 方法3：perf stat 看 CPU 利用率低
# CPUs utilized < 50% → 很可能在等 I/O
```

### 2.3 注意事项

- **性能开销**：10%~50%，生产环境慎用
- CPU 利用率低的程序 strace 开销相对更小（在等 I/O 时采样成本低）

## 三、gprof - 函数级分析

```bash
# 1. 编译加 -pg
g++ -pg -O2 -o program program.cpp

# 2. 运行生成 gmon.out
./program

# 3. 查看报告
gprof program gmon.out > report.txt
```

**与 perf 对比**：

| 特性 | perf | gprof |
|------|------|-------|
| 原理 | 硬件事件采样 | 编译插桩（-pg） |
| 开销 | 低（<5%） | 中等 |
| 需源码 | 否 | 是（需加 -pg） |
| 内核态分析 | 支持 | 不支持 |
| 多线程 | 好 | 有限 |
| 硬件事件 | 支持（cache, branch 等） | 不支持 |
| 适用场景 | 深度分析、生产 | 快速热点定位 |

## 四、C++ 高精度计时

```cpp
#include <chrono>

// 单次测量
auto start = std::chrono::high_resolution_clock::now();
// 被测代码...
auto end = std::chrono::high_resolution_clock::now();
auto us = std::chrono::duration_cast<std::chrono::microseconds>(end - start);
std::cout << "耗时: " << us.count() << " 微秒" << std::endl;

// 多次测量取平均
constexpr int N = 1000;
auto total = std::chrono::nanoseconds(0);
for (int i = 0; i < N; ++i) {
    auto start = std::chrono::high_resolution_clock::now();
    // 被测代码...
    auto end = std::chrono::high_resolution_clock::now();
    total += (end - start);
}
auto avg = total / N;
std::cout << "平均: "
          << std::chrono::duration_cast<std::chrono::nanoseconds>(avg).count()
          << " ns" << std::endl;

// 低延迟场景建议使用 RDTSC（更精确）
#include <x86intrin.h>
inline uint64_t rdtsc() {
    return __rdtsc();
}
// 使用前需校准 TSC 频率：测量一段时间内的 delta 除以时间
```

## 五、工具选择决策

### 5.1 分析流程

```
1. 整体评估 → perf stat（宏观看各项指标是否正常）
2. 热点定位 → perf record + report / 火焰图（找哪里最耗时）
3. 深度诊断 → 根据初步发现选择工具：
   ├── CPU 热点 → perf annotate（看汇编）
   ├── 缓存在意 → perf stat -e cache-misses
   ├── 分支预测 → perf stat -e branch-misses
   ├── 锁竞争 → perf record -e sched:sched_switch
   ├── 系统调用 → strace -c
   ├── 内存泄漏 → AddressSanitizer / Valgrind
   └── I/O 瓶颈 → strace -e trace=file -T
4. 验证优化 → perf stat / perf diff 对比
```

### 5.2 线上 vs 线下

| 阶段 | 推荐工具 | 原因 |
|------|----------|------|
| 线下开发 | Valgrind Memcheck | 全面检测内存问题 |
| 线下测试 | ASan / TSan | 快速、准确 |
| 线下性能 | perf / Callgrind | 深度分析 |
| 线上监控 | perf top / perf stat -I | 实时，低开销 |
| 线上诊断 | perf record -a -g | 临时采样，影响小 |

### 5.3 关键指标速查

| 症状 | 关注指标 | 工具 |
|------|----------|------|
| 程序慢但 CPU 不满 | cache-misses, page-faults | perf stat |
| CPU 高但吞吐低 | IPC, branch-misses | perf stat |
| 延迟抖动大 | context-switches, sched | perf record |
| 内存增长 | RSS, heap | pmap, Massif |
| 锁竞争 | sched_switch | perf / strace |
