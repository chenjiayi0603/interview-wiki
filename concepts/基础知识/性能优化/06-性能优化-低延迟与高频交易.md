# 低延迟与高频交易（HFT）系统优化

## 一、核心目标与设计原则

### 1.1 性能目标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 端到端延迟 | 1~10μs | 从行情到达 → 策略决策 → 下单 |
| P99 延迟 | < 50μs | 尾延迟控制，比均值更重要 |
| 延迟抖动 | < 1μs | 确定性比绝对速度更重要 |
| 吞吐 | > 100K msg/s | 处理能力 |
| 订单处理 | 微秒级 | 从接收 → 风控 → 路由 |

### 1.2 设计原则

1. **确定性优先**：可预测的延迟比偶尔的极速更重要
2. **避免一切阻塞**：无锁、无等待、无系统调用
3. **预分配一切**：启动时完成所有资源分配
4. **专核专用**：关键线程独占 CPU 核心
5. **数据就近**：NUMA 本地分配，避免跨节点访问

## 二、硬件优化

### 2.1 CPU 缓存优化

**缓存结构**：
```
L1: 32KB 数据 + 32KB 指令（延迟 ~1ns）
L2: 256KB（延迟 ~4ns）
L3: 8-30MB 共享（延迟 ~15ns）
内存: （延迟 ~60-100ns）
```

**优化措施**：
- **SoA 布局**：只遍历需要的字段
- **缓存行对齐**：`alignas(64)` 避免 false sharing
- **热冷分离**：频繁访问数据紧凑排列
- **预取**：`_mm_prefetch` 提前加载

### 2.2 NUMA 优化

```bash
# 核绑 + 内存绑（推荐）
numactl --cpunodebind=0 --mempolicy=preferred:0 ./program
```

**核心原则**：
- 线程绑定到特定核心（`pthread_setaffinity_np`）
- 内存分配到线程所在 NUMA 节点（`numa_alloc_onnode`）
- 网络中断绑定到同节点 CPU

### 2.3 避免 CPU 频率缩放

```bash
# 性能模式
echo performance | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor

# 禁用透明大页（THP）
echo never > /sys/kernel/mm/transparent_hugepage/enabled
echo never > /sys/kernel/mm/transparent_hugepage/defrag

# 锁定内存（mlockall）
```

## 三、编程模式

### 3.1 无锁编程

**SPSC（单生产者单消费者）队列**：

```cpp
template<typename T>
class SPSCQueue {
    static constexpr size_t CACHE_LINE = 64;
    
    // 生产者写，消费者读
    alignas(CACHE_LINE) size_t write_idx_ = 0;
    alignas(CACHE_LINE) size_t read_idx_ = 0;
    
    T* buffer_;
    size_t capacity_;
    
public:
    bool push(const T& item) {
        size_t w = write_idx_.load(std::memory_order_relaxed);
        size_t r = read_idx_.load(std::memory_order_acquire);
        if (full(w, r)) return false;
        buffer_[w % capacity_] = item;
        write_idx_.store(w + 1, std::memory_order_release);
        return true;
    }
    
    bool pop(T& item) {
        size_t r = read_idx_.load(std::memory_order_relaxed);
        size_t w = write_idx_.load(std::memory_order_acquire);
        if (r == w) return false;
        item = buffer_[r % capacity_];
        read_idx_.store(r + 1, std::memory_order_release);
        return true;
    }
};
```

**无锁关键知识**：
- `memory_order_relaxed`：只有原子保证，无顺序约束
- `memory_order_acquire`：后续读写不能被重排到此前
- `memory_order_release`：此前读写不能被重排到此后
- `memory_order_acq_rel`：acquire + release
- `memory_order_seq_cst`：全局顺序一致（最慢）

### 3.2 避免系统调用

```cpp
// 错误：热点路径做系统调用
void process() {
    gettimeofday(&tv, NULL);         // 系统调用，~100ns
    timespec_get(&ts, TIME_UTC);     // 某些实现也是系统调用
}

// 正确：使用 VDSO 或 RDTSC
#include <x86intrin.h>
uint64_t now_ns() {
    // RDTSC 指令，用户态，~10ns
    return __rdtsc();
}
// 需要校准 TSC 频率
```

**热点路径要避免的操作**：
- `malloc/free`（改用对象池）
- 系统调用（`read/write/send/recv`→ 批量化）
- 锁（`pthread_mutex_lock` → 无锁/分片锁）
- `throw` 异常（禁用 RTTI 和异常）
- 虚函数调用（尽量用 CRTP/模板）
- `dynamic_cast` / `typeid`
- 日志输出（异步日志）

### 3.3 分支预测优化

```cpp
#define likely(x)   __builtin_expect(!!(x), 1)
#define unlikely(x) __builtin_expect(!!(x), 0)

// 查找表替代 switch
int process(int type) {
    static const int table[] = {10, 20, 30};
    return table[type];  // 无分支
}
```

### 3.4 事件驱动状态机

```cpp
enum class State { INIT, CONNECTED, TRADING, ERROR };

// 函数指针表替代 switch
using handler_t = void(*)(Event);
handler_t handlers[4] = {
    handle_init,
    handle_connected,
    handle_trading,
    handle_error
};

void process_event(Event e, State s) {
    handlers[static_cast<int>(s)](e);  // 无分支
}
```

## 四、网络优化

### 4.1 内核旁路技术

| 技术 | 延迟 | 吞吐 | 复杂度 |
|------|------|------|--------|
| 传统 socket | ~10μs | 中等 | 低 |
| TCP 调优 | ~5μs | 高 | 低 |
| Onload | ~2μs | 高 | 中 |
| DPDK | <1μs | 极高 | 高 |
| RDMA | <1μs | 极高 | 高 |
| XDP | ~1μs | 极高 | 高 |

### 4.2 DPDK

**核心概念**：
- 用户态直接操作网卡 DMA 缓冲区
- 轮询模式（PMD）替代中断
- 零拷贝，无系统调用
- 大页内存（hugepages）

**基本流程**：
```cpp
// 1. EAL 初始化
rte_eal_init(argc, argv);

// 2. 创建内存池
struct rte_mempool* pool = rte_pktmbuf_pool_create("POOL", ...);

// 3. 配置网卡端口
rte_eth_dev_configure(port_id, nb_rx, nb_tx, &conf);

// 4. 设置 RX/TX 队列
rte_eth_rx_queue_setup(port_id, 0, ...);
rte_eth_tx_queue_setup(port_id, 0, ...);

// 5. 启动端口
rte_eth_dev_start(port_id);

// 6. 主循环：收包发包
while (1) {
    uint16_t nb_rx = rte_eth_rx_burst(port_id, 0, bufs, BURST_SIZE);
    if (nb_rx > 0) {
        // 处理数据包
        uint16_t nb_tx = rte_eth_tx_burst(port_id, 0, bufs, nb_rx);
    }
}
```

**DPDK vs 传统 socket 对比**：

| 特性 | DPDK | 传统 socket |
|------|------|-------------|
| 数据路径 | 用户态 ↔ DMA ↔ 网卡 | 用户态 ↔ 内核态 ↔ 网卡 |
| 拷贝次数 | 0 | 1-2 次 |
| 系统调用 | 0 | 每次收发都有 |
| 延迟 | <1μs | ~10μs |
| 开发难度 | 高 | 低 |
| 协议栈 | 需自行实现 | 内核已完成 |

### 4.3 批量处理

```cpp

for (int i = 0; i < 32; ++i) {
    iovs[i].iov_base = buffers[i];
```

### 4.4 TCP 调优

```cpp
// 禁用 Nagle 算法（低延迟必选）
int flag = 1;
setsockopt(sock, IPPROTO_TCP, TCP_NODELAY, &flag, sizeof(flag));

// 禁用延迟确认
```

### 4.5 零拷贝技术

| 技术 | 用途 | 说明 |
|------|------|------|
| `sendfile()` | 文件 → socket | 内核直接搬运，无需用户缓冲区 |
| `mmap()` | 文件 → 用户空间 | 内存映射，避免 read 拷贝 |

### 5.2 Spin-wait 策略

```cpp
// 自旋等待（忙等，适合微秒级等待）
while (!ready_flag.load(std::memory_order_acquire)) {
    _mm_pause();  // PAUSE 指令：减少功耗，提高 SMT 性能
}

// 带退避的自旋（避免缓存一致性风暴）
for (int spin = 1; !ready_flag.load(); spin++) {
    if (spin < 100) {
        _mm_pause();
    } else {
        sched_yield();  // 让出 CPU，适合更长等待
        spin = 0;
    }
}
```

## 七、HFT 系统典型架构

### 7.1 逻辑分层

```
行情源（交易所）
  ↓ 低延迟市场数据
行情网关（FPGA/DPDK）
  ↓ 数据分发
策略引擎（锁无关，事件驱动）
  ↓ 交易信号
风控模块（规则检查）
  ↓
订单路由（交易所连接）
```

### 7.2 线程模型

```
CPU 0: 行情接收线程 (SCHED_FIFO, 优先级 99)
CPU 1: 策略引擎线程 (SCHED_FIFO, 优先级 50)
CPU 2: 风控/订单路由 (SCHED_FIFO, 优先级 40)
CPU 3: 日志/监控 (SCHED_OTHER)
```

### 7.3 延迟预算分配

| 阶段 | 延迟预算 | 优化重点 |
|------|----------|----------|
| 网卡 → 用户态 | 1-2μs | DPDK/零拷贝 |
| 行情解析 | 1-2μs | 零分配，无锁 |
| 策略计算 | 2-5μs | SIMD，无分支 |
| 风控检查 | 1-2μs | O(1) 算法 |
| 订单发送 | 1-2μs | 预创建连接 |

## 八、面试高频追问

### Q1: HFT 系统为什么禁用 Hyper-Threading？
- 超线程的两个逻辑核心共享 L1/L2 缓存和执行单元
- 一个核心的高优先级线程可能被另一个逻辑核心的低优先级任务干扰（资源争用）
- **结论**：BIOS 关闭 HT，每个物理核心只运行一个线程

### Q2: DPDK 相比传统内核协议栈快多少？
| 对比 | 传统内核网络 | DPDK |
|:----:|:----------:|:----:|
| 延迟 | 10-50μs | 1-2μs |
| 吞吐 | 10-50Gbps | 100Gbps+ |
| 抖动 | 大（内核调度不确定） | 极低（用户态轮询） |
| CPU 占用 | 高（中断+拷贝） | 低（无中断） |

### Q3: 无锁编程的核心原则？
1. **避免共享**：每个线程独立数据（thread-local）
2. **不可变**：只读数据不需要锁
3. **原子操作**：`std::atomic` + 合适的内存序（acquire/release）
4. **Hazard Pointer / Epoch-Based Reclamation**：安全回收内存
5. **Seqlock**：读多写少的场景

### Q4: 如何测量微秒级的尾延迟抖动？
- `clock_gettime(CLOCK_MONOTONIC_RAW, ...)`（避开 NTP 调整）
- 使用 TSC（时间戳计数器，`__rdtsc()`），ns 级精度
- 采集 P50/P99/P999 直方图而非平均值
- **busy-spinning 预热**：暖 CPU、避免冷缓存
| 总计 | 6-13μs | |
