# 调度优化与实时系统

## 一、Linux 调度策略

### 1.1 调度策略概览

| 策略 | 优先级范围 | 特点 | 适用场景 |
|------|-----------|------|----------|
| `SCHED_OTHER` | 0（动态） | 普通分时调度，CFS | 大多数应用 |
| `SCHED_BATCH` | 0（动态） | CPU 密集型批处理 | 计算任务 |
| `SCHED_IDLE` | 0（动态） | 极低优先级 | 后台任务 |
| `SCHED_FIFO` | 1-99（实时） | 先进先出，直到阻塞 | HFT/实时主线程 |
| `SCHED_RR` | 1-99（实时） | 时间片轮转 | 多实时线程协作 |
| `SCHED_DEADLINE` | 0（实时） | 指定周期/运行时间/截止时间 | 工业控制 |

### 1.2 SCHED_FIFO vs SCHED_RR

```cpp
#include <pthread.h>
#include <sched.h>

void set_realtime(int policy, int priority) {
    struct sched_param param;
    param.sched_priority = priority;  // 1-99，越大优先级越高
    int ret = pthread_setschedparam(pthread_self(), policy, &param);
    if (ret != 0) {
        perror("pthread_setschedparam failed");
    }
}

// SCHED_FIFO 场景：单一关键线程，极致低延迟
// - 高优先级 FIFO 线程会抢占所有低优先级线程
// - 除非主动让出或阻塞，否则持续运行
// - 适合：HFT 撮合主循环、DPDK 收包线程

// SCHED_RR 场景：多同等重要实时线程
// - 同优先级线程按时间片轮转
// - 防止某个线程饿死
// - 适合：多个实时行情处理、风控检查并行
```

**选择指南**：
- 只有一个极致延迟要求的线程 → `SCHED_FIFO`
- 多个同等重要的实时线程 → `SCHED_RR`
- 不确定时优先选 `SCHED_RR`（更公平）

### 1.3 SCHED_DEADLINE

```bash
# 需内核支持（Linux 3.14+）
# 设置参数：运行时 runtime，周期 period，截止时间 deadline
chrt -d --sched-runtime 50000 \
       --sched-deadline 100000 \
       --sched-period 100000 \
       0 ./program
```

**适用场景**：
- 工业实时控制
- 必须保证周期性执行的任务
- 需要明确的延迟上限保证

## 二、PREEMPT_RT 实时内核

### 2.1 什么是 PREEMPT_RT？

将 Linux 内核转化为硬实时操作系统的补丁集：
- 内核大部分区域可被抢占
- 中断线程化（线程化 IRQ 处理）
- 高精度定时器
- 锁的优先级继承（PI futexes）

### 2.2 安装与配置

```bash
# Ubuntu/Debian 安装
apt-get install linux-image-rt-amd64  # Debian
apt-get install linux-rt              # Ubuntu

# CentOS/RHEL
yum install kernel-rt

# 手动编译内核
# 1. 下载内核源码 + PREEMPT_RT 补丁
# 2. 配置内核：General setup → Preemption Model → Fully Preemptible Kernel
# 3. 编译安装

# 验证当前内核是否 RT
uname -a
# 输出包含 "PREEMPT RT" 字样
```

### 2.3 不同抢占模型对比

| 模型 | 配置选项 | 最大延迟 | 适合场景 |
|------|----------|----------|----------|
| 无抢占 | CONFIG_PREEMPT_NONE | ~ms 级 | 服务器 |
| 自愿抢占 | CONFIG_PREEMPT_VOLUNTARY | ~百μs | 桌面 |
| 低延迟抢占 | CONFIG_PREEMPT | ~十μs | 交互应用 |
| 完全可抢占（RT） | CONFIG_PREEMPT_RT_FULL | ~μs 级 | 实时系统 |

## 三、CPU 隔离与专核

### 3.1 isolcpus

```bash
# 内核启动参数，隔离指定 CPU
# 在 GRUB 配置中添加
isolcpus=1,2,3

# 被隔离的 CPU 上默认不运行任何用户态进程

# /etc/default/grub
GRUB_CMDLINE_LINUX_DEFAULT="quiet isolcpus=1,2,3 nohz_full=1,2,3"
```

### 3.2 nohz_full

```bash
# 关闭隔离 CPU 的时钟中断（减少抖动）
nohz_full=1,2,3

# 配合 rcu_nocbs 避免 RCU 回调干扰
rcu_nocbs=1,2,3
```

## 四、中断绑定（IRQ Affinity）

### 4.1 为什么绑定中断？

- **减少抖动**：避免业务线程所在 CPU 被中断抢占
- **缓存本地化**：网络数据和协议栈在同一 NUMA 节点
- **避免 irqbalance 意外**：手动控制更可靠

### 4.2 配置方法

```bash
# 1. 查看中断分布
cat /proc/interrupts | grep eth0
# 输出示例：24: 150230 0 0 0 PCI-MSI 524288-edge eth0-TxRx-0

# 2. 绑定指定中断到 CPU0
echo 1 > /proc/irq/24/smp_affinity
# CPU 掩码：1=CPU0, 2=CPU1, 3=CPU0+CPU1, 4=CPU2, ...

# 3. 多队列网卡批量绑定
IFACE="eth0"
i=0
for irq in $(cat /proc/interrupts | grep "$IFACE" | awk '{print $1}' | sed 's/://'); do
    mask=$((1 << (i % 4)))  # 循环绑定到 CPU0-3
    printf "%x" $mask > /proc/irq/$irq/smp_affinity
    i=$((i+1))
done

# 4. 关闭 irqbalance
systemctl stop irqbalance
systemctl disable irqbalance
```

### 4.3 中断绑定 vs CPU 绑定

| 特性 | 中断绑定 | CPU 绑定 |
|------|----------|----------|
| 作用对象 | 硬件中断处理程序 | 用户态进程/线程 |
| 设置方式 | `/proc/irq/.../smp_affinity` | `taskset` / `pthread_setaffinity_np` |
| 目的 | 中断不干扰指定 CPU | 线程固定在指定 CPU |
| 配合使用 | 最佳：中断+线程绑同 NUMA 节点 |

**错误配置举例**：
- 业务线程和高频中断绑同一 CPU → 互相抢占
- 中断在 NUMA-0，线程在 NUMA-1 → 缓存失效、延迟翻倍

## 五、内存锁定（mlock）

```cpp
#include <sys/mman.h>

// 锁定所有当前和未来页面
void lock_all() {
    if (mlockall(MCL_CURRENT | MCL_FUTURE) != 0) {
        perror("mlockall failed");
    }
}
```

**为什么需要**：
- 实时线程不能有 page fault（页面错误延迟不可控）
- 内存不足时不被 swap 出去
- 资源限制：`ulimit -l`，生产建议设 `unlimited`

## 六、系统参数调优

### 6.1 内核参数

```bash
# /etc/sysctl.conf

# 实时调度 — 允许实时进程无限运行
kernel.sched_rt_period_us = 1000000
kernel.sched_rt_runtime_us = -1      # -1 表示无限制

# 禁用透明大页（低延迟推荐）
vm.swappiness = 0                     # 禁用 swap

# 其他
kernel.numa_balancing = 0             # 禁用 NUMA balancing（避免自动迁移）
kernel.sched_migration_cost_ns = 0    # 减少迁移成本
```

### 6.2 dynamic tick（nohz）

```bash
# 内核启动参数
nohz_full=1-3      # CPU1-3 关闭周期性 tick
rcu_nocbs=1-3       # 避免 RCU 回调在隔离 CPU 上运行
```

## 七、延迟验证

### 7.1 cyclictest

```bash
# 安装
apt-get install rt-tests

# 测试实时系统延迟
cyclictest -t1 -p99 -i10000 -d0 -l1000000

# 输出解读
# T: 0 Type: FIFO
# P: 99  Priority
# I: 10000  Interval (μs)
# C: 1000000  Count
# Min: 1  Act: 2   Avg: 3    Max: 12
# 
# Max 最重要：反映系统最大延迟
# 普通内核：Max 可能数百 μs；PREEMPT_RT：Max < 50μs
```

### 7.2 延迟预期参考

| 系统类型 | Max 延迟 | P99.999 延迟 |
|----------|----------|-------------|
| 普通 Linux | 1000-5000μs | 100-500μs |
| 调优 Linux | 100-500μs | 20-100μs |
| PREEMPT_RT | 10-50μs | 5-20μs |
| DPDK 专核 | <5μs | <1μs |

## 八、实时编程的 C++ 注意事项

### 8.1 避免的操作

| 避免 | 原因 | 替代方案 |
|------|------|----------|
| `malloc`/`new` | 分配延迟不确定 | 对象池、预分配 |
| `throw` 异常 | 展开栈耗时大 | 错误码返回 |
| `dynamic_cast`/`typeid` | 依赖 RTTI | 静态多态（CRTP） |
| 虚函数（热点） | 间接跳转、无法内联 | 模板、函数指针表 |
| STL 动态扩容 | `vector` 扩容时拷贝 | `reserve` 预分配 |
| 日志/打印 | I/O 阻塞 | 异步日志、环形缓冲区 |

### 8.2 实时安全实践

```cpp
// 1. 预分配所有资源
class RealtimeEngine {
    ObjectPool<Order> order_pool;     // 对象池
    RingBuffer<Event, 65536> events;  // 环形缓冲区
    std::array<char, 4096> scratch;   // 栈上暂存
public:
    RealtimeEngine() {
        events.reserve(65536);
        mlockall(MCL_CURRENT | MCL_FUTURE);
    }
};

// 2. 编译禁用 RTTI 和异常
// g++ -fno-rtti -fno-exceptions -O3 -march=native

// 3. 热点路径零分配
void on_market_data(const MarketData& md) {
    // 错误：std::string 可能堆分配
    // std::string symbol = md.symbol();
    
    // 正确：string_view 零拷贝
    std::string_view symbol = md.symbol_view();
}
```
