# C++ 性能优化面试考点汇总

## 一、核心方法论

### 1.1 优化步骤

1. **建立基线**（无基线 = 无法证明优化）
2. **定位瓶颈**（perf stat/火焰图，而不是猜）
3. **针对性优化**（先解决最大的瓶颈）
4. **验证效果**（对比基线，确认改善）
5. **回归测试**（优化不破坏正确性）

### 1.2 关键指标

| 指标 | 意义 | 面试常见问题 |
|------|------|-------------|
| QPS | 系统吞吐能力 | "如何提升 QPS？" |
| P50/P99/P999 | 延迟分布 | "为什么 P99 高？怎么优化？" |
| IPC | CPU 流水线效率 | "为什么 IPC 低？" |
| cache-misses | 内存访问模式 | "如何减少 cache-misses？" |
| context-switches | 调度效率 | "上下文切换多怎么办？" |

## 二、编译优化

### 2.1 必会

```bash
# 优化级别
-O0 -O1 -O2 -O3 -Os -Ofast

# 常用组合
-O3 -march=native -flto -fomit-frame-pointer

# PGO 三步
-fprofile-generate → 运行 → -fprofile-use
```

**面试题**：`-O2` 和 `-O3` 的区别？
- `-O3` 在 `-O2` 基础上增加向量化、函数内联、循环展开等

### 2.2 likely/unlikely

```cpp
#define likely(x)   __builtin_expect(!!(x), 1)
#define unlikely(x) __builtin_expect(!!(x), 0)

if (likely(condition)) {
    // 告诉编译器这里更可能执行
}
```

**面试题**：likely/unlikely 的作用？写错了会怎样？
- 答：优化分支布局，减少分支预测失败。写错会导致主分支每次都预测失败，性能劣化。

### 2.3 LTO / PGO

**面试题**：什么是 LTO？有什么好处？
- 答：链接时优化，跨编译单元进行内联、常量传播、死代码消除。

**面试题**：PGO 的流程？
- 答：插桩编译 → 代表性输入运行 → 收集 profile → 用 profile 重新编译。

## 三、内存优化

### 3.1 内存布局

**面试题**：如何避免 false sharing？
- 答：缓存行对齐 `alignas(64)`，填充 padding，确保不同线程的共享变量不在同一缓存行。

**面试题**：SoA vs AoS 区别？
- 答：SoA 适合字段选择性遍历（缓存友好），AoS 适合单条记录操作。
- 举例：`struct { float x,y,z; }` AoS vs `struct { float x[],y[],z[]; }` SoA

### 3.2 分配策略

**面试题**：栈分配 vs 堆分配速度和原因？
- 答：栈分配单指令（移动指针），堆分配需要系统调用、锁、查找空闲块。

**面试题**：对象池的原理？
- 答：预分配一批对象，用空闲链表管理，分配释放 O(1)，避免 malloc/free。

**面试题**：string_view 的作用？
- 答：零拷贝字符串引用，避免不必要的字符串拷贝。但不拥有数据，需保障原字符串生命周期。

### 3.3 内存工具

**面试题**：Valgrind 和 AddressSanitizer 的对比？
- 答：Valgrind 慢但检测全面；ASan 快（~2x）但仅限堆/栈溢出和 UAF；生产中无法使用。

**面试题**：进程内存布局从低到高？
- 答：Text → Data → BSS → Heap → --- → Stack → Kernel

## 四、多线程与并发

### 4.1 锁优化

**面试题**：如何减少锁竞争？
1. 缩小临界区（锁内只做必要操作）
2. 分片锁（如 64 分片的 map）
3. 读写锁（shared_mutex）
4. 无锁数据结构（SPSC 队列）
5. 线程本地存储（ThreadLocal）

**面试题**：读写锁适用场景？
- 答：读多写少场景，多个读者可同时访问，写者互斥。

### 4.2 无锁编程

**面试题**：C++ 内存序有哪几种？
```cpp
memory_order_relaxed   // 仅原子保证，无顺序约束
memory_order_acquire   // 后续读写不重排到此前
memory_order_release   // 此前读写不重排到此后
memory_order_acq_rel   // acquire + release
memory_order_seq_cst   // 全局顺序一致（最严格，最慢）
```

**面试题**：SPSC 队列为什么不需要锁？
- 答：单生产者只写 write_idx，单消费者只读 write_idx/写 read_idx，无竞争。

### 4.3 CAS 与 ABA 问题

**面试题**：CAS 的 ABA 问题怎么解决？
- 答：使用 `std::atomic<std::uintptr_t>` 或 tagged pointer（版本号），例如 `compare_exchange_weak` 配合计数器。

## 五、性能分析工具

### 5.1 perf

**面试题**：perf 的原理？
- 答：基于内核 perf_event 子系统，利用硬件性能计数器采样，低开销。

**面试题**：火焰图怎么看？
- 答：X 轴宽 = 耗时多，Y 轴深 = 调用链深，关注最宽的火苗。

**面试题**：perf stat 各项指标意义？
- IPC：每周期指令数（<0.5 需优化），cache-misses（>25% 需优化），branch-misses（>10% 需优化）。

### 5.2 strace

**面试题**：如何判断 I/O 瓶颈？
- 答：strace -c 看 I/O syscall 占比 > 50%；time -v 看 User < Elapsed；perf stat 看 CPUs utilized 低。

## 六、低延迟系统

### 6.1 延迟测量

**面试题**：如何测量微秒级延迟？
- 答：使用 RDTSC 指令（用户态，~10ns），避免 gettimeofday（可能系统调用）。

### 6.2 内核旁路

**面试题**：DPDK 为什么比普通 socket 快？
1. 用户态直接操作网卡 DMA，无系统调用
2. 轮询模式取代中断
3. 零拷贝数据
4. 大页内存减少 TLB miss

**面试题**：DPDK 的缺点？
- 答：开发复杂（需自己实现协议栈），需 root 权限和 hugepages，不可与普通 socket 直接通信。

### 6.3 实时调度

**面试题**：SCHED_FIFO 和 SCHED_RR 区别？
- FIFO：高优先级抢占低优先级，同优先级先到先得，不让出就一直跑
- RR：同优先级时间片轮转，防止单线程饿死

**面试题**：PREEMPT_RT 解决了什么问题？
- 答：使内核大部分区域可抢占，降低内核延迟抖动，将 Linux 变为硬实时系统。

## 七、网络优化

### 7.1 TCP 调优

**面试题**：TCP_NODELAY 的作用？
- 答：禁用 Nagle 算法，禁止小包等待合并，减少延迟。

**面试题**：零拷贝技术有哪些？
- sendfile（文件→socket）、mmap（文件→用户空间）、splice（管道→socket）、MSG_ZEROCOPY（用户空间→socket）

### 7.2 epoll vs io_uring

**面试题**：epoll 的 LT 和 ET 区别？
- LT（水平触发）：只要可读就通知，不读完一直通知
- ET（边缘触发）：从不可读变为可读时通知一次，需一次读完

**面试题**：io_uring 相比 epoll 的优势？
- 答：减少系统调用次数（提交队列/完成队列），支持更多异步操作（读写、open、accept），支持真正零拷贝。

## 八、常见面试场景题

### 8.1 "程序慢，怎么入手优化？"

**答案框架**：
1. 先用 `perf stat` 看宏观指标（CPU 利用率、IPC、cache-misses）
2. 用 `perf record -g` 生成火焰图找热点
3. 根据热点类型分类：
   - 锁热点 → 分片/无锁
   - 内存分配热点 → 对象池
   - 系统调用热点 → 批量化
   - 计算热点 → SIMD/算法优化
4. 修改后回归压测验证

### 8.2 "P99 延迟高，P50 正常，原因？"

**常见原因**：
1. 偶尔的锁竞争
2. THP 合并/分配抖动
3. 中断/调度干扰
4. 缺页中断（page fault）
5. GC（有 GC 的语言）
6. 偶尔的 I/O 等待

### 8.3 "多线程程序性能不如单线程？"

**原因排查**：
1. False sharing（缓存行同步）
2. 锁竞争严重
3. 线程过多导致上下文切换
4. NUMA 远程访问
5. 内存带宽饱和
6. 伪并行（Amdahl 定律）

### 8.4 "QPS 上不去但 CPU 不满？"

**典型根因**：
1. I/O 瓶颈（网络/磁盘）
2. 锁竞争（线程在等锁）
3. 系统调用过多
4. 大量 sleep/等待

## 九、C++ 现代特性

### 9.1 move 语义

```cpp
std::vector<int> create() {
    std::vector<int> v = {1, 2, 3};
    return v;  // C++11 起是 move（非 copy）
}

void process(std::vector<int> v);  // 传值
process(std::move(v));  // 显式 move
```

### 9.2 emplace_back vs push_back

```cpp
v.push_back(std::string("hello"));  // 临时对象构造 + move
v.emplace_back("hello");            // 直接在容器内构造，少一次 move
```

### 9.3 小对象优化（SBO/SOO）

- `std::string` SSO：≤15-22 字节栈存储
- `std::function` SBO：小函数对象栈存储
- `std::any` SBO：小类型栈存储

## 十、系统设计

### 10.1 典型高性能架构

```
1. 异步事件驱动（epoll + 线程池）
2. 无锁数据通道（SPSC 队列）
3. 数据本地化（NUMA 感知）
4. 内存池预分配
5. 专核专用（绑定 CPU + 中断绑定）
```

### 10.2 压测与回滚

- 压测必须：固定环境、固定数据、多轮取稳
- 发版必须：先回放压测、灰度、监控 P99 告警
- 优化必须：每次只改一处、对比基线
