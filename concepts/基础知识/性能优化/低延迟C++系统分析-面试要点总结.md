# 低延迟C++系统分析-面试要点总结

## 常见面试问题

### Q1: 如何设计一个低延迟系统？

**回答要点**：
1. **CPU 优化**：CPU 亲和性、NUMA 优化、分支预测优化
2. **内存优化**：内存池、缓存对齐、热冷数据分离
3. **网络优化**：零拷贝、用户态网络栈（DPDK）、批量处理
4. **编译优化**：-O3、LTO、PGO
5. **系统调优**：内核参数、中断绑定、实时调度
6. **无锁编程**：Lock-Free 数据结构，避免锁竞争

### Q2: 如何减少系统调用开销？

**回答要点**：
- 使用用户态网络栈（DPDK）
- 批量处理减少调用次数
- 预分配资源避免运行时分配
- 使用内存映射（mmap）代替 read/write

### Q3: 如何优化缓存性能？

**回答要点**：
- 缓存行对齐，避免 False Sharing
- 热冷数据分离
- SoA（Structure of Arrays）布局
- 数据预取（prefetch）
- 提高数据局部性

### Q4: Lock-Free 编程的优缺点？

**优点**：
- 无锁竞争，性能高
- 避免死锁
- 可扩展性好

**缺点**：
- 实现复杂
- 难以调试
- 可能 ABA 问题
- 内存顺序需要仔细考虑

### Q5: 如何测量微秒级延迟？

**回答要点**：
- 使用 `std::chrono::high_resolution_clock`
- 使用 RDTSC 指令（CPU 周期计数）
- 多次测量取平均值
- 统计延迟直方图（P50/P90/P99）

## 关键技术速查表

| 技术 | 目标 | 典型收益 |
|------|------|---------|
| CPU 亲和性 | 减少线程迁移 | 5-20% 性能提升 |
| 内存池 | 减少分配开销 | 10-100 倍加速 |
| 缓存对齐 | 避免 False Sharing | 2-10 倍性能提升 |
| 零拷贝 | 减少数据拷贝 | 30-50% 延迟降低 |
| DPDK | 用户态网络栈 | 10-100 倍吞吐提升 |
| 编译优化 | 代码优化 | 20-50% 性能提升 |
| 无锁数据结构 | 避免锁竞争 | 2-5 倍并发性能 |

## 性能优化检查清单

**CPU 优化**：
- [ ] 设置 CPU 亲和性
- [ ] NUMA 节点优化
- [ ] 分支预测优化（likely/unlikely）
- [ ] 禁用 CPU 频率缩放
- [ ] 使用 SIMD 指令

**内存优化**：
- [ ] 使用内存池/对象池
- [ ] 缓存行对齐（避免 False Sharing）
- [ ] 热冷数据分离
- [ ] SoA 布局优化
- [ ] 内存预取

**网络优化**：
- [ ] 零拷贝技术
- [ ] 批量处理
- [ ] 用户态网络栈（如 DPDK）
- [ ] Socket 缓冲区优化

**系统优化**：
- [ ] 内核参数调优
- [ ] 中断绑定
- [ ] 实时调度策略
- [ ] 内存锁定
- [ ] 禁用透明大页

**编译优化**：
- [ ] -O3 优化级别
- [ ] -march=native
- [ ] LTO（链接时优化）
- [ ] PGO（Profile-Guided Optimization）
