# 中断线程化与 IRQ 亲和性

See also: [[Linux线程调度]], [[PREEMPT_RT]], [[低延迟C++实时性保障]], [[Linux系统IO调优]]

## 5.1 PREEMPT_RT 下的中断线程化

结合实时文档：

- 使用 `request_threaded_irq()` 将中断处理放在内核线程中：
  - 该线程可以使用实时调度策略（SCHED_FIFO/ SCHED_RR）。
  - 可以像普通线程一样指定 CPU 亲和性、优先级。
- 剩余真正“硬中断”部分尽量短小，只做唤醒工作线程。

调度收益：

- 中断处理行为从“硬件打断 + 关中断”变成“可控线程执行”，减少长时间关抢占区。
- 实现了“中断也受调度器统筹”的目标。

## 5.2 IRQ 亲和性（中断绑定）与线程亲和性的配合

《低延迟 C++ 系统分析》对 IRQ 亲和性的分析要点：

- **IRQ 亲和（/proc/irq/*/smp_affinity）**：指定某个中断只能/优先在哪些 CPU 上被处理。
- **线程亲和（taskset / pthread_setaffinity_np）**：指定用户线程在哪些 CPU 上运行。

调度层面的区别与协同：

- **对象不同**：
  - IRQ 亲和控制 **中断处理上下文** 调度在哪个 CPU 上；
  - 线程亲和控制 **用户线程** 调度在哪个 CPU 上。
- **最佳实践**：
  - 多队列网卡：多个 RX/TX 队列分别对应多个 IRQ；
  - 为每个队列指定独立 CPU（如 queue0→CPU0, queue1→CPU1...）；
  - **将对应业务线程也绑定到同一个 CPU**，做到：
    - “收包中断 → 协议栈处理 → 用户业务线程”全在同一个核完成；
    - 对该核来说，调度路径短、cache 友好、无需跨核通信。

典型配置步骤（抽象化）：

1. `cat /proc/interrupts | grep <网卡名>` 找到每个队列对应的 IRQ。
2. 为每个 IRQ 写入合适的十六进制 mask 到 `/proc/irq/<irq>/smp_affinity`。
3. 关闭 `irqbalance` 服务，防止自动迁移中断。
4. 在应用中，将处理该队列的线程绑定到相同 CPU。

效果：

- 对关键核来说，中断与业务逻辑关系稳定、可分析。
- 对非关键核，可以集中调度系统后台任务与“杂 IRQ”，减少对实时核的干扰。
