# 高频面试题速记

> HashMap、红黑树 vs AVL、一致性哈希、LRU vs LFU、跳表、布隆过滤器、atoi、N 皇后、链表环、堆栈区别等。

---

## Q1: HashMap 实现原理？

- **数据结构**：数组 + 链表（JDK 8+ 链表长度 ≥ 8 转红黑树）
- **put 流程**：计算 hash → 定位桶 → 插入链表尾部（尾插法）
- **扰动函数**：`hash = key.hashCode() ^ (key.hashCode() >>> 16)` 混合高低位，减少碰撞
- **负载因子**：默认 0.75，超过时扩容为 2 倍并 rehash
- **线程安全**：不安全（扩容时头插法可能死循环）；ConcurrentHashMap 用分段锁/CAS 保证安全

## Q2: 红黑树和 AVL 树区别？

- **平衡度**：AVL 更严格（左右子树高度差 ≤ 1），红黑树较松（最长路径 ≤ 2 倍最短路径）
- **查找**：AVL 更快（更平衡），O(log n)
- **插入/删除**：红黑树开销小（旋转少），AVL 可能需要多次旋转
- **适用**：AVL 适合查多写少（数据库索引）；红黑树适合写多查多（`std::map`, Java TreeMap）
- **C++ `std::map`**：红黑树实现，有序关联容器

## Q3: 一致性哈希？

- **问题**：普通哈希取模在增删节点时导致大量 key 迁移
- **方案**：哈希环 0~2³²-1，节点和 key 都哈希到环上，key 顺时针找第一个节点
- **虚拟节点**：每个物理节点复制多个虚拟节点，解决数据倾斜
- **应用**：Redis 集群、分布式缓存、负载均衡

## Q4: LRU 和 LFU 的区别？

- **LRU（最近最少使用）**：时间维度，最近访问的保留。实现：双向链表 + 哈希表 O(1)
- **LFU（最不经常使用）**：频率维度，访问次数最少的淘汰。实现：双哈希表（频率→key列表 + key→频率值）O(log n) 或 O(1)
- **适用场景**：LRU 适合局部性强的访问模式；LFU 适合突发流量后冷热分明的场景

## Q5: 跳表为什么广泛应用？

- **结构**：多层链表，每层是下层的"快速通道"
- **优点**：实现简单（比红黑树好写）；范围查询 O(log n + k) 高效；插入删除 O(log n) 概率保证；无锁并发友好（可 CAS 指针）
- **Redis ZSet**：有序集合用跳表 + 哈希表实现
- **时间/空间**：O(log n) 平均，空间 O(n)

## Q6: 布隆过滤器？

- **原理**：位数组 + k 个哈希函数。插入时 k 个位置置 1；查询时全部为 1 才可能存在
- **特点**：不存在一定不存在（无假阴性），存在不一定存在（有假阳性）
- **不能删除**：多位映射同一位，删一位会影响其他元素（计数 BF 可解决）
- **应用**：缓存穿透拦截、黑名单、爬虫 URL 去重、数据库查询优化
- **参数**：位数组大小 m、哈希函数数 k、预期元素数 n 决定假阳性率

## Q7: 字符串转换整数 (atoi) 要点？

- 跳过前导空格（`while (isspace(*s)) s++`）
- 处理正负号（`int sign = (*s == '-') ? -1 : 1`）
- 逐位累加（`res = res * 10 + (*s - '0')`）
- **溢出判断**：乘 10 前检查 `res > INT_MAX/10` 或 `res == INT_MAX/10 && digit > 7`
- 遇到非数字字符停止

## Q8: N 皇后问题思路？

- **回溯法**：逐行放置皇后，每列检查是否与已放置的冲突
- **冲突判断**：列冲突（col set）、主对角线冲突（`row - col` 常数）、副对角线冲突（`row + col` 常数）
- **复杂度**：时间复杂度 O(n!)，空间 O(n)
- **变体**：N 皇后 II（LeetCode 52）→ 只返回计数，可用位运算加速

## Q9: 如何判断链表有环？

- **快慢指针**：快指针每次 2 步，慢指针每次 1 步，相遇则有环
- **找入口**：相遇后快指针从头开始，慢指针继续，同速再相遇即环入口（数学证明见 04-链表专题.md）
- **复杂度**：O(n) 时间，O(1) 空间

## Q10: 堆和栈的区别？

| 维度 | 栈（Stack） | 堆（Heap） |
|------|------------|-----------|
| 管理方式 | 自动（编译器） | 手动（new/delete） |
| 内存大小 | 小（~8MB Windows，~1MB Linux） | 大（可用内存） |
| 分配速度 | 快（SP 加减） | 慢（查找空闲块） |
| 碎片 | 无（连续分配） | 有（反复分配释放） |
| 存放内容 | 局部变量、函数参数、返回地址 | 动态分配对象 |
| 生命周期 | 函数返回即释放 | 直到 delete |

## Q11: 排序算法选型？

- **通用排序** → `std::sort`（内省排序 = 快排 + 堆排保底 + 插入排序小数组）
- **需要稳定** → `std::stable_sort`（归并排序）或手写归并
- **Top-K / 优先级调度** → 堆排序 O(n log k)，空间 O(k)
- **数据范围小（≤ 10⁷）** → 计数排序 O(n + k)，线性时间
- **链表排序** → 归并排序（链表不支持随机访问，归并天然适合）
- **近乎有序** → 插入排序，可降到 O(n)
- **大量重复值** → 三路快排（荷兰国旗问题），避免退化为 O(n²)
