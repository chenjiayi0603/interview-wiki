## 一、Socket 编程基础

### 1.1 TCP Server 模板

```cpp
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>

int create_tcp_server(int port) {
    int sockfd = socket(AF_INET, SOCK_STREAM, 0);
    int opt = 1;
    setsockopt(sockfd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));

    struct sockaddr_in addr;
    memset(&addr, 0, sizeof(addr));
    addr.sin_family = AF_INET;
    addr.sin_addr.s_addr = INADDR_ANY;
    addr.sin_port = htons(port);

    bind(sockfd, (struct sockaddr*)&addr, sizeof(addr));
    listen(sockfd, SOMAXCONN);
    return sockfd;
}

int main() {
    int serverfd = create_tcp_server(8080);
    while (true) {
        struct sockaddr_in client;
        socklen_t len = sizeof(client);
        int clientfd = accept(serverfd, (struct sockaddr*)&client, &len);
        // 处理 clientfd...
        close(clientfd);
    }
}
```

### 1.2 TCP Client 模板

```cpp
int create_tcp_client(const char* ip, int port) {
    int sockfd = socket(AF_INET, SOCK_STREAM, 0);

    struct sockaddr_in addr;
    memset(&addr, 0, sizeof(addr));
    addr.sin_family = AF_INET;
    addr.sin_port = htons(port);
    inet_pton(AF_INET, ip, &addr.sin_addr);

    connect(sockfd, (struct sockaddr*)&addr, sizeof(addr));
    return sockfd;
}
```

### 1.3 UDP Server 模板

```cpp
int create_udp_server(int port) {
    int sockfd = socket(AF_INET, SOCK_DGRAM, 0);

    struct sockaddr_in addr;
    memset(&addr, 0, sizeof(addr));
    addr.sin_family = AF_INET;
    addr.sin_addr.s_addr = INADDR_ANY;
    addr.sin_port = htons(port);

    bind(sockfd, (struct sockaddr*)&addr, sizeof(addr));
    return sockfd;
}

// UDP 收发（无连接）
char buf[1024];
struct sockaddr_in client;
socklen_t len = sizeof(client);
ssize_t n = recvfrom(sockfd, buf, sizeof(buf), 0,
                     (struct sockaddr*)&client, &len);
sendto(sockfd, buf, n, 0, (struct sockaddr*)&client, len);
```

**UDP connect 的作用**：
- 调用 connect 指定默认目标地址，之后可用 send/recv 替代 sendto/recvfrom
- 过滤非预期源 IP 的包
- 可收到 ICMP 错误（如端口不可达）

## 二、I/O 多路复用

### 2.1 select / poll

| 特性 | select | poll |
|------|--------|------|
| 监视 fd 数 | FD_SETSIZE（通常 1024） | 无上限 |
| 数据结构 | fd_set 位图 | pollfd 数组 |
| 用户态→内核态 | 每次传递整个 fd_set | 类似 |
| 就绪通知 | 修改 fd_set | 修改 revents 字段 |
| 实现复杂度 | O(n) 遍历 | O(n) 遍历 |

```cpp
// select
fd_set readfds;
FD_ZERO(&readfds);
FD_SET(serverfd, &readfds);
struct timeval timeout = {1, 0};
int n = select(maxfd + 1, &readfds, NULL, NULL, &timeout);
if (FD_ISSET(serverfd, &readfds)) { /* 处理 */ }

// poll
struct pollfd fds[1024];
fds[0].fd = serverfd;
fds[0].events = POLLIN;
int n = poll(fds, 1, 1000);
if (fds[0].revents & POLLIN) { /* 处理 */ }
```

### 2.2 epoll

```cpp
#include <sys/epoll.h>

// 创建
int epfd = epoll_create1(0);

// 添加事件
struct epoll_event ev;
ev.events = EPOLLIN | EPOLLET;
ev.data.fd = serverfd;
epoll_ctl(epfd, EPOLL_CTL_ADD, serverfd, &ev);

// 等待事件
struct epoll_event events[1024];
while (true) {
    int n = epoll_wait(epfd, events, 1024, -1);
    for (int i = 0; i < n; ++i) {
        int fd = events[i].data.fd;
        if (events[i].events & EPOLLIN) { /* 读事件 */ }
        if (events[i].events & EPOLLOUT) { /* 写事件 */ }
    }
}
```

### 2.3 epoll LT vs ET

| 模式 | 水平触发（LT） | 边缘触发（ET） |
|------|---------------|---------------|
| 通知条件 | 只要条件满足就通知 | 状态变化时通知一次 |
| 读取要求 | 一次没读完下次还会通知 | 必须循环读到 EAGAIN |
| 性能 | 较低（重复通知） | 更高（减少系统调用） |
| 代码复杂度 | 简单 | 较复杂（需非阻塞 + 循环） |

**ET 模式正确读取**：
```cpp
// 必须设置为非阻塞
while (true) {
    ssize_t n = read(fd, buf, sizeof(buf));
    if (n > 0) {
        // 处理数据
    } else if (n == 0) {
        break;  // 对端关闭
    } else {
        if (errno == EAGAIN) break;  // 读完
        // 其他错误
    }
}
```

### 2.4 epoll vs select/poll 优势

| 方面 | select/poll | epoll |
|------|-------------|-------|
| fd 管理 | 每次传递全部 fd | 红黑树管理，增删改 O(log n) |
| 就绪返回 | 返回全部 fd，需遍历 | 仅返回就绪 fd，O(1) 获取 |
| 触发模式 | 仅水平触发 | LT + ET |
| 扩展性 | fd 越多性能越差 | fd 增长性能基本线性 |
| 跨平台 | 几乎所有平台 | Linux 专用 |

## 三、Reactor 模型

```cpp
class Reactor {
    int epfd_;
    std::unordered_map<int, Channel*> channels_;

public:
    void addFd(int fd, Channel* ch) {
        struct epoll_event ev;
        ev.events = ch->events();
        ev.data.ptr = ch;
        epoll_ctl(epfd_, EPOLL_CTL_ADD, fd, &ev);
        channels_[fd] = ch;
    }

    void loop() {
        struct epoll_event events[1024];
        while (true) {
            int n = epoll_wait(epfd_, events, 1024, -1);
            for (int i = 0; i < n; ++i) {
                Channel* ch = (Channel*)events[i].data.ptr;
                ch->handle(events[i].events);
            }
        }
    }
};
```

**Reactor 变体**：

| 模式 | 说明 |
|------|------|
| **单 Reactor + 单线程** | 所有 I/O 和业务在单线程处理（Redis） |
| **单 Reactor + 线程池** | I/O 在 Reactor 线程，业务在线程池 |
| **多 Reactor + 线程池** | 主 Reactor 处理 accept，子 Reactor 处理 I/O（Netty、Nginx） |

## 四、线程池

```cpp
class ThreadPool {
    std::vector<std::thread> workers_;
    std::queue<std::function<void()>> tasks_;
    std::mutex mtx_;
    std::condition_variable cv_;
    bool stop_ = false;

public:
    ThreadPool(size_t n) {
        for (size_t i = 0; i < n; ++i) {
            workers_.emplace_back([this] {
                while (true) {
                    std::function<void()> task;
                    {
                        std::unique_lock<std::mutex> lock(mtx_);
                        cv_.wait(lock, [this] { return stop_ || !tasks_.empty(); });
                        if (stop_ && tasks_.empty()) return;
                        task = std::move(tasks_.front());
                        tasks_.pop();
                    }
                    task();
                }
            });
        }
    }

    template<typename F>
    void enqueue(F&& f) {
        {
            std::lock_guard<std::mutex> lock(mtx_);
            tasks_.emplace(std::forward<F>(f));
        }
        cv_.notify_one();
    }

    ~ThreadPool() {
        stop_ = true;
        cv_.notify_all();
        for (auto& t : workers_) t.join();
    }
};
```

## 五、libev 事件库

### 5.1 核心接口

| Watcher 类型 | 结构体 | 事件类型 | 用途 |
|-------------|--------|----------|------|
| I/O | ev_io | EV_READ / EV_WRITE | 监控 fd 读写 |
| 定时器 | ev_timer | EV_TIMEOUT | 定时回调 |
| 信号 | ev_signal | EV_SIGNAL | 信号处理 |
| 空闲 | ev_idle | EV_IDLE | 空闲时回调 |
| 跨线程唤醒 | ev_async | — | 线程通知主循环 |

### 5.2 libev TCP Echo Server 完整代码

```c
#include <ev.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <fcntl.h>
#include <netinet/in.h>
#include <sys/socket.h>

#define PORT 12345

static void set_nonblock(int fd) {
    int flags = fcntl(fd, F_GETFL, 0);
    if (flags < 0) return;
    fcntl(fd, F_SETFL, flags | O_NONBLOCK);
}

static void client_cb(struct ev_loop *loop, ev_io *w, int revents) {
    if (revents & EV_READ) {
        char buf[1024];
        ssize_t n = read(w->fd, buf, sizeof(buf));
        if (n <= 0) {
            close(w->fd);
            ev_io_stop(loop, w);
            free(w);
        } else {
            write(w->fd, buf, n);
        }
    }
}

static void accept_cb(struct ev_loop *loop, ev_io *w, int revents) {
    if (revents & EV_READ) {
        struct sockaddr_in client_addr;
        socklen_t len = sizeof(client_addr);
        int client_fd = accept(w->fd, (struct sockaddr*)&client_addr, &len);
        if (client_fd < 0) return;
        set_nonblock(client_fd);

        ev_io *client_w = (ev_io*)malloc(sizeof(ev_io));
        ev_io_init(client_w, client_cb, client_fd, EV_READ);
        ev_io_start(loop, client_w);
    }
}

int main() {
    int listen_fd = socket(AF_INET, SOCK_STREAM, 0);
    set_nonblock(listen_fd);

    struct sockaddr_in addr;
    memset(&addr, 0, sizeof(addr));
    addr.sin_family = AF_INET;
    addr.sin_port = htons(PORT);
    addr.sin_addr.s_addr = INADDR_ANY;
    bind(listen_fd, (struct sockaddr*)&addr, sizeof(addr));
    listen(listen_fd, 128);

    struct ev_loop *loop = EV_DEFAULT;
    ev_io listen_w;
    ev_io_init(&listen_w, accept_cb, listen_fd, EV_READ);
    ev_io_start(loop, &listen_w);

    ev_run(loop, 0);
    close(listen_fd);
    return 0;
}
// 编译: gcc tcp_echo.c -lev -o tcp_echo
```

## 六、gRPC vs libev+protobuf

### 6.1 架构对比

| 方面 | gRPC | libev + protobuf |
|------|------|------------------|
| 底层网络 | HTTP/2（多路复用/流控） | TCP/UDP，完全自控 |
| 序列化 | protobuf（默认） | protobuf / 自定义 |
| 接口生成 | proto 一键生成 | 全部手写 |
| 异步处理 | 内建 CompletionQueue | 需手工协作 |
| 客户端/负载均衡 | 内建 | 需自实现 |
| 双向流 | 原生支持 | 需设计协议 |
| 生态 | 丰富（追踪、监控、认证） | 需集成 |

### 6.2 性能对比

| 框架 | QPS（单机长连接小包） | 延迟 P99（µs） | 编程复杂度 |
|------|---------------------|----------------|------------|
| libev+protobuf | 50万~100万+ | 30~150 | 很高 |
| gRPC C++（异步） | 15万~60万 | 150~600 | 中等 |
| gRPC C++（同步） | 5万~15万 | 200~1000 | 低~中等 |
| nginx upstream | 50万~150万+ | 100~300 | 低 |

**性能极限**：高度手写优化（libev） ≥ nginx（仅转发） > gRPC（异步） > gRPC（同步）

### 6.3 选型建议

| 场景 | 推荐方案 |
|------|----------|
| 分布式微服务、多语言互通 | **gRPC** |
| 极致性能、自定义协议 | **libev+protobuf** |
| HTTP 反向代理、网关 | **nginx** |
| 资源受限、嵌入式 | **libev** |
| 标准业务系统 | **gRPC**（开发效率优先） |

## 七、高性能服务器设计要点

1. **I/O 多路复用** — epoll ET 模式
2. **Reactor 模式** — 事件驱动架构
3. **线程池** — 分离 I/O 与业务处理
4. **无锁数据结构** — 减少锁竞争
5. **零拷贝** — sendfile、mmap、splice
6. **内存池** — 减少内存分配开销
7. **高效序列化** — protobuf / flatbuffers
8. **连接池** — 复用连接，避免频繁建连
9. **异步日志** — 避免 I/O 阻塞主流程
10. **应用层心跳** — 快速检测死连接

## 八、面试高频追问

### Q1: epoll 的 LT 和 ET 模式区别？如何选择？

| 模式 | 通知方式 | 编码复杂度 | 性能 |
|:----:|---------|:---------:|:----:|
| LT | 有数据就通知 | 简单 | 一般 |
| ET | 状态变化才通知 | 复杂（需非阻塞+循环读） | 更高 |

**选型**：高并发服务器（Nginx/Redis）用 ET；普通场景用 LT 足够。

### Q2: select/poll/epoll 对比？

| 特性 | select | poll | epoll |
|:----:|:------:|:----:|:-----:|
| fd 上限 | 1024 | 无限制 | 无限制 |
| 遍历 | O(n) 全量 | O(n) 全量 | O(1) 仅就绪 |
| 跨平台 | 几乎所有 | POSIX | Linux 专用 |
| 触发模式 | LT | LT | LT+ET |

### Q3: Reactor 和 Proactor 区别？
- **Reactor**：就绪通知 → 用户主动读/写（同步 I/O）
- **Proactor**：操作完成通知 → 用户直接处理数据（异步 I/O，如 Windows IOCP）
- Asio 用 Proactor 模型抽象，但 Linux 下基于 epoll（Reactor）模拟

### Q4: 100 万并发连接服务器需要什么？
- **系统层面**：`fs.file-max` 增大、`ulimit -n` 调大、`tcp_mem` 增大、TIME_WAIT 复用
- **程序层面**：epoll ET + Reactor + 线程池 + 内存池 + 异步日志
- **内存估算**：每连接约 10-50KB（接收/发送缓冲区），100 万约 10-50GB

### Q5: UDP 如何保证可靠性？
应用层实现：seq/ack 确认重传、超时重传、滑动窗口、拥塞控制 → **相当于在 UDP 上实现 TCP**（如 QUIC 协议）
