# TCP 与 UDP 速查

> TCP/UDP 开销对比、有效传输比例、头部字段、流量控制与拥塞控制速查总结。

See also: [[TCP协议|TCP 协议]]

---

## 一、TCP vs UDP 开销与有效传输比例

### 1.1 头部开销

| 协议 | 固定头部 | 可选字段 | 典型总开销 |
|------|----------|----------|------------|
| **UDP** | 8 字节 | 无 | 8 字节 |
| **TCP** | 20 字节 | 最多 40 字节 | 20～60 字节 |

### 1.2 额外开销

| 方面 | TCP | UDP |
|------|-----|-----|
| 连接建立 | 三次握手（2 RTT） | 无 |
| 连接释放 | 四次挥手（1～2 RTT） | 无 |
| 确认 | ACK 包 | 无 |
| 重传 | 丢包重传 | 无（应用自己处理） |
| 拥塞控制 | 有 | 无 |
| 流量控制 | 有 | 无 |
| 状态维护 | 连接状态、序列号等 | 无 |

### 1.3 同等数据量下有效传输比例

| 有效数据量 | UDP 有效比例 | TCP 有效比例 | 备注 |
|------------|--------------|--------------|------|
| 100 字节 | 92.6% | 83.3% | 小包差异明显 |
| 64 字节（RPC 小包） | 88.9% | 76.2% | UDP 约高 10%+ |
| 1500 字节 | 99.5% | 98.7% | 大包差异较小 |

**结论**：小包场景 UDP 有效比例约高 10%～20%；大包时两者都 >98%。若计入 TCP 的 ACK、握手，有效比例再降几个点。

### 1.4 面向连接 vs 无连接（数据报）

| 维度 | 面向连接（TCP） | 无连接（UDP） |
|------|-----------------|---------------|
| **连接** | 需先建连接再传 | 直接发，无连接状态 |
| **数据单位** | 字节流（stream），无边界 | 独立数据报，有边界 |
| **可靠性** | 有重传、顺序保证 | 不保证 |
| **典型场景** | HTTP、FTP、数据库 | DNS、视频流、游戏 |

## 二、UDP 头部（8 字节固定）

| 字段 | 长度 | 说明 |
|------|------|------|
| **源端口** (Source Port) | 16 bit | 发送方端口 |
| **目的端口** (Destination Port) | 16 bit | 接收方端口 |
| **长度** (Length) | 16 bit | UDP 头 + 数据总字节数（最小 8） |
| **校验和** (Checksum) | 16 bit | 头 + 数据 + 伪首部，可为 0 |

---

## 三、TCP 头部（最小 20 字节，最多 60 字节）

### 3.1 固定部分（20 字节）

| 字段 | 长度 | 说明 |
|------|------|------|
| **源端口** | 16 bit | 发送方端口 |
| **目的端口** | 16 bit | 接收方端口 |
| **序列号** (Sequence Number) | 32 bit | 本段第一个字节序号 |
| **确认号** (Acknowledgment Number) | 32 bit | 期望对方下次发的序号 |
| **数据偏移** (Data Offset) | 4 bit | 头部长度（4 字节单位），最小 5 |
| **保留** | 6 bit | 填 0 |
| **标志位** (Flags) | 6 bit | URG/ACK/PSH/RST/SYN/FIN |
| **窗口大小** (Window Size) | 16 bit | 接收窗口，流量控制 |
| **校验和** | 16 bit | 头 + 数据 + 伪首部 |
| **紧急指针** | 16 bit | 与 URG 配合 |

### 3.2 标志位

| 位 | 名称 | 含义 |
|----|------|------|
| URG | Urgent | 紧急指针有效 |
| ACK | Acknowledgment | 确认号有效 |
| PSH | Push | 尽快交付应用层 |
| RST | Reset | 重置连接 |
| SYN | Synchronize | 建连 |
| FIN | Finish | 释放连接 |

### 3.3 可选部分（Options，最多 40 字节）

| 选项 | 说明 |
|------|------|
| MSS | 最大段长度，握手时协商 |
| 窗口扩大 | 窗口按比例放大 |
| 时间戳 | RTT、PAWS |
| SACK 允许 / SACK 块 | 选择性确认 |

**两者均为传输层（Transport Layer）协议。**

## 四、流量控制 vs 拥塞控制

### 4.1 核心区别

| 维度 | 流量控制 | 拥塞控制 |
|------|----------|----------|
| **关心谁** | 接收方的处理能力 | 网络的承载能力 |
| **解决什么问题** | 发太快，接收方缓冲区撑爆 | 发太多，网络拥堵丢包 |
| **依据什么** | 接收方通告的窗口 rwnd | 网络拥塞信号（丢包、超时等） |
| **限制对象** | 发送速率不能超过接收方处理能力 | 发送速率不能超过网络承载能力 |

### 4.2 流量控制（Flow Control）

- **目标**：防止发送方发太快，把接收方缓冲区撑满
- **机制**：接收方在 TCP 头「窗口」字段通告还能接收多少；发送方据此限速
- **实现**：滑动窗口 + rwnd

### 4.3 拥塞控制（Congestion Control）

- **目标**：防止发送方把网络灌满，导致拥塞、丢包
- **机制**：通过丢包、超时等推断拥塞，用 cwnd 限制未确认数据量
- **阶段**：慢启动 → 拥塞避免 → 快速重传 → 快速恢复

| 阶段 | 触发 | 行为 |
|------|------|------|
| 慢启动 | 建连 / 超时 | cwnd 指数增长 |
| 拥塞避免 | 到达 ssthresh | cwnd 线性 +1/RTT |
| 快重传 | 3 个重复 ACK | 立即重传 |
| 快恢复 | 3 个重复 ACK | cwnd 减半，进入拥塞避免 |
| 超时 | RTO | cwnd=1，重新慢启动 |

### 4.4 实际发送窗口

**实际发送窗口 = min(cwnd, rwnd)**
