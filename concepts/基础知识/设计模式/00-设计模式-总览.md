## 二、设计模式全景图

### 2.1 创建型模式（Creational）

| 模式 | 核心思想 | 关键字 |
|------|---------|--------|
| Singleton | 全局唯⼀实例 | `static`、线程安全、Meyers |
| Factory Method | 一个创建接口，子类决定实例化哪个类 | `virtual create()` |
| Abstract Factory | 创建一整个产品族 | 配套产品、换⼯厂换整套 |
| Builder | 分步构建复杂对象 | 链式调用、`build()` |
| Prototype | 克隆已有对象 | `clone()`、深拷⻉ |

### 2.2 结构型模式（Structural）

| 模式 | 核心思想 | 关键字 |
|------|---------|--------|
| Adapter | 兼容不匹配的接口 | 类适配器/对象适配器 |
| Decorator | 递归嵌套增强行为 | 包装、叠加 |
| Proxy | 控制对目标的访问 | 延迟加载、权限、远程 |
| Facade | 统一的高层接口 | 简化子系统调用 |
| Bridge | 抽象与实现分离 | 两个独⽴的继承层次 |

### 2.3 行为型模式（Behavioral）

| 模式 | 核心思想 | 关键字 |
|------|---------|--------|
| Observer | 一对多通知 | `attach/detach/notify` |
| Strategy | 算法族可互换 | 运行时替换策略 |
| Command | 请求封装为对象 | 撤销/重做、队列 |
| Template Method | 骨架固定，步骤可重写 | ⾮虚公共方法 + 虚步骤 |
| State | 状态决定行为 | 状态转移、有限状态机 |
| Chain of Responsibility | 请求链式传递 | 每个处理器决定处理或传递 |
