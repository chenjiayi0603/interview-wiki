# 创建型模式

> 创建型模式关注对象的创建机制，使系统与对象的创建方式解耦。

---

## 一、单例模式（Singleton）

确保一个类只有一个实例，并提供全局访问点。

### 1.1 懒汉 + 双检锁（线程安全）

```cpp
class Singleton {
private:
    static std::atomic<Singleton*> instance;
    static std::mutex mtx;
    Singleton() = default;
public:
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;

    static Singleton* getInstance() {
        auto* p = instance.load(std::memory_order_acquire);
        if (!p) {
            std::lock_guard<std::mutex> lk(mtx);
            p = instance.load(std::memory_order_relaxed);
            if (!p) {
                p = new Singleton();
                instance.store(p, std::memory_order_release);
            }
        }
        return p;
    }
};
```

### 1.2 C++11 局部静态变量（推荐，Meyers Singleton）

```cpp
// C++11 标准保证局部静态变量初始化线程安全
class Singleton {
private:
    Singleton() = default;
public:
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;

    static Singleton& getInstance() {
        static Singleton instance;  // 首次调⽤时构造
        return instance;
    }
};
```

### 1.3 适用场景与权衡

**适用**：日志系统、配置管理器、数据库连接池、线程池
**优点**：节省资源、全局共享、延迟加载
**缺点**：违反单一职责（同时管理自身生命周期）、全局状态在多线程下需加锁、难以单元测试（mock 困难）

### 1.4 面试考点

**Q：单例模式的线程安全实现？**
- 饿汉：程序启动时创建，线程安全（但启动慢、浪费资源）
- 懒汉双检锁：`atomic` + `mutex`，防指令重排与重复创建
- C++11 局部静态（Meyers）：标准保证线程安全，日常最省事

## 二、简单工厂 / 工厂方法

### 2.1 简单工厂

```cpp
class Product {
public:
    virtual ~Product() = default;
    virtual void operation() = 0;
};

class ConcreteProductA : public Product {
public:
    void operation() override { }
};

class SimpleFactory {
public:
    Product* create(const std::string& type) {
        if (type == "A") return new ConcreteProductA();
        if (type == "B") return new ConcreteProductB();
        return nullptr;
    }
};
```

### 2.2 工厂方法

定义一个创建对象的接口，让子类决定实例化哪个类。

```cpp
class Factory {
public:
    virtual Product* createProduct() = 0;
};

class ConcreteFactoryA : public Factory {
public:
    Product* createProduct() override { return new ConcreteProductA(); }
};
```

### 2.3 适用场景与权衡

**简单工厂**：对象创建逻辑简单、类型少。**缺点**：违反 OCP（加类型要改工厂类）。
**工厂方法**：不知道具体实现类，由子类决定。**优点**：符合 OCP，加新产品只需加子类。**缺点**：每加一种产品就要加一个工厂子类。
**抽象工厂**：需要创建配套产品族（如跨平台 UI：WinButton + WinCheckbox 配套使用）。**优点**：保证同一族产品的一致。**缺点**：扩展产品族困难（要改抽象工厂接口）。

### 2.4 抽象工厂

提供一个创建一整个产品族的接口，客户端换工厂即可换整套产品风格。

```cpp
class AbstractFactory {
public:
    virtual ProductA* createProductA() = 0;
    virtual ProductB* createProductB() = 0;
};

class WinFactory : public AbstractFactory {
    ProductA* createProductA() override { return new WinProductA(); }
    ProductB* createProductB() override { return new WinProductB(); }
};

class MacFactory : public AbstractFactory {
    ProductA* createProductA() override { return new MacProductA(); }
    ProductB* createProductB() override { return new MacProductB(); }
};
```

### 2.5 面试考点：工厂方法 vs 抽象工厂

| 对比 | 工厂方法 | 抽象工厂 |
|------|---------|---------|
| 产出 | **一种**产品类型 | **一族**配套产品（产品族） |
| 扩展 | 加一种产品只需加一个子类 | 加一个产品族需加一个⼯厂子类 |
| 增加新产品 | 不破坏现有代码 | 修改抽象工厂接口 |
| 典型场景 | Button 的多种平台实现 | UI 主题：Button + Checkbox + ScrollBar |

## 三、建造者模式（Builder）

分步构建复杂对象，使同样的构建过程可以创建不同的表示。

**适用**：构造函数参数过多（> 4 个）且有大量可选参数时，Builder 比多重构造函数更优雅。**优点**：链式调用可读性好，参数顺序无依赖。**缺点**：增加了类的数量。**变体**：与 Fluent API 结合使用。

```cpp
class Pizza {
private:
    std::string dough;
    std::string sauce;
    std::string topping;
public:
    class Builder {
        Pizza pizza;
    public:
        Builder& setDough(const std::string& d) { pizza.dough = d; return *this; }
        Builder& setSauce(const std::string& s) { pizza.sauce = s; return *this; }
        Builder& setTopping(const std::string& t) { pizza.topping = t; return *this; }
        Pizza build() { return std::move(pizza); }
    };

    static Builder create() { return Builder(); }
};

// 使⽤
Pizza p = Pizza::create()
    .setDough("thin")
    .setSauce("tomato")
    .setTopping("cheese")
    .build();
```

## 四、原型模式（Prototype）

通过复制已有对象来创建新对象，而不是通过 new。

```cpp
class Prototype {
public:
    virtual Prototype* clone() const = 0;
    virtual ~Prototype() = default;
};

class ConcretePrototype : public Prototype {
    int data;
public:
    ConcretePrototype(int d) : data(d) {}
    ConcretePrototype(const ConcretePrototype& other) : data(other.data) {}

    Prototype* clone() const override {
        return new ConcretePrototype(*this);  // 调用拷⻉构造函数
    }
};
```

## 五、创建型模式对比

| 模式 | 核心问题 | 解决方式 |
|------|---------|---------|
| Singleton | 全局唯一实例 | 静态实例 + 禁止拷⻉ |
| Factory Method | 不知道要创建哪个具体类 | 子类决定创建哪个类 |
| Abstract Factory | 需要创建配套产品族 | 一个⼯厂类负责一整套产品 |
| Builder | 复杂对象的多步骤构建 | 分步构建，链式调用 |
| Prototype | 避免重复创建的开销 | 克隆已有对象 |
