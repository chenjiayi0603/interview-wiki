# 结构型模式

> 结构型模式关注类和对象的组合，通过继承或组合形成更大结构。

---

## 一、适配器模式（Adapter）

将一个类的接口转换成客户期望的另一个接口，解决接口不兼容问题。

**适用**：想复用已有的类但接口不匹配；需要整合多个不兼容的第三方库。**权衡**：类适配器（继承）直接、简单但不够灵活；**对象适配器（组合）推荐**，更灵活、可适配子类。**变体**：双向适配器（同时实现 Target 和 Adaptee 接口）。

### 1.1 类适配器（继承）

```cpp
class Target {
public:
    virtual void request() = 0;
};

class Adaptee {
public:
    void specificRequest() { /* 特殊接口 */ }
};

class Adapter : public Target, private Adaptee {
public:
    void request() override {
        specificRequest();  // 转换接口
    }
};
```

### 1.2 对象适配器（组合，推荐）

```cpp
class Adapter : public Target {
    Adaptee* adaptee;
public:
    Adapter(Adaptee* a) : adaptee(a) {}
    void request() override {
        adaptee->specificRequest();
    }
};
```

## 二、装饰器模式（Decorator）

动态地给对象添加额外职责，比继承更灵活（避免类爆炸）。

**适用**：运行时按需叠加能力，如日志、缓存、权限、数据压缩。**权衡**：装饰器嵌套过多增加调试复杂度；装饰器与组件接口必须一致（is-a 关系）。**注意**：装饰器链中对象相等性比较困难。

```cpp
class Component {
public:
    virtual ~Component() = default;
    virtual std::string operation() = 0;
};

class ConcreteComponent : public Component {
public:
    std::string operation() override { return "Concrete"; }
};

class Decorator : public Component {
protected:
    Component* component;
public:
    Decorator(Component* c) : component(c) {}
};

class ConcreteDecoratorA : public Decorator {
public:
    ConcreteDecoratorA(Component* c) : Decorator(c) {}
    std::string operation() override {
        return "A(" + component->operation() + ")";
    }
};

class ConcreteDecoratorB : public Decorator {
public:
    ConcreteDecoratorB(Component* c) : Decorator(c) {}
    std::string operation() override {
        return "B(" + component->operation() + ")";
    }
};

// 使⽤：运行时嵌套包装
// Component* c = new ConcreteDecoratorB(
//     new ConcreteDecoratorA(
//         new ConcreteComponent()
//     )
// );
// c->operation() = "B(A(Concrete))"
```

### 面试考点：装饰器 vs 继承

| 对比 | 装饰器 | 继承 |
|------|--------|------|
| 时机 | 运行时动态组合 | 编译期静态绑定 |
| 类爆炸 | ❌ 避免：N 个功能只需 N 个装饰器 | ✅ 每个组合一个子类 |
| 叠加顺序 | 任意排序，灵活 | 固定顺序 |
| 适用 | 按需叠加能力 | 明确的层次关系 |

## 三、代理模式（Proxy）

为另一个对象提供一个替身以控制对它的访问（延迟加载、权限、远程等）。

**适用**：延迟加载（虚拟代理）、访问控制（保护代理）、远程调用（远程代理）、缓存（缓存代理）。**变体**：动态代理（运行期生成，Java 反射/C++ 模板）。**权衡**：增加了额外间接层，可能影响性能。

```cpp
class Subject {
public:
    virtual void request() = 0;
};

class RealSubject : public Subject {
public:
    void request() override { /* 真实操作 */ }
};

// 通用代理
class Proxy : public Subject {
    RealSubject* real;
public:
    ~Proxy() { delete real; }
    void request() override {
        if (!real) real = new RealSubject();
        // 权限检查 / 缓存 / 日志
        real->request();
    }
};

// 保护代理
class AccessProxy : public Subject {
    Subject* real;
    std::string user;
public:
    bool hasAccess() { return user == "admin"; }
    void request() override {
        if (!hasAccess()) throw std::runtime_error("Access denied");
        real->request();
    }
};
```

### 面试考点：代理 vs 装饰器

| 对比 | 代理 | 装饰器 |
|------|------|--------|
| 意图 | **控制访问** | **增强行为** |
| 对外表现 | 尽量像本体（透明） | 调⽤方知道包了一层也无妨 |
| 典型 | 延迟加载、权限、远程、缓存 | 加日志、加边框、加滚动条 |
| 比喻 | "替你挡事" | "替你加料" |

## 四、外观模式（Facade）

为子系统提供统一的高层接口，简化客户端使⽤。

**适用**：简化复杂子系统的调用入口；作为系统分层边界（层与层之间用 Facade 通信）。**权衡**：Facade 可能成为"上帝对象"耦合所有子系统；不限制客户端直接访问子系统。**变体**：Facade vs Mediator——Facade 对外简化，Mediator 对内协调。

```cpp
class CPU {
public:
    void freeze() { }
    void jump(long addr) { }
    void execute() { }
};

class Memory {
public:
    void load(long pos, const char* data) { }
};

class HardDrive {
public:
    char* read(long lba, int size) { return nullptr; }
};

class ComputerFacade {  // 统一接口
    CPU* cpu;
    Memory* memory;
    HardDrive* disk;
public:
    ComputerFacade() {
        cpu = new CPU();
        memory = new Memory();
        disk = new HardDrive();
    }

    void start() {  // 简化调⽤
        cpu->freeze();
        memory->load(0, disk->read(0, 1024));
        cpu->jump(0);
        cpu->execute();
    }
};

// Client 只需调⽤ start()，不需了解内部细节
```

## 五、桥接模式（Bridge）

将抽象部分与实现部分分离，使两者可以独立变化。

**适用**：两个维度独立变化（如 设备 × 遥控器、消息类型 × 发送方式、图形 × 渲染API）。**权衡**：增加系统复杂度；对仅单一维度的场景过度设计。**对比**：Bridge vs Adapter——Bridge 是设计时就考虑分离，Adapter 是事后接口兼容。

```cpp
// 实现部分（独⽴变化）
class Device {
public:
    virtual bool isEnabled() = 0;
    virtual void enable() = 0;
    virtual void disable() = 0;
    virtual int getVolume() = 0;
    virtual void setVolume(int) = 0;
};

class TV : public Device {
    bool on = false;
    int volume = 30;
public:
    bool isEnabled() override { return on; }
    void enable() override { on = true; }
    void disable() override { on = false; }
    int getVolume() override { return volume; }
    void setVolume(int v) override { volume = v; }
};

// 抽象部分（可以扩展）
class RemoteControl {
protected:
    Device* device;
public:
    RemoteControl(Device* d) : device(d) {}
    virtual void togglePower() {
        if (device->isEnabled()) device->disable();
        else device->enable();
    }
    virtual void volumeUp() {
        device->setVolume(device->getVolume() + 10);
    }
};

class AdvancedRemote : public RemoteControl {
public:
    AdvancedRemote(Device* d) : RemoteControl(d) {}
    void mute() { device->setVolume(0); }
};

// 两个维度独立扩展：RemoteControl 层次 | Device 层次
```

## 六、结构型模式对比

| 模式 | 核心意图 | 组合 vs 继承 |
|------|---------|:------------:|
| Adapter | 接口转换 | 对象适配器用组合 |
| Decorator | 动态增强 | 组合（嵌套包装） |
| Proxy | 控制访问 | 组合 |
| Facade | 统⼀入口 | 组合 |
| Bridge | 抽象与实现分离 | 组合 + 两个继承层次 |
