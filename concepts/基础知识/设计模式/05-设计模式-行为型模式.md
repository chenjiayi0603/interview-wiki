# 行为型模式

> 行为型模式关注对象之间的通信和职责分配。

---

## 一、观察者模式（Observer）

定义一对多依赖关系，当一个对象状态改变时，所有依赖对象自动收到通知。

**适用**：事件驱动系统、UI 事件监听、状态监控、消息推送。**权衡**：Subject 直接持有 Observer 列表导致耦合；通知顺序不可控；循环通知可能导致死循环。**注意**：多线程场景下通知时需保证 Observer 列表不被修改（用 copy-on-write 或读写锁）。

### 1.1 标准实现

```cpp
class Observer {
public:
    virtual void update(const std::string& msg) = 0;
    virtual ~Observer() = default;
};

class Subject {
private:
    std::vector<Observer*> observers;
public:
    void attach(Observer* o) { observers.push_back(o); }
    void detach(Observer* o) {
        observers.erase(std::remove(observers.begin(), observers.end(), o), observers.end());
    }
    void notify(const std::string& msg) {
        for (auto* o : observers) o->update(msg);
    }
};

class ConcreteObserver : public Observer {
    std::string name;
public:
    ConcreteObserver(const std::string& n) : name(n) {}
    void update(const std::string& msg) override {
        std::cout << name << " received: " << msg << std::endl;
    }
};
```

### 1.2 观察者 vs 发布-订阅

| 对比 | 观察者 | 发布-订阅 |
|------|--------|----------|
| 耦合度 | Subject 直接持有 Observer | 发布者与订阅者不互相认识 |
| 中间代理 | 无 | Broker / 事件总线 |
| 跨进程 | 不支持 | 支持 |
| 松耦合 | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ |

```cpp
// 发布订阅（极简）：中间 map 主题 -> 回调
using Handler = std::function<void(const std::string& payload)>;
std::unordered_map<std::string, std::vector<Handler>> bus;

void publish(const std::string& topic, const std::string& payload) {
    for (auto& h : bus[topic]) h(payload);
}
```

## 二、策略模式（Strategy）

定义算法族，使它们可以互换。客户端主动注入算法。

**适用**：同一行为有多种实现（如排序算法、压缩算法、定价策略）；需要避免大量 if-else/switch。**权衡**：客户端必须了解不同策略的区别；策略类增多增加维护成本。**变体**：策略 + 简单工厂组合，客户端传枚举即可获得对应策略。

```cpp
class SortStrategy {
public:
    virtual ~SortStrategy() = default;
    virtual void sort(std::vector<int>&) = 0;
};

class BubbleSort : public SortStrategy {
public:
    void sort(std::vector<int>& v) override { /* 冒泡 */ }
};

class QuickSort : public SortStrategy {
public:
    void sort(std::vector<int>& v) override { /* 快速排序 */ }
};

class Context {
    SortStrategy* strategy;
public:
    Context(SortStrategy* s) : strategy(s) {}
    void setStrategy(SortStrategy* s) { strategy = s; }
    void doSort(std::vector<int>& v) { strategy->sort(v); }
};
```

## 三、命令模式（Command）

将请求封装为对象，使请求可参数化、可排队、可撤销。

**适用**：操作撤销/重做（Undo/Redo）、操作队列/日志、GUI 按钮菜单绑定。**权衡**：每个命令一个类，可能导致类爆炸。**变体**：宏命令（CompositeCommand 组合多个命令）；命令模式 + Memento 模式实现完整撤销功能。

```cpp
class Command {
public:
    virtual ~Command() = default;
    virtual void execute() = 0;
};

class Light {
public:
    void on() { }
    void off() { }
};

class LightOnCommand : public Command {
    Light* light;
public:
    LightOnCommand(Light* l) : light(l) {}
    void execute() override { light->on(); }
};

class RemoteControl {
    std::vector<Command*> commands;
public:
    void setCommand(Command* cmd) { commands.push_back(cmd); }
    void buttonPressed(int slot) {
        if (slot < commands.size()) commands[slot]->execute();
    }
};
```

## 四、模板方法模式（Template Method）

定义算法的骨架，将某些步骤延迟到子类实现。

**适用**：多个类有相同的算法结构但实现细节不同（如数据挖掘、测试框架、构建流程）。**权衡**：子类越多维护成本越高；模板方法用继承复用代码，违反"组合优于继承"原则。**对比**：Template Method vs Strategy——前者继承复用算法骨架，后者组合更换算法实现。

```cpp
class DataMiner {
public:
    // 模板方法：不可重写
    void mine(const std::string& path) {
        auto* file = openFile(path);
        auto* rawData = extractData(file);
        auto* data = parseData(rawData);
        auto* analysis = analyzeData(data);
        sendReport(analysis);  // 通用步骤
        closeFile(file);
    }

    virtual File* openFile(const std::string&) = 0;
    virtual RawData* extractData(File*) = 0;
    virtual Data* parseData(RawData*) = 0;
    virtual Analysis* analyzeData(Data*) = 0;
    void sendReport(Analysis* a) { /* 通用实现 */ }
    virtual void closeFile(File*) = 0;
};

class PDFDataMiner : public DataMiner {
    File* openFile(const std::string& path) override { /* PDF */ }
    RawData* extractData(File*) override { /* PDF */ }
    Data* parseData(RawData*) override { /* PDF */ }
    Analysis* analyzeData(Data*) override { /* PDF */ }
    void closeFile(File*) override { /* PDF */ }
};
```

## 五、状态模式（State）

对象内部状态变化时改变其行为，状态对象通常知道下一状态。

**适用**：对象行为依赖于其状态且状态可枚举（如 TCP 连接状态、订单状态、游戏人物状态）。**权衡**：状态类数量 = 状态数，状态过多时类爆炸。**变体**：状态模式 + 享元模式共享无状态的状态对象；有限状态机（FSM）的实现方式之一。

```cpp
class State {
public:
    virtual ~State() = default;
    virtual void handle(Context*) = 0;
};

class ConcreteStateA : public State {
public:
    void handle(Context* ctx) override {
        // 状态转移
        ctx->setState(new ConcreteStateB());
    }
};

class ConcreteStateB : public State {
public:
    void handle(Context* ctx) override {
        ctx->setState(new ConcreteStateA());
    }
};

class Context {
    State* state;
public:
    Context(State* s) : state(s) {}
    void setState(State* s) { delete state; state = s; }
    void request() { state->handle(this); }
};
```

### 面试考点：策略 vs 状态

| 对比 | 策略模式 | 状态模式 |
|------|---------|---------|
| 目的 | 算法可替换 | 状态决定行为 |
| 谁控制 | 客户端主动注入 | 内部状态自动转移 |
| 状态转移 | 无（策略独立） | 有（状态知道下一状态） |
| 比喻 | "换工具" | "换模式" |

## 六、责任链模式（Chain of Responsibility）

使多个对象都有机会处理请求，形成链式传递。

**适用**：请求需要多级处理（如权限→日志→缓存→业务）；处理者动态组合。**权衡**：请求未被任何处理者处理的情况需兜底；调试时链路过长难跟踪。**对比**：Chain vs Decorator——责任链找处理者后终止，装饰器层层加工后返回。**变体**：树状责任链（每个节点有多个子节点）。

```cpp
class Handler {
protected:
    Handler* next;
public:
    Handler(Handler* n = nullptr) : next(n) {}
    virtual ~Handler() { delete next; }

    void setNext(Handler* h) { next = h; }

    virtual void handle(Request* req) {
        if (next) next->handle(req);
    }
};

class AuthHandler : public Handler {
public:
    AuthHandler(Handler* n) : Handler(n) {}
    void handle(Request* req) override {
        if (!req->isAuthenticated()) { /* 拒绝 */ return; }
        Handler::handle(req);  // 传递
    }
};

class LogHandler : public Handler {
public:
    LogHandler(Handler* n) : Handler(n) {}
    void handle(Request* req) override {
        log(req);
        Handler::handle(req);
    }
};

// 使用：AuthHandler -> LogHandler -> CacheHandler -> ...
```

## 七、行为型模式对比

| 模式 | 核心意图 | 关系 |
|------|---------|------|
| Observer | 一对多通知 | Subject → Observer |
| Strategy | 算法族互换 | Context 持有 Strategy |
| Command | 请求封装为对象 | Invoker → Command → Receiver |
| Template Method | 骨架固定，步骤可定制 | 继承复写 |
| State | 状态决定行为 | Context 持有 State（可转移） |
| Chain of Resp. | 请求链式传递 | 链表结构 |
