# 观察者模式深入

> 本文聚焦观察者模式在 C++ 现代智能指针下的实践：循环引用、weak_ptr 最佳实践、enable_shared_from_this 原理、多 Subject 管理。

---

## 一、循环引用问题

### 1.1 问题场景

Subject 和 Observer 互相持有 `shared_ptr` 会导致循环引用，内存泄漏：

```cpp
class WeatherStation : public Subject {
    std::vector<std::shared_ptr<Observer>> observers_;  // shared_ptr
};

class PhoneDisplay : public Observer {
    std::shared_ptr<Subject> subject_;  // shared_ptr
};
```

```
weatherStation -> phone (shared_ptr)
phone -> weatherStation (shared_ptr)
→ 引用计数永不为 0，内存泄漏！
```

### 1.2 解决方案：使用 `weak_ptr`

**Subject 用 `vector<weak_ptr<Observer>>`，Observer 用 `weak_ptr<Subject>`**，至少一方使用 `weak_ptr`。

```cpp
// Subject
class WeatherStation : public Subject {
    std::vector<std::weak_ptr<Observer>> observers_;  // 不增加引用计数
    float temperature_;
public:
    void attach(std::shared_ptr<Observer> observer) override {
        observers_.push_back(observer);
    }

    void detach(std::shared_ptr<Observer> observer) override {
        observers_.erase(
            std::remove_if(observers_.begin(), observers_.end(),
                [&observer](const std::weak_ptr<Observer>& wp) {
                    auto locked = wp.lock();
                    return !locked || locked == observer;
                }),
            observers_.end()
        );
    }

    void notify(const std::string& message) override {
        for (auto it = observers_.begin(); it != observers_.end();) {
            if (auto sp = it->lock()) {
                sp->update(message);
                ++it;
            } else {
                it = observers_.erase(it);  // 清理失效的 weak_ptr
            }
        }
    }

    void setTemperature(float temp) {
        temperature_ = temp;
        notify("温度变为 " + std::to_string(temp));
    }
};
```

## 二、enable_shared_from_this

### 2.1 为什么需要

当 Observer 需要将自己注册到 Subject 时，需要获取指向自己的 `shared_ptr`。**不能**直接 `std::shared_ptr<Observer>(this)`——这会在同一对象上创建多个控制块，导致未定义行为。

### 2.2 正确使⽤

```cpp
class MultiSubjectObserver : public Observer,
                             public std::enable_shared_from_this<MultiSubjectObserver> {
    std::string name_;
    std::vector<std::weak_ptr<Subject>> subjects_;
public:
    MultiSubjectObserver(const std::string& name) : name_(name) {}

    void subscribe(std::shared_ptr<Subject> subject) {
        if (!subject) return;
        subjects_.push_back(subject);
        subject->attach(shared_from_this());  // ✅ 安全获取 shared_ptr
    }

    void unsubscribeAll() {
        for (auto& wp : subjects_) {
            if (auto subject = wp.lock()) {
                if (auto sp = shared_from_this()) {
                    subject->detach(sp);
                }
            }
        }
        subjects_.clear();
    }

    void update(const std::string& message) override {
        std::cout << name_ << " received: " << message << std::endl;
    }

    ~MultiSubjectObserver() { unsubscribeAll(); }
};
```

### 2.3 使用要求

1. 类必须继承 `std::enable_shared_from_this<T>`
2. 对象必须由 `shared_ptr` 管理（不能用栈对象）
3. **不能在构造函数中调⽤ `shared_from_this()`**

```cpp
// ✅ 正确
auto observer = std::make_shared<MultiSubjectObserver>("test");
observer->subscribe(subject);

// ❌ 错误：栈对象
MultiSubjectObserver obs("test");
obs.subscribe(subject);  // 抛 std::bad_weak_ptr

// ❌ 错误：构造函数中调⽤
MultiSubjectObserver() {
    shared_from_this();  // 抛 std::bad_weak_ptr
}
```

### 2.4 内部原理

```cpp
// enable_shared_from_this 内部维护一个 weak_ptr
template<typename T>
class enable_shared_from_this {
    mutable std::weak_ptr<T> weak_this_;

    std::shared_ptr<T> shared_from_this() {
        return std::shared_ptr<T>(weak_this_);  // 从 weak_ptr 构造
    }

    // 由 shared_ptr 构造函数调⽤，设置 weak_this_
    void _internal_accept_owner(std::shared_ptr<T> const* p) const {
        if (weak_this_.expired()) {
            weak_this_ = std::shared_ptr<T>(*p, static_cast<T*>(this));
        }
    }
};
```

| 操作 | 引用计数影响 | 说明 |
|------|:----------:|------|
| `shared_ptr` → `weak_ptr`（设置 weak_this_） | 不增加 use_count | `weak_ptr` 不拥有对象 |
| `weak_ptr` → `shared_ptr`（shared_from_this） | 增加 use_count | 安全获取所有权 |

## 三、两种设计方案

### 方案A：Subject 持有 Observer（标准）

```cpp
class WeatherStation : public Subject {
    std::vector<std::weak_ptr<Observer>> observers_;
};
```

**适用**：一个事件源 → 多个监听者（如气象站 → 多个手机 App）

### 方案B：Observer 持有 Subject（多订阅）

```cpp
class MultiSubjectObserver : public Observer {
    std::vector<std::weak_ptr<Subject>> subjects_;
};
```

**适用**：一个监听者 ← 多个事件源（如一个监控系统观察多个传感器）

### 对比表

| 对比维度 | 方案A（Subject→Observer） | 方案B（Observer→Subject） |
|---------|-------------------------|--------------------------|
| 核心关系 | 一对多 | 多对一 |
| 控制权 | Subject 控制通知 | Observer 控制订阅 |
| 代码复杂度 | ⭐⭐ 简单 | ⭐⭐⭐ 中等 |
| 典型场景 | 一个事件源多个监听者 | 一个监听者多个事件源 |
| 多个监听者×多个事件源 | 不推荐 | ✅ 推荐 |

### 复杂场景：多个监听者 × 多个事件源

**推荐方案B**：每个 Observer 独立管理自己的 Subject 列表。

```cpp
auto monitor1 = std::make_shared<MultiSubjectObserver>("监控1");
auto monitor2 = std::make_shared<MultiSubjectObserver>("监控2");

auto station1 = std::make_shared<WeatherStation>();
auto station2 = std::make_shared<WeatherStation>();
auto station3 = std::make_shared<WeatherStation>();

monitor1->subscribe(station1);  // 监控1 只关心 station1
monitor1->subscribe(station2);

monitor2->subscribe(station2);  // 监控2 关心 station2, station3
monitor2->subscribe(station3);
```

## 四、weak_ptr 利弊分析

| 特性 | weak_ptr | shared_ptr |
|-----|---------|-----------|
| 循环引用 | ✅ 不会导致 | ❌ 会导致内存泄漏 |
| 引用计数 | ✅ 不增加 | ❌ 增加 |
| 对象生命周期 | ✅ 不影响 | ❌ 延长 |
| 访问对象 | ⚠️ 需要 lock() | ✅ 直接访问 |
| 安全性 | ✅ 可检测对象是否已销毁 | ❌ 可能悬空指针 |

**结论**：weak_ptr 利大于弊，在观察者模式中是标准做法。

## 五、面试考点

- **Q**：如何避免观察者模式中的循环引⽤？→ 使用 `weak_ptr`
- **Q**：为什么不能在构造函数中调⽤ `shared_from_this()`？→ 此时 `weak_this_` 还未被设置
- **Q**：`weak_ptr::lock()` 什么时候返回空指针？→ 对象已销毁、weak_ptr 默认构造、weak_ptr 被 reset
- **Q**：观察者 vs 发布-订阅？→ 耦合度、中间 Broker、跨进程能力
- **Q**：一个 Observer 观察多个 Subject 用什么方案？→ 方案B（Observer 持有多个 Subject 的 weak_ptr）
