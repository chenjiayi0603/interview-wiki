# 实时安全 C++ 编程实践

## 6.1 分配策略

- **预分配**：启动时分配好所有实时任务所需内存（对象、缓冲区、队列等）。
- **池化**：固定大小对象池，`acquire`/`release` 只做指针管理，无堆分配。
- **栈上对象**：在实时线程栈上使用固定大小数组、`std::array` 等，避免堆。
- **自定义 allocator**：若使用 STL，为容器提供不调用 `::operator new` 的 allocator（例如基于池或静态存储）。

### 固定大小对象池与 jemalloc 对比

- **原理**
  - 固定大小对象池：预先分配一块连续大内存，切分为等长小块（槽），通过空闲链表或位图管理；只适用于一种定长类型。分配/释放仅做指针操作，延迟极低且固定。
  - jemalloc：更通用的多用途高性能内存分配器，支持多种尺寸分配与多线程并发，自动处理碎片。应用无需感知对象类型，可替换 glibc malloc。

- **缺点**
  - 固定大小对象池：仅能服务单一类型/尺寸对象，需要在程序初始化时确定池的大小。池满后无法自动扩容，会返回 nullptr，要求业务端处理。浪费空间的可能性高，不适合尺寸和数量剧烈变化或多类型对象混合的场景。
  - jemalloc：虽然比标准 malloc 更快、更抗碎片，但其本质是通用动态分配，某些极端实时场景下分配延迟和最差情况下的抖动仍不可完全预测。超大分配时仍可能落到慢路径（如 mmap），在特别高实时性（硬实时）场合不如池分配可控。

- **适用场景**
  - 固定大小对象池：适合高实时/硬实时要求、对象数据结构已知且尺寸固定、对象总数有物理上限的系统（如实时音视频包缓冲、消息传递、任务池等），可以极大提升分配的确定性并消除碎片，常用于嵌入式、工业、极致低延迟服务等场合。
  - jemalloc：适合 C++ 服务端、分配对象多类型/多尺寸或工作集变化较大、需提升 malloc/free 整体性能、降低碎片和锁争用的通用场景。尤其适用于大规模线上服务器和通用后端进程。

**总结**：
- 定长对象且强控延迟选对象池，易于分析和保证单次分配/释放耗时；
- 通用应用、分配模式复杂场合优选 jemalloc，支持平滑替换原有 malloc，提高整体服务器性能和资源利用率；
- 二者可组合使用：关键路径用池，其他用 jemalloc，兼顾效率与灵活性。

### 固定大小对象池代码

```cpp
// 示例：简单对象池（无堆分配）
template<typename T, size_t N>
struct ObjectPool {
    alignas(T) unsigned char storage[N * sizeof(T)];
    bool used[N] = {};

    T* acquire() {
        for (size_t i = 0; i < N; ++i) {
            if (!used[i]) {
                used[i] = true;
                return new (&storage[i * sizeof(T)]) T();
            }
        }
        return nullptr;
    }

    void release(T* p) {
        p->~T();
        size_t i = (reinterpret_cast<char*>(p) - reinterpret_cast<char*>(storage)) / sizeof(T);
        used[i] = false;
    }
};
```

## 6.2 禁用异常与 RTTI（编译选项）

```bash
# GCC / Clang
-std=c++17 -fno-exceptions -fno-rtti
```

代码中避免 `throw`、`try`/`catch`、`dynamic_cast`、`typeid`；若用第三方库，需确认其是否依赖异常或 RTTI。

## 6.3 实时路径代码原则

- **小、短、平**：函数简短，调用链浅，逻辑清晰，便于分析和测试。
- **少分支**：减少难以预测的分支；若分支概率极度倾斜，可用 `__builtin_expect` 等。
- **无锁优先**：实时线程间尽量用无锁队列、原子操作、内存序清晰的 lock-free 结构；若必须用锁，优先考虑**优先级继承**（如 `PTHREAD_PRIO_INHERIT`）减轻优先级反转。
- **避免递归**：深度不可控，栈与 WCET 难以分析；若确需递归，应严格限制深度并证明有界。

## 6.4 与「低延迟 C++」的衔接

实时系统与低延迟系统有很多共通点，可结合本项目 **《低延迟 C++ 系统分析》** 中的内容：

- **CPU 亲和性**、**NUMA 绑定**：实时线程绑核、内存本地化，减少迁移与远程访问。
- **内存锁定**（`mlock`/`mlockall`）：避免缺页与 swap，降低延迟抖动。
- **SCHED_FIFO/SCHED_RR** 使用建议、**`mlock` 使用注意**（如锁定的容量、RLIMIT_MEMLOCK）。
- **缓存行对齐**、**避免 false sharing**、**分支预测提示**等，在实时路径中同样适用。
