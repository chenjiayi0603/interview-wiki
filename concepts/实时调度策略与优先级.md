# 实时调度策略与优先级

## 3.1 实时调度类

| 策略 | 含义 | 时间片 | 典型用途 |
|------|------|--------|----------|
| **SCHED_FIFO** | 同优先级 FIFO，高优先抢占 | 无（跑满） | 单一关键实时线程、极致低延迟 |
| **SCHED_RR** | 同优先级轮转 | 有 | 多实时任务公平共享 CPU |
| **SCHED_DEADLINE** | 基于截止时间（CBS） | 按 deadline | 周期/偶发实时任务 |

**SCHED_OTHER**（CFS）为普通策略，优先级低于所有实时策略；实时线程就绪时总会抢占 CFS。

## 3.2 实时优先级范围

- 实时优先级：**1–99**，数值**越大优先级越高**。
- 普通优先级（nice）：通常映射到 100–139，**数值越大优先级越低**。

## 3.3 使用 SCHED_FIFO / SCHED_RR 的示例

```cpp
#include <pthread.h>
#include <sched.h>
#include <stdio.h>

void set_realtime_priority(int policy, int priority) {
    struct sched_param param;
    param.sched_priority = priority;

    int ret = pthread_setschedparam(pthread_self(), policy, &param);
    if (ret != 0) {
        perror("pthread_setschedparam");
        return;
    }
    // policy: SCHED_FIFO 或 SCHED_RR
    // priority: 1–99，越高越优先
}

int main() {
    // 需要 root 或 CAP_SYS_NICE
    set_realtime_priority(SCHED_FIFO, 80);
    // 实时主循环...
    return 0;
}
```

**注意**：
- 使用实时策略通常需 **root** 或 **CAP_SYS_NICE**，否则 `pthread_setschedparam` 可能失败。
- **SCHED_FIFO** 下若线程不主动让出（如 `sched_yield()`、阻塞 I/O），会一直占用 CPU，导致同核其他任务饿死；多实时任务共享 CPU 时，**SCHED_RR** 更稳妥。
- 可配合 **CPU 亲和性**（如 `pthread_setaffinity_np`）将实时线程绑到专用核，避免与普通任务争抢。

## 3.4 SCHED_DEADLINE 简述

`SCHED_DEADLINE` 按**运行时间 / 周期（或 deadline）** 预留 CPU 带宽，适合周期性的硬实时任务。使用 `sched_setattr()` 设置；需要内核支持 `CONFIG_SCHED_DEADLINE`。
