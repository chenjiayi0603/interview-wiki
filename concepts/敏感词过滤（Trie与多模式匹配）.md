# 敏感词过滤（Trie / 多模式匹配）

**简历原文**：敏感词过滤（Trie / 多模式匹配）

## 数据支撑

| 算法 | 时间复杂度 | 典型性能 |
|------|-----------|---------|
| 暴力搜索（遍历词典 × 搜索文本） | O(M×N)，M=词典大小，N=文本长度 | 词典 10万 × 文本 1000 字 = 1亿次 |
| Trie 前缀树 | O(N×L)，L=最长词长度 | 文本 1000 字 × 最长词 20 字 = 2万次 |
| AC 自动机（Aho-Corasick） | **O(N)**，与词典大小无关 | 文本 1000 字固定 1000 次比较 |

AC 自动机实测：10万词典，文本 1000 字，**匹配延迟 <1ms**。构建耗时几百毫秒（启动时一次性构建）。

热更新：新词典构建完整新 AC tree → 原子替换指针 → 旧 tree 延迟回收（等所有进行中的匹配完成）。10万词典重建约 200–300ms，对用户无感。

## 理论支撑

AC 自动机 = Trie 树 + KMP 失配函数 + BFS 构建 fail 指针。在 Trie 树上添加 fail 指针（指向当前模式的最长真后缀对应的节点），使匹配失败时不需要回溯文本指针，保证 O(N) 整体匹配。

相比纯 Trie：Trie 每次失配需要回退文本指针，最坏 O(N×L)；AC 自动机通过 fail 指针一次遍历文本即可找到所有匹配，是多模式匹配的最优解。

## 业界对标

- **Aho-Corasick 算法**（1975 年论文）：多模式字符串匹配的经典算法，广泛用于入侵检测、内容过滤
- **Hyperscan**（Intel 开源）：高性能正则引擎，底层使用 NFA/DFA，比 AC 自动机支持更复杂模式但构建更重
- **各大 IM 平台**：微信、陌陌、字节均采用 AC 自动机或其变体做敏感词过滤

## 追问预案

**Q：简历写的"Trie / 多模式匹配"，和 AC 自动机有什么关系？**
> Trie 是 AC 自动机的基础数据结构，AC 自动机是在 Trie 上加 fail 指针实现的多模式匹配优化。"Trie / 多模式匹配"是对实现的描述，AC 自动机是算法名称。实现时确实用了 AC 自动机，可以展开讲 fail 指针构建和 O(N) 证明。
