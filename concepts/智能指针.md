# 智能指针

See also: [[C++语言特性]], [[C++高频面试问题]], [[C++指针体系]]

## 为什么需要智能指针？

| 问题 | 原始指针 | 智能指针 |
|------|---------|---------|
| 内存泄漏 | 容易忘记 delete | 自动管理 |
| 悬空指针 | 难以追踪 | 引用计数/所有权管理 |
| 异常安全 | 异常时可能泄漏 | RAII 保证释放 |
| 所有权语义 | 不明确 | 明确的所有权语义 |

**RAII 原则：** Resource Acquisition Is Initialization（资源获取即初始化）。智能指针是 RAII 的典型应用。

## 智能指针类型对比

| 类型 | 所有权 | 拷贝 | 移动 | 性能开销 | 使用场景 |
|------|--------|------|------|---------|---------|
| `unique_ptr` | 独占 | ❌ | ✅ | 几乎无 | 单所有者 |
| `shared_ptr` | 共享 | ✅ | ✅ | 引用计数 | 多所有者 |
| `weak_ptr` | 无 | ✅ | ✅ | 弱引用计数 | 观察者模式 |

## unique_ptr

- **独占所有权**：同一时刻只有一个 `unique_ptr` 拥有对象
- **不可拷贝**：只能移动（move）
- **零开销**：几乎等同于原始指针的性能

```cpp
std::unique_ptr<int> p1 = std::make_unique<int>(42);
std::unique_ptr<int> p3 = std::move(p1);  // p1 变为空
int* raw = p3.release();  // 释放所有权
p3.reset(new int(200));   // 重置
```

## shared_ptr

- **共享所有权**：多个 `shared_ptr` 可以共享同一对象
- **引用计数**：自动管理对象生命周期
- **线程安全**：引用计数操作是原子的（C++11 起）

### 线程安全性

| 操作 | 线程安全性 |
|------|-------------|
| 不同线程持有不同的 shared_ptr（指向同一对象）并只读 | ✅ 安全 |
| 不同线程对同一 shared_ptr 实例进行读写 | ❌ 不安全 |
| 多线程修改 use_count（复制、销毁 shared_ptr） | ✅ 安全 |
| 多线程同时修改对象本身（`*ptr`） | ❌ 不安全（需额外同步） |

### make_shared vs shared_ptr(new T)

| 特性 | `make_shared` | `shared_ptr(new T)` |
|------|--------------|---------------------|
| 内存分配 | 1 次（控制块+对象） | 2 次 |
| 异常安全 | ✅ 更强 | ⚠️ 可能泄漏 |
| 性能 | 更快（缓存局部性） | 较慢 |

**循环引用问题：** 使用 `weak_ptr` 打破循环。

## weak_ptr

- **不拥有对象**：不增加 `use_count`
- **观察者模式**：观察对象是否还存在
- **避免循环引用**：解决 `shared_ptr` 循环引用问题

```cpp
std::weak_ptr<int> wp = sp;
if (auto locked = wp.lock()) {
    *locked = 100;  // 对象还存在
} else {
    // 对象已被销毁
}
```

## 控制块机制

```
对象生命周期：由 strong_count 管理
  strong_count > 0 → 对象存活
  strong_count = 0 → 对象销毁

控制块生命周期：由 (strong_count + weak_count) 管理
  strong_count = 0 && weak_count = 0 → 控制块销毁
```

**shared_ptr 内部结构：**

```
shared_ptr<T>
├── ptr (T*) → 实际对象
└── control block
    ├── strong_count (use_count)
    ├── weak_count
    └── deleter / allocator
```

## enable_shared_from_this

当类需要从 `this` 返回 `shared_ptr` 时使用，避免创建新的控制块导致双重删除：

```cpp
class Widget : public std::enable_shared_from_this<Widget> {
public:
    std::shared_ptr<Widget> getShared() {
        return shared_from_this();  // ✅ 正确
    }
};
```

**使用要求：** 对象必须被 `shared_ptr` 管理；不能在构造函数中调用 `shared_from_this()`。

## 常见陷阱与面试题

**陷阱 1：从原始指针创建多个 shared_ptr**

```cpp
int* raw = new int(42);
std::shared_ptr<int> p1(raw);
std::shared_ptr<int> p2(raw);  // ❌ 双重删除
```

**陷阱 2：循环引用** — 使用 `weak_ptr` 打破

**陷阱 3：shared_ptr 与 this 指针** — 使用 `enable_shared_from_this`

**陷阱 4：多线程同时写同一 shared_ptr 实例** — 加锁或 `std::atomic<std::shared_ptr<T>>`（C++20）

## 性能分析

| 类型 | 对象大小（64位） | 额外开销 |
|------|----------------|---------|
| `T*` | 8 字节 | 无 |
| `unique_ptr<T>` | 8 字节 | 几乎无 |
| `shared_ptr<T>` | 16 字节 | 控制块（~40字节） |
| `weak_ptr<T>` | 16 字节 | 控制块（共享） |

## 最佳实践

**推荐：** 优先 `make_shared`/`make_unique`；默认用 `unique_ptr`；需要共享时用 `shared_ptr`；避免循环引用用 `weak_ptr`；接口参数用原始指针（不改变所有权）。

**不推荐：** 避免从原始指针创建 shared_ptr；避免不必要的 shared_ptr；避免在构造函数中使用 `shared_from_this`。
