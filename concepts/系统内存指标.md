# 系统内存指标

## 核心概念

### 内存指标速览

| 指标 | 含义 | 关注场景 |
|------|------|---------|
| **VSZ** | 虚拟地址空间总量（"承诺"的内存） | 查看进程地址空间布局 |
| **RSS** | 实际占用的物理内存（"真实"的内存） | 评估实际内存压力 |
| **PSS** | 按比例分摊的物理内存（共享库按进程数分摊） | 更公平地评估进程内存占用 |

**核心关系**：`VSZ ≥ RSS`，通常 `VSZ >> RSS`

### 为什么 VSZ >> RSS？

| 原因 | 说明 | 影响 |
|------|------|------|
| **延迟分配** | malloc 申请虚拟地址，写入时才分配物理页 | 堆内存 VSZ 大但 RSS 小 |
| **共享库** | 多个进程共享同一物理内存，但每个进程 VSZ 都计算完整大小 | VSZ 重复计算，RSS 共享优化 |
| **内存映射文件** | 整个文件映射到虚拟地址，但只加载活跃部分 | VSZ 包含文件大小，RSS 只包含已加载部分 |
| **Swap 换出** | 内存被换出到磁盘，RSS 减少但 VSZ 不变 | 物理内存不足时常见 |

### 如何选择观察指标

- **关注物理内存的实际压力**：应主要看 **RSS**。因为它直接反映了进程当前消耗的宝贵物理资源。
- **需要更精确评估内存占用**：可以关注 **PSS**（Proportional Set Size）。PSS 在处理共享内存时，会将其平均分摊到共享的进程中，避免了 RSS 的重复计算问题，能更公平地反映每个进程的实际内存开销。
- **查看进程虚拟地址空间布局**：可以使用 `pmap -x <pid>` 命令，它能显示虚拟地址空间中各个内存段的详细信息。

### VSZ 和 RSS 差值特别大的情况

| 主要原因 | 典型场景 | 通常意味着什么 |
|---------|---------|---------------|
| **内存 Overcommit（预分配）** | 程序（如 Java 服务）启动时申请大量地址空间（mmap）但尚未完全使用 | 进程预留了很大的"可能性"，但当前实际占用不大 |
| **共享库（Shared Libraries）** | 多个进程使用相同的公共库（如 C 标准库、图形库） | RSS 因共享机制而优化，系统内存使用效率高 |
| **内存映射文件（Memory-mapped Files）** | 数据库（如 MySQL）、视频编辑软件将大文件映射到内存地址空间 | VSZ 包含整个映射文件大小，但 RSS 仅加载活跃部分 |
| **已被换出的内存（Swapped-Out Memory）** | 系统物理内存紧张时，内核将非活跃内存页移至交换分区（Swap） | **需警惕**，可能意味着系统物理内存不足 |
| **大量线程堆栈预留空间** | 高并发应用创建大量线程，每个线程的栈都会预留地址空间 | VSZ 会较大，但多数线程栈实际使用不多，RSS 增长有限 |
