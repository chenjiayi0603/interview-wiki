# 虚拟地址转换

## 核心步骤

Linux 的虚拟内存转换核心思想是通过页表，将进程使用的虚拟地址映射到实际的物理内存地址。这个过程主要由硬件单元 MMU（内存管理单元）完成，其核心步骤可归纳为以下三步：

| 核心步骤 | 关键操作 | 主要参与者 |
|---------|---------|-----------|
| **1. 地址分解** | CPU 将虚拟地址拆分为页号和页内偏移量 | CPU, MMU |
| **2. 页表查询** | MMU 使用页号作为索引，查询页表，找到对应的物理页框号 | MMU, 页表 |
| **3. 地址合成** | 将找到的物理页框号与第一步得到的页内偏移量组合，得到最终的物理地址 | MMU |

## 三步转换流程

### 1. 地址分解

CPU 将虚拟地址（如 `0x12345678`）拆分为两部分：
- **页号**（Page Number）：高位部分，用于索引页表
- **页内偏移量**（Offset）：低位部分，在页内的偏移

### 2. 页表查询

- **首先查询 TLB**：检查是否有缓存的映射关系
- **TLB 命中**：直接从 TLB 获取物理页框号（快速路径）
- **TLB 未命中**：需要查询多级页表（慢速路径）
  - 从 CR3 寄存器获取顶级页目录地址
  - 使用页号逐级查询（PGD → PUD → PMD → PTE）
  - 从 PTE 获取物理页框号
  - 更新 TLB 缓存

### 3. 地址合成

将物理页框号与页内偏移量组合，得到最终的物理地址。CPU 使用物理地址访问实际内存。

## 核心要点与优化

### 多级页表

- 现代 Linux 系统通常使用多级页表（如四级：PGD、PUD、PMD、PTE）来管理巨大的地址空间
- 这种方式能有效减少页表的内存占用
- 转换的起点是 CPU 的 CR3 寄存器，它保存了当前进程顶级页目录的物理地址

### TLB 加速

- 为避免每次地址转换都需遍历多级页表带来的性能损耗，MMU 中集成了一个名为 TLB（转址旁路缓存）的高速缓存
- 它用于存储最近使用过的虚拟地址到物理地址的映射关系
- 当 CPU 访问一个地址时，首先查询 TLB，若找到（命中）则瞬间完成转换，大大提升了效率
