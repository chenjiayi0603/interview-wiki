# 进程内存分析工具

## 常用分析工具速览

| 工具/文件 | 用途 | 关键信息 |
|----------|------|---------|
| `ps aux` | 快速查看 VSZ、RSS | VSZ、RSS 列 |
| `/proc/<pid>/status` | 详细内存统计 | VmRSS（物理内存）、VmSize（虚拟内存） |
| `/proc/<pid>/maps` | 完整内存映射布局 | 地址范围、权限、映射文件 |
| `pmap -x <pid>` | 格式化显示内存映射 | 虚拟大小、RSS、脏页大小 |

## /proc/<pid>/maps

这是获取进程虚拟内存映射最详细的信息源。你可以通过 `cat /proc/<PID>/maps` 查看特定进程的内存布局。

输出示例片段分析：

```
55f8a4b7a000-55f8a4b9b000 r-xp 00000000 08:01 7874622 /usr/bin/cat
```

- **地址范围**：`55f8a4b7a000-55f8a4b9b000` 代表该内存区域的起始和结束虚拟地址
- **权限**：`r-xp` 表示该段内存可读、可执行、私有。权限字符依次是读、写、执行和映射标志（p=私有 或 s=共享）
- **偏移量**：`00000000` 表示该段内容在映射文件中的起始偏移
- **设备号**：`08:01` 表示文件所在设备的主设备号和次设备号
- **inode 号**：`7874622` 是文件的 inode 编号。inode 为 0 通常表示匿名映射
- **映射文件/标签**：最后是映射的文件路径或内核标签，如 [heap], [stack], [anon] 等

## /proc/<pid>/status

这个文件提供了进程内存使用情况的一个更易读的概览，它实际上汇总了 maps 中的信息。其中一些关键指标包括：

```bash
Name:   bash        # 进程名称
VmPeak:  131168 kB  # 进程运行至今所使用的虚拟内存峰值
VmSize:  131168 kB  # 进程当前使用的虚拟内存总量
VmLck:       0 kB   # 被锁定无法换出的内存大小
VmHWM:    13484 kB  # 进程运行至今驻留物理内存的峰值（"高水位线"）
VmRSS:    13484 kB  # 进程当前实际驻留在物理内存中的大小
VmData:   10332 kB  # 数据段（初始化/未初始化数据、堆）的虚拟内存大小
VmStk:      136 kB  # 主线程栈的大小
VmExe:      992 kB  # 代码段（可执行指令）的大小
VmLib:     2104 kB  # 使用的共享库代码大小
VmPTE:       76 kB  # 进程页表大小
VmSwap:      0 kB   # 被交换到 Swap 分区的内存大小
```

**解读技巧**：
- 关注 **VmRSS**：这个值最接近任务管理器里看到的"内存占用"，因为它表示实际消耗的物理内存
- 判断内存泄漏：如果 VmHWM（物理内存峰值）或 VmPeak（虚拟内存峰值）持续上升，可能提示存在内存泄漏
- 分析内存构成：通过 VmData、VmExe、VmLib 等字段，可以了解内存主要用在代码、数据还是共享库上

## pmap 命令

`pmap` 命令是一个专用于显示进程内存映射的工具，它对 `/proc/<pid>/maps` 的信息进行了格式化和汇总，更便于阅读。基本用法是 `pmap [选项] <PID>`。

- 使用 `pmap -x <PID>` 可以显示扩展信息，包括每个映射的虚拟大小、常驻大小、脏页大小等
- 使用 `pmap -XX <PID>` 可以显示内核提供的所有可用信息，内容非常详细

**输出示例及其解读**：

```
Address           Kbytes     RSS   Dirty Mode  Mapping
000055a3db326000   22528       0       0 r---- dockerd  # 程序只读数据
000055a3dc926000   30452    1452       0 r-x-- dockerd  # 程序可执行代码
00007fbd18000000     132       4       4 rw---   [ anon ]  # 匿名私有可读写内存
...
00007ffe5c5e2000     132      12      12 rw---   [ stack ]  # 主线程栈
...
-------------------------------------- 
total kB          177312   12344    8540
```

**各列含义解读**：
- **Address**: 内存映射区域的起始地址
- **Kbytes**: 该区域占用的虚拟内存大小
- **RSS**: 驻留集大小，即该映射当前实际在物理内存中的部分
- **Dirty**: 脏页大小，代表该内存区域中已被修改、需要写回磁盘的部分
- **Mode**: 内存区域的权限（r=读, w=写, x=执行, s=共享, p=私有）
- **Mapping**: 区域的后备存储，如程序文件、共享库（如 libc.so.6）、[heap]、[stack] 或 [anon]（匿名映射，常由动态内存分配如 malloc 产生）

**解读技巧**：
- 查找大块内存分配：按 Kbytes 排序，快速定位最大的虚拟内存块
- 识别实际内存占用：结合 RSS 列，查看哪些映射实际占用了较多的物理内存
- 分析共享内存：注意 Mode 列为 s（共享）的映射。多个进程共享的库，其物理内存只存一份，这有助于准确评估进程的真实内存开销

## 实用分析技巧

实际分析时，可以结合使用这些工具：

1. 用 `ps aux` 或 `top` 找到你关心的进程的 PID
2. 使用 `pmap -x <PID>` 快速获得一个内存布局的清晰概览
3. 如果需要更底层的细节，如查看具体哪些共享库被映射，可以查阅 `/proc/<PID>/maps`
4. 关注 VmRSS 和 VmSize 的差值，如果差值很大，可能意味着进程申请了大量内存但尚未实际使用
