# 静多态与动态多态

See also: [[C++面向对象]], [[C++特有面向对象特性]], [[C++语言特性]], [[设计模式]]

## 一、C++ 中的静多态有哪些

静多态（编译期多态）的本质是：**在编译期就能确定调用哪个函数/生成哪段代码，不依赖虚表和运行时绑定**。常见形式：

- **函数重载（Function Overloading）**  
  同一作用域下函数名相同、参数列表不同。编译器根据**实参类型和个数**在编译期决定调用哪个版本。

- **运算符重载（Operator Overloading）**  
  本质是函数重载的一种语法糖，如重载 `operator+`、`operator==` 等。编译器同样在编译期根据操作数类型选择具体重载。

- **模板多态（Templates）**  
  - 函数模板：`template<typename T> void f(T x);`  
  - 类模板：`template<typename T> struct Vector;`  
  编译器在使用时为不同类型**实例化出不同版本**的函数/类，相当于"按类型展开"的多态。

- **模板特化 / 偏特化**  
  对特定模板参数（如 `T*`、某个具体类型）给出特殊实现。编译器在编译期根据模板参数选择"最匹配"的特化版本，实现按类型分发。

  ```cpp
  // 函数模板：仅全特化
  template<typename T> void print(T x) { std::cout << "generic\n"; }
  template<> void print<int>(int x) { std::cout << "int\n"; }

  // 类模板：全特化 + 偏特化（仅类模板支持偏特化）
  template<typename T> struct Wrapper { static const char* name() { return "T"; } };
  template<> struct Wrapper<int> { static const char* name() { return "int"; } };           // 全特化
  // 这是类模板的"偏特化"：只对 T* 这种类型进行特化，保留了类型参数 T 的泛型能力。
  template<typename T> struct Wrapper<T*> { static const char* name() { return "T*"; } };   // 这是偏特化，因为只有 T* 才用这个实现
  ```
  
- **CRTP 静态多态（Curiously Recurring Template Pattern，奇异递归模板模式）**  
  典型写法：`template<class Derived> class Base { … }; struct D : Base<D> { … };`  
  基类通过模板参数拿到派生类类型，在编译期就能"静态调用"派生类接口，实现类似虚函数的多态效果，但**没有虚表与运行时开销**。适合性能敏感、接口稳定的场景。

```cpp
#include <iostream>

template<typename Derived>
struct Base {
    void call() { static_cast<Derived*>(this)->impl(); }  // 编译期"多态"调用
};
struct A : Base<A> { void impl() { std::cout << "A\n"; } };
struct B : Base<B> { void impl() { std::cout << "B\n"; } };


int main() {
    std::cout << "c\n";
    Base<A>* pa = new A;
    Base<B>* pb = new B;
    pa->call();  // 输出 A（无虚表，编译期已绑定）
    pb->call();  // 输出 B
    return 0;
}
// A
// B
```

## 二、静多态 vs 动态多态 对比小结

- **绑定时机**：  
  - 静多态：编译期绑定（重载、模板、CRTP）。  
  - 动态多态：运行期绑定（虚函数 + vtable）。
- **开销与灵活性**：  
  - 静多态：无虚调用开销，可内联，性能最好，但需要在编译期知道具体类型，接口变动需重编二进制。  
  - 动态多态：通过基类指针/引用在运行时根据实际对象类型分发，更灵活、对 ABI 更友好，但有一次虚调用开销。
