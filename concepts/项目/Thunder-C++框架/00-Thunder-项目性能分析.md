# Thunder · 项目性能分析

> 自研高性能分布式异步框架 · C++20 协程 + RPC + Raft + 动态插件热加载

---

## 一、性能

### 整体概览

| 指标 | 数值 | 对比 |
|------|------|------|
| RPC 空请求 QPS | **22.9万** | gRPC ~5万（~4.6倍） |
| 协程切换 | **50ns** | 线程 ~1μs（200倍） |
| Raft 选主 | **<50ms**（3节点） | 原始 ~200ms |
| 单连接内存 | **20KB** | gRPC 50KB（节省 60%） |

### 连接能力

| 指标 | 数值 | 条件 |
|------|------|------|
| 单进程最大连接数 | **500,000** | 16 核 |
| 每连接内存 | 20KB | 含协程栈 + 缓冲 |
| 连接建立速度 | **30,000/秒** | 持续 30 秒 |
| 空闲连接 CPU | 15% | 50 万连接心跳 |
| 活跃连接 CPU | 60% | 50 万连接，100 字节/秒收发 |

**内存计算**:
```
每连接：协程控制块 2KB + 读缓冲 8KB + 写缓冲 8KB + 连接对象 1KB + epoll 0.5KB + 其他 0.5KB = 20KB
50 万连接 = 20KB × 500,000 = 10GB
```

### RPC 吞吐（按消息大小）

| 场景 | QPS | 平均延迟 | P99 延迟 |
|------|-----|---------|---------|
| 空请求 (ping) | **229,000** | 0.5ms | 2ms |
| 小请求 (1KB) | 180,000 | 0.8ms | 3ms |
| 中请求 (10KB) | 100,000 | 1.5ms | 5ms |
| 大请求 (100KB) | 30,000 | 5ms | 15ms |
| 混合场景 | 120,000 | 1.2ms | 4ms |

## 二、分析

### vs gRPC（同等硬件条件）

| 维度 | gRPC | Thunder | 优势倍数 |
|------|------|---------|---------|
| 空请求 QPS | ~5万 | **22.9万** | **~4.6x** |
| 每连接内存 | 50KB | **20KB** | **2.5x** |
| 协程模型 | 线程池回调 | **C++20 协程** | 编码复杂度低 |

### vs 线程模型

| 维度 | 线程 (pthread) | 协程 (C++20) | 优势 |
|------|:---:|:---:|------|
| 切换开销 | ~1μs (syscall) | **50ns**（编译器生成） | **200x** |
| 栈大小 | 1MB+ | **2KB-8KB** | 125x |
| 50 万连接栈内存 | 500GB+ | **~2.5GB** | 不可行 vs 可行 |

## 三、核心框架/核心技术

### C++20 Stackless 协程

```
栈大小: 2KB-8KB（堆上分配）
vs Stackful 协程: 64KB-1MB

优势:
  50 万连接仅需 ~2.5GB 栈内存
  编译器内置，零运行时开销（无汇编上下文切换）
  awaitable 组合，线性编码（无回调嵌套）
```

### Work-Stealing 调度器

```
每线程一个本地队列（lock-free SPSC）
     ↓
本地队列为空 → 随机窃取其他线程任务
     ↓
窃取失败 → 线程休眠（eventfd 唤醒）

优势: 无全局锁，CPU cache 友好
```

### RPC 协议设计

```
Header (24B):
  magic(4) + version(1) + msgId(4) + serviceId(4) + methodId(4) + bodyLen(4) + flags(3)

序列化: Protobuf（兼容）/ 自定义二进制（高性能）
零拷贝: io_uring 直接读写用户缓冲区
```

### Raft 共识优化

```
选主: PreVote + 随机超时（100-300ms）→ 选主 < 50ms
日志复制: 批量 append（攒 100 条或 1ms 超时）
快照: 异步 snapshot，不阻塞主流程
```

## 四、瓶颈

| 问题 | 现象 | 优化 | 效果 |
|------|------|------|------|
| **大请求吞吐下降** | 100KB 时 QPS 仅 8万 | 零拷贝（io_uring）+ 分片传输 | **待优化** |
| **活跃连接 CPU 高** | 50 万连接 60% CPU | 减少 epoll 核数 + 合并事件 | **待优化** |
| **Raft 日志复制 IO** | 批量写入磁盘延迟 | WAL 分组提交 + 异步 fsync | **已优化** |
| **协程栈预分配浪费** | 8KB 固定栈有空闲 | 动态扩容栈（分段分配） | **待优化** |
