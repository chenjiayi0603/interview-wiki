# Thunder 分布式异步集群框架

> 自研高性能分布式异步框架，整合 RPC、协程、Raft 共识算法，支持动态插件热加载。

## 项目信息

| 项目 | 内容 |
|------|------|
| 技术栈 | C++20 + CMake + GTest |
| 类型 | 个人开源项目 |
| 核心特性 | RPC + 协程 + Raft + 动态插件 |

## 性能数据

| 版本 | QPS | 优化措施 |
|------|-----|---------|
| V0.1 基准 | 10 万 | 原始版本 |
| V0.3 内存池 | 50 万 | 对象池复用，零分配 |
| V0.4 锁消除 | 120 万 | Per-CPU 队列 + 无锁队列 |
| V0.5 Batch | 200 万 | 批量处理减少 RTT |
| **最终** | **200 万空请求** | 综合优化 |

## 技术难点与解决方案

### 1. Raft 选主死循环

**问题**：选举超时太短，三个节点几乎同时超时都变成 Candidate
**解决**：随机化选举超时 150ms + random(0~150ms)，延长心跳间隔
**效果**：3节点集群 50ms 内选出新 Leader

### 2. 协程选型：Stackless vs Stackful

| 特性 | Stackful | Stackless |
|------|----------|-----------|
| 栈大小 | 64KB-1MB | 2KB-8KB |
| 切换开销 | 200ns | 50ns |
| 50万并发内存 | 32GB | 1GB |

**结论**：选 Stackless，50万并发只需 1GB 内存

### 3. 动态插件热加载

用 dlopen 加载 .so，dlsym 获取工厂函数，OnUnload + dlclose 热卸载

## 面试问答

**Q: 和 gRPC 比有什么优势？**
空请求 QPS 200万 vs gRPC 5万，单连接内存 20KB vs 50KB，内置 Raft 无需额外集成

**Q: 和 brpc 比有什么优势？**
Thunder 内置 Raft，协程原生支持（非半同步），内存占用更低
