# 网络问题排查

> 生产环境网络问题排查指南，涵盖延迟突增、建连失败、连接中断、吞吐骤降等场景。

## 问题分类

| 类型 | 现象 | 典型根因 |
|------|------|---------|
| **延迟突增** | P99 从 2ms 跳到 200ms | 交换机抖动、网卡丢包、带宽打满 |
| **建连失败** | SYN 发出没回应、connection timeout | 防火墙/安全组、端口耗尽、半连接队列满 |
| **连接中断** | 已建立的连接突然断开 | 中间设备超时淘汰、对端重启、NAT 超时 |
| **吞吐骤降** | QPS 腰斩但 CPU/内存正常 | 带宽瓶颈、TCP 重传率高、滑动窗口缩小 |

## 面试答题框架

> "前端到后端突然网络抽风"，排查路径：
>
> **1. 先看有没有规律**
> - 是某个机房？某个可用区？某个运营商？还是全网？
> - 通过多维度的调用链和监控快速缩小范围
>
> **2. TCP 层面排查**
> - `netstat -s` 看 TCP 重传统计、timeout 统计
> - `ss -ti` 看当前连接的状态和 RTT
> - 关注 `TcpRetransSegs` 是否有突增——如果有，说明链路丢包
> - 看 `TcpExt.TCPTimeouts` 是否异常
>
> **3. 应用层面排查**
> - 检查连接池状态：是否打满、是否有泄漏
> - 检查 DNS 解析：是否有超时、是否有缓存失效导致的解析风暴
> - 检查是建连慢还是传输慢——tcpdump 抓包看 SYN-SYN/ACK-ACK 的时间差
>
> **4. 如果是偶发性网络问题（最难查）**
> - 全链路埋点，在调用链上记录每一步的耗时
> - 出问题时对比正常时期的数据，找出是哪个 hop 变慢了
> - 用持续 ping/mtr 监控网络质量，长期积累数据

## 常见坑与应对

| 问题 | 应对 |
|------|------|
| **TIME_WAIT 过多** | 调 `tcp_tw_reuse`、`tcp_timestamps`；或改用长连接 |
| **半连接队列满** | 增大 `tcp_max_syn_backlog`、开启 `tcp_syncookies` |
| **NAT 超时断开** | 启用 TCP keepalive，设置合理的探测间隔 |
| **容器网络抖动** | overlay 网络额外开销；考虑 macvlan/ipvlan 或 hostNetwork |
| **安全组/防火墙误拦截** | 建立网络策略变更的审批和通知机制 |
