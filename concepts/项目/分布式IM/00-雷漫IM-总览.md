## 三、核心架构组件

```
客户端(浏览器/APP)
    │ WSS (SSL加密)
    ▼
Nginx 反向代理 (SSL终止)
    │ WS (明文)
    ▼
Access 网关节点 (WebSocket网关)
    │
    ├──→ Login服务 (认证鉴权)
    ├──→ Msg服务 (消息处理)
    ├──→ PushServer (消息推送)
    └──→ Redis (缓存)
              │
         ┌────┴────┐
         ▼         ▼
      MongoDB    MySQL
     (消息存储)  (业务数据)
```

| 组件 | 职责 | 技术选型 |
|------|------|---------|
| **Access 网关** | 长连接管理、消息路由、加解密、限流 | 自研 C++ |
| **Login 服务** | 用户认证、Token 验证、Session 管理 | 自研 |
| **Msg 服务** | 消息处理、持久化、业务逻辑 | 自研 |
| **PushServer** | 消息推送、在线/离线分发 | 自研 |
| **Redis** | 登录状态、Token、消息缓存 | Redis/Codis |
| **MongoDB** | 消息持久化存储 | MongoDB 分片集群 |
| **MySQL** | 用户、好友、群组等业务数据 | MySQL MGR |

## 四、关键设计决策

| 决策 | 方案 | 原因 |
|------|------|------|
| **长连接协议** | WebSocket (WSS) | 浏览器原生支持，穿透性好 |
| **加密通道** | ECDH + RSA + AES 混合 | 安全与性能平衡 |
| **消息存储** | MongoDB | 读写性能优于 MySQL，成本更低 |
| **业务数据** | MySQL MGR | 强一致性，事务支持 |
| **缓存层** | Redis + Codis | 大容量分布式缓存 |
| **父子进程通信** | 共享内存队列 (SHM) | 替代 socketpair，减少 syscall |
