## 一、性能

| 指标 | 数值 |
|------|------|
| 单机连接数 | **120万**（16核32GB） |
| 每连接内存 | **12KB**（Connection 4KB + 读缓冲 4KB + 写缓冲 2KB + ev_io 1KB + 其他 1KB） |

| 心跳处理能力 | 10 万/秒 |
| CPU 占用（空闲） | 30% |

### 消息吞吐

| 场景 | 吞吐 | P99 延迟 |
|------|------|--------|
| 单聊消息 | **5万条/秒** | 30ms |
| 群聊（100人） | 5000条/秒 | 50ms |
| 群聊（1000人） | 500条/秒 | 200ms |
| 离线消息拉取 | 2万条/秒 | 20ms |

**延迟分解（单聊 20ms）**: 网络 2ms + 解析 1ms + 路由 2ms + DB 5ms + MQ 2ms + 推送 3ms + 网络推 5ms

### 加密性能

| 操作 | 耗时 |
|------|------|

| Token 验证（查 Redis） | 0.1ms |
| 复用 Token 省 RSA | **省 90%+ RSA 操作** |
| AES-256-GCM 加解密 | 500ns/次（AES-NI 硬件加速） |

## 二、分析

### 存储选型对比

| 维度 | MySQL | MongoDB |
|------|-------|---------|
| 集群规模 | 64×4=256 套 | 4 分片 |
| CPU 消耗 | 1024 核 | 64 核（**16:1**） |
| 内存消耗 | 4096 GB | 256 GB（**16:1**） |
| 磁盘消耗 | 120 TB | 36 TB（**3.3:1**） |

结论：IM 消息写多读少、无复杂事务，MongoDB 分片集群天然适合，资源消耗仅为 MySQL 的 1/10。

### MQ 削峰收益

```
无队列: MsgServer → PushServer(单条) → Access × 999次
有队列: MsgServer → [MQ] → PushServer(批量拉取→分组→合并) → Access × N次(网关数)
```

队列带来三个收益：削峰填谷（群聊 @所有人）、解耦容灾（PushServer 重启无损）、批量合并（按网关聚合推送）。

## 三、核心框架/核心技术

### epoll ET 模式百万连接

```
1 个 acceptor → N 个 worker（绑定 CPU）
每个 worker: epoll_wait + 非阻塞循环读写
连接分配: accept 后按 fd % N 分发
无锁通信: SPSC 队列跨线程投递
```

### 消息推送 & ACK 机制

```
MsgServer → 写 MongoDB → MQ → PushServer → 查Redis在线路由 → Access网关 → 客户端
                                              ↓ 离线
                                          离线存储 + APNs/FCM 第三方推送

ACK时机: 网关 TCP 确认后立即 ACK MQ（不等客户端 ACK，防离线卡队列）
失败重试: RECONSUME_LATER 阶梯重试（1s/5s/10s/30s...）→ 16次超限进死信队列
```

### 消息有序性 & 未读数

```
有序性: 每会话独立 seq（Redis INCR），客户端按 seq 排序展示
预分配: 每 10000 条一次 INCRBY，Redis 压力降 10000 倍

未读数: MongoDB count(msgId > lastReadMsgId AND fromId != self AND msgState != 4)
  选 MongoDB count 而非 Redis INCR → 避免撤回 DECR 丢失、避免大群写扩散
```

## 四、瓶颈

| 问题 | 现象 | 优化 | 效果 |
|------|------|------|------|
| **群消息推送量线性增长** | 1000人群 P99 200ms | 按网关节点合并 RPC | **3000次→~10次，P99→50ms** |
| **每连接内存开销大** | 原生连接 > 50KB | Connection 对象池 + 共用缓冲区 | **降至 12KB** |
| **msgseq Redis 高频 INCR** | Redis 压力大 | 批次预分配（每 10000 条一次） | **Redis 压力降 10000 倍** |
| **未读数 INCR 丢失/写扩散** | 撤回 DECR 丢失、大群写放大 | MongoDB count 替代 | **精确、无写扩散** |
| **连接风暴** | 瞬间大量建连打挂服务 | 三层限流（iptables+Nginx+Access） | **每 IP 60s 限 5 新连接** |
