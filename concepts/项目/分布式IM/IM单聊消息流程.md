# IM单聊消息流程

> 本页涵盖雷漫分布式IM系统的单聊消息发送流程，包括端到端加密和非端到端加密两种模式，以及未读数计算规则。

## 8.1 用户A发单聊到B-端到端加密-完整流程

**端到端加密单聊消息发送完整流程**:

```
┌──────────┐         ┌──────────┐         ┌──────────┐
│  用户A   │         │  服务端   │         │  用户B   │
└────┬─────┘         └────┬─────┘         └────┬─────┘
     │                    │                    │
     │ 1. 用户A输入消息    │                    │
     │                    │                    │
     │ 2. 检查A与B会话     │                    │
     │    ├─ 存在 → 复用会话ID                  │
     │    └─ 不存在 → 新建会话ID                 │
     │                    │                    │
     │ 3. 查询本地端到端密钥│                    │
     │    ├─ 有效 → 直接使用                     │
     │    └─ 无效/过期 → 发起密钥协商(见6.1流程) │
     │                    │                    │
     │ 4. 用keyX加密消息   │                    │
     │    计算HMAC签名     │                    │
     │                    │                    │
     │ 5. 封装消息体       │                    │
     │    (加密内容+密钥版本+msgId+元数据)       │
     │                    │                    │
     │─────────── 发送消息 ────────────────────▶│
     │                    │                    │
     │                    │ 6. 校验token/session│
     │                    │                    │
     │                    │ 7. 写入MongoDB      │
     │                    │    (msg_c2c表)      │
     │                    │                    │
     │                    │ 8. 更新session活跃  │
     │                    │    更新消息序列号   │
     │                    │                    │
     │                    │ 9. 查询B在线状态    │
     │                    │    ├─ 在线 → 立即推送│
     │                    │    └─ 离线 → 离线队列│
     │                    │                    │
     │                    │ 10. 更新B未读数缓存 │
     │                    │                    │
     │                    │─────────── 推送消息 ────▶│
     │                    │                    │
     │                    │                    │ 11. 收到消息包
     │                    │                    │
     │                    │                    │ 12. 解析消息体
     │                    │                    │    用本地keyX解密
     │                    │                    │    ├─ 成功 → 展示明文
     │                    │                    │    └─ 失败 → 发起密钥协商
     │                    │                    │
     │                    │                    │ 13. 记录已读消息ID
     │                    │                    │
     │                    │◀────────── 已读回执 ─────│
     │                    │                    │
     │                    │ 14. 更新A端会话状态  │
     │                    │    更新已读位置     │
     │                    │                    │
     │ 15. 本地持久化消息  │                    │ 15. 本地持久化消息
     │    加密消息+会话信息│                    │    加密消息+会话信息
```

## 8.2 用户A发单聊到B-不用端到端加密-完整流程

**非端到端加密单聊消息发送完整流程**:

```
┌──────────┐         ┌──────────┐         ┌──────────┐
│  用户A   │         │  服务端   │         │  用户B   │
└────┬─────┘         └────┬─────┘         └────┬─────┘
     │                    │                    │
     │ 1. 用户A发起消息    │                    │
     │                    │                    │
     │ 2. 获取B信息        │                    │
     │    (userId、设备等) │                    │
     │                    │                    │
     │ 3. 生成消息内容     │                    │
     │    (明文，含图片/文件)│                    │
     │    分配msgId/seq   │                    │
     │                    │                    │
     │ 4. 封装消息体       │                    │
     │    (JSON/Proto格式) │                    │
     │                    │                    │
     │ 5. 携带token/session│                    │
     │─────────── 发送消息 ────────────────────▶│
     │                    │                    │
     │                    │ 6. 校验好友关系     │
     │                    │    检查是否拉黑    │
     │                    │    ├─ 拉黑 → 拒绝投递│
     │                    │    └─ 正常 → 继续处理│
     │                    │                    │
     │                    │ 7. Redis分配msgSeq │
     │                    │    (消息序列号)     │
     │                    │                    │
     │                    │ 8. 写入MongoDB     │
     │                    │    (msg_c2c表)     │
     │                    │    (存储2份: A→B和B→A)│
     │                    │                    │
     │                    │ 9. 查询B在线状态   │
     │                    │    (Redis查询)     │
     │                    │                    │
     │                    │ 10. 推送决策       │
     │                    │     ├─ 在线 → 长连接推送│
     │                    │     └─ 离线 → 离线队列│
     │                    │                    │
     │                    │─────────── 推送消息 ────▶│
     │                    │                    │
     │                    │                    │ 11. 收到消息
     │                    │                    │
     │                    │                    │ 12. 本地保存消息
     │                    │                    │    加入会话列表
     │                    │                    │
     │                    │                    │ 13. 展示消息内容
     │                    │                    │
     │                    │                    │ 14. 用户阅读消息
     │                    │                    │    记录已读位置
     │                    │                    │
     │                    │◀────────── 已读回执 ─────│
     │                    │    (最新已读msgId)  │
     │                    │                    │
     │                    │ 15. 更新A端会话     │
     │                    │    更新已读状态     │
     │                    │                    │
     │ 16. 本地持久化      │                    │ 16. 本地持久化
     │    消息+会话信息    │                    │    消息+会话信息
```

**已读回执说明**:
- 已读回执本质上属于消息响应，即每次B客户端读到A发的消息并主动上报已读进度时，这个"已读消息"也作为一条消息记录（具有独立的msgId/seq），存储进消息表（如msg_c2c）中
- 单聊的已读回执消息的content字段通常存储的是"被已读的消息的msgId或msgSeq"

## 8.3 未读数计算

**未读数通常不直接存入MySQL表，而是只存于Redis等缓存系统**:
- 高频读写，性能需求高
- 源数据可根据消息表重算
- 缓存为主，最终一致
- 极少跨端边界持久化

**未读数缓存结构**:
```python
redis.hset(f'unread:{userid}:{sessionid}', mapping={
    'readSeq': ...,
    'lastMsgSeq': ...,
    'unreadCount': ...
})
```

**未读数计算规则**:
- 统计大于本地已读消息msgId的所有消息（cmdType为原始聊天/通知消息，fromId ≠ self），得到总数A
- "删除自己"（msgState=5）状态消息不纳入未读消息统计
- 未读数公式：未读数 = A（大于lastReadMsgId的原始消息总数，排除自己发送的）

**离线时统计未读数**:
- 用户离线时，系统统计所有会话未读数，写入MySQL的tb_no_read_sum表
- 用户再次上线时，优先从这个MySQL表里查上次离线时服务端保存的未读数
- 之后在客户端维护与服务端推送保持同步的增量消息计数
