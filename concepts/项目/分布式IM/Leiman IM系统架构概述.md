# Leiman IM系统架构概述

## 一、系统架构概述

### 1.1 整体架构

Leiman IM系统采用分层架构设计，主要包括：

```
┌─────────────────┐
│ 客户端(浏览器/APP) │
└────────┬────────┘
         │ WSS连接 (SSL加密)
         │
         ▼
┌─────────────────┐
│ Nginx反向代理     │  SSL终止，协议转换
│ (SSL反向代理)     │
└────────┬────────┘
         │ WS转发 (明文)
         │
         ▼
┌─────────────────────────┐
│  Access网关节点          │
│  (WebSocket网关)        │
└─────┬───────────────────┘
      │
      ├──────────┬──────────┬──────────┐
      │          │          │          │
      ▼          ▼          ▼          ▼
┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐
│Login服务 │ │Msg服务  │ │PushServer│ │  Redis  │
│ (认证)   │ │(消息处理)│ │(消息推送)│ │ (缓存)  │
└─────────┘ └─────────┘ └─────────┘ └────┬────┘
                                           │
                    ┌──────────────────────┴──────────────┐
                    │                                     │
                    ▼                                     ▼
            ┌──────────────┐                    ┌──────────────┐
            │   MongoDB    │                    │    MySQL     │
            │  (消息存储)   │                    │  (业务数据)   │
            └──────────────┘                    └──────────────┘
```

### 1.2 核心组件

- **Nginx反向代理**：处理WSS协议，SSL终止，转发到Access网关
- **Access网关**：WebSocket长连接管理、消息路由、加解密、限流
- **Login服务**：用户认证、Token验证、Session管理
- **Msg服务**：消息处理、持久化、业务逻辑
- **PushServer**：消息推送、在线/离线判断、厂商推送
- **Redis**：热点数据缓存、在线状态、会话信息
- **MongoDB**：消息持久化存储（分片）
- **MySQL**：业务数据存储（分库分表）

### 1.3 多设备支持

系统完全支持用户多设备同时在线：
- Redis用户登录状态缓存采用Hash类型，所有字段都带有`${deviceid}`后缀
- 每台设备独立管理sessionkey、clienttype、loginseq等
- 同一用户可在手机、平板、PC等多终端同时在线，服务端精确识别区分每台设备
