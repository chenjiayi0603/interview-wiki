# K3s 与 K8s 技术对比

> 轻量级 K3s vs 标准 K8s：架构差异、适用场景、选型建议。

---

## 一、核心区别概览

| 特性 | K3s | K8s |
|------|-----|-----|
| **内存占用** | ~512MB | 2-4GB（最小化部署） |
| **二进制大小** | ~70MB | 单组件 100-200MB |
| **组件数量** | 单进程，多合一 | 多进程，独立部署 |
| **存储后端** | SQLite（默认）/ etcd | etcd（强一致性） |
| **默认 Ingress** | Traefik | Nginx Ingress |
| **高可用** | 外部 DB + 多 Server | etcd 集群 + 多 Master |
| **设计目标** | 轻量边缘、IoT、CI/CD | 企业级生产 |

---

## 二、架构差异

### 2.1 K8s 架构

```
多组件分离，每个控制面组件独立运行：
  API Server  × 3（高可用）
  Scheduler   × 3
  Controller  × 3
  etcd        × 3（强一致性集群）
```

- 高可用设计：多 Master + etcd Raft
- 模块化：组件可独立升级
- 资源需求高：最小化部署 2-4GB

### 2.2 K3s 架构

```
单进程多合一：
  k3s server（含 API Server/Scheduler/Controller）
     └─ 存储：SQLite（单节点）/ 外部 MySQL/PostgreSQL（高可用）
  
  k3s agent（含 kubelet + kube-proxy）
```

- 精简组件：移除 Alpha 特性、云提供商插件、旧版 API
- 存储：默认 SQLite（省资源），可选 etcd/MySQL/PostgreSQL
- 二进制 ~70MB，部署秒级完成

---

## 三、选型建议

| 场景 | 推荐 | 原因 |
|------|------|------|
| 边缘计算 / IoT | K3s | 资源受限，单机部署 |
| 开发 / CI/CD 环境 | K3s | 快速搭建，低内存开销 |
| 本地测试 Istio 网格 | K3s | K3s 完全兼容标准 K8s API |
| 企业级生产 | K8s | etcd 强一致性，成熟 HA 方案 |
| 混合部署 | 边缘 K3s + 中心 K8s | 统一 API，按节点规格选择 |

**K3s 完全兼容标准 K8s API**，Istio/Envoy 等网格组件可直接运行在 K3s 上，仅性能表现受节点规格影响。
