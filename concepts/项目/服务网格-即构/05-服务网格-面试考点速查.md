# 服务网格面试考点速查

> 面试 Q&A、STAR 故事、性能数据速查。

---

## 一、项目一句话

在即构基础架构团队，从零搭建基于 K8s + Istio 的服务网格平台，沉淀统一服务治理能力（流量管理、限流熔断、故障自愈），并配套 Go 版 gRPC/HTTP SDK 与 Envoy Wasm 自适应熔断插件，推动 **10+ 业务线落地**，支撑 **QPS 5 万+**。

## 二、STAR 故事

### 背景 (Situation)

- 公司业务增长后，微服务数量和调用关系快速增加
- 各业务线治理能力不统一：重试、熔断、观测、灰度发布各自实现
- 稳定性压力大，故障恢复时间长

### 任务 (Task)

- 从零搭建服务网格平台
- 支持负载均衡、限流熔断、故障自愈等核心治理能力
- 降低业务接入成本，推动多业务线落地

### 行动 (Action)

| 模块 | 行动 | 要点 |
|------|------|------|
| **网格底座** | K8s + Istio + Envoy 架构搭建 | CRD 灰度、xDS 配置下发 |
| **Go SDK** | 统一 gRPC/HTTP 客户端 | 元数据透传、trace、指标、重试 |
| **Wasm 插件** | Envoy 自适应熔断 | 滑动窗口 + 概率熔断算法 |
| **性能调优** | Sidecar 开销压测 | 连接池、Wasm 精简、降采样 |
| **业务推动** | 标准化接入流程 | 脚手架 + 文档 + 观测看板 |

### 结果 (Result)

| 指标 | 数值 |
|------|------|
| 平台 QPS | 5 万+ |
| 覆盖业务线 | 10+ |
| 故障恢复时间 | < 5s |
| Sidecar 延迟开销 | +1~3ms |
| Sidecar QPS 损失 | ~15% |

## 三、高频面试 Q&A

### Q1: 服务网格和传统微服务框架的区别？

| 维度 | 传统框架（Spring Cloud） | 服务网格（Istio） |
|------|------------------------|------------------|
| 治理逻辑位置 | 业务代码中 | Sidecar 代理中 |
| 业务侵入性 | 高（需引入框架 SDK） | 低（业务代码无感知） |
| 升级成本 | 业务线逐服务升级 | 运维统一升级 Sidecar |
| 性能 | 无额外跳转 | 多一层代理，+1~3ms |
| 多语言支持 | 限制框架语言 | 任意语言（代理统一） |

### Q2: Istio 流量管理原理？

**答题主线：控制面 + 数据面 + 配置对象**

1. **控制面 Istiod** 将 VirtualService/DestinationRule 转为 xDS 协议
2. **数据面 Envoy** 接收 xDS 配置，执行路由、负载均衡、熔断
3. **VirtualService** 定义路由规则（path/header/权重）
4. **DestinationRule** 定义目标策略（subset/LB/连接池/熔断）

### Q3: Sidecar 开销到底有多大？

**给区间 + 说明因素 + 提优化**：

- 常见区间：CPU +5%~10%，延迟 +1~3ms
- 影响因素：QPS、包大小、连接复用、TLS、过滤器数量、日志级别
- 优化手段：连接池调优、精简 Wasm 逻辑、降采样日志、协议复用

### Q4: Wasm 插件和原生 Envoy Filter 怎么选？

| 维度 | Wasm 插件 | 原生 Filter |
|------|----------|------------|
| 安全性 | 沙箱隔离 | 进程内运行 |
| 动态加载 | ✓（热加载） | ✗（需编译 Envoy） |
| 性能 | 略低（0.5ms/请求） | 更高 |
| 调试 | 困难（沙箱限制） | 直接 |
| 选型原因 | 快速迭代治理逻辑，不改 Envoy 主体 | 核心性能路径 |

### Q5: 自适应熔断怎么做？

**观测输入 + 策略决策 + 执行动作**：

1. 输入：错误率、超时率、RT、并发水位
2. 决策：滑动窗口统计 + 概率公式 `k × accepts >= total - protection`？
3. 动作：概率返回 503（熔断）/ 半开试探 / 恢复
4. 目标：故障时快速隔离，恢复时平滑放量，< 5s 恢复

### Q6: 故障恢复 < 5 秒是怎么做到的？

1. **检测快**：Envoy 主动健康探测 + 被动调用结果统计
2. **策略快**：网格侧快速路由切换 / 熔断降级
3. **回切快**：半开试探 + 渐进放量，避免流量瞬时回灌

### Q7: SDK 解决了什么问题？

- 屏蔽网格接入细节：业务不需要关心 Sidecar 通信
- 统一中间件链：trace、metrics、metadata 透传
- 降低接入成本：脚手架 + 默认配置，业务代码几乎不改

### Q8: 如何推动 10+ 业务线接入？

1. **产品化**：脚手架 + 文档 + 默认配置，降低试错成本
2. **低风险**：灰度模板 + 回滚手册，迁移出问题可快速回退
3. **可视化**：观测看板量化收益（故障率、恢复时长、发布成功率）
