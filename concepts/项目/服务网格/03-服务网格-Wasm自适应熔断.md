# Wasm 自适应熔断

> Envoy Wasm 插件设计、自适应熔断算法、Go vs C++ Wasm 对比、性能数据。

---

## 一、自适应熔断概述

### 1.1 为什么需要自适应熔断

| 熔断方式 | 缺点 |
|---------|------|
| 固定阈值（错误率 > 50% 熔断） | 不同服务的容错能力不同，固定阈值不合理 |
| 静态配置 | 需要人工调参，无法适应流量抖动 |
| 无熔断 | 故障放大，级联雪崩 |

**自适应熔断思路**：根据实时错误率/延迟，**动态计算熔断概率**，故障时快速隔离，恢复时平滑放量。

### 1.2 算法原理

```
输入：滑动窗口内的统计数据
  - accepts: 成功请求数
  - total: 总请求数
  - protection: 最小保护值（默认 5，请求少于 5 不触发熔断）
  - k: 敏感系数（1.1~2.0，默认 1.5，越小越容易熔断）

判断逻辑：
  if total <= protection → 不熔断（请求太少，采样不足）
  else if k × accepts >= total - protection → 不熔断（正常）
  else → 概率熔断
         熔断概率 = (((total - protection) - (k × accepts)) / total + 1) × 100%
```

**关键参数**：
- `k = 1.5`：敏感系数，越小越容易熔断
- `window = 10s`：滑动窗口大小
- `protection = 5`：请求数 <= 5 时不触发熔断（避免冷启动误判）

### 1.3 算法特点

| 特性 | 说明 |
|------|------|
| **反馈型** | 熔断概率随错误率动态变化，错误降自动恢复 |
| **概率熔断** | 不是一刀切全熔断，按比例放量试探 |
| **无需预设阈值** | 自适应不同服务的正常错误率基线 |

## 二、Envoy Wasm 插件实现

### 2.1 架构位置

```
请求 → Envoy → Wasm Filter(自适应熔断) → Cluster(后端服务)
                    │
                    ├─ accepts++（正常响应）
                    ├─ rejects++（错误/超时）
                    └─ 计算熔断概率 → 直接 503 或转发
```

### 2.2 Go Wasm SDK 功能支持

| 功能 | Go Wasm | C++ Wasm |
|------|---------|----------|
| 定时回调 (OnTick) | ✓ | ✓ |
| 主动发送 HTTP | ✓ (ProxyHttpCall) | ✓ |
| 主动发送 gRPC | ✗ | ✓ |
| 修改 HTTP body/header | ✓ | ✓ |
| 配置动态更新 | ✓ | ✓ |
| 共享数据 (SharedData) | ✓ | ✓ |
| 原子计数 (Metric) | ✓ | ✓ |
| 时间函数 | 部分 (Unix/UnixNano) | ✓ |
| JSON 解析 | ✓ (buger/jsonparser) | ✓ (cjson) |
| 文件系统 | ✗ (os.Stat/Open 不可用) | ✗ |
| 反射 | ✗ (TinyGo 不支持) | ✓ |
| goroutine | ✗ (事件驱动，不可用) | ✓ |

### 2.3 Go Wasm 限制

- **TinyGo 限制**：不支持 `encoding/json`（反射）、`recover`、`goroutine`、`time.Now()`
- **VM 隔离**：每个 Envoy 启动多个 Wasm VM，VM 间数据隔离，需用 `proxywasm.SharedData` API 跨 VM 共享数据
- **适用场景**：轻量级统计 + 简单逻辑判定；复杂逻辑建议用 C++ Wasm 或下沉到业务服务

### 2.4 C++ Wasm 实现性能

| 指标 | 数值 |
|------|------|
| 插件编译后大小 | 2MB |
| 冷启动时间 | 50ms |
| 热执行时间 | 0.5ms/请求 |
| 内存占用 | 50MB |
| CPU 占用 | 5% |

## 三、熔断测试数据

### 3.1 原生 vs Wasm 熔断

| 指标 | 原生熔断 | Wasm 自适应熔断 (k=1.5, window=10s) |
|------|---------|-----------------------------------|
| QPS | ~7,500 | ~7,458 |
| Code 501 (自定义错误) | — | 0.5% |
| Code 504 (网关超时) | — | 99.5% |

两者 QPS 接近，Wasm 自适应熔断额外开销可忽略。

### 3.2 压测结论

| 条件 | 结论 |
|------|------|
| QPS 较低时 | k 系数越小熔断概率越高；滑动窗口越大熔断概率越高 |
| 请求数不足时 | 算法为反馈型，开始无采样数据，结果不准确 |
| 请求数越多 | 压测结果越准确，熔断越接近预期概率 |
| 统计窗口越大 | 计算结果越准确，但增加熔断生效时延 |

### 3.3 熔断恢复

| 指标 | 数值 |
|------|------|
| 熔断触发 | 错误率超过动态阈值 |
| 半开试探 | 概率放量试探是否恢复 |
| 恢复时间 | < 5s（从熔断到正常） |
