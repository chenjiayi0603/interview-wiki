# 社交 IM 数据存储

> Redis 数据结构设计、MySQL 分片策略、Key 命名规范。

---

## 一、Redis 数据结构设计

### 1.1 Key 命名规范

```
格式：{数据类型}:{业务编码}:{功能}:{标识字段}:{标识值}
```

| 段位 | 说明 | 示例 |
|------|------|------|
| 第 1 位 | 数据类型：1=Hash, 2=Set, 4=String, 6=Sorted Set | `1` |
| 第 2-4 位 | 业务编码（功能编号） | `001` |
| 后续 | 功能描述 + 标识字段 + 标识值 | `imuid` |

### 1.2 用户数据

#### IM 用户属性 (Hash)

```
Key:  1:1:{imuid}
Field:
  imid                      IM 用户 ID
  guid                      业务用户 ID
  nickname                  用户昵称
  avatar_url                用户头像
  introduction              用户简介
  sex                       性别
  location                  所在地
  last_login_time           最后一次上线时间
  last_logout_time          最后一次下线时间
  login_count               登录次数
  online_time               总在线时长
  member_level              会员等级
  mobile                    手机号码（加密）
  password                  密码
  login_history             登录记录
  ...（更多字段见源码定义）
```

#### 用户在线状态 (Hash)

```
Key:  1:5:{imuid}
Fields:
  token     登录验证 Token
  app       移动端接入的 Access 节点，如 192.168.11.12:9988.2
  web       Web 端接入的 HttpAccess 节点，如 192.168.10.16:8081.3
  deviceInfo 设备号
```

### 1.3 好友关系

#### 好友关系 (Hash)

```
Key:  1:2:{imuid}
Fields:  {friend_imuid} → 好友关系记录
```

#### 关注列表 (Sorted Set)

```
Key:  6:15:{imuid}
Score:  time（uint64）
Member: {followed_imuid}
```

#### 粉丝列表 (Sorted Set)

```
Key:  6:16:{imuid}
Score:  time（uint64）
Member: {fans_imuid}
```

### 1.4 群数据

#### 群信息 (Hash)

```
Key:  1:3:{group_id}
Fields:
  group_id        群 ID
  owner_id        群主 ID
  guid            群主业务 ID
  group_name      群名称
  group_theme     群主题
  group_avatar    群头像
  group_intro     群简介
  group_type      群类型
  is_valid        是否有效
  group_scale     群规模
  group_count     成员数量
  is_public       是否公开
  joinverify_type 加群验证
  group_loc       所在地
  group_liveness  活跃度
  create_time     创建时间
  project_id      业务标识 ID
```

#### 群成员信息 (Hash)

```
Key:  1:4:{group_id}
Fields:  {imuid} → 成员在群中的信息
```

#### 用户拥有的群列表 (Hash)

```
Key:  1:8:{imuid}
Fields:  {group_id} → 群基础信息
```

#### 群 ID 生成器 (String)

```
Key:  4:9:GET_GROUPID
Value: INCR 自增
```

### 1.5 消息存储

#### 单聊 — 接收者消息 (Hash，不失效)

```
Key:  1:1001:{self_imuid}:{other_imuid}
Field:  {msg_serial_t} → Message Record
```

用于接收方拉取单聊消息。

#### 单聊 — 发送者消息 (Hash，有时效)

```
Key:  1:1022:{self_imuid}:{other_imuid}
Field:  {msg_serial_t} → Message Record
```

#### 单聊消息好友列表 (Set)

```
Key:  2:1002:{imuid}
Values:  {uid1} {uid2} {uid3} ...
```

离线消息推送完毕后从 Set 中删除对应 uid。

#### 群聊消息结构 (Hash，按天分块)

```
Key:  1:1003:{group_id}:{YYYYMMDD}
Field:  {msg_serial_t}
Value:  Message Record（PB 序列化）
```

每周日为一周开始，按周生成一个 key。

#### 群聊消息 ID 列表 (Sorted Set)

```
Key:  6:1004:{group_id}:{YYYYMMDD}
Member:  {msgid}
Score:   时间戳
```

用于消息失败重发或离线推送。

#### 群聊消息接收状态 (Hash)

```
Key:  1:1005:{imuid}
Fields:  {group_id} → 最近一条 msg_serial_t
```

每个用户对每个群最近接收的消息 ID。

#### 群最近消息 ID (String)

```
Key:  4:1006:{group_id}
Value:  最近一条消息的 serial_t（永久保存）
```

### 1.6 群通知

#### 群通知详情 (String，保存 1 个月)

```
Key:  4:1009:{group_id}:{msg_id}
Value:  Message Record（PB 序列化）
```

#### 群通知列表 (Sorted Set，保存 1 个月)

```
Key:  6:1010:{group_id}
Member:  {msgid}
Score:   时间戳
```

用于通知失败重发或离线通知推送。

#### 群通知接收状态 (Hash，保存 3 个月)

```
Key:  1:1011:{imuid}
Fields:  {group_id} → 最近一条 msg_serial_t
```

Redis 中无此结构时，将用户所在群的未读通知全部推送。

### 1.7 个人通知

#### 通知详情 (String)

```
Key:  4:1007:{imuid}:{msg_id}
Value:  Message Record（保存 3 个月）
```

用户确认收到后从 Redis 中删除。

#### 通知列表 (Set)

```
Key:  2:1008:{imuid}
Values:  {msg_id1} {msg_id2} ...
```

通知确认送达后从列表中删除。

### 1.8 你我圈（朋友圈）

#### 说说内容 (Hash，分块存储)

```
Key:  1:1013:{msgid}:{index}
Field:  {msg_serial_t} → Message Record
```

每块最多 2000 条（说说 + 评论 + 回复 + 点赞），index 从 0 开始。

#### 发表的说说列表 (Sorted Set)

```
Key:  6:1014:{imuid}
Score:  {msgid}
Member: 说说 ID
```

用于查看自己的说说，利用 msgid 的时间有序性。

#### 收听的说说列表 (Sorted Set)

```
Key:  6:1015:{imuid}
Score:  {msgid}
Member: {imuid}:{msgid}
```

用户发表说说时，遍历其粉丝写入此列表。保留最近一年的数据，每次写入时 `ZREMRANGEBYSCORE` 删除一年前的记录。若列表不存在，则遍历好友列表拉取。

#### 点赞用户列表 (Hash)

```
Key:  1:1016:{msgid}
Fields:  {imuid} → {点赞消息 ID}
```

每个用户对一条说说只能点赞一次。客户端拉取说说时附带点赞状态。

#### 评论数量 (String)

```
Key:  4:1017:{msgid}
Value:  评论/回复数量（INCR 增加，DECR 减少）
```

### 1.9 敏感词库

#### 敏感词列表 (Set)

```
Key:  2:23:{sensitive_type}:{secondary_type}
Values:  {word} {word} {word} ...
```

## 二、MySQL 分库分表

### 2.1 分片规则

```cpp
// 32 个库，按用户 ID 取模
int GetShardId(uint64_t user_id) {
    return user_id % 32;
}

// 每库 64 张表，按用户 ID 二次取模
int GetTableId(uint64_t user_id) {
    return (user_id / 32) % 64;
}
```

### 2.2 容量验证

```
用户数：1000 万
每用户平均消息：100 条
总消息量：10 亿条

分片后：
- 32 库 × 64 表 = 2048 张表
- 每表约 10亿 / 2048 = 48.8 万条
- 单表 < 500 万，满足设计要求
```

## 三、总结

| 维度 | 存储方案 |
|------|---------|
| **热数据** | Redis（Codis 集群 16 节点 / 128GB / 95% 命中率） |
| **消息主存储** | MySQL（32 库 × 64 表，按 user_id 分片） |
| **冷数据** | MongoDB（历史消息归档） |
| **敏感词** | Redis Set + DFA 算法匹配 |
| **缓存策略** | 先更新 DB，再失效缓存 |
