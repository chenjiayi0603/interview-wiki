# 高频交易 / 实时系统的调度配置模板

## 概述

将两个文档内容抽象成一个典型“低延迟服务”的调度优化模板，可用于面试回答或实战 checklist。

[src: raw/ingested/2技术/性能优化/调度优化-调度优化-总结-九、高频交易---实时系统的调度配置模板（示例）.md]

## 1. 内核与系统层

- 使用 PREEMPT_RT 内核（如需要软实时/准硬实时）。
- `kernel.sched_rt_period_us=1000000`、`kernel.sched_rt_runtime_us=-1`（专机场景）或适度配置。
- 禁用透明大页 THP；`vm.swappiness=0`；CPU governor 设置为 `performance`。

[src: raw/ingested/2技术/性能优化/调度优化-调度优化-总结-九、高频交易---实时系统的调度配置模板（示例）.md]

## 2. CPU / NUMA 规划

- 挑出 N 个物理核作为“实时核”，隔离普通任务与大部分内核线程。
- 每个实时核上只跑一个关键业务线程 + 对应的网卡队列 IRQ + 必要内核线程。
- 使用 `numa_run_on_node` + `numa_alloc_onnode` 等实现本地计算 + 本地内存。

[src: raw/ingested/2技术/性能优化/调度优化-调度优化-总结-九、高频交易---实时系统的调度配置模板（示例）.md]

## 3. 中断与网络路径

- 为每个网卡 RX/TX 队列指定 IRQ 亲和到对应 CPU。
- 关闭 `irqbalance`，防止内核自动迁移中断。
- 若使用 DPDK 等用户态网络栈，则让 poll 线程与队列/核一一对应。

[src: raw/ingested/2技术/性能优化/调度优化-调度优化-总结-九、高频交易---实时系统的调度配置模板（示例）.md]

## 4. 线程调度策略

- 关键环路：`SCHED_FIFO` + 高实时优先级（如 80~95），绑定专用核。
- 多个实时子模块：`SCHED_RR`，合理分配优先级，避免饿死。
- 非关键线程：`SCHED_OTHER`，适度提高 nice。

[src: raw/ingested/2技术/性能优化/调度优化-调度优化-总结-九、高频交易---实时系统的调度配置模板（示例）.md]

## 5. 内存与页面

- 关键进程启动后立即 `mlockall(MCL_CURRENT | MCL_FUTURE)`，并预热主要数据结构。
- 对关键队列/池/Buffer 使用预分配 + 对象池，消除运行期 new/delete 导致的不可预测阻塞。

[src: raw/ingested/2技术/性能优化/调度优化-调度优化-总结-九、高频交易---实时系统的调度配置模板（示例）.md]

## 6. 验证与回归

- 利用 cyclictest 或等价程序，在每次大改调度/系统参数后重新打基线。
- 持续统计 P50/P99/P99.9/Max，尤其观测尾部延迟是否收敛。
- 对异常尖峰用 ftrace/perf/BPF 做一次“根因定位”，避免隐患长期存在。

## 小结

- 调度优化是 **“调度策略 + CPU/NUMA 拓扑 + 中断路由 + 内存行为 + 系统参数”** 的综合工程，而不是单一参数调优。
- PREEMPT_RT、SCHED_FIFO/SCHED_RR、CPU & IRQ 亲和、NUMA 本地化、mlock + 预热，是两个文档中在调度层面最值得“背下来并实战”的一组组合拳。
- 结合 cyclictest 等工具，可以形成一套“可度量、可回归”的调度优化闭环，用于支撑高频交易、实时控制、低延迟网关等对确定性要求极高的系统。
